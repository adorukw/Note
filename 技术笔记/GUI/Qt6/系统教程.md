# 第一章：Qt6 基础入门

本章带你从零开始认识 Qt6，搭建开发环境，编写第一个程序，并理解 Qt 项目的组织方式与构建系统。完成本章后，你将具备独立创建、编译、运行 Qt6 项目的能力。

## 第 1 讲：Qt6 简介与环境搭建

### 概念

**Qt** 是一个跨平台 C++ 应用程序开发框架，由挪威 Trolltech 公司于 1995 年发布，现由 Qt Company 维护。**Qt6** 是其第六个大版本，于 2020 年 12 月正式发布，基于 C++17 标准，引入了新的图形架构（RHI）、QML 引擎升级（V8 → QV4 → 新 QML 类型编译器）、以及更现代化的 C++ API。

Qt 不仅是 GUI 库，它是一个完整的"应用开发框架"，涵盖：网络、数据库、多媒体、3D、定位、传感器、并发等模块。一次编写，可在 Windows、macOS、Linux、Android、iOS、嵌入式 Linux 等平台运行。

### 原理

Qt6 的核心设计思想有三点：

1. **元对象系统（Meta-Object System）**：通过 `Q_OBJECT` 宏和 `moc`（Meta-Object Compiler）编译器，在标准 C++ 之上扩展出"信号槽""属性系统""动态类型信息"等能力。`moc` 会在编译前预处理头文件，生成额外的 `moc_xxx.cpp` 文件，把类的元信息（类名、信号、槽函数签名等）以数据结构形式嵌入。

2. **跨平台抽象层**：Qt 把不同平台的 API（Win32、Cocoa、X11/Wayland）封装在底层，向上提供统一的 C++ API。例如 `QFile` 在 Windows 上调用 `CreateFile`，在 Linux 上调用 `open()`，但用户代码完全一致。

3. **RHI（Rendering Hardware Interface）**：Qt6 引入的新图形抽象层，把 OpenGL、Vulkan、Metal、Direct3D 统一为一套 API，让 Qt Quick 在不同平台自动选择最优后端，无需用户关心。

### 例子

**安装 Qt6（以 Ubuntu/Debian 为例）**：

```bash
# 安装 Qt6 开发包与构建工具
sudo apt update
sudo apt install qt6-base-dev qt6-base-dev-tools cmake build-essential

# 验证安装
qmake6 --version
# 输出示例：QMake version 3.1, using Qt version 6.5.0
```

**Windows / macOS 用户**：推荐从官网下载 Qt Online Installer，选择 Qt 6.5+ 与 MinGW/MSVC（Windows）或 clang（macOS）套件。

**最小可运行项目结构**：

```
hello/
├── CMakeLists.txt
└── main.cpp
```

`CMakeLists.txt`：

```cmake
cmake_minimum_required(VERSION 3.16)
project(hello LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

find_package(Qt6 REQUIRED COMPONENTS Core Widgets)

qt_standard_project_setup()

add_executable(hello main.cpp)
target_link_libraries(hello PRIVATE Qt6::Core Qt6::Widgets)
```

### 总结

- **关键要点**：Qt6 是跨平台 C++ 框架，核心由元对象系统、跨平台抽象层、RHI 图形架构三大支柱构成。
- **环境搭建**：Linux 用包管理器，Windows/macOS 用官方安装器；务必选 Qt 6.5+ 与 C++17 编译器。
- **常见坑**：
  - 不要混用 Qt5 和 Qt6 的开发包，会导致符号冲突。
  - Windows 上若用 MSVC，需安装 Visual Studio 2019+；若用 MinGW，需选 64 位版本。
  - CMake 必须是 3.16 以上，否则不支持 `qt_standard_project_setup()`。

## 第 2 讲：第一个 Qt 程序 —— Hello World

### 概念

本讲通过一个最简单的窗口程序，让你直观感受 Qt 程序的运行流程。我们将创建一个带按钮的窗口，点击按钮时退出程序。这个例子虽小，但涵盖了 Qt GUI 程序的"骨架"：`QApplication`、`QWidget`、事件循环、信号槽连接。

### 原理

Qt GUI 程序的运行机制：

1. **`QApplication` 对象**：每个 GUI 程序有且仅有一个 `QApplication` 实例，它负责初始化 Qt 资源、解析命令行参数、启动**事件循环（Event Loop）**。
2. **事件循环**：`app.exec()` 启动一个无限循环，不断从操作系统消息队列取出事件（鼠标点击、键盘按键、定时器、网络响应等），分发给对应的窗口/控件处理。直到调用 `quit()` 才退出。
3. **窗口显示**：`widget.show()` 把窗口加入事件队列，下一轮事件循环时由系统真正绘制到屏幕。
4. **信号槽连接**：`QObject::connect()` 把"按钮被点击"这个信号（`clicked`）与"程序退出"这个槽（`quit`）绑定，实现"点击即退出"。

### 例子

`main.cpp`：

```cpp
#include <QApplication>
#include <QPushButton>
#include <QWidget>
#include <QVBoxLayout>

int main(int argc, char *argv[]) {
    // 1. 创建应用对象（管理 GUI 程序资源）
    QApplication app(argc, argv);

    // 2. 创建主窗口
    QWidget window;
    window.setWindowTitle("Hello Qt6");
    window.resize(320, 200);

    // 3. 创建按钮并放入布局
    QPushButton *button = new QPushButton("点击我退出", &window);
    QVBoxLayout *layout = new QVBoxLayout(&window);
    layout->addWidget(button);

    // 4. 信号槽：按钮点击 -> 程序退出
    QObject::connect(button, &QPushButton::clicked, &app, &QApplication::quit);

    // 5. 显示窗口
    window.show();

    // 6. 启动事件循环（阻塞，直到 quit 被调用）
    return app.exec();
}
```

**编译运行**：

```bash
mkdir build && cd build
cmake ..
make -j$(nproc)
./hello
```

运行后会出现一个 320×200 的窗口，标题为 "Hello Qt6"，中间一个按钮，点击即退出。

### 总结

- **关键要点**：Qt GUI 程序的骨架是 `QApplication` + 窗口 + `show()` + `exec()`；信号槽是连接用户操作与程序响应的桥梁。
- **`exec()` 是阻塞的**：调用后代码不会继续往下走，直到事件循环退出。
- **常见坑**：
  - 忘记调用 `show()`，窗口不会显示。
  - 在 `exec()` 之前创建的窗口，必须在 `exec()` 之前 `show()`，否则要等下一次事件触发。
  - `QPushButton::clicked` 是信号，`QApplication::quit` 是槽，连接时用函数指针形式（Qt5+ 推荐写法），比传统的 `SIGNAL()/SLOT()` 宏更安全（编译期检查）。

## 第 3 讲：项目结构与 CMake 构建系统

### 概念

真实项目不会只有一个 `main.cpp`，而是由多个类、UI 文件、资源文件、翻译文件组成。Qt6 推荐使用 **CMake** 作为构建系统（Qt5 时代的 `qmake` 仍支持但已不推荐新项目使用）。本讲讲解 Qt6 项目的标准结构，以及 CMake 中常用的 Qt 专用命令。

### 原理

CMake 是一个"构建系统生成器"：它根据 `CMakeLists.txt` 生成对应平台的构建文件（Linux 的 Makefile、Windows 的 .sln、macOS 的 .xcodeproj），再由底层工具执行编译。

Qt6 在 CMake 中提供了一组专用命令，封装了 `moc`、`uic`（UI 编译器）、`rcc`（资源编译器）的调用：

| 命令 | 作用 |
|------|------|
| `find_package(Qt6 COMPONENTS Core Widgets ...)` | 查找 Qt6 模块 |
| `qt_standard_project_setup()` | 启用 Qt6 的默认 CMake 设置（自动 moc/uic/rcc） |
| `qt_add_executable(name src...)` | 创建可执行目标（替代 `add_executable`，处理 Android 等特殊平台） |
| `qt_add_resources(name file.qrc)` | 编译 .qrc 资源文件 |
| `qt_add_translation(name ts...)` | 编译翻译文件 |

**自动 moc**：当 `qt_standard_project_setup()` 启用后，CMake 会自动扫描源文件，发现含 `Q_OBJECT` 宏的类就自动调用 `moc`，无需手动指定。

### 例子

**典型项目结构**：

```
myapp/
├── CMakeLists.txt
├── main.cpp
├── mainwindow.h
├── mainwindow.cpp
├── mainwindow.ui          # Qt Designer 设计的界面
└── resources.qrc          # 资源文件（图片、图标等）
```

`CMakeLists.txt`：

```cmake
cmake_minimum_required(VERSION 3.16)
project(myapp LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_AUTOMOC ON)        # 自动处理 moc
set(CMAKE_AUTOUIC ON)        # 自动处理 uic（.ui 文件）
set(CMAKE_AUTORCC ON)        # 自动处理 rcc（.qrc 文件）

find_package(Qt6 REQUIRED COMPONENTS Core Widgets Gui)

qt_standard_project_setup()

qt_add_executable(myapp
    main.cpp
    mainwindow.cpp
    mainwindow.h
    mainwindow.ui
)

target_link_libraries(myapp PRIVATE
    Qt6::Core
    Qt6::Gui
    Qt6::Widgets
)

# 安装规则（可选）
install(TARGETS myapp DESTINATION bin)
```

`resources.qrc` 示例：

```xml
<RCC>
    <qresource prefix="/">
        <file>images/logo.png</file>
        <file>icons/app.ico</file>
    </qresource>
</RCC>
```

代码中访问资源：`QPixmap(":/images/logo.png")`，前缀 `:` 表示从编译进二进制的资源中读取。

### 总结

- **关键要点**：Qt6 项目用 CMake 管理；`qt_standard_project_setup()` + `CMAKE_AUTOMOC/AUTOUIC/AUTORCC` 三件套自动处理 moc/uic/rcc。
- **资源系统**：`.qrc` 文件把图片等资源编译进二进制，运行时用 `:/path` 访问，避免依赖外部文件路径。
- **常见坑**：
  - 头文件中含 `Q_OBJECT` 但未启用 `AUTOMOC`，链接时报 "undefined reference to vtable"。
  - `.ui` 文件修改后未重新编译，运行时界面不更新（CMake 一般会自动检测，但偶尔需要 `make clean`）。
  - `qt_add_executable` 比 `add_executable` 更推荐，因为它处理了 Android 等平台的特殊需求。

## 第 4 讲：Qt 命名规范与核心模块概览

### 概念

Qt 有一套严格的命名规范，遵循它能让代码风格统一、可读性高，也便于阅读 Qt 官方文档。同时，Qt6 由数十个模块组成，了解模块划分有助于快速定位所需功能。

### 原理

**命名规范**：

| 元素 | 规范 | 示例 |
|------|------|------|
| 类名 | 大驼峰，前缀 `Q` | `QString`、`QPushButton` |
| 函数名 | 小驼峰 | `setText()`、`isEnabled()` |
| 信号 | 小驼峰，过去式或名词 | `clicked()`、`textChanged()` |
| 槽函数 | 小驼峰，常以 `on_` 开头 | `onButtonClicked()` |
| 成员变量 | 小驼峰，常以 `m_` 前缀 | `m_count`、`m_window` |
| 枚举值 | 大驼峰 | `Qt::AlignCenter`、`QIODevice::ReadOnly` |
| 宏 | 全大写 | `Q_OBJECT`、`Q_DECLARE_METATYPE` |

**信号槽命名约定**：信号通常用动词或动词过去式（`clicked`、`triggered`），槽函数描述"做什么"（`openFile`、`closeWindow`）。

**核心模块概览**：

| 模块 | 作用 | 典型类 |
|------|------|--------|
| Qt Core | 核心非 GUI 功能：对象模型、容器、I/O、线程 | `QObject`、`QString`、`QFile`、`QThread` |
| Qt GUI | GUI 基础：窗口、事件、图像、字体 | `QWindow`、`QImage`、`QFont`、`QPainter` |
| Qt Widgets | 传统桌面控件 | `QWidget`、`QPushButton`、`QMainWindow` |
| Qt Network | TCP/UDP/HTTP 网络编程 | `QTcpSocket`、`QNetworkAccessManager` |
| Qt SQL | 数据库访问 | `QSqlDatabase`、`QSqlQuery` |
| Qt Multimedia | 音视频播放/录制 | `QMediaPlayer`、`QAudioOutput` |
| Qt QML | 声明式 UI 语言 | `QQmlApplicationEngine` |
| Qt Quick | QML 的可视化元素 | `QQuickView`、`QQuickItem` |
| Qt Concurrent | 高级并发 API | `QtConcurrent::run`、`QFuture` |
| Qt SVG | SVG 渲染 | `QSvgRenderer` |

### 例子

**命名规范示例**：

```cpp
class Player : public QObject {
    Q_OBJECT
public:
    explicit Player(QObject *parent = nullptr);

    int currentScore() const;
    void setScore(int score);

signals:
    void scoreChanged(int newScore);   // 信号：值变化

public slots:
    void onLevelUp();                   // 槽：升级处理

private:
    int m_score = 0;                    // 成员变量
    QString m_playerName;
};
```

**模块使用示例**（在 CMake 中链接不同模块）：

```cmake
# 网络模块
find_package(Qt6 REQUIRED COMPONENTS Core Network)
target_link_libraries(myapp PRIVATE Qt6::Core Qt6::Network)

# 数据库模块
find_package(Qt6 REQUIRED COMPONENTS Core Sql)
target_link_libraries(myapp PRIVATE Qt6::Core Qt6::Sql)
```

代码中：

```cpp
#include <QNetworkAccessManager>   // Qt Network
#include <QSqlDatabase>            // Qt SQL
#include <QMediaPlayer>            // Qt Multimedia
```

### 总结

- **关键要点**：Qt 命名规范是"类大驼峰+Q前缀、函数小驼峰、成员 m_ 前缀"；模块化设计让按需引入成为可能。
- **模块依赖**：`Qt Widgets` 依赖 `Qt GUI` 依赖 `Qt Core`，链接时只需写最上层，CMake 自动传递依赖。
- **常见坑**：
  - 忘记在 CMake 中 `find_package` 对应模块，编译报 "No such file or directory"。
  - 类名不加 `Q` 前缀虽然能编译，但不符合 Qt 风格，团队协作时会被吐槽。
  - 信号命名避免用 `onXxx`，因为 Qt 的"自动连接"机制（`QMetaObject::connectSlotsByName`）会把 `on_<对象名>_<信号名>` 自动连到槽，命名冲突会引发意外连接。

# 第二章：核心基础

本章深入 Qt 的"心脏"：对象模型、信号槽、字符串、容器。这些是所有 Qt 程序的基石，理解它们才能写出地道的 Qt 代码。

## 第 5 讲：QObject 与 Qt 对象模型

### 概念

`QObject` 是 Qt 所有类的根基类（GUI 类、非 GUI 类大多继承自它）。它提供了三大核心能力：**对象树（自动内存管理）**、**信号槽**、**事件处理**。理解 `QObject` 是理解 Qt 的关键。

### 原理

**1. 对象树与自动内存管理**

每个 `QObject` 都有一个 `parent` 指针，指向其父对象；父对象维护一个 `children()` 列表。当父对象被 `delete` 时，会自动 `delete` 所有子对象。这种"树形所有权"机制让 Qt 程序很少出现内存泄漏，也无需手动管理子对象生命周期。

```
QMainWindow (parent)
├── QMenuBar
├── QStatusBar
└── QWidget (central widget)
    ├── QLabel
    ├── QLineEdit
    └── QPushButton
```

销毁 `QMainWindow` 时，整棵树自动递归销毁。

**2. 元对象系统**

`Q_OBJECT` 宏在类声明中展开为一组静态元数据，`moc` 编译器读取这些数据，生成 `moc_xxx.cpp`，其中包含：
- 类名、父类名
- 所有信号的签名
- 所有槽的签名
- 属性信息
- `qt_metacall()` 函数：通过字符串名调用槽、获取属性

这使得 Qt 支持"运行时反射"——可以用字符串名调用方法，QML/JavaScript 也能调用 C++ 对象。

**3. 事件处理**

`QObject` 有 `event(QEvent*)` 虚函数，所有事件都经过它分发。子类可重写以拦截事件。

### 例子

**对象树示例**：

```cpp
#include <QObject>
#include <QDebug>

class Widget : public QObject {
public:
    Widget(const QString &name, QObject *parent = nullptr)
        : QObject(parent), m_name(name) {
        qDebug() << m_name << "created";
    }
    ~Widget() override {
        qDebug() << m_name << "destroyed";
    }
private:
    QString m_name;
};

int main() {
    Widget *root = new Widget("root");

    // 子对象自动加入 root 的 children 列表
    Widget *child1 = new Widget("child1", root);
    Widget *child2 = new Widget("child2", root);
    Widget *grandchild = new Widget("grandchild", child1);

    // 只 delete root，所有后代自动销毁
    delete root;
    // 输出顺序：
    // root created / child1 created / child2 created / grandchild created
    // grandchild destroyed / child2 destroyed / child1 destroyed / root destroyed
}
```

**Q_OBJECT 宏的必要性**：

```cpp
class Bad : public QObject {
    // 没有 Q_OBJECT，信号槽不工作！
};

class Good : public QObject {
    Q_OBJECT   // 必须有，否则 moc 不处理此类
public slots:
    void doSomething() {}
};
```

### 总结

- **关键要点**：`QObject` 提供对象树（自动内存管理）、元对象系统（反射）、事件处理三大能力；`Q_OBJECT` 宏是启用元对象系统的开关。
- **对象树规则**：创建子对象时传入 `parent`，父对象销毁时子对象自动销毁；栈上的 `QObject` 不要指定堆上的 `parent`（会导致 double free）。
- **常见坑**：
  - 类继承 `QObject` 但忘了 `Q_OBJECT` 宏 → 信号槽失效，且 `qobject_cast` 返回 `nullptr`。
  - 局部 `QObject` 变量（栈对象）指定了 `parent` → 函数返回时栈对象析构，`parent` 仍持有其指针，后续访问崩溃。
  - 同一对象 `delete` 两次 → 通常因为手动 `delete` 了已有 `parent` 的子对象，应改为 `deleteLater()`。

## 第 6 讲：信号与槽机制

### 概念

**信号（Signal）** 是对象状态变化时发出的通知；**槽（Slot）** 是响应信号的函数。信号槽机制是 Qt 的核心特性，让任意两个对象能松耦合地通信，是"观察者模式"的优雅实现。

### 原理

**信号槽 vs 回调函数**：

| 特性 | 回调函数 | 信号槽 |
|------|---------|--------|
| 耦合度 | 高（调用方需知道被调函数签名） | 低（只关心信号名） |
| 多对多 | 难（需维护函数指针列表） | 天然支持（一个信号可连多个槽，多个信号可连一个槽） |
| 跨线程 | 需手动同步 | 自动队列连接 |

**连接类型**（`Qt::ConnectionType`）：

| 类型 | 行为 |
|------|------|
| `Qt::DirectConnection` | 立即在发射线程直接调用槽（同步） |
| `Qt::QueuedConnection` | 把调用事件放入槽所在线程的事件队列，等其事件循环处理（异步） |
| `Qt::AutoConnection`（默认） | 同线程→Direct，跨线程→Queued，自动判断 |
| `Qt::BlockingQueuedConnection` | 队列连接，但发射方阻塞等待槽执行完（仅跨线程） |
| `Qt::UniqueConnection` | 防重复连接，相同连接只生效一次 |

**底层机制**：`connect()` 时，Qt 把"信号指针"和"槽指针"记录在 `QObject` 的连接表中。`emit signal()` 实际是调用 `moc` 生成的 `signal()` 函数，遍历连接表，按连接类型调用对应槽。

### 例子

**自定义信号槽**：

```cpp
// counter.h
#include <QObject>

class Counter : public QObject {
    Q_OBJECT
public:
    explicit Counter(int value = 0, QObject *parent = nullptr)
        : QObject(parent), m_value(value) {}

    int value() const { return m_value; }

signals:
    void valueChanged(int newValue);   // 信号声明（无需实现）

public slots:
    void setValue(int value) {
        if (m_value == value) return;   // 值未变，不发射信号
        m_value = value;
        emit valueChanged(m_value);     // 发射信号
    }

private:
    int m_value;
};
```

**使用**：

```cpp
#include "counter.h"
#include <QDebug>

int main() {
    Counter a(10);
    Counter b(0);

    // a 的值变化 -> b 的 setValue
    QObject::connect(&a, &Counter::valueChanged,
                     &b, &Counter::setValue);

    // 一个信号连多个槽
    QObject::connect(&a, &Counter::valueChanged,
                     [](int v) { qDebug() << "Lambda got:" << v; });

    a.setValue(20);   // 触发：b.value 变 20，Lambda 打印 "Lambda got: 20"
    qDebug() << "a:" << a.value() << " b:" << b.value();

    return 0;
}
```

**Lambda 作为槽**（Qt5+ 推荐写法，适合简单逻辑）：

```cpp
QPushButton *btn = new QPushButton("Click");
connect(btn, &QPushButton::clicked, [](bool checked) {
    qDebug() << "Button clicked, checked =" << checked;
});
```

### 总结

- **关键要点**：信号槽是松耦合通信机制；`connect()` 用函数指针形式（编译期检查）；默认 `AutoConnection` 自动处理跨线程。
- **信号只需声明，无需实现**：`moc` 会自动生成实现。
- **常见坑**：
  - 信号槽参数不匹配：信号参数必须 ≥ 槽参数（槽可忽略多余参数），且类型兼容。
  - `connect` 第五参数指定 `Qt::DirectConnection` 跨线程连接槽，槽函数访问 GUI 控件 → 崩溃（GUI 必须在主线程）。
  - 临时对象发射信号后立即销毁，槽函数访问其成员 → 崩溃。用 `QObject::deleteLater()` 延迟销毁。
  - 重复 `connect` 同一对信号槽 → 槽被调用多次。用 `Qt::UniqueConnection` 防重复。

## 第 7 讲：QString 字符串处理

### 概念

`QString` 是 Qt 的字符串类，使用 UTF-16 编码，提供丰富的字符串操作 API。相比 `std::string`，它原生支持 Unicode、隐式共享（写时复制）、与 Qt 其他类无缝集成。在 Qt 程序中应优先使用 `QString` 而非 `std::string`。

### 原理

**1. 隐式共享（Copy-On-Write）**

`QString` 内部维护一个引用计数的共享数据块。复制 `QString` 时只增加引用计数，不真正拷贝数据；只有当修改时才真正复制（COW）。这让传值 `QString` 几乎和传指针一样高效。

```cpp
QString a = "hello";   // 引用计数 1
QString b = a;          // 引用计数 2，共享数据
b[0] = 'H';             // b 触发 COW，复制数据；a 仍指向原数据
```

**2. UTF-16 编码**

每个字符用 16 位（`QChar`）存储，能直接表示 BMP（基本多文种平面）字符。对于补充平面字符（如 emoji），用代理对（surrogate pair）表示，需用 `QChar::isSurrogate()` 判断。

**3. 与 C 字符串互转**

- `QString → const char*`：`qPrintable(str)` 或 `str.toUtf8().constData()`（临时对象，仅短期使用）
- `const char* → QString`：`QString::fromUtf8(cstr)` 或 `QString(cstr)`

### 例子

**常用操作**：

```cpp
#include <QString>
#include <QDebug>

int main() {
    // 构造
    QString s1 = "Hello";
    QString s2 = QString("Qt %1").arg(6);   // "Qt 6"
    QString s3 = QString::number(3.14);      // "3.14"

    // 拼接
    QString s4 = s1 + " " + s2;              // "Hello Qt 6"
    s1.append(" World");                      // s1 = "Hello World"

    // 查找与判断
    bool contains = s4.contains("Qt", Qt::CaseInsensitive);  // true
    int idx = s4.indexOf("Qt");               // 6
    bool starts = s4.startsWith("Hello");     // true

    // 截取
    QString mid = s4.mid(6, 2);               // "Qt"
    QString left = s4.left(5);                // "Hello"
    QString right = s4.right(2);              // " 6"

    // 替换与分割
    QString replaced = s4;
    replaced.replace("Qt", "C++");            // "Hello C++ 6"

    QStringList parts = s4.split(' ');        // ["Hello", "Qt", "6"]

    // 大小写转换
    QString upper = s4.toUpper();             // "HELLO QT 6"
    QString lower = s4.toLower();             // "hello qt 6"

    // 去空白
    QString trimmed = "  hi  ".trimmed();     // "hi"
    QString simplified = "  a   b  ".simplified();  // "a b"

    // 数字与字符串互转
    int n = QString("42").toInt();
    double d = QString("3.14").toDouble();
    QString numStr = QString::number(255, 16);  // "ff"（16进制）

    // arg() 格式化（比 sprintf 类型安全）
    QString formatted = QString("%1 + %2 = %3")
                            .arg(1).arg(2).arg(3);   // "1 + 2 = 3"

    qDebug() << s4 << contains << idx;
    return 0;
}
```

**与 std::string 互转**：

```cpp
#include <string>

std::string stdStr = "hello";
QString qStr = QString::fromStdString(stdStr);
std::string back = qStr.toStdString();
```

### 总结

- **关键要点**：`QString` 是 UTF-16、隐式共享的字符串类；`arg()` 格式化比 `sprintf` 类型安全；`split/join/trimmed/simplified` 是高频操作。
- **性能**：传 `QString` 参数用 `const QString&` 避免引用计数操作；频繁拼接用 `QStringBuilder`（`%` 运算符）减少临时对象。
- **常见坑**：
  - `qPrintable(str)` 返回的 `const char*` 在 `str` 析构后失效，不要存到变量长期使用。
  - `QString::fromLocal8Bit()` 在不同系统行为不同（Linux 是 UTF-8，Windows 是 GBK），跨平台代码用 `fromUtf8()`。
  - 中文乱码：源文件保存为 UTF-8，编译器加 `-finput-charset=UTF-8`；或用 `QStringLiteral("中文")` 在编译期生成 `QString`，避免运行时转换。

## 第 8 讲：Qt 容器类

### 概念

Qt 提供一套自己的容器类：`QList`、`QVector`、`QMap`、`QHash`、`QSet`、`QLinkedList` 等。它们与 STL 容器功能相似，但提供**隐式共享**（COW）、**更友好的 API**、**与 Qt 其他类无缝集成**。在 Qt 程序中通常优先使用 Qt 容器。

### 原理

**1. 隐式共享**

与 `QString` 一样，Qt 容器复制时只增加引用计数，修改时才真正拷贝。这让"返回容器值"几乎零成本：

```cpp
QList<int> makeList() {
    QList<int> list;
    for (int i = 0; i < 1000; ++i) list << i;
    return list;   // 不深拷贝
}
```

**2. Qt6 容器变化**

Qt6 中 `QList` 和 `QVector` 合并：`QList` 就是 `QVector`（连续内存数组）。`QLinkedList` 在 Qt6 中被移除（用 `std::list` 替代）。

**3. 与 STL 兼容**

Qt 容器提供 `begin()/end()` 迭代器，可用 STL 算法；也提供 Java 风格迭代器 `QListIterator`、`QMutableListIterator`。

**4. 选择指南**

| 容器 | 适用场景 | 复杂度 |
|------|---------|--------|
| `QList<T>` | 通用动态数组 | 随机访问 O(1)，尾部增 O(1) 均摊 |
| `QMap<K,V>` | 有序键值对（按 key 排序） | 查找 O(log n) |
| `QHash<K,V>` | 无序键值对（哈希表） | 查找 O(1) 均摊 |
| `QSet<T>` | 集合（去重） | 查找 O(1) 均摊 |
| `QVector<T>` | Qt6 中等同 `QList` | — |

### 例子

**QList**：

```cpp
#include <QList>
#include <QDebug>
#include <algorithm>

int main() {
    QList<int> list;
    list << 1 << 2 << 3 << 4 << 5;     // 流式插入

    list.append(6);                      // 尾部追加
    list.prepend(0);                     // 头部插入
    list.insert(3, 99);                  // 在索引 3 插入

    qDebug() << list;                    // [0, 1, 2, 99, 3, 4, 5, 6]
    qDebug() << "size:" << list.size();
    qDebug() << "first:" << list.first();
    qDebug() << "at(3):" << list.at(3);  // 99

    list.removeAt(3);                    // 删除索引 3
    list.removeOne(6);                   // 删除第一个等于 6 的元素
    qDebug() << list.contains(3);        // true
    qDebug() << list.indexOf(2);         // 2

    // STL 风格迭代
    for (int v : list) qDebug() << v;

    // Java 风格迭代器
    QListIterator<int> it(list);
    while (it.hasNext()) qDebug() << it.next();

    // 算法
    std::sort(list.begin(), list.end());
    qDebug() << "sorted:" << list;

    return 0;
}
```

**QMap 与 QHash**：

```cpp
#include <QMap>
#include <QHash>
#include <QDebug>

int main() {
    // QMap：按 key 排序
    QMap<QString, int> ages;
    ages["Alice"] = 30;
    ages["Bob"] = 25;
    ages["Charlie"] = 35;

    qDebug() << ages;   // QMap("Alice", 30)("Bob", 25)("Charlie", 35) - 已排序

    for (auto it = ages.begin(); it != ages.end(); ++it) {
        qDebug() << it.key() << ":" << it.value();
    }

    // QHash：无序，查找更快
    QHash<QString, QColor> colorMap;
    colorMap["red"] = Qt::red;
    colorMap["green"] = Qt::green;
    colorMap["blue"] = Qt::blue;

    if (colorMap.contains("red")) {
        qDebug() << "red found:" << colorMap.value("red");
    }

    return 0;
}
```

### 总结

- **关键要点**：Qt 容器隐式共享，传值高效；Qt6 中 `QList = QVector`；`QMap` 有序、`QHash` 快但无序。
- **API 友好性**：`<<` 流式插入、`contains()`、`value(key, default)` 等比 STL 更直观。
- **常见坑**：
  - 用 `QHash` 但需要按 key 排序遍历 → 应改用 `QMap`。
  - 遍历容器时修改容器（增删元素）→ 迭代器失效，用 `QMutableListIterator` 或先拷贝。
  - `QList<QObject*>` 存指针，Qt 容器**不会**自动管理指针内存，需手动 `delete` 或用智能指针。
  - 大数据量场景下 `QList<T>`（T 大于指针）会退化，考虑 `std::vector<T>`。

# 第三章：GUI 编程基础

本章是 Qt 桌面开发的核心。从 `QWidget` 窗口系统开始，逐步学习布局管理、常用控件、事件处理。完成本章后，你能搭建出功能完整的桌面界面。

## 第 9 讲：QWidget 窗口系统

### 概念

`QWidget` 是所有可视化控件的基类——`QPushButton`、`QLabel`、`QMainWindow` 都是它的子类。`QWidget` 本身也能作为独立窗口显示。理解 `QWidget` 的属性、坐标系统、显示机制，是构建复杂界面的基础。

### 原理

**1. 窗口与控件的双重身份**

`QWidget` 既是"窗口"（可独立显示、有标题栏），也是"控件"（嵌入父 widget 中）。区别在于：**没有父 widget 的 `QWidget` 是窗口**，有父 widget 的是子控件。窗口默认有标题栏和边框，子控件则没有。

**2. 坐标系统**

- 屏幕：左上角为原点 (0,0)，x 向右增，y 向下增。
- 每个 `QWidget` 有自己的局部坐标系，左上角为 (0,0)。
- `pos()` 返回相对父 widget 的位置；`mapToGlobal()` 转换为屏幕坐标；`mapToParent()` 转换为父坐标。

**3. 显示机制**

- `show()`：把 widget 加入待绘制队列，下一轮事件循环时绘制。
- `hide()`：隐藏。
- `isVisible()`：当前是否可见。
- 父 widget 隐藏时，所有子 widget 也隐藏（但 `isVisible()` 仍可能返回 true，需用 `isVisibleTo(parent)` 判断实际可见性）。

**4. 关键属性**

| 属性 | 作用 |
|------|------|
| `geometry()` | 相对父 widget 的位置和大小 (x, y, w, h) |
| `frameGeometry()` | 含窗口边框的位置和大小 |
| `size()` / `width()` / `height()` | 尺寸 |
| `pos()` | 相对父的位置 |
| `minimumSize` / `maximumSize` | 最小/最大尺寸约束 |
| `sizePolicy` | 布局时的尺寸策略 |
| `font` / `palette` | 字体和颜色 |
| `enabled` | 是否启用（禁用时灰显） |
| `visible` | 是否可见 |

### 例子

**自定义 Widget**：

```cpp
// mywidget.h
#include <QWidget>
#include <QPaintEvent>
#include <QPainter>

class MyWidget : public QWidget {
    Q_OBJECT
public:
    explicit MyWidget(QWidget *parent = nullptr) : QWidget(parent) {
        setMinimumSize(200, 150);
        setMouseTracking(true);   // 即使不按按钮也接收鼠标移动事件
    }

protected:
    void paintEvent(QPaintEvent *) override {
        QPainter p(this);
        p.fillRect(rect(), Qt::white);
        p.setPen(Qt::blue);
        p.setFont(QFont("Arial", 20));
        p.drawText(rect(), Qt::AlignCenter, "Hello Widget");
    }

    void mouseMoveEvent(QMouseEvent *e) override {
        setWindowTitle(QString("Mouse: %1, %2")
                           .arg(e->pos().x()).arg(e->pos().y()));
    }
};
```

**作为窗口使用**：

```cpp
#include <QApplication>
#include "mywidget.h"

int main(int argc, char *argv[]) {
    QApplication app(argc, argv);

    MyWidget w;            // 无 parent，作为窗口
    w.setWindowTitle("My First Widget");
    w.resize(400, 300);
    w.show();

    return app.exec();
}
```

**坐标转换示例**：

```cpp
QWidget *parent = new QWidget;
parent->resize(500, 500);
parent->move(100, 100);          // 屏幕坐标 (100,100)

QWidget *child = new QWidget(parent);
child->move(50, 50);             // 相对父 (50,50)

QPoint localPos = child->pos();                  // (50, 50)
QPoint parentPos = child->mapToParent(QPoint(0,0));   // (50, 50)
QPoint globalPos = child->mapToGlobal(QPoint(0,0));   // (150, 150)
```

### 总结

- **关键要点**：`QWidget` 是所有控件基类；无 parent 时是窗口，有 parent 时是子控件；每个 widget 有局部坐标系，用 `mapToGlobal/mapToParent` 转换。
- **绘制**：重写 `paintEvent(QPaintEvent*)` 用 `QPainter` 自定义绘制；不要在 `paintEvent` 外直接绘制。
- **常见坑**：
  - 在构造函数中调用 `width()/height()` 返回默认尺寸（如 100x30），不是 `resize()` 后的值——`resize()` 在事件循环中才生效。用 `QResizeEvent` 或 `showEvent` 监听真实尺寸。
  - 子 widget 必须有 parent 或被布局管理，否则不会显示。
  - `show()` 后立即调用 `width()` 仍可能不准，因为窗口管理器可能尚未处理尺寸请求。

## 第 10 讲：布局管理器

### 概念

**布局管理器（Layout Manager）** 自动管理子控件的尺寸和位置，让界面在不同窗口大小、字体、DPI 下都正确显示。Qt 提供 `QHBoxLayout`（水平）、`QVBoxLayout`（垂直）、`QGridLayout`（网格）、`QFormLayout`（表单）等布局类。**绝对定位（`move()`）几乎总是坏实践**，应优先用布局。

### 原理

**1. 布局的工作机制**

布局不是 widget，它附着在一个 widget 上，管理该 widget 的子控件。当父 widget 大小变化时，布局按规则重新计算每个子控件的位置和大小。

**2. 尺寸提示与尺寸策略**

每个 `QWidget` 有三个关键尺寸：
- `sizeHint()`：推荐尺寸（控件"想"多大）
- `minimumSizeHint()`：最小推荐尺寸
- `minimumSize` / `maximumSize`：硬性约束

`sizePolicy` 描述控件如何响应布局空间：
- `Fixed`：固定为 `sizeHint()`
- `Preferred`：偏好 `sizeHint()`，可伸缩
- `Expanding`：希望尽可能大
- `Minimum`：不能小于 `sizeHint()`，可放大
- `Maximum`：不能大于 `sizeHint()`，可缩小

**3. 伸缩因子（Stretch Factor）**

布局中每个控件有伸缩因子（默认 0），决定多余空间如何分配。`addWidget(widget, stretch)` 中第二个参数即伸缩因子。

**4. 嵌套布局**

布局可嵌套：`QVBoxLayout` 中可包含 `QHBoxLayout`，通过 `addLayout()` 嵌入。复杂界面通常由多层嵌套布局构成。

### 例子

**水平 + 垂直布局**：

```cpp
#include <QApplication>
#include <QWidget>
#include <QVBoxLayout>
#include <QHBoxLayout>
#include <QPushButton>
#include <QLineEdit>

int main(int argc, char *argv[]) {
    QApplication app(argc, argv);

    QWidget window;
    window.setWindowTitle("Layout Demo");

    // 主垂直布局
    QVBoxLayout *mainLayout = new QVBoxLayout(&window);

    // 顶部水平布局：输入框 + 按钮
    QHBoxLayout *topLayout = new QHBoxLayout;
    QLineEdit *input = new QLineEdit;
    input->setPlaceholderText("输入内容...");
    QPushButton *addBtn = new QPushButton("添加");
    topLayout->addWidget(input, 1);    // 输入框伸缩因子 1
    topLayout->addWidget(addBtn, 0);   // 按钮不伸缩
    mainLayout->addLayout(topLayout);

    // 中间按钮区
    QHBoxLayout *btnLayout = new QHBoxLayout;
    btnLayout->addWidget(new QPushButton("左"));
    btnLayout->addStretch(1);          // 弹性空间
    btnLayout->addWidget(new QPushButton("中"));
    btnLayout->addStretch(1);
    btnLayout->addWidget(new QPushButton("右"));
    mainLayout->addLayout(btnLayout);

    // 底部弹性空间 + 退出按钮
    mainLayout->addStretch(1);
    QPushButton *quitBtn = new QPushButton("退出");
    mainLayout->addWidget(quitBtn, 0, Qt::AlignRight);
    QObject::connect(quitBtn, &QPushButton::clicked, &app, &QApplication::quit);

    window.resize(400, 300);
    window.show();
    return app.exec();
}
```

**网格布局**：

```cpp
#include <QGridLayout>
#include <QLabel>
#include <QLineEdit>

// 登录表单
QGridLayout *grid = new QGridLayout;
grid->addWidget(new QLabel("用户名:"), 0, 0);
grid->addWidget(new QLineEdit, 0, 1);
grid->addWidget(new QLabel("密码:"), 1, 0);
grid->addWidget(new QLineEdit, 1, 1);
grid->setColumnStretch(1, 1);   // 第二列伸缩
// 跨列：grid->addWidget(widget, row, col, rowSpan, colSpan);
```

**表单布局**（适合标签+输入框对）：

```cpp
#include <QFormLayout>

QFormLayout *form = new QFormLayout;
form->addRow("姓名:", new QLineEdit);
form->addRow("邮箱:", new QLineEdit);
form->addRow("电话:", new QLineEdit);
```

### 总结

- **关键要点**：布局自动管理控件尺寸位置；通过 `sizeHint`、`sizePolicy`、`stretch` 控制分配；布局可嵌套。
- **绝对定位 vs 布局**：除非做游戏、绘图等需要像素级控制的场景，否则永远用布局。
- **常见坑**：
  - 同时给 widget 设 `move()` 和布局 → 布局覆盖 `move()`，行为混乱。
  - 忘记 `addStretch()` → 控件挤在一起，窗口拉伸时大片空白在底部。
  - 控件 `sizePolicy` 设为 `Fixed` 但希望它伸缩 → 改为 `Expanding` 或 `Preferred`。
  - 嵌套布局时父布局用 `addLayout`，子控件用 `addWidget`，混淆会编译错误。

## 第 11 讲：常用控件

### 概念

Qt Widgets 模块提供丰富的预制控件：按钮、输入框、标签、列表、滑块、进度条等。本讲介绍最常用的几类，掌握它们能覆盖 80% 的界面需求。

### 原理

**控件分类**：

| 类别 | 控件 | 用途 |
|------|------|------|
| 按钮 | `QPushButton`、`QCheckBox`、`QRadioButton`、`QToolButton` | 触发动作、选择 |
| 输入 | `QLineEdit`（单行）、`QTextEdit`（多行富文本）、`QPlainTextEdit`（多行纯文本）、`QComboBox`（下拉）、`QSpinBox`（数字） | 文本/数字输入 |
| 显示 | `QLabel`、`QTextBrowser`、`QProgressBar`、`QLCDNumber` | 信息展示 |
| 容器 | `QGroupBox`、`QTabWidget`、`QScrollArea`、`QFrame` | 组织其他控件 |
| 项视图 | `QListWidget`、`QTreeWidget`、`QTableWidget` | 列表/树/表格（简单版） |
| 滑动 | `QSlider`、`QScrollBar`、`QDial` | 范围选择 |

**信号机制**：每个控件有特定信号，如 `QPushButton::clicked`、`QLineEdit::textChanged`、`QComboBox::currentIndexChanged`。通过连接这些信号响应交互。

### 例子

**综合示例**：

```cpp

#include <QWidget>
#include <QVBoxLayout>
#include <QFormLayout>
#include <QGroupBox>
#include <QPushButton>
#include <QCheckBox>
#include <QRadioButton>

#include <QComboBox>
#include <QSpinBox>
#include <QSlider>
#include <QProgressBar>
#include <QLabel>
#include <QTextEdit>

int main(int argc, char *argv[]) {
    QApplication app(argc, argv);
    QWidget window;
    window.setWindowTitle("常用控件演示");

    QVBoxLayout *mainLayout = new QVBoxLayout(&window);

    // 1. 表单输入区
    QGroupBox *formGroup = new QGroupBox("用户信息");
    QFormLayout *form = new QFormLayout(formGroup);
    QLineEdit *nameEdit = new QLineEdit;
    QComboBox *genderCombo = new QComboBox;
    genderCombo->addItems({"男", "女", "其他"});

    ageSpin->setRange(0, 150);
    ageSpin->setValue(25);

    form->addRow("性别:", genderCombo);
    form->addRow("年龄:", ageSpin);

    QGroupBox *prefGroup = new QGroupBox("偏好设置");

    autoUpdateCheck->setChecked(true);

    QRadioButton *themeLight = new QRadioButton("浅色主题");
    QRadioButton *themeDark = new QRadioButton("深色主题");
    themeLight->setChecked(true);
    prefLayout->addWidget(notifyCheck);
    prefLayout->addWidget(autoUpdateCheck);
    prefLayout->addSpacing(10);
    prefLayout->addWidget(themeLight);
    prefLayout->addWidget(themeDark);
    mainLayout->addWidget(prefGroup);

    slider->setRange(0, 100);

    progress->setRange(0, 100);

    mainLayout->addWidget(slider);
```

- **关键要点**：Qt 控件分按钮、输入、显示、容器、项视图、滑动六大类；通过信号响应用户交互。

- **常见坑**：
  - `QLineEdit::text()` 返回当前文本；`QTextEdit::toPlainText()` 才是纯文本，`toHtml()` 是富文本，别用错。
  - `QRadioButton` 同一父 widget 下自动互斥；要分组用 `QButtonGroup` 或放入不同 `QGroupBox`。
  - `QComboBox` 用 `addItem` 添加项，`currentIndexChanged(int)` 传索引，`currentTextChanged(QString)` 传文本，按需选择。

## 第 12 讲：事件系统与事件过滤器

### 概念

Qt 的事件系统是 GUI 程序的"神经系统"：鼠标点击、键盘按键、窗口缩放、定时器触发等都被封装为 `QEvent` 对象，分发给对应 widget 处理。理解事件系统，才能实现自定义交互、快捷键、拖放等高级功能。

### 原理

**1. 事件循环与事件分发**

`QApplication::exec()` 启动事件循环，不断从事件队列取出 `QEvent`，调用 `QApplication::notify(receiver, event)`，最终调用 `receiver->event(event)`。`event()` 根据事件类型分发给具体的虚函数：

| 事件类型 | 虚函数 |
|---------|--------|
| 鼠标按下 | `mousePressEvent(QMouseEvent*)` |
| 鼠标移动 | `mouseMoveEvent(QMouseEvent*)` |
| 鼠标释放 | `mouseReleaseEvent(QMouseEvent*)` |
| 鼠标滚轮 | `wheelEvent(QWheelEvent*)` |
| 键盘按下 | `keyPressEvent(QKeyEvent*)` |
| 键盘释放 | `keyReleaseEvent(QKeyEvent*)` |
| 大小变化 | `resizeEvent(QResizeEvent*)` |
| 绘制 | `paintEvent(QPaintEvent*)` |
| 关闭 | `closeEvent(QCloseEvent*)` |

**2. 事件过滤器（Event Filter）**

`QObject::installEventFilter()` 让一个对象监视另一个对象的事件。被监视对象的事件先发给过滤器的 `eventFilter()`，过滤器可决定是否拦截：

```cpp
bool eventFilter(QObject *watched, QEvent *event) override {
    if (watched == target && event->type() == QEvent::KeyPress) {
        // 处理并拦截
        return true;
    }
    return QObject::eventFilter(watched, event);  // 放行
}
```

**3. 事件接受与忽略**

事件处理后默认"接受"，不再向上传播。调用 `event->ignore()` 让事件传播给父 widget。`QKeyEvent` 等按 Esc 键默认会关闭对话框，重写时若不想关闭需 `ignore()`。

**4. 自定义事件**

继承 `QEvent`，用 `QEvent::registerEventType()` 注册类型，`QCoreApplication::postEvent()` 异步发送或 `sendEvent()` 同步发送。

### 例子

**自定义键盘处理**：

```cpp
class GameCanvas : public QWidget {
    Q_OBJECT
protected:
    void keyPressEvent(QKeyEvent *e) override {
        switch (e->key()) {
        case Qt::Key_Left:  movePlayer(-10, 0); break;
        case Qt::Key_Right: movePlayer(10, 0);  break;
        case Qt::Key_Up:    movePlayer(0, -10); break;
        case Qt::Key_Down:  movePlayer(0, 10);  break;
        case Qt::Key_Escape: close(); break;
        default:
            QWidget::keyPressEvent(e);  // 未处理的事件交给父类
        }
    }
    void movePlayer(int dx, int dy) { /* ... */ }
};
```

**事件过滤器：全局快捷键**：

```cpp
class ShortcutFilter : public QObject {
    Q_OBJECT
public:
    using QObject::QObject;
protected:
    bool eventFilter(QObject *watched, QEvent *event) override {
        if (event->type() == QEvent::KeyPress) {
            QKeyEvent *ke = static_cast<QKeyEvent*>(event);
            if (ke->key() == Qt::Key_F1 && (ke->modifiers() & Qt::ControlModifier)) {
                qDebug() << "Ctrl+F1 pressed!";
                return true;   // 拦截，不再传播
            }
        }
        return QObject::eventFilter(watched, event);
    }
};

// 安装到主窗口
MainWindow w;
w.installEventFilter(new ShortcutFilter(&w));
```

**关闭事件确认**：

```cpp
void MainWindow::closeEvent(QCloseEvent *event) override {
    auto ret = QMessageBox::question(this, "确认", "确定要退出吗？");
    if (ret != QMessageBox::Yes) {
        event->ignore();   // 阻止关闭
    } else {
        event->accept();   // 允许关闭
    }
}
```

### 总结

- **关键要点**：事件经 `event()` 分发到具体虚函数；重写虚函数处理特定事件；事件过滤器实现跨对象事件拦截；`accept/ignore` 控制事件传播。
- **事件 vs 信号**：事件由系统产生（鼠标、键盘），信号由对象发射（按钮点击）。按钮点击本质是鼠标事件被 `QPushButton` 处理后发射 `clicked` 信号。
- **常见坑**：
  - 重写 `keyPressEvent` 但不调用父类实现 → Tab 切换焦点、Esc 关闭等默认行为失效。
  - 事件过滤器忘记 `return false` 放行 → 所有事件被拦截，控件无响应。
  - `mouseMoveEvent` 默认只在按住按钮时触发；要持续跟踪鼠标需 `setMouseTracking(true)`。
  - 自定义事件类型 ID 必须用 `QEvent::registerEventType()` 获取，不能硬编码。

# 第四章：窗口与对话框

本章聚焦桌面应用的核心窗口元素：主窗口（`QMainWindow`）、对话框（`QDialog`）、菜单/工具栏/状态栏。完成本章后，你能构建出符合桌面应用规范的完整界面骨架。

## 第 13 讲：QMainWindow 主窗口

### 概念

`QMainWindow` 是 Qt 为"主窗口"预设的模板类，比普通 `QWidget` 多了四个内置区域：菜单栏、工具栏、状态栏、停靠面板，以及一个中央区域。绝大多数桌面应用的主窗口都继承 `QMainWindow`。

### 原理

**QMainWindow 的布局结构**：

```
┌─────────────────────────────────────┐
│  Menu Bar (QMenuBar)                │  顶部
├─────────────────────────────────────┤
│  Toolbars (QToolBar, 可多个)         │  菜单栏下方，可拖动
├──┬──────────────────────┬───────────┤
│D │                       │  D       │
│o │   Central Widget      │  o       │  停靠面板
│c │   (setCentralWidget)  │  c       │  (QDockWidget)
│k │                       │  k       │
├──┴──────────────────────┴───────────┤
│  Status Bar (QStatusBar)            │  底部
└─────────────────────────────────────┘
```

**关键特性**：
- 中央区域是必须的，用 `setCentralWidget()` 设置，主内容放这里。
- 菜单栏、工具栏、状态栏由 `QMainWindow` 自动管理，用 `menuBar()/addToolBar()/statusBar()` 获取。
- 停靠面板（`QDockWidget`）可拖出窗口浮动，常用于侧边栏、属性面板。
- 工具栏可拖动到窗口四边，由 `Qt::ToolBarArea` 控制。

### 例子

**完整主窗口示例**：

```cpp
// mainwindow.h
#include <QMainWindow>
#include <QTextEdit>

class MainWindow : public QMainWindow {
    Q_OBJECT
public:
    explicit MainWindow(QWidget *parent = nullptr) : QMainWindow(parent) {
        // 1. 中央控件：文本编辑器
        textEdit = new QTextEdit(this);
        setCentralWidget(textEdit);

        // 2. 菜单栏
        QMenu *fileMenu = menuBar()->addMenu("文件(&F)");
        QAction *newAction = fileMenu->addAction("新建", QKeySequence::New);
        QAction *openAction = fileMenu->addAction("打开...", QKeySequence::Open);
        fileMenu->addSeparator();
        QAction *quitAction = fileMenu->addAction("退出", QKeySequence::Quit);

        QMenu *editMenu = menuBar()->addMenu("编辑(&E)");
        editMenu->addAction("撤销", QKeySequence::Undo, textEdit, &QTextEdit::undo);
        editMenu->addAction("重做", QKeySequence::Redo, textEdit, &QTextEdit::redo);

        // 3. 工具栏
        QToolBar *toolbar = addToolBar("主工具栏");
        toolbar->addAction(newAction);
        toolbar->addAction(openAction);
        toolbar->addSeparator();
        toolbar->addAction("加粗", [this]() {
            textEdit->setFontWeight(QFont::Bold);
        });

        // 4. 状态栏
        statusLabel = new QLabel("就绪");
        statusBar()->addWidget(statusLabel);
        statusBar()->showMessage("提示：按 Ctrl+N 新建", 3000);  // 3秒后消失

        // 5. 停靠面板
        QDockWidget *dock = new QDockWidget("大纲", this);
        QListWidget *outline = new QListWidget;
        outline->addItems({"第一章", "第二章", "第三章"});
        dock->setWidget(outline);
        addDockWidget(Qt::RightDockWidgetArea, dock);

        // 6. 信号连接
        connect(newAction, &QAction::triggered, this, &MainWindow::newFile);
        connect(openAction, &QAction::triggered, this, &MainWindow::openFile);
        connect(quitAction, &QAction::triggered, qApp, &QApplication::quit);

        // 7. 窗口属性
        setWindowTitle("文本编辑器");
        resize(800, 600);
    }

private slots:
    void newFile() {
        textEdit->clear();
        statusLabel->setText("新文件");
    }
    void openFile() {
        QString path = QFileDialog::getOpenFileName(this, "打开文件");
        if (!path.isEmpty()) {
            QFile f(path);
            if (f.open(QIODevice::ReadOnly)) {
                textEdit->setPlainText(QString::fromUtf8(f.readAll()));
                statusLabel->setText("已打开: " + path);
            }
        }
    }

private:
    QTextEdit *textEdit;
    QLabel *statusLabel;
};
```

**使用**：

```cpp
#include <QApplication>
#include "mainwindow.h"

int main(int argc, char *argv[]) {
    QApplication app(argc, argv);
    MainWindow w;
    w.show();
    return app.exec();
}
```

### 总结

- **关键要点**：`QMainWindow` 提供菜单栏、工具栏、状态栏、停靠面板、中央区域五大组件；用 `setCentralWidget` 设置主内容。
- **`QAction` 是核心**：菜单项、工具栏按钮、快捷键都通过 `QAction` 抽象，一个 Action 可同时出现在菜单和工具栏。
- **常见坑**：
  - 不调用 `setCentralWidget` → 中央区域为空，窗口显示异常。
  - 在 `QMainWindow` 上直接 `setLayout()` → 不生效，`QMainWindow` 有自己的布局，必须用 `setCentralWidget`。
  - `QAction::triggered` 信号带 `bool checked` 参数，连接无参槽时 Qt 自动忽略，但 Lambda 要注意参数。

## 第 14 讲：对话框与标准对话框

### 概念

**对话框（Dialog）** 是用于短期交互的顶层窗口，分两类：**模态（Modal）**——阻塞父窗口，必须关闭才能继续；**非模态（Modeless）**——可与父窗口同时操作。Qt 提供 `QDialog` 基类，以及一组**标准对话框**（文件、颜色、字体、消息等）覆盖常见需求。

### 原理

**1. 模态级别**

| 类型 | 行为 | API |
|------|------|-----|
| 应用模态 | 阻塞所有应用窗口 | `setWindowModality(Qt::ApplicationModal)` |
| 窗口模态 | 仅阻塞父窗口及兄弟 | `setWindowModality(Qt::WindowModal)` |
| 非模态 | 不阻塞 | `Qt::NonModal`（默认） |

**2. `exec()` vs `open()` vs `show()`**

- `exec()`：阻塞式，返回 `QDialog::Accepted/Rejected`，适合简单模态对话框。
- `open()`：非阻塞但模态，通过信号通知结果，适合现代异步风格。
- `show()`：非模态，立即返回。

**3. 标准对话框**

Qt 内置常用对话框，无需自己实现：

| 类 | 用途 |
|----|------|
| `QFileDialog` | 打开/保存文件、选择目录 |
| `QColorDialog` | 选择颜色 |
| `QFontDialog` | 选择字体 |
| `QInputDialog` | 输入文本/数字/列表项 |
| `QMessageBox` | 信息提示、确认、警告 |
| `QProgressDialog` | 进度对话框 |

### 例子

**标准对话框综合演示**：

```cpp
    window.setWindowTitle("对话框演示");
    window.resize(400, 300);
    window.show();
```

**自定义对话框**：

```cpp
class LoginDialog : public QDialog {
    Q_OBJECT
public:
    explicit LoginDialog(QWidget *parent = nullptr) : QDialog(parent) {
        setWindowTitle("登录");
        QFormLayout *form = new QFormLayout(this);
        userEdit = new QLineEdit;
        passEdit = new QLineEdit;
        passEdit->setEchoMode(QLineEdit::Password);
        form->addRow("用户名:", userEdit);
        form->addRow("密码:", passEdit);

        QDialogButtonBox *btns = new QDialogButtonBox(
            QDialogButtonBox::Ok | QDialogButtonBox::Cancel);
        form->addRow(btns);

        connect(btns, &QDialogButtonBox::accepted, this, &QDialog::accept);
        connect(btns, &QDialogButtonBox::rejected, this, &QDialog::reject);
    }
    QString username() const { return userEdit->text(); }
    QString password() const { return passEdit->text(); }
private:
    QLineEdit *userEdit, *passEdit;
};

// 使用
LoginDialog dlg;
if (dlg.exec() == QDialog::Accepted) {
    qDebug() << "User:" << dlg.username() << "Pass:" << dlg.password();
}
```

### 总结

- **关键要点**：对话框分模态/非模态；`exec()` 阻塞返回结果，`show()` 非模态；标准对话框覆盖文件、颜色、字体、输入、消息等常见场景。
- **`QDialogButtonBox`**：跨平台按钮组，自动使用系统标准文案（OK/Cancel 在不同语言环境自动翻译）。
- **常见坑**：
  - 模态对话框用 `show()` → 不阻塞，用户可继续操作父窗口，行为不符合预期。
  - `QMessageBox::question` 默认按钮是 Yes/No，要自定义按钮用 `QMessageBox` 实例 + `addButton`。
  - 自定义对话框忘记连接 `accept/reject` → 点确定/取消无反应。

## 第 15 讲：菜单、工具栏与状态栏

### 概念

菜单、工具栏、状态栏是桌面应用的"标配"，让用户高效访问功能、查看状态。本讲深入讲解三者的使用，以及 `QAction` 这个统一抽象——同一个 Action 可同时出现在菜单、工具栏、右键菜单、快捷键中。

### 原理

**1. QAction：统一动作抽象**

`QAction` 封装了"一个用户动作"的所有信息：文本、图标、快捷键、是否可选、状态提示等。把它添加到菜单、工具栏、右键菜单后，所有入口共享同一状态——禁用 Action 时所有入口都灰显。

**2. 菜单结构**

- `QMenuBar`：顶部菜单栏，包含多个 `QMenu`。
- `QMenu`：下拉菜单，包含 `QAction` 或子 `QMenu`。
- 上下文菜单（右键菜单）：通过 `setContextMenuPolicy(Qt::CustomContextMenu)` + 信号 `customContextMenuRequested` 实现。

**3. 工具栏特性**

- 可拖动到窗口四边（`Qt::ToolBarArea`）。
- 可浮动（拖出窗口成为独立窗口）。
- 可包含按钮、控件（`addWidget`）。
- 大图标/小图标模式（`setIconSize`）。

**4. 状态栏**

- `QStatusBar` 分两部分：临时消息（`showMessage`，定时消失）和永久消息（`addWidget`，常驻）。
- 适合显示操作提示、当前文件、坐标等。

### 例子

**完整菜单/工具栏/状态栏集成**：

# 第五章：模型/视图架构

Qt 的 Model/View 架构是处理"数据 + 展示"的核心设计，把数据（Model）、展示（View）、编辑代理（Delegate）三者分离，让同一份数据可用多种视图展示，同一视图可对接不同数据源。这是 Qt 中最强大也最常被误解的架构之一。

## 第 16 讲：Model/View 架构原理

### 概念

**Model/View 架构** 把数据与展示分离：Model 负责管理数据，View 负责显示，Delegate 负责编辑和自定义绘制。三者通过信号槽通信，实现松耦合。相比 `QListWidget` 这类"便捷类"（数据与控件绑定），Model/View 适合大数据量、多视图、复杂数据结构场景。

### 原理

**1. 三大组件**

```
┌──────────┐  数据请求   ┌──────────┐  绘制请求   ┌──────────┐
│   Model  │ ←───────── │   View   │ ←───────── │ Delegate │
│  (数据)   │ ─────────→ │  (展示)  │ ─────────→ │ (编辑/绘制)│
└──────────┘  数据返回   └──────────┘  绘制指令   └──────────┘
     ↑
     │ 数据变化通知 (dataChanged, rowsInserted, ...)
     └─────────────────────────────────────────────
```

- **Model**：继承 `QAbstractItemModel`，提供 `data()`、`rowCount()`、`columnCount()` 等接口供 View 查询数据；数据变化时发射 `dataChanged` 等信号通知 View 刷新。
- **View**：继承 `QAbstractItemView`，向 Model 请求数据并绘制；用户操作时通过 Model 的 `setData()` 修改数据。
- **Delegate**：继承 `QStyledItemDelegate`，控制每个单元格的绘制（`paint()`）和编辑（`createEditor()`）。

**2. 索引系统（QModelIndex）**

Model 用 `QModelIndex` 标识数据项。`QModelIndex` 包含 `row`、`column`、`parent` 三个信息，能表达表格、树、列表等任意结构：

- 列表：`QModelIndex(row, 0, root)`
- 表格：`QModelIndex(row, col, root)`
- 树：`QModelIndex(row, col, parentIndex)`，parent 形成层级

**3. 角色系统（Qt::ItemDataRole）**

同一数据项可对不同角色返回不同值。常用角色：

| 角色 | 用途 |
|------|------|
| `Qt::DisplayRole` | 显示文本 |
| `Qt::EditRole` | 编辑时的值 |
| `Qt::DecorationRole` | 图标 |
| `Qt::ToolTipRole` | 工具提示 |
| `Qt::TextAlignmentRole` | 对齐方式 |
| `Qt::ForegroundRole` / `BackgroundRole` | 前景/背景色 |
| `Qt::FontRole` | 字体 |
| `Qt::CheckStateRole` | 复选状态 |
| `Qt::UserRole` | 自定义数据（用户数据） |

**4. 便捷类 vs Model/View**

| 类型 | 类 | 适用场景 |
|------|----|----|
| 便捷类 | `QListWidget`、`QTableWidget`、`QTreeWidget` | 数据少、单视图、简单场景 |
| Model/View | `QListView`+`QAbstractListModel` 等 | 数据多、多视图、复杂结构 |

便捷类内部其实也是 Model/View，只是把 Model 内置了，使用更简单但灵活性低。

### 例子

**自定义列表 Model**：

```cpp
// stringlistmodel.h
#include <QAbstractListModel>
#include <QStringList>

class StringListModel : public QAbstractListModel {
    Q_OBJECT
public:
    explicit StringListModel(const QStringList &strings, QObject *parent = nullptr)
        : QAbstractListModel(parent), m_data(strings) {}

    // 必须实现：行数
    int rowCount(const QModelIndex &parent = QModelIndex()) const override {
        return parent.isValid() ? 0 : m_data.size();
    }

    // 必须实现：数据
    QVariant data(const QModelIndex &index, int role = Qt::DisplayRole) const override {
        if (!index.isValid() || index.row() >= m_data.size())
            return {};
        if (role == Qt::DisplayRole || role == Qt::EditRole)
            return m_data.at(index.row());
        if (role == Qt::ToolTipRole)
            return QString("第 %1 项").arg(index.row());
        return {};
    }

    // 可选：可编辑
    Qt::ItemFlags flags(const QModelIndex &index) const override {
        if (!index.isValid()) return Qt::NoItemFlags;
        return Qt::ItemIsEnabled | Qt::ItemIsSelectable | Qt::ItemIsEditable;
    }

    bool setData(const QModelIndex &index, const QVariant &value, int role) override {
        if (role != Qt::EditRole || index.row() >= m_data.size())
            return false;
        m_data[index.row()] = value.toString();
        emit dataChanged(index, index, {role});
        return true;
    }

    // 可选：增删行
    bool insertRows(int row, int count, const QModelIndex &parent) override {
        beginInsertRows(parent, row, row + count - 1);
        for (int i = 0; i < count; ++i)
            m_data.insert(row, "");
        endInsertRows();
        return true;
    }

    bool removeRows(int row, int count, const QModelIndex &parent) override {
        beginRemoveRows(parent, row, row + count - 1);
        for (int i = 0; i < count; ++i)
            m_data.removeAt(row);
        endRemoveRows();
        return true;
    }

private:
    QStringList m_data;
};
```

**使用**：

```cpp
#include <QApplication>
#include <QListView>
#include <QVBoxLayout>
#include <QPushButton>
#include "stringlistmodel.h"

int main(int argc, char *argv[]) {
    QApplication app(argc, argv);

    QWidget w;
    QVBoxLayout *layout = new QVBoxLayout(&w);

    StringListModel *model = new StringListModel({"苹果", "香蕉", "橙子"}, &w);

    QListView *view = new QListView;
    view->setModel(model);
    layout->addWidget(view);

    QPushButton *addBtn = new QPushButton("添加项");
    QObject::connect(addBtn, &QPushButton::clicked, [model]() {
        model->insertRows(model->rowCount(), 1);
        model->setData(model->index(model->rowCount()-1), "新项");
    });
    layout->addWidget(addBtn);

    w.show();
    return app.exec();
}
```

### 总结

- **关键要点**：Model/View 把数据、展示、编辑三者分离；Model 通过 `QModelIndex` 标识数据、通过角色提供不同维度信息；数据变化时发射信号通知 View。
- **何时用 Model/View**：数据量大（>1000 项）、需要多视图共享数据、数据来自数据库/网络、需要自定义绘制单元格。
- **常见坑**：
  - 增删行忘记 `beginInsertRows/endInsertRows` → View 不更新，且可能崩溃。
  - `data()` 不处理 `Qt::DisplayRole` → 列表为空。
  - Model 在 View 之前销毁 → View 指向野指针崩溃，应让 Model 的 parent 是 View 或更长生命周期对象。

## 第 17 讲：QListView、QTableView、QTreeView

### 概念

Qt 提供三种预置视图：`QListView`（列表）、`QTableView`（表格）、`QTreeView`（树）。它们都继承 `QAbstractItemView`，可对接任何 `QAbstractItemModel`。本讲讲解三种视图的使用，以及 Qt 内置的 `QStringListModel`、`QStandardItemModel` 等通用 Model。

### 原理

**1. 三种视图的适用结构**

| 视图 | 数据结构 | 典型 Model |
|------|---------|------------|
| `QListView` | 一维列表 | `QStringListModel`、`QAbstractListModel` |
| `QTableView` | 二维表格 | `QStandardItemModel`、`QSqlQueryModel` |
| `QTreeView` | 树形层级 | `QStandardItemModel`、`QFileSystemModel` |

**2. QStandardItemModel**

通用 Model，用 `QStandardItem` 表示每个数据项。`QStandardItem` 自带文本、图标、字体、对齐、复选等属性，适合中小数据量、不需要自定义 Model 的场景。

**3. 选择模型（QItemSelectionModel）**

每个 View 有一个 `QItemSelectionModel`，记录当前选中项。多个 View 可共享同一 SelectionModel，实现"选中同步"。选择模式由 `QAbstractItemView::SelectionMode` 控制：单选、多选、扩展选、连续选。

**4. 表格视图的表头**

`QTableView` 有水平/垂直表头，由 `QHeaderView` 管理。可隐藏、可点击排序、可拖动调整宽度。

### 例子

**QTableView + QStandardItemModel**：

```cpp
#include <QApplication>
#include <QTableView>
#include <QStandardItemModel>
#include <QHeaderView>
#include <QVBoxLayout>
#include <QPushButton>

int main(int argc, char *argv[]) {
    QApplication app(argc, argv);

    QWidget w;
    QVBoxLayout *layout = new QVBoxLayout(&w);

    // 1. 创建 Model
    QStandardItemModel *model = new QStandardItemModel(&w);
    model->setHorizontalHeaderLabels({"姓名", "年龄", "城市", "薪资"});

    // 2. 填充数据
    QList<QStringList> data = {
        {"张三", "28", "北京", "15000"},
        {"李四", "35", "上海", "22000"},
        {"王五", "24", "广州", "12000"},
        {"赵六", "42", "深圳", "30000"},
    };
    for (const auto &row : data) {
        QList<QStandardItem*> items;
        for (const auto &cell : row)
            items.append(new QStandardItem(cell));
        model->appendRow(items);
    }

    // 3. 自定义单元格
    QStandardItem *highlightItem = model->item(2, 2);
    highlightItem->setBackground(QColor(255, 255, 0));
    highlightItem->setFont(QFont("Arial", 10, QFont::Bold));

    // 4. 创建 View
    QTableView *view = new QTableView;
    view->setModel(model);
    view->setSelectionBehavior(QAbstractItemView::SelectRows);  // 整行选中
    view->setSelectionMode(QAbstractItemView::SingleSelection);
    view->setAlternatingRowColors(true);   // 隔行变色
    view->horizontalHeader()->setSectionResizeMode(QHeaderView::Stretch);
    view->setSortingEnabled(true);          // 点击表头排序

    layout->addWidget(view);

    // 5. 获取选中行
    QPushButton *btn = new QPushButton("显示选中");
    QObject::connect(btn, &QPushButton::clicked, [view, model]() {
        QModelIndexList selected = view->selectionModel()->selectedRows();
        for (const QModelIndex &idx : selected) {
            QString name = model->data(model->index(idx.row(), 0)).toString();
            qDebug() << "选中:" << name;
        }
    });
    layout->addWidget(btn);

    w.resize(500, 400);
    w.show();
    return app.exec();
}
```

**QTreeView + QFileSystemModel**（文件浏览器）：

```cpp

```

**QListView + QStringListModel**：

```cpp

QListView *list = new QListView;

list->setEditTriggers(QAbstractItemView::DoubleClicked);  // 双击编辑
```

### 总结

- **关键要点**：三种视图对应列表/表格/树结构；`QStandardItemModel` 是通用 Model，适合中小数据量；`QItemSelectionModel` 管理选中状态。
- **`QFileSystemModel`**：内置文件系统 Model，**异步加载**，监听文件变化自动更新。
- **常见坑**：
  - `QFileSystemModel` 调用 `setRootPath` 后立即访问 `index(path)` 可能返回无效索引（尚未加载），需等 `directoryLoaded` 信号。
  - `QTableView` 默认列宽固定，要自适应内容用 `resizeColumnsToContents()`，要填满窗口用 `setSectionResizeMode(Stretch)`。
  - 大数据量用 `QStandardItemModel` 性能差（每项一个对象），应自定义 Model 或用 `QTableWidget`。

## 第 18 讲：自定义模型与委托

### 概念

当内置 Model 不满足需求（如数据来自数据库、需要特殊结构、性能要求高），需自定义 Model。当需要自定义单元格绘制（如进度条、图标、富文本）或编辑控件（如日期选择器、下拉框），需自定义 Delegate。本讲通过实战案例讲解两者。

### 原理

**1. 自定义 Model 的核心虚函数**

继承 `QAbstractTableModel`（表格）或 `QAbstractListModel`（列表）需实现：

| 函数 | 作用 |
|------|------|
| `rowCount()` | 行数 |
| `columnCount()`（仅表格） | 列数 |
| `data()` | 返回指定索引+角色的数据 |
| `headerData()` | 表头数据 |
| `flags()` | 项标志（可选、可编辑等） |
| `setData()` | 编辑数据（若支持编辑） |

数据变化时必须发射对应信号：
- 修改数据：`dataChanged`
- 插入行：`beginInsertRows` / `endInsertRows`
- 删除行：`beginRemoveRows` / `endRemoveRows`
- 重置：`beginResetModel` / `endResetModel`

**2. 自定义 Delegate**

继承 `QStyledItemDelegate`，重写：

| 函数 | 作用 |
|------|------|
| `paint()` | 自定义绘制单元格 |

```cpp
// taskmodel.h
#include <QAbstractTableModel>
#include <QVector>

struct Task {
    QString name;
    int progress;     // 0-100
    bool done;
};

class TaskModel : public QAbstractTableModel {
    Q_OBJECT
public:
    explicit TaskModel(QObject *parent = nullptr) : QAbstractTableModel(parent) {
        m_tasks = {{"设计文档", 100, true}, {"编码实现", 60, false}, {"测试", 20, false}};
    }

    int rowCount(const QModelIndex &) const override { return m_tasks.size(); }
    int columnCount(const QModelIndex &) const override { return 3; }

    QVariant data(const QModelIndex &index, int role) const override {
        if (!index.isValid() || index.row() >= m_tasks.size())
            return {};
        const Task &t = m_tasks[index.row()];
        switch (role) {
        case Qt::DisplayRole:
            if (index.column() == 0) return t.name;
            if (index.column() == 1) return QString("%1%").arg(t.progress);
            if (index.column() == 2) return t.done ? "完成" : "进行中";
            break;
        case Qt::CheckStateRole:
            if (index.column() == 2) return t.done ? Qt::Checked : Qt::Unchecked;
            break;
        case Qt::TextAlignmentRole:
            if (index.column() == 1 || index.column() == 2)
                return Qt::AlignCenter;
            break;
        case Qt::ForegroundRole:
            if (index.column() == 2)
                return t.done ? QColor(Qt::green) : QColor(Qt::red);
            break;
        case Qt::UserRole:   // 自定义角色，返回原始数据
            if (index.column() == 1) return t.progress;
            break;
        }
        return {};
    }

    QVariant headerData(int section, Qt::Orientation o, int role) const override {
        if (role != Qt::DisplayRole || o != Qt::Horizontal)
            return {};
        switch (section) {
        case 0: return "任务名";
        case 1: return "进度";
        case 2: return "状态";
        }
        return {};
    }

    Qt::ItemFlags flags(const QModelIndex &index) const override {
        Qt::ItemFlags f = Qt::ItemIsEnabled | Qt::ItemIsSelectable;
        if (index.column() == 2) f |= Qt::ItemIsUserCheckable;
        return f;
    }

    bool setData(const QModelIndex &idx, const QVariant &value, int role) override {
        if (!idx.isValid() || idx.row() >= m_tasks.size())
            return false;
        if (role == Qt::CheckStateRole && idx.column() == 2) {
            m_tasks[idx.row()].done = (value == Qt::Checked);
            emit dataChanged(idx, idx, {role});
            return true;
        }
        return false;
    }

    void addTask(const QString &name) {
        beginInsertRows(QModelIndex(), m_tasks.size(), m_tasks.size());
        m_tasks.append({name, 0, false});
        endInsertRows();
    }

private:
    QVector<Task> m_tasks;
};
```

# 第六章：进阶主题

本章涵盖实际项目必备的两大能力：文件 I/O 与多线程。文件 I/O 让程序持久化数据、读写配置；多线程让耗时操作不阻塞 UI。掌握这两者，你已具备开发完整桌面应用的能力。

## 第 19 讲：文件 I/O 与 QDataStream

### 概念

Qt 提供完整的文件 I/O 体系：`QFile` 读写文件、`QTextStream` 处理文本、`QDataStream` 处理二进制、`QDir` 操作目录、`QFileInfo` 查询文件信息、`QSettings` 读写配置。本讲聚焦最常用的 `QFile` + `QDataStream` 组合。

### 原理

**1. Qt I/O 类层次**

```
QIODevice (抽象基类)
├── QFile        (文件)
├── QBuffer      (内存缓冲区)
├── QProcess     (进程)
├── QAbstractSocket
│   ├── QTcpSocket
│   └── QUdpSocket
└── QLocalSocket

QIODevice 提供基础读写接口：read(), write(), close(), atEnd() 等
```

**2. QTextStream vs QDataStream**

| 类 | 用途 | 特点 |
|----|------|------|
| `QTextStream` | 文本 I/O | 自动编码转换、行操作、格式化 |
| `QDataStream` | 二进制 I/O | 类型安全、跨平台字节序一致、可序列化 Qt 类型 |

**3. QDataStream 的序列化能力**

`QDataStream` 重载了 `<<` 和 `>>` 操作符，支持所有 Qt 基本类型：`QString`、`QList`、`QMap`、`QColor`、`QFont`、`QImage` 等。写入和读取顺序必须一致，否则数据错乱。

**4. 文件打开模式**

`QIODevice::OpenMode` 标志：
- `ReadOnly`、`WriteOnly`、`ReadWrite`
- `Append`（追加）、`Truncate`（清空）
- `Text`（文本模式，Windows 换行转换）
- `Unbuffered`（无缓冲）

### 例子

**文本文件读写**：

```cpp

        return;
```

**二进制文件读写（QDataStream）**：

```cpp
#include <QFile>
#include <QDataStream>
#include <QColor>
#include <QFont>
#include <QMap>

// 自定义结构序列化
struct UserSettings {
    QString name;
    int age;
    QColor color;
    QFont font;
    QStringList hobbies;
};

// 重载 << 和 >> 实现序列化
QDataStream &operator<<(QDataStream &out, const UserSettings &s) {
    out << s.name << s.age << s.color << s.font << s.hobbies;
    return out;
}

QDataStream &operator>>(QDataStream &in, UserSettings &s) {
    in >> s.name >> s.age >> s.color >> s.font >> s.hobbies;
    return in;
}

void saveSettings(const QString &path, const UserSettings &s) {
    QFile file(path);
    if (file.open(QIODevice::WriteOnly)) {
        QDataStream out(&file);
        out.setVersion(QDataStream::Qt_6_0);   // 固定版本，保证兼容
        out << quint32(0xA0B0C0D0);             // 魔数，校验文件格式
        out << s;
    }
}

bool loadSettings(const QString &path, UserSettings &s) {
    QFile file(path);
    if (!file.open(QIODevice::ReadOnly))
        return false;
    QDataStream in(&file);
    in.setVersion(QDataStream::Qt_6_0);
    quint32 magic;
    in >> magic;
    if (magic != 0xA0B0C0D0) {
        qDebug() << "文件格式错误";
        return false;
    }
    in >> s;
    return true;
}

// 使用
UserSettings s{"张三", 28, QColor(255, 100, 50),
               QFont("Microsoft YaHei", 12), {"读书", "编程", "旅行"}};
saveSettings("settings.dat", s);

UserSettings loaded;
if (loadSettings("settings.dat", loaded)) {
    qDebug() << loaded.name << loaded.age << loaded.color << loaded.hobbies;
}
```

  - `QFile` 忘记 `close()` → 通常析构时自动关闭，但提前关闭可释放资源。
  - `QSettings` 在 Windows 写注册表、macOS 写 plist、Linux 写 ini，路径不同但 API 一致。

## 第 20 讲：多线程与 QThread

### 概念

GUI 程序的主线程（UI 线程）负责处理事件循环和界面绘制。耗时操作（网络、文件、计算）若在主线程执行，会导致界面卡顿。`QThread` 是 Qt 的线程抽象，配合信号槽实现线程间通信。本讲讲解 `QThread` 的两种用法、`QObject::moveToThread`、以及线程安全要点。

### 原理

**1. QThread 的本质**

`QThread` 是一个对象，管理一个操作系统线程。它本身**不是线程**，而是线程的"管理器"。线程的执行入口是 `QThread::run()`，默认实现是 `exec()`——启动一个事件循环，让在该线程的对象能接收事件和信号。

**2. 两种用法**

**用法一：重写 run()**
- 继承 `QThread`，重写 `run()`，在 `run()` 中写循环逻辑。
- 适合"一次性任务"，不需要事件循环。
- 不能在 `run()` 中直接操作 UI，需通过信号通知主线程。

**用法二：moveToThread（推荐）**
- 创建 `QObject` 子类，把对象 `moveToThread(&thread)`。
- 对象的槽函数在 `thread` 中执行。
- 适合"长期任务"、"需要响应信号的任务"。
- 更符合 Qt 的对象模型，官方推荐。

**3. 跨线程信号槽**

`QObject::connect` 第 5 个参数指定连接类型：

| 类型 | 行为 |
|------|------|
| `Qt::DirectConnection` | 直接调用，在发射信号的线程执行 |
| `Qt::QueuedConnection` | 队列，在接收者所在线程的事件循环执行 |
| `Qt::AutoConnection`（默认） | 自动：同线程 Direct，跨线程 Queued |
| `Qt::BlockingQueuedConnection` | 队列且阻塞，等待槽执行完（不能同线程） |
| `Qt::UniqueConnection` | 防重复连接 |

跨线程信号槽依赖事件循环，所以接收者线程必须 `exec()`。

**4. 线程安全要点**

- **绝不在子线程操作 UI**：所有 `QWidget` 方法必须在主线程调用。
- **跨线程数据传递**：通过信号槽（参数会被拷贝）或 `QMutex` 保护共享数据。
- **对象归属**：`QObject` 的线程归属由 `thread()` 决定，子对象必须与父对象同线程。
- **`delete` 跨线程对象**：用 `QObject::deleteLater()` 而非直接 `delete`。

### 例子

**用法一：重写 run()（耗时计算）**：

```cpp
// worker.h
#include <QThread>

class PrimeWorker : public QThread {
    Q_OBJECT
public:
    PrimeWorker(int start, int end, QObject *parent = nullptr)
        : QThread(parent), m_start(start), m_end(end) {}

    void run() override {
        QList<int> primes;
        for (int n = m_start; n <= m_end; ++n) {
            if (isPrime(n)) {
                primes.append(n);
                if (primes.size() % 10 == 0)
                    emit progress(primes.size());
            }
        }
        emit resultReady(primes);
    }

    bool isPrime(int n) {
        if (n < 2) return false;
        for (int i = 2; i * i <= n; ++i)
            if (n % i == 0) return false;
        return true;
    }

signals:
    void progress(int count);
    void resultReady(const QList<int> &primes);

private:
    int m_start, m_end;
};

// 使用
class MainWindow : public QMainWindow {
    Q_OBJECT
    QProgressBar *progress;
    QTextEdit *output;

    void startCompute() {
        auto *worker = new PrimeWorker(1, 1000000, this);
        connect(worker, &PrimeWorker::progress,
                progress, &QProgressBar::setValue);
        connect(worker, &PrimeWorker::resultReady, [this](const QList<int> &p) {
            output->setPlainText(QString("找到 %1 个素数").arg(p.size()));
        });
        connect(worker, &QThread::finished, worker, &QObject::deleteLater);
        worker->start();
    }
};
```

**用法二：moveToThread（推荐，长期任务）**：

```cpp
// worker.h
#include <QObject>

class FileWorker : public QObject {
    Q_OBJECT
public slots:
    void doProcessFile(const QString &path) {
        // 在 worker 线程执行
        QFile file(path);
        if (!file.open(QIODevice::ReadOnly)) {
            emit error("无法打开文件");
            return;
        }
        qint64 total = file.size();
        qint64 read = 0;
        QByteArray chunk;
        while (!file.atEnd()) {
            chunk = file.read(8192);
            read += chunk.size();
            emit progress(read * 100 / total);
            QThread::msleep(10);   // 模拟耗时
        }
        emit finished();
    }

signals:
    void progress(int percent);
    void finished();
    void error(const QString &msg);
};

// 使用
class MainWindow : public QMainWindow {
    Q_OBJECT
    QThread workerThread;
    FileWorker *worker;

public:
    MainWindow() {
        worker = new FileWorker;
        worker->moveToThread(&workerThread);

        connect(&workerThread, &QThread::finished, worker, &QObject::deleteLater);
        connect(this, &MainWindow::processFile,
                worker, &FileWorker::doProcessFile);
        connect(worker, &FileWorker::progress,
                this, &MainWindow::onProgress);
        connect(worker, &FileWorker::finished,
                this, &MainWindow::onFinished);

        workerThread.start();
    }

    ~MainWindow() {
        workerThread.quit();
        workerThread.wait();   // 等待线程退出
    }

signals:
    void processFile(const QString &path);

private slots:
    void onProgress(int p) { /* 更新进度条 */ }
    void onFinished() { /* 提示完成 */ }

    void onButtonClicked() {
        emit processFile("large_file.dat");   // 触发 worker 线程执行
    }
};
```

**QtConcurrent：简化并行计算**：

```cpp
#include <QtConcurrent>
#include <QFuture>
#include <QFutureWatcher>

// 异步执行
QFuture<int> future = QtConcurrent::run([]() {
    int sum = 0;
    for (int i = 0; i < 1000000; ++i) sum += i;
    return sum;
});

// 用 Watcher 监听完成（不阻塞）

connect(watcher, &QFutureWatcher<int>::finished, [future]() {
    qDebug() << "结果:" << future.result();
});
watcher->setFuture(future);

// 并行处理列表
QList<int> nums = {1, 2, 3, 4, 5, 6, 7, 8};

    return x * x;
});
```

### 总结

- **关键要点**：`QThread` 管理线程；推荐用 `moveToThread` 而非重写 `run()`；跨线程通信用信号槽（默认 `AutoConnection` 自动切换）；`QtConcurrent` 适合简单并行任务。
- **线程退出**：调用 `quit()` 让事件循环退出，`wait()` 等待线程真正结束；不要 `terminate()`，会导致资源泄漏。
- **常见坑**：
  - 在 worker 线程直接调用 `widget->update()` → 崩溃，必须通过信号通知主线程。
  - `moveToThread` 后对象不能有 parent → parent 会强制同线程，调用 `moveToThread` 报错。
  - 跨线程信号槽传引用 → 参数会被拷贝（值传递），不能传引用；要传大数据用指针或 `QSharedPointer`。
  - `QThread::finished` 信号在 `run()` 返回后发射，但线程对象本身还在，用 `deleteLater` 安全删除。
  - `QtConcurrent::run` 默认用全局线程池，任务多时会排队，可用 `QThreadPool::globalInstance()->setMaxThreadCount(n)` 调整。

- **Qt 图形与绘图**：`QPainter` 2D 绘图、`QGraphicsView` 图形视图框架、`QOpenGLWidget` 3D 渲染
- **Qt 多媒体**：`QMediaPlayer`、`QCamera` 音视频处理
- **Qt 国际化**：`tr()` + `.ts` 文件实现多语言支持
- **Qt 部署**：`windeployqt`/`macdeployqt` 打包发布

Qt 的精髓在于"信号槽"和"对象模型"——理解了这两点，其他模块都是在此基础上的扩展。多写代码、多看官方文档（`doc.qt.io`）、多读 Qt 源码，你会逐渐从"会用 Qt"走向"精通 Qt"。
