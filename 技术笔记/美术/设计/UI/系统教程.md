# 第1章 UI设计基础

## 第1讲 什么是UI设计：概念、范畴与价值

### 概念

UI（User Interface，用户界面）设计是指对软件的人机交互、操作逻辑、界面美观的整体设计。UI设计不仅是"让界面好看"，更是"让界面好用且好看"。它关注用户与数字产品交互的所有触点——从按钮的形状、颜色的选择，到页面的布局、信息的层级，都属于UI设计的范畴。

UI设计常与UX（User Experience，用户体验）设计并列讨论。简单来说，UX关注"用户为什么用、用得顺不顺"，UI关注"用户看到什么、怎么操作"。两者相辅相成，但在实际工作中常常由同一人或同一团队承担。

### 原理

UI设计的核心原理建立在**认知心理学**和**人机交互理论**之上。人类的工作记忆容量有限（米勒定律：7±2个信息块），因此界面需要将信息分块、分层呈现。人类视觉系统对对比、运动、颜色敏感，因此可以通过视觉手段引导注意力。

UI设计的价值体现在三个层面：

1. **功能价值**：降低用户学习成本，提高任务完成效率。一个好的UI能让用户无需阅读说明书即可上手操作。
2. **情感价值**：通过美观的视觉设计建立品牌认知，增强用户信任感和愉悦感。研究表明，视觉吸引力高的产品，用户对其可用性的评价也更高（审美可用性效应）。
3. **商业价值**：优秀的UI设计能显著提升转化率、降低跳出率。例如，将按钮颜色从绿色改为红色，可能使点击率提升21%（这是HubSpot的经典A/B测试案例）。

### 例子

以一个登录页面为例，对比"差的UI"和"好的UI"：

**差的UI设计**：
```
┌─────────────────────────────┐
│  登录                        │
│                             │
│  用户名                      │
│  [______________________]   │
│                             │
│  密码                        │
│  [______________________]   │
│                             │
│  [登录]  [注册]  [忘记密码]  │
│                             │
└─────────────────────────────┘
```
问题：按钮层级混乱，三个按钮同等重要，用户不知道该先点哪个；输入框没有占位提示；没有视觉焦点。

**好的UI设计**：
```
┌─────────────────────────────┐
│                             │
│        📱 欢迎回来            │
│        请登录您的账户          │
│                             │
│  📧 邮箱                     │
│  [______________________]   │
│                             │
│  🔒 密码                     │
│  [______________________]   │
│                             │
│  ┌─────────────────────┐    │
│  │       登  录         │    │
│  └─────────────────────┘    │
│                             │
│  没有账户？注册  |  忘记密码   │
│                             │
└─────────────────────────────┘
```
改进：主按钮"登录"视觉突出，次要操作降级为文字链接；输入框有图标提示；标题建立情感连接。

### 总结

- UI设计是"好用+好看"的综合设计，不是单纯的视觉美化
- UI与UX紧密相关，UI是UX的视觉化呈现
- UI设计的价值体现在功能、情感、商业三个层面
- 好的UI设计应降低认知负荷、引导用户注意力、建立品牌信任
- **常见误区**：把UI设计等同于"画图"，忽略了交互逻辑和用户体验

## 第2讲 UI设计的发展历程：从命令行到空间计算

### 概念

UI设计的发展历程，本质上是人机交互方式不断演进的历史。从早期的打孔卡片、命令行界面（CLI），到图形用户界面（GUI），再到如今的触控界面、语音交互、空间计算界面，每一次演进都让交互变得更自然、更直观。

理解这段历史，有助于设计师把握UI设计的本质——**技术驱动形式，但以人为本的核心理念不变**。

### 原理

UI演进背后的核心原理是**交互带宽的扩展**：

1. **命令行时代（1960s-1980s）**：交互带宽极窄，用户需要记忆大量命令。学习成本高，仅限专业用户。代表：UNIX Shell、DOS。
2. **图形界面时代（1980s-2000s）**：引入WIMP范式（Window窗口、Icon图标、Menu菜单、Pointer指针），用视觉隐喻降低学习成本。用户可以"所见即所得"。代表：Mac OS、Windows。
3. **Web时代（1990s-2010s）**：超链接打破线性结构，信息以网状组织。响应式设计让同一套界面适配多设备。代表：Google、Facebook。
4. **移动时代（2007-至今）**：触控交互取代鼠标，手势成为新语言。屏幕变小，信息密度降低，强调"一屏一任务"。代表：iPhone、微信。
5. **多模态时代（2015-至今）**：语音、手势、眼动等多种交互方式融合。AI开始理解自然语言，界面变得"会对话"。代表：Siri、ChatGPT。
6. **空间计算时代（2024-）**：数字内容融入物理空间，界面不再局限于矩形屏幕。代表：Apple Vision Pro。

每一次演进都遵循一个规律：**交互方式越来越接近人类自然的沟通方式**。从需要学习"机器的语言"，到机器理解"人的语言"。

### 例子

以"删除一个文件"这个操作为例，看交互方式的演变：

**命令行时代**：
```bash
$ rm document.txt
```
用户需要记住`rm`命令和文件名，没有视觉反馈，误删风险高。

**图形界面时代**：
```
┌──────────────┐
│ 📄 document  │  ← 选中文件
└──────────────┘
   [Delete]       ← 按键删除
```
用户看到文件图标，选中后按键删除。有视觉反馈，但仍是"间接操作"。

**触控时代**：
```
┌──────────────┐
│ 📄 document  │  ← 长按
└──────────────┘
   ┌─────────┐
   │  🗑️ 删除  │  ← 弹出菜单
   └─────────┘
```
用户直接用手指操作，更自然。但需要学习"长按"手势。

**语音/AI时代**：
```
用户："帮我把document.txt删了"
AI："好的，已删除document.txt"
```
用户用自然语言表达意图，AI理解并执行。学习成本最低。

### 总结

- UI设计经历了CLI → GUI → Web → Mobile → 多模态 → 空间计算的演进
- 演进的核心规律：交互方式越来越接近人类自然沟通方式
- 每次技术革新都扩展了交互带宽，降低了用户学习成本
- 理解历史有助于预测未来趋势：更自然、更智能、更沉浸
- **注意事项**：新技术不等于好设计，核心仍是解决用户需求。不要为了炫技而使用新交互方式

## 第3讲 UI设计的核心原则：可用性、一致性、美观性

### 概念

UI设计的核心原则是指导设计决策的基本准则。业界广泛认可的有三大原则：**可用性**（Usability，让用户能完成任务）、**一致性**（Consistency，让用户能举一反三）、**美观性**（Aesthetics，让用户愿意使用）。

此外，还有雅各布·尼尔森（Jakob Nielsen）提出的**十大可用性原则**，以及本·施奈德曼（Ben Shneiderman）的**八大黄金法则**，都是UI设计的重要理论支撑。

### 原理

**1. 可用性原则**

可用性是指用户能否高效、有效地完成目标任务。尼尔森的可用性包含五个维度：
- **易学性**：新手能否快速上手
- **效率**：熟练用户完成任务的速度
- **可记忆性**：间歇用户能否重新上手
- **错误率**：用户犯错的频率和严重性
- **满意度**：用户是否愿意继续使用

**2. 一致性原则**

一致性源于认知心理学中的**转移效应**（Transfer of Learning）。当用户在一个地方学到的操作模式能应用到其他地方时，学习成本大幅降低。一致性分为：
- **内部一致性**：同一产品内，相同功能用相同方式表达
- **外部一致性**：遵循行业惯例和平台规范（如"齿轮"代表设置）

**3. 美观性原则**

美观性不仅是视觉享受，更有认知功能。根据**审美可用性效应**（Aesthetic-Usability Effect），用户倾向于认为美观的产品更好用。美观的设计能：
- 建立积极的第一印象
- 容忍小的可用性问题
- 增强品牌信任感

**尼尔森十大可用性原则**（精简版）：
1. 系统状态可见性
2. 系统与现实世界匹配
3. 用户控制和自由
4. 一致性与标准
5. 错误预防
6. 识别而非回忆
7. 使用的灵活性与效率
8. 美观与极简设计
9. 帮助用户识别、诊断、恢复错误
10. 帮助文档

### 例子

以**电商App的购物车**为例，看三大原则的应用：

**可用性**：
```
购物车页面应包含：
✓ 商品列表（图片、名称、规格、价格、数量）
✓ 全选/反选功能
✓ 数量增减按钮
✓ 删除/移入收藏
✓ 优惠券/满减提示
✓ 合计金额（突出显示）
✓ 结算按钮（固定底部，始终可见）
```
用户能清晰看到所有信息，快速完成结算。

**一致性**：
```
全App的"删除"操作统一用红色文字
全App的"确认"按钮统一在右侧
全App的数量增减统一用 [- 1 +] 样式
全App的价格统一用 ¥符号 + 两位小数
```
用户在购物车学到的操作模式，能应用到收藏夹、订单页等其他场景。

**美观性**：
```
✓ 商品图片统一圆角8px
✓ 价格用品牌色（如红色）突出
✓ 间距统一，留白充足
✓ 结算按钮用品牌主色，足够大（高度≥44pt）
✓ 图标风格统一（线性/填充一致）
```
视觉整洁，重点突出，用户愿意停留和操作。

### 总结

- 三大核心原则：可用性（能用）、一致性（好用）、美观性（爱用）
- 可用性是基础，一致性是效率，美观性是加分项
- 尼尔森十大原则是检验设计质量的重要工具
- 一致性要兼顾内部一致和外部一致（平台规范）
- **常见误区**：过度追求美观而牺牲可用性，或过度追求创新而破坏一致性
- **实践建议**：设计前先问"用户要完成什么任务"，再问"如何让任务更简单"，最后才考虑"如何更美观"

## 第4讲 UI设计师的工作流程：从需求到交付

### 概念

UI设计师的工作流程是指从接到产品需求到最终设计交付的完整过程。一个规范的流程能确保设计质量、减少返工、提高团队协作效率。典型的UI设计流程包含六个阶段：**需求理解 → 用户研究 → 信息架构 → 交互设计 → 视觉设计 → 设计交付**。

不同公司、不同项目规模下，流程会有所简化或扩展，但核心环节不变。

### 原理

UI设计流程背后的原理是**以用户为中心的设计**（User-Centered Design, UCD）和**设计思维**（Design Thinking）。UCD强调在设计全过程中持续关注用户需求；设计思维强调"理解→定义→构思→原型→测试"的迭代循环。

流程的价值在于：

1. **降低风险**：通过用户研究和原型测试，在开发前验证设计方向，避免"开发完了才发现不对"
2. **提高效率**：明确的阶段和交付物，减少沟通成本和返工
3. **保证质量**：每个阶段有评审和验收，确保设计符合标准
4. **可追溯**：设计决策有依据，便于后续优化和新人理解

**双钻模型**（Double Diamond）是理解设计流程的经典框架：
- **第一钻（发现→定义）**：发散问题，收敛到正确的问题定义
- **第二钻（开发→交付）**：发散解决方案，收敛到最优方案

### 例子

以"设计一个音乐播放器App"为例，展示完整流程：

**阶段1：需求理解**
```
输入：产品需求文档（PRD）
- 目标用户：18-35岁音乐爱好者
- 核心功能：在线听歌、创建歌单、发现新歌
- 商业目标：提升用户停留时长，增加会员转化
输出：设计目标确认书
- 设计目标：让用户3步内开始播放歌曲
- 约束条件：iOS/Android双平台，3个月内上线
```

**阶段2：用户研究**
```
方法：用户访谈（10人）、竞品分析（网易云、QQ音乐、Spotify）
发现：
- 用户最常做的操作是"继续播放上次的歌曲"
- 用户抱怨"找歌太麻烦，推荐不准"
- 用户喜欢"看歌词"功能
输出：用户画像、用户旅程图
```

**阶段3：信息架构**
```
App结构：
├── 首页（推荐、最近播放）
├── 发现（排行榜、分类、电台）
├── 我的（歌单、收藏、下载）
└── 播放页（全屏播放器）
输出：站点地图、功能清单
```

**阶段4：交互设计**
```
输出：线框图、交互原型
- 首页线框：顶部搜索栏 + "继续播放"卡片 + 推荐列表
- 播放页交互：上滑展开全屏，下滑收起
- 原型工具：Figma制作可点击原型
- 用户测试：5人测试，验证"3步开始播放"目标
```

**阶段5：视觉设计**
```
输出：高保真设计稿
- 色彩：主色#1DB954（绿色），背景#121212（深色）
- 字体：标题24pt/600，正文14pt/400
- 图标：线性风格，2pt描边
- 组件：按钮、卡片、列表统一样式
- 适配：iOS和Android各一套规范
```

**阶段6：设计交付**
```
输出：设计标注稿、切图、设计规范文档
- 标注：使用Figma标注插件，导出尺寸、颜色、字体
- 切图：导出@2x、@3x图标和图片
- 规范：组件库、色彩规范、字体规范
- 协作：开发评审会议，解答疑问
```

### 总结

- UI设计流程六阶段：需求理解 → 用户研究 → 信息架构 → 交互设计 → 视觉设计 → 交付
- 流程的核心是"以用户为中心"和"迭代验证"
- 每个阶段有明确的输入和输出，确保可追溯
- 实际工作中流程可灵活调整，但核心环节不能省略
- **常见误区**：跳过用户研究直接画图；做完视觉设计不交付标注；不与开发沟通导致还原度低
- **实践建议**：建立设计评审机制，每个阶段结束有评审和验收；使用Figma等协作工具提高效率

# 第2章 视觉设计基础

## 第5讲 色彩理论：色相、明度、饱和度与配色方案

### 概念

色彩是UI设计中最具表现力的视觉元素。理解色彩理论，需要掌握三个核心维度：**色相**（Hue，颜色的种类，如红、蓝、绿）、**明度**（Value/Lightness，颜色的明暗程度）、**饱和度**（Saturation，颜色的鲜艳程度），合称HSV/HSB模型。

在UI设计中，色彩不仅用于美观，更承担着**信息传达、状态反馈、品牌识别**三大功能。一套好的配色方案，能让界面层次清晰、操作引导明确、品牌印象深刻。

### 原理

**1. 色彩三要素**

- **色相（H）**：色彩的基本属性，用色相环（0°-360°）表示。0°=红色，120°=绿色，240°=蓝色。
- **明度（L/V）**：从黑到白的过渡。高明度=浅色，低明度=深色。明度差异是建立视觉层次的关键。
- **饱和度（S）**：色彩的纯度。高饱和=鲜艳，低饱和=灰暗。饱和度影响情感表达——高饱和显活力，低饱和显沉稳。

**2. 配色方案类型**

基于色相环，常见配色方案有：
- **单色配色**（Monochromatic）：同一色相不同明度/饱和度。和谐统一，适合新手。
- **类似色配色**（Analogous）：色相环上相邻的颜色（如蓝-青-绿）。自然舒适。
- **互补色配色**（Complementary）：色相环上相对的颜色（如红-绿）。对比强烈，用于强调。
- **三元配色**（Triadic）：色相环上等距的三个颜色。丰富活泼，需注意主次。
- **分割互补**（Split-Complementary）：一个颜色+其互补色两侧的颜色。对比适中。

**3. UI配色的60-30-10法则**

借鉴室内设计的经典法则：
- **60%** 主色（通常是背景色，中性色）
- **30%** 辅助色（次级背景、卡片色）
- **10%** 强调色（按钮、链接、重要操作）

**4. 色彩心理学**

不同颜色引发不同情感联想：
- 红色：热情、警示、紧迫（常用于错误、促销）
- 蓝色：信任、专业、冷静（常用于金融、科技）
- 绿色：自然、安全、成功（常用于成功状态、环保）
- 黄色：活力、注意、温暖（常用于警告、提示）
- 紫色：优雅、神秘、创意（常用于奢侈品、艺术）

### 例子

以一个**金融App**的配色方案为例：

**色彩系统定义**：
```css

--color-primary-hover: #4096FF;  /* 悬停态 */
```

**应用60-30-10法则**：
```

```

**色彩层次示例**：

### 总结

- 色彩三要素：色相（H）、明度（L）、饱和度（S），用HSB模型理解
- 五种配色方案：单色、类似色、互补色、三元、分割互补
- UI配色遵循60-30-10法则：60%主色、30%辅助色、10%强调色
- 色彩有心理学含义，选择需考虑品牌调性和使用场景
- **常见误区**：使用过多颜色（超过3种主色）；忽视明度对比导致可读性差；功能色混用（如用绿色表示错误）
- **实践建议**：建立色彩系统，定义主色、功能色、中性色及其变体；使用HSL而非RGB调整色彩，更直观

## 第6讲 字体排版：字体选择、字号层级与行距

### 概念

字体排版（Typography）是UI设计中传递信息最直接的手段。好的排版能让内容清晰易读、层次分明；差的排版会让用户阅读疲劳、找不到重点。

UI排版的核心要素包括：**字体家族**（Font Family，如无衬线、衬线）、**字号**（Font Size）、**字重**（Font Weight，如Regular、Bold）、**行高**（Line Height）、**字间距**（Letter Spacing）和**段落间距**。

### 原理

**1. 字体分类**

- **无衬线体**（Sans-Serif）：笔画粗细均匀，没有装饰线。现代、简洁、屏幕显示清晰。UI设计首选。代表：Helvetica、Arial、PingFang SC、思源黑体。
- **衬线体**（Serif）：笔画有装饰线，粗细有变化。传统、正式、印刷品常用。代表：Times New Roman、宋体、思源宋体。
- **等宽体**（Monospace）：每个字符宽度相同。用于代码展示。代表：Consolas、Source Code Pro。

**2. 字号层级**

UI设计中，字号层级通常遵循**模块化比例**（Modular Scale），常见比例有：
- **1.2倍（Minor Third）**：12 → 14 → 17 → 20 → 24 → 29
- **1.25倍（Major Third）**：12 → 15 → 19 → 24 → 30 → 38
- **1.333倍（Perfect Fourth）**：12 → 16 → 21 → 28 → 38 → 50

一般建议UI使用3-5个字号层级，过多会增加认知负荷。

**3. 行高规则**

- 正文行高：字号的1.4-1.6倍（如16px字号，行高24px）
- 标题行高：字号的1.1-1.3倍（标题越大，行高比例越小）
- 按钮文字：行高=字号，紧凑显示

**4. 字重使用**

- Regular（400）：正文
- Medium（500）：次级标题、强调
- SemiBold（600）：标题
- Bold（700）：主标题、按钮

**5. 中文排版注意事项**

- 中文字体没有衬线/无衬线的严格区分，但"黑体"类≈无衬线，"宋体"类≈衬线
- 中英文混排时，英文字号通常比中文小1-2px，视觉才平衡
- 中文行高比英文大，通常1.5-1.8倍

### 例子

以一个**新闻App**的排版系统为例：

**字体系统定义**：
```css
/* 字体家族 */

               "PingFang SC", "Microsoft YaHei", 
               sans-serif;

/* 字号层级（1.25倍比例） */
--font-size-caption:  12px;  /* 辅助说明 */
--font-size-body:     15px;  /* 正文 */
--font-size-subtitle: 19px;  /* 小标题 */
--font-size-title:    24px;  /* 标题 */
--font-size-headline: 30px;  /* 大标题 */

/* 字重 */
--font-weight-regular:  400;
--font-weight-medium:   500;
--font-weight-semibold: 600;
--font-weight-bold:     700;

/* 行高 */
--line-height-tight:   1.2;   /* 标题 */
--line-height-normal:  1.5;   /* 正文 */
--line-height-relaxed: 1.75;  /* 长文阅读 */
```

**排版应用示例**：

### 总结

- UI首选无衬线字体，屏幕显示更清晰
- 字号使用模块化比例（1.2-1.333倍），建议3-5个层级
- 行高：正文1.4-1.6倍，标题1.1-1.3倍
- 字重用Regular/Medium/SemiBold/Bold四档足够
- 中英文混排需微调字号和字体
- **常见误区**：字号层级过多（超过6种）；行高过紧导致阅读困难；中英文用同一字号导致视觉不平衡
- **实践建议**：建立字体系统，统一定义字号、字重、行高；使用系统字体栈保证各平台一致性；长文阅读行高适当放大（1.6-1.8倍）

## 第7讲 间距系统：8点栅格与视觉节奏

### 概念

间距是UI设计中最容易被忽视、却最能体现设计专业度的元素。统一的间距系统能让界面产生**视觉节奏感**，让用户感知到秩序和专业。

业界最广泛使用的是**8点栅格系统**（8-point Grid System），即所有间距都是8的倍数（8, 16, 24, 32, 48...）。部分场景会配合4点栅格做微调。

### 原理

**1. 为什么是8？**

- 8能被2、4、8整除，方便等分
- 主流屏幕分辨率（1920x1080、1440x900）都能被8整除
- iOS和Android的基准单位都接近8的倍数
- 8px是视觉上可感知的最小间距单位

**2. 8点栅格的优势**

- **一致性**：所有间距遵循同一规则，界面自然统一
- **效率**：设计师不用每次纠结"用12还是14"，直接选8的倍数
- **协作**：开发还原时，间距数值清晰，减少沟通成本
- **缩放**：8的倍数在不同屏幕密度下都能精确渲染

**3. 间距层级**

典型的8点间距系统：
```
4px   - 极小间距（图标与文字间距）
8px   - 小间距（相关元素间距）
16px  - 中间距（卡片内边距、列表项间距）
24px  - 大间距（区块间距）
32px  - 区块间距（大段落间距）
48px  - 页面级间距
64px  - 大型留白
```

**4. 间距语义化**

将数值赋予语义，便于复用：
- `spacing.xs` = 4px
- `spacing.sm` = 8px
- `spacing.md` = 16px
- `spacing.lg` = 24px
- `spacing.xl` = 32px
- `spacing.xxl` = 48px

**5. 内间距与外间距**

- **内间距**（Padding）：元素内部到边缘的距离，如按钮文字到按钮边缘
- **外间距**（Margin）：元素与元素之间的距离，如两个按钮之间的距离
- 规则：内间距用小值（8-16px），外间距用大值（16-32px）

### 例子

以一个**设置页面**为例，展示间距系统的应用：

**间距系统定义**：
```css
:root {
  --space-xs:  4px;   /* 图标与文字 */
  --space-sm:  8px;   /* 紧密元素 */
  --space-md:  16px;  /* 常规间距 */
  --space-lg:  24px;  /* 区块内间距 */
  --space-xl:  32px;  /* 区块间间距 */
  --space-xxl: 48px;  /* 页面级间距 */
}
```

**页面间距应用**：
```

│                                     │

│  │                                │  │
```

### 总结

- 8点栅格系统是UI间距设计的行业标准，所有间距用8的倍数
- 4px用于微调（如图标与文字间距）
- 建立语义化间距变量（xs/sm/md/lg/xl/xxl），便于复用
- 内间距用小值，外间距用大值
- **常见误区**：间距随意取值（如13px、17px）；间距层级过多；内外间距混用
- **实践建议**：在Figma中设置8px栅格和布局网格，强制对齐；间距系统与字体系统配合使用，保持整体节奏一致

## 第8讲 图标设计：风格统一与语义表达

### 概念

图标是UI设计中高度浓缩的视觉语言，用简洁的图形传递信息。一个好的图标应该具备**识别性**（用户能看懂）、**一致性**（风格统一）、**美观性**（视觉舒适）三大特征。

UI图标按风格可分为：**线性图标**（Outline/Stroke）、**面性图标**（Fill/Solid）、**双色图标**（Two-tone）、**多色图标**（Multi-color）。按功能可分为：**操作图标**（如删除、编辑）、**导航图标**（如首页、搜索）、**状态图标**（如成功、警告）、**内容图标**（如音乐、视频）。

### 原理

**1. 图标设计原则**

- **简洁性**：去除多余细节，用最少的元素表达含义。复杂图标在小尺寸下会模糊。
- **识别性**：用户能在1秒内理解含义。优先使用约定俗成的符号（如齿轮=设置）。
- **一致性**：同一套图标的描边粗细、圆角大小、视觉重量保持统一。
- **可扩展性**：设计时考虑不同尺寸的显示效果（16px/24px/32px）。

**2. 图标栅格**

专业图标设计使用**24x24px**的标准画布，内部留出2px安全边距，实际内容区域为20x20px。关键形状（圆形、方形、三角形）有不同的视觉中心，需要通过光学对齐调整：

```
┌────────────────────┐
│  2px 安全边距        │
│  ┌──────────────┐  │
│  │              │  │
│  │   图标内容    │  │  20x20 内容区
│  │              │  │
│  └──────────────┘  │
│                    │
└────────────────────┘
       24x24 画布
```

**3. 描边规范**

- 描边粗细：1.5px / 2px / 3px（根据图标尺寸选择）
- 线帽：圆角（Round）或平角（Butt），全套统一
- 连接点：圆角（Round）或斜角（Miter），全套统一
- 内外圆角：保持视觉一致，通常外圆角=内圆角+描边粗细

**4. 图标语义**

常见图标的约定含义：
- 🔍 放大镜 = 搜索
- ⚙️ 齿轮 = 设置
- 🏠 房子 = 首页
- ❤️ 心形 = 收藏/喜欢
- 🗑️ 垃圾桶 = 删除
- ✏️ 铅笔 = 编辑
- ➕ 加号 = 新增
- ⬇️ 向下箭头 = 下载

以一套**消息App图标**为例，展示风格统一：

**图标规范定义**：
```

风格：线性
```

## 第9讲 视觉层次：通过对比引导用户注意力

### 概念

视觉层次（Visual Hierarchy）是指通过设计手段安排界面元素的重要性顺序，引导用户按预期顺序浏览。好的视觉层次能让用户**第一眼看到最重要的内容**，无需思考就知道该做什么。

视觉层次通过**对比**（Contrast）来实现——大小、颜色、间距、位置、字重等元素的差异，都会影响用户的视觉优先级。

### 原理

**1. 视觉层次的影响因素**

按影响力从大到小排列：
- **大小**（Size）：越大越重要
- **颜色**（Color）：越鲜艳/对比越强越重要
- **位置**（Position）：左上角和中心更受关注（F型/Z型阅读模式）
- **间距**（Spacing）：周围留白越多越突出
- **字重**（Weight）：越粗越重要
- **对比度**（Contrast）：与背景差异越大越突出

**2. 阅读模式**

用户浏览网页时遵循特定模式：
- **F型模式**（F-Pattern）：内容型页面，用户从左到右、从上到下扫描，形成F形轨迹
- **Z型模式**（Z-Pattern）：简单页面（如登录页），用户沿Z形对角线浏览
- **层叠蛋糕模式**（Layer Cake）：用户横向扫描标题，感兴趣才读正文

**3. 对比手法**

- **大小对比**：标题24px vs 正文14px
- **颜色对比**：主按钮#1677FF vs 次按钮#FFFFFF
- **字重对比**：标题Bold vs 正文Regular
- **间距对比**：重要元素周围留白多
- **形状对比**：圆形头像 vs 方形卡片

**4. 三秒法则**

用户打开页面后3秒内应能：
1. 知道这个页面是做什么的
2. 找到最重要的操作入口
3. 理解内容的基本结构

如果3秒内做不到，说明视觉层次有问题。

### 例子

以一个**商品详情页**为例，分析视觉层次：

**层次设计目标**：
1. 第一眼：商品图片和名称（吸引注意）
2. 第二眼：价格和促销信息（促成转化）
3. 第三眼：加入购物车按钮（引导操作）
4. 第四眼：商品详情和评价（辅助决策）

**层次实现**：
```
┌─────────────────────────────────────┐
│                                     │
│  ┌───────────────────────────────┐  │
│  │                               │  │
│  │      商品大图（300px高）        │  │  ← 层次1：最大视觉面积
│  │                               │  │
│  └───────────────────────────────┘  │
│                                     │
│  24px间距                            │
│                                     │
│  无线蓝牙耳机                        │  ← 层次2：20px标题，加粗
│  主动降噪 · 超长续航                  │  ← 14px副标题，灰色
│                                     │
│  16px间距                            │
│                                     │
│  ¥299  ¥499  限时特惠                │  ← 层次3：价格24px红色
│   ↑    ↑     ↑                      │     原价14px灰色删除线
│  大小  原价  标签                    │     标签12px红底白字
│  对比  对比  对比                    │
│                                     │
│  24px间距                            │
│                                     │
│  ┌───────────────────────────────┐  │
│  │     🛒 加入购物车              │  │  ← 层次4：主按钮，品牌色

│  ┌───────────────────────────────┐  │
│  │       立即购买                 │  │  ← 次按钮，白底蓝字
│  └───────────────────────────────┘  │
│                                     │

│                                     │
```

**对比分析**：
```

  - 位置：页面顶部，第一眼可见

  - 字号对比：20px > 副标题14px

  - 颜色对比：黑色 > 灰色

  - 大小对比：24px > 14px
  - 装饰对比：原价有删除线

层次4：操作按钮
  - 颜色对比：品牌色背景 vs 白色背景
  - 大小对比：高度48px（足够大）
  - 位置：固定底部，始终可见
```

### 总结

- 视觉层次通过对比实现：大小、颜色、位置、间距、字重
- 用户阅读遵循F型、Z型等模式，重要内容放在视觉热点
- 三秒法则：3秒内让用户理解页面目的和主要操作
- 层次不宜过多，3-4个层次足够
- **常见误区**：所有元素同等重要（没有重点）；对比不足（层次模糊）；对比过度（到处都是重点=没有重点）
- **实践建议**：设计前先列出内容优先级（1-2-3-4），再通过对比手段实现；眯眼测试（Squint Test）——眯起眼睛看，最突出的元素是否是你想强调的

# 第3章 布局与构图

## 第10讲 布局原则：平衡、对齐、对比与留白

### 概念

布局是指界面元素在页面中的排列方式。好的布局能让信息清晰、操作流畅、视觉舒适。UI布局有四大基本原则，源自设计经典《写给大家看的设计书》（CRAP原则）：

- **对比**（Contrast）：让不同元素有视觉差异
- **重复**（Repetition）：相同元素用相同方式呈现
- **对齐**（Alignment）：元素之间有视觉连接
- **亲密性**（Proximity）：相关元素靠近放置

此外，**平衡**（Balance）和**留白**（White Space）也是布局的核心概念。

### 原理

**1. 四大原则详解**

- **对比**：避免元素相似。如果两个元素不同，就让它们**非常不同**。对比能创造视觉兴趣，引导注意力。如标题与正文的字号差异、主按钮与次按钮的颜色差异。
- **重复**：在整个产品中重复使用相同的设计元素（颜色、字体、间距、组件），创造一致性和专业感。重复是建立设计系统的基础。
- **对齐**：每个元素都应与页面上的其他元素有视觉连接。不要随意放置元素。对齐能创造秩序感，让界面看起来"干净"。
- **亲密性**：将相关的元素靠近，不相关的元素远离。亲密性能组织信息，减少视觉混乱。

**2. 平衡的类型**

- **对称平衡**：左右或上下镜像，庄重正式。适合登录页、官方首页。
- **不对称平衡**：左右不同但视觉重量相等，活泼现代。适合内容型页面。
- **径向平衡**：元素围绕中心点排列，聚焦感强。适合仪表盘。

**3. 留白的作用**

留白不是"浪费空间"，而是重要的设计元素：
- **分隔内容**：用留白代替分割线，更优雅
- **引导视线**：重要元素周围留白多，自然吸引注意
- **提升品质感**：充足留白=高端感（奢侈品网站常用）
- **降低认知负荷**：留白让大脑"喘息"，信息更易消化

**4. 对齐方式**

- **左对齐**：最符合阅读习惯，正文首选
- **居中对齐**：正式庄重，标题和短文本可用
- **右对齐**：数字、日期等需要对比的内容
- **两端对齐**：慎用，易产生不规则间距

### 例子

以一个**个人名片**为例，展示CRAP原则的应用：

**差的布局**（无原则）：
```
┌─────────────────────────────┐
│ 张三                         │
│      产品设计师               │
│                          📧  │
│   zhangsan@email.com        │
│  📱 138-0000-0000           │
│                    某某公司   │
└─────────────────────────────┘
```
问题：元素随意放置，没有对齐；信息没有分组；视觉混乱。

**好的布局**（应用CRAP）：
```
┌─────────────────────────────┐
│                             │
│  张三                        │  ← 左对齐，24px Bold
│  产品设计师                    │  ← 左对齐，14px Regular 灰色
│                             │
│  ─────────────              │  ← 分隔线（亲密性：上下分组）
│                             │
│  📧 zhangsan@email.com       │  ← 左对齐，图标+文字对齐
│  📱 138-0000-0000            │  ← 左对齐，与上一行对齐
│                             │
│                    某某公司   │  ← 右对齐，与上方形成对比
│                             │
└─────────────────────────────┘
```

**原则分析**：
```
对比（Contrast）：
  - 姓名24px Bold vs 职位14px Regular（字号+字重对比）
  - 姓名#000000 vs 职位#8C8C8C（颜色对比）

重复（Repetition）：
  - 邮箱和电话用相同的图标+文字格式
  - 所有文字左对齐

对齐（Alignment）：
  - 左侧所有元素左对齐，形成一条隐形竖线
  - 公司名右对齐，与左侧形成对比

亲密性（Proximity）：
  - 姓名+职位靠近（同一信息组）
  - 邮箱+电话靠近（同一信息组）
  - 两组之间用分隔线+留白分隔
```

**留白应用**：
```
┌─────────────────────────────┐
│ 24px顶部留白                  │
│                             │
│  [姓名组]                    │
│ 16px组内间距                  │
│  [职位]                      │
│                             │
│ 24px组间留白                  │
│  [分隔线]                    │
│ 24px组间留白                  │
│                             │
│  [邮箱]                      │
│ 8px组内间距                   │
│  [电话]                      │
│                             │
│ 24px底部留白                  │
└─────────────────────────────┘
```

### 总结

- CRAP四大原则：对比、重复、对齐、亲密性
- 平衡分对称、不对称、径向三种，根据场景选择
- 留白是设计元素，不是空间浪费——分隔、引导、提升品质
- 对齐创造秩序，左对齐最符合阅读习惯
- **常见误区**：元素随意放置不对齐；留白不足导致拥挤；所有元素居中（缺乏活力）
- **实践建议**：在Figma中开启对齐参考线；设计时先确定对齐方式，再放置元素；用留白代替分割线，更优雅

## 第11讲 栅格系统：12列栅格与模块化布局

### 概念

栅格系统（Grid System）是UI布局的基础框架，通过将页面划分为等宽的列（Columns）和间距（Gutters），为元素放置提供统一的对齐参考。Web设计中最常用的是**12列栅格系统**，因为12能被2、3、4、6整除，灵活性最高。

栅格系统让布局有据可依，保证不同页面、不同设计师的作品风格统一，也便于团队协作和开发还原。

### 原理

**1. 栅格的组成**

一个完整的栅格系统包含：
- **列**（Columns）：内容区域的垂直划分，12列最常见
- **列宽**（Column Width）：每列的宽度，通常用百分比或固定值
- **间距**（Gutter）：列与列之间的空白
- **边距**（Margin）：页面边缘到栅格的空白
- **安全区**（Container）：栅格的总宽度

```
┌──────────────────────────────────────────┐
│ Margin                          Margin   │
│  ↓                               ↓       │
│  ┌──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┐  │
│  │  │  │  │  │  │  │  │  │  │  │  │  │  │
│  │C1│C2│C3│C4│C5│C6│C7│C8│C9│10│11│12│  │
│  │  │  │  │  │  │  │  │  │  │  │  │  │  │
│  └──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┘  │
│    ↑  ↑                                 │
│   Gutter                                │
└──────────────────────────────────────────┘
│←──────── Container ──────────────→│
```

**2. 为什么是12列？**

12的因数有1、2、3、4、6、12，可以灵活组合：
- 12 = 12（整行）
- 12 = 6 + 6（两等分）
- 12 = 4 + 4 + 4（三等分）
- 12 = 3 + 3 + 3 + 3（四等分）
- 12 = 8 + 4 或 4 + 8（2:1 或 1:2）
- 12 = 3 + 9 或 9 + 3（1:3 或 3:1）

**3. 常见布局模式**

基于12列栅格，常见布局有：
- **全宽**（12列）：Banner、导航栏
- **1/2**（6+6）：两栏内容
- **1/3**（4+4+4）：三栏内容、商品列表
- **1/4**（3+3+3+3）：四栏内容、图标列表
- **2/3 + 1/3**（8+4）：主内容+侧边栏
- **1/3 + 2/3**（4+8）：侧边栏+主内容

**4. 响应式栅格**

不同屏幕宽度使用不同列数：
- 手机（<768px）：4列，通常只占1列
- 平板（768-1024px）：8列
- 桌面（>1024px）：12列

以一个**电商首页**为例，展示12列栅格的应用：

**栅格配置**：

```
│商品4│
└────┘

手机端（<768px）：1列商品展示
┌──────────┐
│  商品1    │
└──────────┘
┌──────────┐
│  商品2    │
└──────────┘
...（垂直排列）
```

### 总结

- 12列栅格是Web设计的标准，因12的因数丰富，组合灵活
- 栅格由列、间距、边距、安全区组成
- 常见布局：全宽、1/2、1/3、1/4、2/3+1/3
- 响应式设计时，不同屏幕使用不同列数
- **常见误区**：不用栅格随意布局；栅格列数选择不当（如用10列）；移动端仍用桌面栅格
- **实践建议**：在Figma中设置Layout Grid，可视化栅格；前端用CSS Grid或Flexbox实现；栅格间距遵循8点系统（16px/24px）

## 第12讲 响应式设计：断点设置与流式布局

### 概念

响应式设计（Responsive Design）是指同一套设计能自适应不同屏幕尺寸（手机、平板、桌面），提供最优的浏览体验。其核心是**断点**（Breakpoint）和**流式布局**（Fluid Layout）。

断点是屏幕宽度的临界值，当宽度变化跨越断点时，布局会调整。流式布局是指元素宽度用百分比而非固定像素，让内容自然填充可用空间。

### 原理

**1. 响应式设计三要素**

- **流式网格**（Fluid Grid）：用百分比/em/rem定义宽度，而非固定px
- **弹性图片**（Flexible Images）：图片最大宽度100%，自适应容器
- **媒体查询**（Media Query）：根据屏幕宽度应用不同CSS

**2. 主流断点设置**

参考Bootstrap和Tailwind的断点：
```
手机：    < 640px   (sm)
平板竖屏：640 - 768px  (md)
平板横屏：768 - 1024px (lg)
桌面：   1024 - 1280px (xl)
大桌面：  > 1280px  (2xl)
```

**3. 移动优先 vs 桌面优先**

- **移动优先**（Mobile First）：先设计手机端，再向上适配。CSS默认是手机样式，用`min-width`媒体查询向上扩展。推荐做法。
- **桌面优先**（Desktop First）：先设计桌面端，再向下适配。CSS默认是桌面样式，用`max-width`媒体查询向下缩减。

**4. 响应式策略**

- **列数变化**：桌面4列 → 平板2列 → 手机1列
- **导航变化**：桌面顶部导航 → 手机汉堡菜单
- **内容隐藏**：次要内容在手机端隐藏
- **布局重排**：桌面左右布局 → 手机上下布局
- **字号调整**：桌面大标题 → 手机适当缩小

### 例子

以一个**新闻网站**为例，展示响应式设计：

**断点定义**：

## 第13讲 信息架构：内容组织与导航设计

### 概念

信息架构（Information Architecture, IA）是组织和标注内容的方式，帮助用户高效找到所需信息。好的信息架构是UI设计的基础——如果内容组织混乱，再好看的界面也无法拯救。

信息架构的核心是**组织系统**（如何分类）、**标签系统**（如何命名）、**导航系统**（如何到达）、**搜索系统**（如何查找）。

### 原理

**1. 组织结构类型**

- **层级结构**（Hierarchy）：树状结构，最常见。首页→分类→子分类→详情。适合内容有明确从属关系。
- **矩阵结构**（Matrix）：允许多种路径到达同一内容。如电商商品可按品类、品牌、价格多种方式浏览。
- **线性结构**（Linear）：按顺序浏览。如教程、问卷、结账流程。
- **网状结构**（Web）：自由链接，无固定路径。如Wiki百科。

**2. 组织原则**

- **MECE原则**：Mutually Exclusive, Collectively Exhaustive（相互独立、完全穷尽）。分类不重叠、不遗漏。
- **用户心智模型**：分类方式应符合用户预期，而非企业内部结构。如用户找"手机"，不应按"通讯事业部"分类。
- **深度与广度平衡**：层级太深（点击次数多）或太广（每页选项太多）都不好。经验法则：3次点击内到达任何页面。

**3. 导航类型**

- **全局导航**（Global Navigation）：全站可见，指向主要板块。如顶部导航栏。
- **局部导航**（Local Navigation）：当前板块内的导航。如侧边栏。
- **面包屑**（Breadcrumb）：显示当前位置路径。如"首页 > 科技 > 手机"。
- **辅助导航**（Utility Navigation）：辅助功能。如搜索、登录、购物车。
- **页脚导航**（Footer Navigation）：底部链接，通常放次要内容。

**4. 标签设计原则**

- **简洁**：用最少的字表达（"首页"而非"网站首页"）
- **熟悉**：用用户熟悉的词（"购物车"而非"购物篮"，根据地区）
- **一致**：同一概念全站用同一词（不要混用"删除"和"移除"）
- **可扫描**：用户扫描而非阅读，标签要能一眼识别

### 例子

以一个**在线教育平台**的信息架构为例：

**层级结构设计**：

- 标签设计：简洁、熟悉、一致、可扫描
- **常见误区**：按企业结构而非用户心智分类；层级太深（超过3级）；标签用内部术语

# 第4章 组件设计

## 第14讲 按钮设计：类型、状态与交互

### 概念

按钮是UI中最基础、最常用的交互组件，用于触发操作。按钮设计看似简单，但要做到好用、一致、专业，需要考虑**类型**（主按钮、次按钮、文字按钮）、**状态**（默认、悬停、按下、禁用、加载中）、**尺寸**（大、中、小）和**位置**（页面、表单、对话框）等多个维度。

### 原理

**1. 按钮类型层级**

按钮的视觉层级反映操作的重要性：
- **主按钮**（Primary Button）：品牌色填充，白色文字。每屏最多1个，表示最重要操作。如"提交"、"保存"。
- **次按钮**（Secondary Button）：白底，品牌色边框和文字。辅助操作。如"取消"、"返回"。
- **文字按钮**（Text Button）：无背景无边框，仅文字。最轻量。如"查看更多"、"跳过"。
- **图标按钮**（Icon Button）：仅图标，节省空间。如"关闭"、"分享"。
- **危险按钮**（Danger Button）：红色填充。破坏性操作。如"删除"。

**2. 按钮状态**

每个按钮应有以下状态：
- **默认**（Default）：正常显示
- **悬停**（Hover）：鼠标悬停，颜色略深
- **按下**（Active/Pressed）：点击瞬间，颜色更深
- **禁用**（Disabled）：灰色，不可点击
- **加载中**（Loading）：显示加载动画，防止重复点击
- **聚焦**（Focus）：键盘聚焦，有外框，用于无障碍

**3. 按钮尺寸**

遵循8点栅格：
- **大按钮**：高度48px，用于移动端主要操作
- **中按钮**：高度40px，桌面端默认
- **小按钮**：高度32px，紧凑场景

**4. 按钮位置规则**

- **对话框**：主按钮在右，次按钮在左（遵循阅读顺序，最后看到主按钮）
- **表单**：按钮在表单底部，主按钮在右
- **页面底部**：主按钮固定底部，全宽（移动端）
- **工具栏**：相关按钮成组，用分隔线区隔

### 例子

以一套**按钮组件**为例：

**按钮样式定义**：

- 按钮类型：主按钮（最重要）、次按钮（辅助）、文字按钮（最轻）、图标按钮（省空间）、危险按钮（破坏性）
- 每个按钮需设计6种状态：默认、悬停、按下、禁用、加载、聚焦
- 尺寸遵循8点栅格：大48px、中40px、小32px
- 位置规则：主按钮在右，次按钮在左；移动端主按钮固定底部
- **常见误区**：一屏多个主按钮（用户不知道点哪个）；缺少加载状态导致重复提交；禁用状态不明显
- **实践建议**：每屏最多1个主按钮；破坏性操作用危险按钮+二次确认；按钮文字用动词（"保存"而非"确定"）

## 第15讲 表单设计：输入、验证与反馈

### 概念

表单是用户输入信息的界面，广泛用于注册、登录、下单、设置等场景。表单设计的好坏直接影响转化率——表单越长、越复杂，用户放弃的概率越高。

表单设计的核心目标是**降低用户填写成本**，通过合理的字段组织、清晰的标签、即时的验证反馈，让用户快速、准确地完成填写。

### 原理

**1. 表单设计原则**

- **精简**：只收集必要信息。每多一个字段，转化率下降约5-10%。
- **清晰**：标签明确，占位提示有帮助，错误信息易懂。
- **高效**：合理默认值、自动填充、智能联想，减少用户输入。
- **宽容**：允许格式灵活（如电话号码有无横线都接受），即时验证而非提交后才报错。

**2. 标签位置**

- **顶部标签**（Top Label）：标签在输入框上方。最易阅读，适合移动端。垂直空间占用多。
- **左侧标签**（Left Label）：标签在输入框左侧。节省垂直空间，适合长表单。标签与输入框距离远，阅读稍慢。
- **浮动标签**（Floating Label）：标签初始在输入框内（作为占位符），聚焦后上浮为标签。节省空间，但认知稍复杂。
- **图标标签**（Icon Label）：仅用图标。最简洁，但含义可能不明确。

**3. 输入框类型**

根据内容选择合适的输入类型：
- **文本框**（Text Input）：单行文本
- **文本域**（Textarea）：多行文本
- **密码框**（Password）：隐藏输入内容
- **数字框**（Number）：纯数字，移动端弹出数字键盘
- **日期选择器**（Date Picker）：选择日期
- **下拉选择**（Select）：从列表中选择
- **单选/多选**（Radio/Checkbox）：选择选项
- **开关**（Switch）：二选一

**4. 验证策略**

- **即时验证**（Inline Validation）：输入完成即验证，显示对勾或叉号
- **提交验证**（On Submit）：提交时统一验证
- **失焦验证**（On Blur）：输入框失去焦点时验证

推荐：即时验证+失焦验证结合，提交时做最终检查。

**5. 错误反馈**

- **位置**：错误信息在输入框下方，红色文字
- **内容**：说明错误原因+如何修正（"邮箱格式不正确，请输入完整邮箱地址"）
- **时机**：即时反馈，不要等提交后
- **清除**：用户修改后立即清除错误状态

## 第16讲 导航设计：顶部导航、侧边栏与标签栏

### 概念

导航是用户在产品中移动的"路标"，决定了用户能否高效找到所需内容。根据平台和场景不同，导航有多种形式：**顶部导航栏**（Web桌面端）、**侧边栏**（后台管理系统）、**标签栏**（移动端底部）、**抽屉导航**（移动端隐藏式）、**Tab切换**（内容分区）等。

### 原理

**1. 导航设计原则**

- **可见性**：用户随时知道自己在哪、能去哪
- **一致性**：导航位置和样式全站统一
- **简洁性**：导航项不超过7个（米勒定律）
- **反馈性**：当前所在位置有明确高亮

**2. 导航类型与适用场景**

- **顶部导航栏**（Top Nav）：Web桌面端标配。水平排列主要板块。适合内容层级浅（1-2级）的网站。
- **侧边栏**（Sidebar）：后台管理系统标配。垂直排列，可展开折叠。适合层级深、功能多的系统。
- **标签栏**（Tab Bar）：移动端底部标配。3-5个主要入口。适合移动App。
- **抽屉导航**（Drawer）：隐藏在侧边，点击汉堡菜单展开。适合次要功能多的移动端。
- **面包屑**（Breadcrumb）：显示当前位置路径。辅助导航，配合主导航使用。
- **Tab切换**（Tabs）：同层级内容切换。适合内容分类。

**3. 移动端导航策略**

- **底部标签栏**：3-5个核心入口，始终可见
- **顶部标签**：内容分类切换
- **汉堡菜单**：收纳次要功能（但会降低发现性，慎用）
- **浮动按钮**（FAB）：突出主要操作

**4. 导航状态**

- **默认**：正常显示
- **悬停**：鼠标悬停，背景变化
- **选中/激活**：当前所在页面，高亮显示
- **禁用**：不可访问

## 第17讲 卡片与列表：内容展示的最佳实践

### 概念

卡片和列表是UI中展示内容的两种主要形式。**卡片**以独立区块展示信息，适合视觉丰富的内容（如商品、文章、用户）。**列表**以行排列信息，适合结构化、可扫描的内容（如消息、订单、设置项）。

选择卡片还是列表，取决于内容类型、信息密度和设备屏幕。

### 原理

**1. 卡片设计**

卡片是一个独立的信息容器，通常包含：
- **媒体区**：图片、视频、图标
- **标题区**：内容标题
- **描述区**：摘要文字
- **操作区**：按钮、链接

卡片的优势：
- 视觉吸引力强
- 信息分组清晰
- 响应式友好（列数可变）
- 适合触控操作

卡片的劣势：
- 空间利用率低
- 信息密度低
- 不适合大量同类内容

**2. 列表设计**

列表以行排列信息，每行包含：
- **前缀**：图标、头像、缩略图
- **主体**：标题、描述
- **后缀**：时间、状态、操作

列表的优势：
- 信息密度高
- 扫描效率高
- 空间利用率高
- 适合大量同类内容

列表的劣势：
- 视觉单调
- 不适合图片为主的内容

**3. 选择标准**

| 因素 | 卡片 | 列表 |
|------|------|------|
| 图片重要性 | 高 | 低 |
| 信息密度 | 低 | 高 |
| 内容数量 | 少 | 多 |
| 扫描需求 | 浏览 | 查找 |
| 移动端 | 网格 | 单列 |

**4. 卡片/列表状态**

- 默认
- 悬停（阴影加深或上浮）
- 选中（边框高亮）
- 禁用（灰色）

# 第5章 交互设计

## 第18讲 交互设计基础：用户旅程与状态流转

### 概念

交互设计关注用户与产品之间的"对话"过程——用户做了什么，系统如何响应，接下来会发生什么。如果说UI视觉设计是"静态"的，交互设计就是"动态"的，它定义了界面如何随用户操作而变化。

交互设计的两个核心工具是**用户旅程图**（User Journey Map）和**状态流转图**（State Flow Diagram）。前者描述用户完成目标的步骤，后者描述系统在不同状态间的切换。

### 原理

**1. 用户旅程图**

用户旅程图从用户视角描述完成某个目标的完整过程，包含：
- **阶段**（Stages）：用户经历的步骤
- **行为**（Actions）：用户做了什么
- **触点**（Touchpoints）：与产品交互的界面
- **情绪**（Emotions）：用户在每个阶段的感受
- **痛点**（Pain Points）：用户遇到的困难
- **机会**（Opportunities）：改进空间

**2. 状态流转图**

状态流转图描述系统在不同状态间的切换，包含：
- **状态**（States）：系统当前的情况
- **事件**（Events）：触发状态变化的操作
- **转换**（Transitions）：从一个状态到另一个状态的过程
- **条件**（Conditions）：转换发生的前提

**3. 交互设计原则**

- **可见性**（Visibility）：让用户看到能做什么
- **反馈**（Feedback）：让用户知道做了什么
- **约束**（Constraint）：限制用户能做什么，防止错误
- **映射**（Mapping）：控件与结果的关系要自然
- **一致性**（Consistency）：相似操作有相似结果
- **撤销**（Reversibility）：允许用户撤销操作

**4. 尼尔森十大可用性原则**

1. 系统状态可见性
2. 系统与现实世界匹配
3. 用户控制和自由
4. 一致性与标准
5. 防错
6. 识别而非回忆
7. 使用的灵活性与效率
8. 美观与极简设计
9. 帮助用户识别、诊断和恢复错误
10. 帮助文档

## 第19讲 微交互设计：细节决定体验

### 概念

微交互（Microinteraction）是产品中单一任务的细小交互，通常持续1-3秒。如点赞时的心形动画、下拉刷新时的加载图标、开关切换时的滑动效果。微交互虽小，却能极大提升用户体验，让产品"有温度"。

微交互的核心理念是：**关注细节，让每个操作都有回应**。好的微交互让用户感到愉悦、惊喜，甚至形成肌肉记忆。

### 原理

**1. 微交互的四个要素**

根据Dan Saffer的《微交互》一书，微交互包含：
- **触发器**（Trigger）：启动微交互的动作（用户操作或系统条件）
- **规则**（Rules）：决定微交互如何运行
- **反馈**（Feedback）：让用户知道发生了什么
- **循环与模式**（Loops & Modes）：微交互的重复和变化

**2. 微交互的作用**

- **提供反馈**：让用户知道操作已被接收
- **引导操作**：提示用户下一步该做什么
- **增强愉悦感**：让枯燥的操作变得有趣
- **传达状态**：显示系统当前状态
- **减少焦虑**：加载动画让等待不那么难熬

**3. 微交互设计原则**

- **有意义**：不为动画而动画，每个微交互应有目的
- **简洁**：持续时间短（150-300ms），不喧宾夺主
- **一致**：相似操作用相似微交互
- **自然**：动画符合物理直觉（如重力、弹性）
- **克制**：不要过度使用，避免视觉疲劳

**4. 常见微交互场景**

- 点赞/收藏动画
- 下拉刷新
- 加载动画
- 开关切换
- 按钮点击反馈
- 输入框聚焦
- 拖拽排序
- 消息提示（Toast）
- 页面转场

- 动画时长建议：微交互150-300ms，转场300-500ms

## 第20讲 动效设计：缓动函数与运动原则

### 概念

动效设计是UI设计中关于"运动"的学问。好的动效不仅让界面"活起来"，更能引导注意力、解释界面关系、增强空间感。动效设计的核心是**缓动函数**（Easing Function）和**运动原则**（Principles of Motion）。

缓动函数决定了动画的速度变化——是匀速、加速还是减速。运动原则则指导动画如何符合物理直觉和用户预期。

### 原理

**1. 缓动函数类型**

- **线性**（Linear）：匀速运动。机械感强，适合进度条，不适合UI过渡。
- **缓入**（Ease In）：开始慢，逐渐加速。如物体下落。
- **缓出**（Ease Out）：开始快，逐渐减速。如物体落地。UI中最常用。
- **缓入缓出**（Ease In-Out）：先加速后减速。如门的开合。适合页面转场。

**2. 缓动曲线**

```
线性 Linear          缓入 Ease In        缓出 Ease Out       缓入缓出 Ease In-Out
    │                    │                    │                    │
  1 ┤                  1 ┤                  1 ┤                  1 ┤
    │ \                  │   _                │ ‾                  │   _
    │  \                 │    ‾               │  \                 │  / \
    │   \                │     \              │   \                │ /   \
    │    \               │      \             │    \               │/     \
  0 ┤______\________   0 ┤________\_______  0 ┤______\________   0 ┤______\_______
    0      1   time       0      1   time       0      1   time       0      1   time
```

**3. Material Design运动原则**

- **自然**（Natural）：模拟真实物理，用缓动而非线性
- **适度**（Restrained）：动画服务于功能，不喧宾夺主
- **有目的**（Purposeful）：每个动画都有明确目的

**4. 动画时长标准**

| 类型 | 时长 | 场景 |
|------|------|------|
| 微交互 | 100-200ms | 按钮点击、开关切换 |
| 小范围过渡 | 200-300ms | 颜色变化、尺寸变化 |
| 大范围过渡 | 300-500ms | 页面转场、元素出现 |
| 复杂动画 | 500-800ms | 引导动画、故事叙述 |

**5. 运动的12原则（迪士尼动画原则在UI中的应用）**

1. 挤压与拉伸（Squash & Stretch）
2. 预备动作（Anticipation）
3. 呈现（Staging）
4. 直接动作与姿态对姿态
5. 跟随与重叠（Follow Through）
6. 缓入缓出（Slow In & Slow Out）
7. 弧线运动（Arcs）
8. 次级动作（Secondary Action）
9. 节奏（Timing）
10. 夸张（Exaggeration）
11. 稳重的绘制（Solid Drawing）
12. 吸引力（Appeal）

### 例子

以**页面转场动画**为例，展示动效设计：

**1. 缓动函数CSS实现**：
```css
/* 线性（不推荐用于UI） */
.transition-linear {
  transition: all 0.3s linear;
}

/* 缓出（最常用） */
.transition-ease-out {
  transition: all 0.3s ease-out;
  /* 等价于 cubic-bezier(0, 0, 0.58, 1) */
}

/* 缓入缓出（适合页面转场） */
.transition-ease-in-out {
  transition: all 0.3s ease-in-out;
  /* 等价于 cubic-bezier(0.42, 0, 0.58, 1) */
}

/* Material Design标准缓动 */
.transition-material {
  transition: all 0.3s cubic-bezier(0.4, 0, 0.2, 1);
}

/* 弹性效果（适合卡片弹出） */
.transition-spring {
  transition: all 0.5s cubic-bezier(0.68, -0.55, 0.265, 1.55);
}
```

**2. 页面转场动画**：

### 总结

- 缓动函数决定动画速度变化：线性、缓入、缓出、缓入缓出
- UI中最常用缓出（Ease Out），符合"减速停止"的物理直觉
- 动画时长：微交互100-200ms，小过渡200-300ms，大过渡300-500ms
- Material Design运动三原则：自然、适度、有目的
- 迪士尼12动画原则在UI中同样适用（如挤压拉伸、预备动作、跟随重叠）
- **常见误区**：用线性动画（机械感强）；动画过长影响效率；动画无目的（炫技）
- **实践建议**：UI过渡用ease-out；页面转场用ease-in-out；弹性效果慎用（易过度）；列表项依次出现用stagger animation；尊重`prefers-reduced-motion`无障碍设置

# 第6章 设计系统

## 第21讲 设计系统概述：从组件到规范

### 概念

设计系统（Design System）是设计标准的单一真相来源（Single Source of Truth），包含设计原则、设计令牌、组件库、模式库、使用规范等。它不仅是组件的集合，更是一套完整的设计语言。

设计系统解决的核心问题是**规模化的一致性**——当产品有几十个页面、多个团队协作时，如何保证设计统一、开发高效。知名的设计系统有Google的Material Design、Apple的HIG、Ant Design、IBM的Carbon等。

### 原理

**1. 设计系统的组成**

一个完整的设计系统包含：
- **设计原则**（Principles）：指导设计的价值观
- **设计令牌**（Design Tokens）：颜色、字体、间距等基础变量
- **组件库**（Component Library）：可复用的UI组件
- **模式库**（Pattern Library）：常见交互模式
- **使用规范**（Guidelines）：何时用、如何用
- **资源**（Resources）：Figma库、代码库、图标库

**2. 设计系统的层级**

```
设计系统
├── 基础（Foundations）
│   ├── 颜色
│   ├── 字体
│   ├── 间距
│   ├── 圆角
│   ├── 阴影
│   └── 图标
├── 组件（Components）
│   ├── 原子（Atoms）：按钮、输入框、图标
│   ├── 分子（Molecules）：表单项、搜索栏
│   ├── 有机体（Organisms）：导航栏、卡片组
│   └── 模板（Templates）：页面布局
└── 页面（Pages）
    └── 具体页面实例
```

这是原子设计（Atomic Design）方法论，由Brad Frost提出，将UI从简单到复杂分为原子、分子、有机体、模板、页面五层。

**3. 设计系统的价值**

- **一致性**：全产品视觉和交互统一
- **效率**：复用组件，减少重复设计
- **协作**：设计师和开发者有共同语言
- **可维护**：修改一处，全局生效
- **可扩展**：新功能基于现有组件快速搭建

**4. 设计系统 vs 组件库 vs 风格指南**

| 概念 | 范围 | 内容 |
|------|------|------|
| 风格指南 | 最小 | 颜色、字体、Logo规范 |
| 组件库 | 中等 | 可复用组件 + 代码 |
| 设计系统 | 最大 | 原则 + 令牌 + 组件 + 模式 + 规范 |

### 例子

以**Ant Design**为例，展示设计系统的结构：

**1. 设计原则**：
```
Ant Design的四大原则：

1. 亲密性（Intimacy）
   - 如果信息关联性高，它们应该靠得更近
   
2. 对齐（Alignment）
   - 保持元素在视觉上的对齐
   
3. 对比（Contrast）
   - 通过对比突出重要信息
   
4. 重复（Repetition）
   - 相同元素用相同方式呈现
```

**2. 设计令牌**：

```
- 行高：1.5
- 字重：400 (Regular) / 500 (Medium) / 600 (Semibold)

- 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48

- 小：2px
- 中：4px

```

**3. 组件层级**：

### 总结

- 设计系统是设计标准的单一真相来源，包含原则、令牌、组件、模式、规范
- 原子设计方法论：原子→分子→有机体→模板→页面
- 设计系统价值：一致性、效率、协作、可维护、可扩展
- 设计系统 > 组件库 > 风格指南
- **常见误区**：把设计系统等同于组件库；只做组件不做规范；设计系统不随产品迭代
- **实践建议**：从基础令牌开始建立设计系统；用Figma Variables/Styles管理令牌；组件文档要包含使用规范和反面案例；参考成熟设计系统（Ant Design、Material Design）

## 第22讲 设计令牌：颜色、间距、字体的系统化

### 概念

设计令牌（Design Tokens）是设计系统的最小构建单元，以名称-值对的形式存储设计决策。如`color-primary: #1677FF`、`spacing-md: 16px`、`font-size-lg: 20px`。

设计令牌的核心价值是**将设计决策与实现分离**——设计师定义令牌，开发者在各平台（Web、iOS、Android）使用同一套令牌名称，但值可以不同。这保证了跨平台的一致性，同时允许平台适配。

### 原理

**1. 令牌的层级**

设计令牌通常分三层：
- **全局令牌**（Global Tokens）：最基础的值，如`blue-500: #1677FF`
- **别名令牌**（Alias Tokens）：有语义的全局令牌引用，如`color-primary: {blue-500}`
- **组件令牌**（Component Tokens）：特定组件使用的令牌，如`button-primary-bg: {color-primary}`

**2. 令牌的类型**

- **颜色令牌**（Color）：品牌色、功能色、中性色、背景色
- **字体令牌**（Typography）：字号、字重、行高、字间距
- **间距令牌**（Spacing）：内边距、外边距、间距
- **尺寸令牌**（Size）：宽度、高度
- **圆角令牌**（Radius）：圆角大小
- **阴影令牌**（Shadow）：阴影层级
- **动效令牌**（Motion）：时长、缓动函数
- **断点令牌**（Breakpoint）：响应式断点

**3. 命名规范**

好的令牌命名应：
- **语义化**：用用途而非外观（`color-primary`而非`color-blue`）
- **层级化**：用前缀分组（`spacing-sm`、`spacing-md`、`spacing-lg`）
- **一致化**：全系统用同一命名规则

**4. 令牌的跨平台转换**

设计令牌可以转换为各平台的实现：
- Web：CSS变量、SCSS变量
- iOS：Swift常量
- Android：XML资源
- Flutter：Dart常量

### 总结

- 设计令牌是设计系统的最小构建单元，以名称-值对存储
- 令牌分三层：全局令牌、别名令牌、组件令牌
- 令牌类型：颜色、字体、间距、尺寸、圆角、阴影、动效、断点
- 命名规范：语义化、层级化、一致化
- 令牌可跨平台转换（Web CSS变量、iOS Swift、Android XML）
- **常见误区**：用外观命名（`color-blue`而非`color-primary`）；令牌层级混乱；硬编码值而非用令牌
- **实践建议**：用Figma Variables管理设计令牌；用Style Dictionary等工具自动生成各平台代码；令牌变更需走评审流程；定期清理未使用的令牌

## 第23讲 组件库建设：从原子到模板

### 概念

组件库是设计系统的核心产出物，是可复用UI组件的集合。好的组件库应具备**一致性**（视觉统一）、**完整性**（覆盖常用场景）、**灵活性**（可定制）、**可维护性**（易于更新）。

组件库建设遵循原子设计方法论，从最基础的原子（按钮、输入框）开始，逐步组合成分子（表单项）、有机体（导航栏）、模板（页面布局）。

### 原理

**1. 组件库建设流程**

1. **需求分析**：梳理产品用到的所有组件
2. **原子设计**：从原子开始定义基础组件
3. **属性定义**：确定每个组件的属性（类型、尺寸、状态）
4. **变体管理**：用Figma Variants管理组件变体
5. **文档编写**：每个组件配使用文档
6. **开发实现**：前端将设计组件转为代码组件
7. **迭代维护**：根据使用反馈持续优化

**2. 组件属性设计**

每个组件应定义：
- **类型**（Type/Variant）：主按钮、次按钮等
- **尺寸**（Size）：大、中、小
- **状态**（State）：默认、悬停、按下、禁用
- **内容**（Content）：文字、图标
- **属性**（Props）：是否禁用、是否加载中等

**3. Figma Variants管理**

Figma的Variants功能让组件管理更高效：
- 用属性（Property）定义变体维度
- 用斜杠（/）命名组织组件
- 用Variant Group管理相关变体

**4. 组件文档要素**

- 组件名称和描述
- 组件预览
- 属性说明
- 使用规范（何时用、如何用）
- 反面案例（不该怎么用）
- 代码示例

### 例子

以**按钮组件库**为例，展示组件库建设：

**1. 组件属性定义**：
```
按钮组件属性：

属性1：Type（类型）
├── Primary（主按钮）
├── Default（次按钮）
├── Dashed（虚线按钮）
├── Text（文字按钮）
└── Link（链接按钮）

属性2：Size（尺寸）
├── Large（大，48px）
├── Middle（中，40px）
└── Small（小，32px）

属性3：State（状态）
├── Default（默认）
├── Hover（悬停）
├── Active（按下）
├── Disabled（禁用）
└── Loading（加载中）

属性4：Icon（图标）
├── None（无图标）
├── Left（左图标）
└── Right（右图标）
```

**2. Figma Variants命名**：
```
按钮组件命名规则：
Type=Primary, Size=Large, State=Default, Icon=None
Type=Primary, Size=Large, State=Default, Icon=Left
Type=Primary, Size=Large, State=Hover, Icon=None
...

Figma中组织：
Button
├── Type=Primary
│   ├── Size=Large
│   │   ├── State=Default
│   │   ├── State=Hover
│   │   └── State=Disabled
│   ├── Size=Middle
│   └── Size=Small
├── Type=Default
└── Type=Text
```

**3. 组件文档**：
```
# Button 按钮

## 描述
按钮用于触发一个操作，如提交表单、打开对话框等。

## 何时使用
- 标记了一个（或一组）操作命令
- 用户点击后会触发相应的业务逻辑

## 组件预览
[主按钮] [次按钮] [虚线] [文字] [链接]

## API

| 属性 | 说明 | 类型 | 默认值 |
|------|------|------|--------|
| type | 类型 | primary/default/dashed/text/link | default |
| size | 尺寸 | large/middle/small | middle |
| disabled | 禁用 | boolean | false |
| loading | 加载中 | boolean | false |
| icon | 图标 | ReactNode | - |
| onClick | 点击回调 | (event) => void | - |

## 使用规范

✓ 正确用法：
- 每屏最多1个主按钮
- 按钮文字用动词（"提交"而非"确定"）
- 破坏性操作用danger样式

✗ 错误用法：
- 一屏多个主按钮
- 按钮文字过长
- 用主按钮做次要操作

## 代码示例
import { Button } from '@/components';

<Button type="primary" size="large" onClick={handleSubmit}>
  提交
</Button>
```

```
│   ├── Button.test.tsx     # 单元测试
│   ├── Button.stories.tsx  # Storybook文档
│   ├── Button.md           # 使用文档
│   └── index.ts            # 导出
├── Input/
├── Select/
├── Modal/
├── Table/
├── Form/
└── index.ts                # 统一导出

Storybook示例：

};

    <Button type="dashed">虚线按钮</Button>
    <Button type="text">文字按钮</Button>
  </>
);
```

### 总结

- 组件库建设遵循原子设计：原子→分子→有机体→模板
- 每个组件需定义类型、尺寸、状态、内容、属性
- 用Figma Variants管理组件变体，用斜杠命名组织
- 组件文档包含：描述、何时使用、预览、API、使用规范、代码示例
- **常见误区**：组件变体过多（维护成本高）；缺少使用规范（误用）；设计与代码不同步
- **实践建议**：用Storybook管理组件文档；组件变更需版本管理；定期审查组件使用情况，清理冗余；组件库迭代要向后兼容

# 第7章 平台设计规范

## 第24讲 Web设计规范：桌面端最佳实践

### 概念

Web设计是最传统的UI设计领域，运行在浏览器中，跨操作系统。Web设计的核心特点是**屏幕大、鼠标交互、多浏览器兼容**。与移动端相比，Web端有更大的展示空间、更精确的鼠标操作、更复杂的交互模式。

Web设计需要考虑不同浏览器（Chrome、Safari、Firefox、Edge）的兼容性，以及不同屏幕尺寸（笔记本、显示器、大屏）的适配。

### 原理

**1. Web设计的特点**

- **大屏幕**：通常1280px-1920px宽，可展示更多内容
- **鼠标交互**：精确点击，支持悬停（Hover）状态
- **键盘操作**：支持快捷键、Tab导航
- **多窗口**：可同时打开多个标签页
- **网络依赖**：加载状态设计很重要

**2. Web端尺寸规范**

- **常见屏幕宽度**：1366px、1440px、1536px、1920px
- **内容安全区**：通常1200px-1400px居中
- **侧边栏宽度**：200px-280px（可折叠）
- **顶部导航高度**：56px-64px
- **内容区间距**：24px-40px

**3. Web端交互模式**

- **悬停菜单**：鼠标悬停展开下拉菜单
- **右键菜单**：右键弹出上下文菜单
- **拖拽**：拖拽排序、拖拽上传
- **快捷键**：Ctrl+C/V/S等
- **滚动**：垂直滚动为主，水平滚动慎用
- **分页/无限滚动**：大量内容的加载方式

**4. Web端排版规范**

- **正文字号**：14px-16px
- **行高**：1.5-1.8
- **行宽**：45-75字符（中文30-40字）
- **段落间距**：1em
- **对齐**：左对齐为主

## 第25讲 iOS设计规范：Human Interface Guidelines

### 概念

iOS设计规范即Apple的Human Interface Guidelines（HIG），是iOS应用设计的官方指南。iOS设计的核心理念是**清晰**（Clarity）、**顺从**（Deference）、**深度**（Depth），强调内容优先、简洁优雅。

iOS设计需要考虑iPhone和iPad两种设备，以及不同尺寸（从iPhone SE到iPhone 15 Pro Max）。理解iOS设计规范，能让你的App看起来"原生"，符合用户预期。

### 原理

**1. iOS设计三大原则**

- **清晰**（Clarity）：文字易读、图标精确、装饰恰当
- **顺从**（Deference）：UI服务于内容，不喧宾夺主
- **深度**（Depth）：通过层级和动效传达信息关系

**2. iOS尺寸规范**

- **逻辑分辨率**（pt）：设计用单位
- **物理分辨率**（px）：实际像素，@2x/@3x倍率
- **常见iPhone尺寸**：
  - iPhone SE：375 × 667 pt
  - iPhone 15：393 × 852 pt
  - iPhone 15 Pro Max：430 × 932 pt
- **安全区域**：避开顶部刘海和底部Home指示条

**3. iOS核心组件**

- **导航栏**（Navigation Bar）：顶部，44pt高
- **标签栏**（Tab Bar）：底部，49pt高
- **工具栏**（Toolbar）：底部，44pt高
- **标签页**（Segmented Control）：分段选择
- **列表**（Table View）：行列表
- **集合视图**（Collection View）：网格
- **模态视图**（Modal View）：弹出层
- **操作表**（Action Sheet）：底部操作菜单
- **警告框**（Alert）：居中警告

**4. iOS设计要点**

- **大标题**（Large Title）：导航栏大标题，滚动时缩小
- **圆角设计**：卡片、按钮用圆角
- **毛玻璃**（Blur）：半透明背景效果
- **触觉反馈**（Haptic Feedback）：操作时的震动反馈
- **手势**：左滑返回、下拉刷新、长按

## 第26讲 Android设计规范：Material Design

### 概念

Material Design是Google推出的设计系统，是Android应用的官方设计规范。Material Design的核心理念是**材质隐喻**（Material Metaphor）——将界面元素视为物理材质（如纸张），有厚度、阴影、边界。

Material Design 3（M3）是最新版本，引入了动态色彩（Dynamic Color）、更圆润的形状、更丰富的动效。理解Material Design，能设计出符合Android用户预期的应用。

### 原理

**1. Material Design核心原则**

- **材质隐喻**：界面元素是物理材质，有厚度、阴影
- **鲜明形象**：有意、有意义的图形
- **有意义的动效**：动效服务于功能

**2. Material Design的"材质"**

- **高度**（Elevation）：通过阴影表现层级
  - 卡片：1dp-8dp
  - 对话框：24dp
  - 导航抽屉：16dp
  - FAB：6dp
- **表面**（Surface）：材质的表面，可叠加
- **边缘**（Edge）：材质的边界
- **阴影**（Shadow）：表现高度和层级

**3. Material Design 3核心组件**

- **应用栏**（App Bar）：顶部导航，56dp高
- **底部导航**（Bottom Navigation）：80dp高
- **卡片**（Card）：圆角容器
- **FAB**（Floating Action Button）：浮动操作按钮
- **抽屉导航**（Navigation Drawer）：侧滑菜单
- **标签页**（Tabs）：内容切换
- **对话框**（Dialog）：模态弹窗
- **底部表单**（Bottom Sheet）：底部弹出
- **Snackbar**：底部消息提示

**4. Material Design 3特色**

- **动态色彩**（Dynamic Color）：根据壁纸自动生成配色
- **形状系统**（Shape System）：圆角、切角等
- **排版系统**（Type Scale）：5种字号层级
- **动效系统**（Motion System）：转场动画

**5. Android尺寸规范**

- **单位**：dp（密度无关像素）、sp（缩放像素，用于文字）
- **常见屏幕**：360dp、411dp、600dp（平板）
- **触摸目标**：最小48×48dp
- **间距**：8dp栅格

# 第8章 可访问性与进阶

## 第27讲 无障碍设计：WCAG标准与包容性设计

### 概念

无障碍设计（Accessibility，简称a11y）是指让所有人——包括残障人士——都能使用产品的设计。无障碍设计不仅是道德要求，在许多国家也是法律要求。

无障碍设计的核心标准是**WCAG**（Web Content Accessibility Guidelines，Web内容无障碍指南），目前广泛使用的是WCAG 2.1版本。WCAG遵循**POUR原则**：可感知、可操作、可理解、健壮性。

### 原理

**1. WCAG的POUR原则**

- **可感知**（Perceivable）：信息必须能被用户感知
  - 为图片提供替代文字
  - 提供字幕和转录
  - 内容结构清晰
  - 颜色对比度足够

- **可操作**（Operable）：界面必须能被操作
  - 所有功能可用键盘操作
  - 不限制时间
  - 不闪烁（防止癫痫）
  - 提供导航方式

- **可理解**（Understandable）：内容和操作必须可理解
  - 文字易读
  - 内容可预测
  - 帮助用户避免和纠正错误

- **健壮性**（Robust）：能被各种工具解析
  - 兼容辅助技术
  - 语义化HTML

**2. WCAG合规级别**

- **A级**（Level A）：最低要求，30条准则
- **AA级**（Level AA）：标准要求，20条准则，大多数法规要求
- **AAA级**（Level AAA）：最高要求，28条准则

**3. 颜色对比度标准**

WCAG对颜色对比度的要求：
- **正常文字**（<18pt）：AA级≥4.5:1，AAA级≥7:1
- **大文字**（≥18pt或14pt粗体）：AA级≥3:1，AAA级≥4.5:1
- **非文字元素**（图标、边框）：AA级≥3:1

**4. 常见无障碍设计要点**

- **语义化HTML**：用正确的标签（button、nav、main等）
- **替代文字**：图片提供alt属性
- **键盘可操作**：所有功能可用键盘完成
- **焦点可见**：键盘聚焦时有明显样式
- **ARIA标签**：为辅助技术提供语义信息
- **表单标签**：每个表单项有关联的label
- **错误提示**：错误信息明确，用文字而非仅颜色

### 例子

以**无障碍设计实践**为例：

**1. 颜色对比度检查**：

- 无障碍设计让所有人都能使用产品，包括残障人士
- WCAG遵循POUR原则：可感知、可操作、可理解、健壮性
- 合规级别：A级（最低）、AA级（标准）、AAA级（最高）
- 颜色对比度：正常文字≥4.5:1，大文字≥3:1

## 第28讲 暗黑模式设计：色彩适配与对比度

### 概念

暗黑模式（Dark Mode）是近年来流行的界面主题，使用深色背景替代浅色背景。暗黑模式的优势包括：在低光环境下减少眼睛疲劳、节省OLED屏幕电量、提供不同的视觉风格。

暗黑模式不是简单地将颜色反转，而需要重新设计配色方案，确保对比度、可读性和视觉层次。

### 原理

**1. 暗黑模式设计原则**

- **不要纯黑**：用深灰（如#121212）而非纯黑（#000000），减少眼部疲劳
- **避免高饱和度**：暗色背景上高饱和度颜色会"刺眼"
- **调整对比度**：确保文字与背景对比度≥4.5:1
- **层级用颜色深度**：越上层的表面颜色越浅
- **阴影调整**：暗色模式下阴影效果减弱

**2. Material Design暗黑模式规范**

- **背景色**：#121212
- **表面层级**：
  - 0dp（背景）：#121212
  - 1dp：#1E1E1E
  - 2dp：#222222
  - 3dp：#242424
  - 4dp：#272727
  - 6dp：#2C2C2C
- **主色**：饱和度降低200-300（HSL中的S值）
- **文字**：主文字#FFFFFF，次要文字rgba(255,255,255,0.7)

**3. 颜色适配策略**

| 元素 | 浅色模式 | 暗黑模式 |
|------|---------|---------|
| 背景 | #FFFFFF | #121212 |
| 表面 | #F5F5F5 | #1E1E1E |
| 主文字 | #000000 | #FFFFFF |
| 次要文字 | #595959 | rgba(255,255,255,0.7) |
| 边框 | #D9D9D9 | rgba(255,255,255,0.12) |
| 主色 | #1677FF | #4493FF（提亮） |

**4. 图片和图标处理**

- **图片**：降低亮度或加暗色遮罩
- **图标**：用currentColor，自动适配
- **Logo**：提供暗色版本
- **图表**：调整配色方案

### 例子

以**暗黑模式适配**为例：

```javascript
const prefersDark = window.matchMedia('(prefers-color-scheme: dark)');
console.log(prefersDark.matches);  // true=暗黑模式

// 监听主题变化
prefersDark.addEventListener('change', (e) => {
  if (e.matches) {
    document.documentElement.setAttribute('data-theme', 'dark');
  } else {
    document.documentElement.setAttribute('data-theme', 'light');
  }
});

// 手动切换
function toggleTheme() {
  const current = document.documentElement.getAttribute('data-theme');
  const next = current === 'dark' ? 'light' : 'dark';
  document.documentElement.setAttribute('data-theme', next);
  localStorage.setItem('theme', next);  // 记住用户选择

if (savedTheme === 'system') {
  document.documentElement.setAttribute('data-theme', 
    prefersDark.matches ? 'dark' : 'light'
  );
} else {
  document.documentElement.setAttribute('data-theme', savedTheme);
}
```

- 表面层级用颜色深度区分：越上层越浅
- 阴影在暗黑模式下减弱

## 第29讲 设计交付与协作：从Figma到开发

### 概念

设计交付是UI设计流程的最后环节，将设计稿传递给开发团队实现。好的交付能减少沟通成本、提高还原度、加快开发速度。

现代设计交付工具以**Figma**为核心，配合Zeplin、Storybook等工具，实现设计-开发的高效协作。交付内容包括：设计稿、标注、切图、组件库、交互原型、设计规范。

### 原理

**1. 设计交付的内容**

- **设计稿**：所有页面的视觉设计
- **标注**（Spec）：尺寸、颜色、字体、间距等参数
- **切图**（Assets）：图标、图片资源
- **交互原型**（Prototype）：可点击的交互演示
- **组件库**（Component Library）：可复用组件
- **设计规范**（Guidelines）：使用说明

**2. Figma交付功能**

- **Dev Mode**：开发者模式，显示代码和标注
- **Inspect**：检查面板，查看元素属性
- **Export**：导出切图
- **Prototype**：交互原型
- **Comments**：评论协作
- **Variables**：设计令牌

**3. 交付检查清单**

- [ ] 所有页面设计完成
- [ ] 所有状态设计完成（默认、悬停、选中、禁用、错误）
- [ ] 响应式设计完成（桌面、平板、手机）
- [ ] 暗黑模式适配
- [ ] 组件命名规范
- [ ] 切图导出（SVG、PNG@2x/@3x）
- [ ] 交互原型可点击
- [ ] 设计规范文档

**4. 设计-开发协作流程**

```
设计师：
  设计稿 → 标注 → 切图 → 原型 → 交付
                                      ↓
开发者：
  接收 → 评审 → 实现 → 走查 → 修复 → 上线
```

## 第31讲 设计作品集：如何展示你的设计能力

### 概念

设计作品集是设计师的"名片"，是展示设计能力、获取工作机会的关键。一个好的作品集不仅展示最终设计稿，更要展示**设计思考过程**——为什么这样设计、解决了什么问题、如何权衡取舍。

作品集的目标是让看的人（招聘方、客户）在3-5分钟内理解你的设计能力和思维方式。本讲将教你如何策划、制作、展示设计作品集。

### 原理

**1. 作品集的核心要素**

一个完整的设计作品集项目应包含：
- **项目背景**：产品是什么、为谁设计
- **问题定义**：要解决什么问题
- **设计过程**：调研、分析、构思、迭代
- **设计决策**：为什么这样设计
- **最终方案**：设计成果展示
- **成果影响**：数据或用户反馈
- **反思总结**：学到了什么

**2. 作品集的展示原则**

- **质量重于数量**：3-5个精品项目胜过10个平庸项目
- **过程重于结果**：展示思考过程比展示最终图更重要
- **故事性**：每个项目讲一个完整的故事
- **针对性**：根据目标岗位调整作品集内容
- **可读性**：排版清晰、重点突出

**3. 作品集的结构**

```
作品集结构：
1. 封面（个人信息 + 设计风格）
2. 个人简介（技能、经验、设计理念）
3. 项目1（最满意的项目，详细展示）
4. 项目2（不同类型的项目）
5. 项目3（展示多样性）
6. 其他作品（练习、概念设计等）
7. 联系方式
```

**4. 项目展示模板**

每个项目按以下结构展示：
```
1. 项目概述（1页）
   - 项目名称、时间、角色
   - 一句话描述
   - 核心成果

2. 背景与问题（1-2页）
   - 业务背景
   - 用户痛点
   - 设计挑战

3. 设计过程（2-3页）
   - 调研发现
   - 设计探索
   - 方案迭代

4. 最终方案（3-5页）
   - 核心设计
   - 关键页面
   - 交互演示

5. 成果与反思（1页）
   - 数据成果
   - 用户反馈
   - 个人收获
```

### 总结

- 作品集是设计师的能力名片，核心是展示设计思考过程
- 每个项目按"背景→问题→过程→方案→成果"讲故事
- 质量重于数量，3-5个精品项目足够
- 针对目标岗位调整作品集内容
- 展示设计决策的"为什么"比展示"是什么"更重要
- **常见误区**：只放最终设计稿不展示过程；项目描述太技术化；排版混乱重点不突出
- **实践建议**：每个项目讲一个完整故事；用数据证明设计价值；展示多样性的项目类型；保持作品集更新；准备1分钟、5分钟、15分钟三个版本的讲解

## 课程总结

恭喜你完成了《UI设计系统教程》的全部31讲！让我们回顾一下学习旅程：

### 知识体系回顾

**第1章 UI设计基础**：建立了UI设计的基本认知，理解了UI设计的概念、发展历程、核心原则和工作流程。

**第2章 视觉设计基础**：掌握了色彩、字体、间距、图标、视觉层次五大视觉要素，这是UI设计的"基本功"。

**第3章 布局与构图**：学会了CRAP原则、栅格系统、响应式设计、信息架构，能合理组织界面元素。

**第4章 组件设计**：掌握了按钮、表单、导航、卡片等核心组件的设计方法，理解了组件的状态和交互。

**第5章 交互设计**：理解了用户旅程、状态流转、微交互、动效设计，让界面"活起来"。

**第6章 设计系统**：学会了建立设计系统、设计令牌、组件库，实现规模化的一致性。

**第7章 平台设计规范**：掌握了Web、iOS、Android三大平台的设计规范，能设计出"原生"体验。

**第8章 可访问性与进阶**：理解了无障碍设计、暗黑模式、设计交付，让设计更包容、更专业。

**第9章 实战项目**：通过完整案例和作品集指导，将所学知识融会贯通。

### 持续学习建议

UI设计是一个不断发展的领域，学习永无止境。建议你：
