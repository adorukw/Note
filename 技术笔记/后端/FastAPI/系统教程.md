## 第一章 FastAPI 入门基础

### 第 1 讲 FastAPI 简介与环境搭建

#### 概念

FastAPI 是一个用于构建现代 Web API 的高性能 Python 框架，由 Sebastián Ramírez 于 2018 年创建。它基于 Python 的类型提示（Type Hints）标准，结合 Starlette（负责 Web 部分）和 Pydantic（负责数据部分）两大底层库，提供了快速开发、自动文档、强类型校验等核心特性。FastAPI 的设计哲学是"以最少的代码完成最多的功能，同时保持高性能与可维护性"，它被认为是目前 Python 生态中速度最快的 Web 框架之一，性能可与 Node.js、Go 等语言的框架相媲美。

FastAPI 特别适合构建 RESTful API、微服务后端、机器学习模型服务以及实时数据处理接口。它原生支持异步编程（async/await），能够高效处理大量并发请求，这使得它在 I/O 密集型场景下表现尤为出色。同时，FastAPI 内置了 OpenAPI 和 JSON Schema 的自动生成机制，开发者无需额外编写文档，框架会根据代码自动生成交互式 API 文档。

#### 原理

FastAPI 的高性能与高开发效率源于其精心设计的架构。在底层，FastAPI 构建在 Starlette 之上，Starlette 是一个轻量级的 ASGI（Asynchronous Server Gateway Interface）框架，负责处理 HTTP 请求/响应的生命周期、路由分发、中间件等 Web 层逻辑。ASGI 是 WSGI 的异步升级版，它允许服务器与框架之间以异步方式通信，从而支持 WebSocket、HTTP2 等现代协议。

在数据层，FastAPI 使用 Pydantic 库进行数据校验和序列化。Pydantic 基于Python 的类型提示（Type Hints，PEP 484）工作，当你在函数参数上标注类型时，Pydantic 会自动进行类型转换和校验。FastAPI 会解析函数签名中的类型注解，将其转换为 JSON Schema，并进一步生成 OpenAPI 规范文档。这种"类型即文档"的设计使得代码本身就是最权威的 API 文档，避免了文档与代码不同步的问题。

FastAPI 的工作流程大致为：请求到达 → ASGI 服务器（如 Uvicorn）接收 → Starlette 路由匹配 → FastAPI 解析依赖与参数 → Pydantic 校验数据 → 执行业务函数（同步或异步）→ 序列化响应 → 返回客户端。整个流程中，参数校验、类型转换、文档生成都是自动完成的。

#### 例子

下面是环境搭建的完整步骤。首先创建一个虚拟环境并安装 FastAPI 及其 ASGI 服务器 Uvicorn：

```bash
# 创建项目目录
mkdir fastapi_project && cd fastapi_project

# 创建虚拟环境
python -m venv venv

# 激活虚拟环境
# Linux/macOS:
source venv/bin/activate
# Windows:
# venv\Scripts\activate

# 安装 FastAPI 和 Uvicorn（含标准额外依赖）
pip install "fastapi[all]"
```

`fastapi[all]` 会安装 FastAPI 及一系列常用依赖，包括 Uvicorn、Pydantic、python-multipart（用于表单）、Jinja2（模板）、itsdangerous（会话）等。如果只需要最小安装，可以单独安装：

```bash
pip install fastapi
pip install "uvicorn[standard]"
```

安装完成后，可以验证版本：

```bash
python -c "import fastapi; print(fastapi.__version__)"
```

建议使用 `requirements.txt` 或 `pyproject.toml` 管理依赖。一个典型的 `requirements.txt` 如下：

```text
fastapi>=0.100.0
uvicorn[standard]>=0.23.0
pydantic>=2.0.0
```

#### 总结

- FastAPI 是基于 Starlette 和 Pydantic 的高性能异步 Web 框架，专注于 API 开发。
- 它的核心优势是：高性能、自动文档、强类型校验、原生异步支持。
- 环境搭建的核心是安装 `fastapi` 和 `uvicorn`，推荐使用 `pip install "fastapi[all]"` 一键安装。
- 务必使用虚拟环境隔离项目依赖，避免污染全局 Python 环境。
- 注意 Pydantic v2 与 v1 存在较大差异，本教程基于 Pydantic v2 进行讲解。

### 第 2 讲 第一个 FastAPI 应用

#### 概念

本讲通过编写第一个 FastAPI 应用来理解框架的基本使用方式。一个 FastAPI 应用的核心由三部分组成：应用实例（`FastAPI` 类的实例）、路由装饰器（如 `@app.get()`）以及路径操作函数（处理请求的函数）。应用实例是整个应用的入口，路由装饰器将 URL 路径与处理函数绑定，路径操作函数则定义了具体的业务逻辑并返回响应数据。FastAPI 会自动将函数返回的 Python 字典、列表或 Pydantic 模型转换为 JSON 响应。

#### 原理

FastAPI 使用装饰器模式来注册路由。当你调用 `@app.get("/path")` 时，FastAPI 内部会将这个路径和 HTTP 方法（GET）以及被装饰的函数注册到路由表中。当请求到达时，Starlette 的路由系统会根据请求的 URL 和方法匹配到对应的处理函数。

FastAPI 支持所有标准 HTTP 方法：`@app.get()`、`@app.post()`、`@app.put()`、`@app.delete()`、`@app.patch()`、`@app.options()`、`@app.head()`。每个装饰器都对应一种 HTTP 方法，语义清晰。

路径操作函数可以是同步函数（`def`）也可以是异步函数（`async def`）。FastAPI 会自动识别：对于 `async def` 函数，它会在事件循环中直接调用；对于普通 `def` 函数，它会在外部线程池中执行，以避免阻塞事件循环。这种设计让开发者可以自由选择同步或异步风格，而不会影响整体并发性能。

#### 例子

创建文件 `main.py`，编写第一个 FastAPI 应用：

```python
from fastapi import FastAPI

# 创建应用实例
app = FastAPI()

# 定义根路径的 GET 请求处理
@app.get("/")
def read_root():
    return {"message": "Hello, FastAPI!"}

# 定义带路径参数的 GET 请求
@app.get("/items/{item_id}")
def read_item(item_id: int, q: str = None):
    return {"item_id": item_id, "q": q}

# 定义 POST 请求
@app.post("/items/")
def create_item(item: dict):
    return {"created": item}
```

启动应用（在终端中运行）：

```bash
uvicorn main:app --reload
```

参数说明：
- `main:app`：表示 `main.py` 文件中的 `app` 变量。
- `--reload`：开发模式，代码修改后自动重启服务器，仅用于开发环境。

启动后，服务器默认监听 `http://127.0.0.1:8000`。你可以用浏览器或 curl 测试：

```bash
curl http://127.0.0.1:8000/
# 返回：{"message":"Hello, FastAPI!"}

curl http://127.0.0.1:8000/items/5?q=test
# 返回：{"item_id":5,"q":"test"}
```

注意 `item_id: int` 的类型注解，FastAPI 会自动将 URL 中的字符串 `"5"` 转换为整数 `5`，如果传入非数字（如 `/items/abc`），会自动返回 422 错误并给出详细的校验信息。

#### 总结

- FastAPI 应用的三大要素：应用实例、路由装饰器、路径操作函数。
- 使用 `uvicorn main:app --reload` 启动开发服务器。
- 路径操作函数支持 `def` 和 `async def` 两种形式，FastAPI 会自动处理执行方式。
- 函数返回的字典、列表会自动序列化为 JSON。
- 类型注解（如 `item_id: int`）会被 FastAPI 用于自动类型转换和校验，这是 FastAPI 的核心特性之一。
- `--reload` 仅用于开发，生产环境不要使用。

### 第 3 讲 自动交互式文档与项目结构

#### 概念

FastAPI 最受开发者欢迎的特性之一是它自动生成的交互式 API 文档。基于 OpenAPI 规范（前身是 Swagger Specification）和 JSON Schema，FastAPI 会根据你的代码自动生成两套交互式文档界面：Swagger UI（路径 `/docs`）和 ReDoc（路径 `/redoc`）。这两个界面不仅展示 API 的结构，还允许开发者直接在浏览器中发送请求进行测试，极大地提升了开发和联调效率。本讲同时介绍 FastAPI 项目的推荐目录结构，为后续大型项目开发奠定基础。

#### 原理

FastAPI 在应用启动时会收集所有路由的元数据，包括路径、HTTP 方法、参数类型、请求体模型、响应模型等。这些信息被组织成符合 OpenAPI 3.x 规范的 JSON 文档，默认存放在 `/openapi.json` 路径下。Swagger UI 和 ReDoc 都是前端 JavaScript 应用，它们读取这份 OpenAPI JSON 并渲染出美观的交互界面。

OpenAPI 规范定义了一套描述 RESTful API 的标准格式，包含 paths、components、schemas 等部分。FastAPI 通过分析函数签名、Pydantic 模型、参数默认值等，自动构建这份规范。你可以在 `FastAPI()` 构造函数中传入 `title`、`description`、`version` 等元信息来定制文档。

文档的生成是实时的：每次代码修改并重启后，文档会自动更新，永远与代码保持同步。这解决了传统项目中"文档过期"的痛点。

#### 例子

首先看如何定制文档元信息：

```python
from fastapi import FastAPI

app = FastAPI(
    title="My Blog API",
    description="一个用于学习 FastAPI 的博客系统 API",
    version="1.0.0",
    docs_url="/docs",        # Swagger UI 路径，设为 None 可禁用
    redoc_url="/redoc",      # ReDoc 路径，设为 None 可禁用
    openapi_url="/openapi.json"  # OpenAPI JSON 路径
)

@app.get("/users/{user_id}", tags=["用户管理"], summary="获取用户信息")
def get_user(user_id: int):
    """
    根据用户 ID 获取用户的详细信息。

    - **user_id**: 用户的唯一标识，必须为正整数
    """
    return {"user_id": user_id, "name": "张三"}
```

启动后访问：
- `http://127.0.0.1:8000/docs`：Swagger UI 界面，可直接点击"Try it out"测试接口。
- `http://127.0.0.1:8000/redoc`：ReDoc 界面，排版更适合阅读。
- `http://127.0.0.1:8000/openapi.json`：原始 OpenAPI JSON。

文档中的 `tags` 用于接口分组，`summary` 是接口标题，函数的 docstring 会作为接口的详细描述显示在文档中。

接下来是推荐的项目结构。对于中大型项目，建议按功能模块组织：

```text
fastapi_project/
├── app/
│   ├── __init__.py
│   ├── main.py              # 应用入口，创建 app 实例
│   ├── core/
│   │   ├── config.py        # 配置管理
│   │   └── security.py      # 安全相关
│   ├── api/
│   │   ├── __init__.py
│   │   ├── deps.py          # 公共依赖
│   │   └── v1/
│   │       ├── __init__.py
│   │       ├── router.py    # 路由聚合
│   │       ├── users.py     # 用户模块路由
│   │       └── items.py     # 商品模块路由
│   ├── models/              # 数据库模型
│   │   └── user.py
│   ├── schemas/             # Pydantic 模型
│   │   └── user.py
│   ├── crud/                # 数据库操作
│   │   └── user.py
│   └── services/            # 业务逻辑层
│       └── user.py
├── tests/                   # 测试目录
│   ├── conftest.py
│   └── test_users.py
├── requirements.txt
└── README.md
```

`main.py` 中通过 APIRouter 聚合各模块路由：

```python
from fastapi import FastAPI
from app.api.v1.router import api_router

app = FastAPI(title="My API")
app.include_router(api_router, prefix="/api/v1")
```

#### 总结

- FastAPI 自动生成两套交互式文档：Swagger UI（`/docs`）和 ReDoc（`/redoc`）。
- 文档基于 OpenAPI 规范，原始 JSON 在 `/openapi.json`。
- 通过 `FastAPI()` 构造参数可定制文档标题、描述、路径，甚至禁用文档。
- 使用 `tags`、`summary`、docstring 丰富文档内容，提升可读性。
- 中大型项目应按模块分层组织：api、models、schemas、crud、services、core。
- 生产环境中出于安全考虑，可以通过设置 `docs_url=None` 禁用文档接口。

## 第二章 路由与请求处理

### 第 4 讲 路径参数与类型校验

#### 概念

路径参数（Path Parameters）是 URL 路径中动态变化的部分，用花括号 `{}` 包裹，例如 `/users/{user_id}` 中的 `user_id`。路径参数是 RESTful API 中标识资源的最常见方式，比如获取某个用户、某篇文章、某个订单。FastAPI 会从 URL 中提取路径参数，并根据函数签名中的类型注解进行自动类型转换和校验。如果类型不匹配，FastAPI 会返回清晰的 422 错误，告知客户端具体的校验失败原因。

#### 原理

当请求到达时，Starlette 的路由系统使用 URL 模板匹配请求路径。模板中的 `{param}` 部分会被提取为字符串，然后 FastAPI 根据函数参数的类型注解（如 `int`、`str`、`float`、`bool`、`UUID` 等）调用 Pydantic 进行类型转换。例如，注解为 `int` 时，Pydantic 会尝试将字符串转为整数，转换失败则触发 `ValidationError`，FastAPI 将其包装为 422 响应。

路径参数的顺序很重要：`/users/me` 和 `/users/{user_id}` 中，`/users/me` 必须定义在前，否则 `me` 会被当作 `user_id` 匹配到动态路由。FastAPI 按定义顺序匹配路由，先定义的优先。

FastAPI 还支持使用 `Enum` 类型作为路径参数，这样可以将取值限定在枚举范围内，并自动在文档中展示可选值。此外，通过 `Path()` 函数可以对路径参数添加额外约束，如最大值、最小值、正则匹配等。

#### 例子

基本路径参数的使用：

```python
from fastapi import FastAPI

app = FastAPI()

# 基本路径参数，类型为 int
@app.get("/items/{item_id}")
def read_item(item_id: int):
    return {"item_id": item_id}

# 多个路径参数
@app.get("/users/{user_id}/posts/{post_id}")
def read_user_post(user_id: int, post_id: int):
    return {"user_id": user_id, "post_id": post_id}

# 路径顺序：固定路径必须在动态路径之前
@app.get("/users/me")
def read_current_user():
    return {"user": "当前登录用户"}

@app.get("/users/{user_id}")
def read_user(user_id: str):
    return {"user_id": user_id}
```

使用 Enum 限定取值：

```python
from enum import Enum

class ModelName(str, Enum):
    alexnet = "alexnet"
    resnet = "resnet"
    lenet = "lenet"

@app.get("/models/{model_name}")
def get_model(model_name: ModelName):
    if model_name is ModelName.alexnet:
        return {"model": model_name, "message": "Deep Learning FTW!"}
    return {"model": model_name}
```

使用 `Path()` 添加约束：

```python
from fastapi import FastAPI, Path

app = FastAPI()

@app.get("/items/{item_id}")
def read_item(
    item_id: int = Path(..., title="商品ID", description="商品的唯一标识", ge=1, le=1000)
):
    return {"item_id": item_id}
```

`Path(...)` 中第一个参数 `...` 表示必填（Ellipsis），`ge=1` 表示大于等于 1，`le=1000` 表示小于等于 1000。如果传入 `/items/0` 或 `/items/1001`，会返回 422 错误。

#### 总结

- 路径参数用 `{}` 包裹，类型由函数参数注解决定，FastAPI 自动转换和校验。
- 固定路径必须定义在动态路径之前，否则会被错误匹配。
- 支持 `Enum` 类型限定取值范围，文档会自动展示可选项。
- 使用 `Path()` 可添加约束：`ge`（>=）、`gt`（>）、`le`（<=）、`lt`（<）、`min_length`、`max_length`、`regex` 等。
- 类型不匹配或约束不满足时返回 422 错误，错误信息包含详细原因。
- 路径参数在 URL 中是必填的，无法设为可选。

### 第 5 讲 查询参数与默认值

#### 概念

查询参数（Query Parameters）是 URL 中问号 `?` 后面的键值对，用于传递非资源标识的附加信息，如分页、过滤、排序、搜索关键词等。例如 `/items?skip=0&limit=10` 中，`skip` 和 `limit` 就是查询参数。与路径参数不同，查询参数不在路径模板中声明，而是直接通过函数参数定义。FastAPI 会自动识别哪些参数是路径参数（出现在路径模板中）、哪些是查询参数（不出现在路径模板中），并分别处理。

#### 原理

FastAPI 通过对比函数参数名与路径模板中的占位符来区分参数类型：出现在路径模板 `{}` 中的是路径参数，其余的（且不是请求体）就是查询参数。函数参数的默认值决定了查询参数是否必填：有默认值的是可选参数，无默认值（或使用 `...`）的是必填参数。

类型注解同样适用于查询参数，FastAPI 会进行类型转换和校验。布尔类型有特殊处理：`True`、`true`、`1`、`yes`、`on` 都会被转换为 `True`，其余为 `False`。

对于需要更精细控制的场景，可以使用 `Query()` 函数，它支持设置默认值、最大长度、最小长度、正则约束、是否必填、描述信息、是否弃用（deprecated）等。`Query()` 还支持接收列表类型，例如 `?q=a&q=b&q=c` 会被解析为 `["a", "b", "c"]`。

#### 例子

基本查询参数：

```python
from fastapi import FastAPI

app = FastAPI()

fake_items_db = [{"item_name": "Apple"}, {"item_name": "Banana"}, {"item_name": "Cherry"}]

@app.get("/items/")
def read_items(skip: int = 0, limit: int = 10):
    # skip 和 limit 都有默认值，是可选参数
    return fake_items_db[skip : skip + limit]

# 必填查询参数（无默认值）
@app.get("/search")
def search(keyword: str):  # keyword 必填
    return {"keyword": keyword}

# 布尔类型转换
@app.get("/config/{config_name}")
def get_config(config_name: str, enabled: bool = False):
    return {"config": config_name, "enabled": enabled}
```

访问示例：
- `/items/?skip=0&limit=2` → 返回前两项
- `/search?keyword=fastapi` → 正常返回
- `/search` → 422 错误，缺少必填参数
- `/config/debug?enabled=true` → `{"config":"debug","enabled":true}`

使用 `Query()` 添加约束：

```python
from fastapi import FastAPI, Query

app = FastAPI()

@app.get("/items/")
def read_items(
    q: str | None = Query(default=None, min_length=3, max_length=50, pattern="^fixed"),
    limit: int = Query(default=10, ge=1, le=100, description="返回数量，1-100之间"),
):
    results = {"items": [{"item_id": i} for i in range(limit)]}
    if q:
        results.update({"q": q})
    return results
```

接收列表查询参数：

```python
@app.get("/items/")
def read_items(q: list[str] | None = Query(default=None)):
    return {"q": q}
```

访问 `/items/?q=a&q=b&q=c` 返回 `{"q":["a","b","c"]}`。

标记为弃用：

```python
@app.get("/items/")
def read_items(
    q: str | None = Query(default=None, deprecated=True, description="已弃用，请使用 keyword"),
):
    return {"q": q}
```

文档中会显示删除线，提示该参数已弃用。

#### 总结

- 查询参数是 URL `?` 后的键值对，通过函数参数声明，不出现在路径模板中。
- 有默认值的参数是可选的，无默认值或使用 `...` 的是必填的。
- 布尔参数支持多种真值形式：`true`、`1`、`yes`、`on` 等。
- 使用 `Query()` 可添加约束：`min_length`、`max_length`、`pattern`、`ge`、`le` 等。
- `Query()` 支持列表类型，用于接收重复的查询参数。
- 使用 `deprecated=True` 标记弃用参数，文档会给出提示。
- 查询参数适合分页、过滤、排序等场景，路径参数适合标识资源。

### 第 6 讲 请求体与 Pydantic 模型

#### 概念

请求体（Request Body）是客户端发送给服务器的数据，通常在 POST、PUT、PATCH 请求中用于创建或更新资源。与路径参数和查询参数不同，请求体携带的是结构化数据（通常是 JSON），可以包含复杂的嵌套结构。在 FastAPI 中，请求体使用 Pydantic 模型（继承自 `BaseModel` 的类）来定义。Pydantic 模型声明了请求体的字段、类型和约束，FastAPI 会自动解析 JSON、校验数据、转换类型，并将结果作为参数传入路径操作函数。

#### 原理

当函数参数的类型注解是一个 Pydantic `BaseModel` 子类时，FastAPI 会将其识别为请求体参数。请求到达时，FastAPI 从请求的 body 中读取 JSON 数据，使用 Pydantic 模型进行解析和校验。Pydantic 会检查每个字段：必填字段缺失则报错，类型不符则尝试转换，转换失败则报错，约束不满足则报错。校验通过后，FastAPI 将一个模型实例传入函数。

Pydantic 模型的字段通过 `Field()` 函数添加约束，如默认值、最大长度、最小值、描述等。模型支持嵌套（模型字段类型是另一个模型）、列表、字典、可选类型等复杂结构。Pydantic v2 还支持 `model_config` 配置类，可以设置额外字段处理策略、ORM 模式等。

一个函数可以同时接收路径参数、查询参数和请求体：FastAPI 根据类型自动区分。路径参数出现在路径模板中，Pydantic 模型是请求体，其余简单类型（int、str 等）是查询参数。

#### 例子

定义请求体模型并使用：

```python
from fastapi import FastAPI
from pydantic import BaseModel, Field
from typing import Optional

app = FastAPI()

class Item(BaseModel):
    name: str
    description: Optional[str] = Field(default=None, max_length=300)
    price: float = Field(..., gt=0, description="价格必须大于0")
    tax: Optional[float] = None
    tags: list[str] = []

@app.post("/items/")
def create_item(item: Item):
    return item

@app.put("/items/{item_id}")
def update_item(item_id: int, item: Item, q: Optional[str] = None):
    result = {"item_id": item_id, **item.model_dump()}
    if q:
        result.update({"q": q})
    return result
```

客户端发送 POST 请求：

```bash
curl -X POST "http://127.0.0.1:8000/items/" \
     -H "Content-Type: application/json" \
     -d '{"name":"手机","price":2999.99,"tags":["电子","通讯"]}'
```

嵌套模型示例：

```python
class Image(BaseModel):
    url: str
    name: str

class Item(BaseModel):
    name: str
    description: Optional[str] = None
    price: float
    images: Optional[list[Image]] = None  # 嵌套模型列表

@app.post("/items/")
def create_item(item: Item):
    return item
```

对应的 JSON 请求体：

```json
{
    "name": "手机",
    "price": 2999.99,
    "images": [
        {"url": "http://example.com/1.jpg", "name": "正面图"},
        {"url": "http://example.com/2.jpg", "name": "背面图"}
    ]
}
```

使用 `model_config` 严格模式（禁止额外字段）：

```python
class Item(BaseModel):
    model_config = {"extra": "forbid"}  # 传入未定义字段会报错
    name: str
    price: float
```

`extra` 可选值：`"allow"`（允许并保留）、`"ignore"`（忽略）、`"forbid"`（禁止，报错）。

#### 总结

- 请求体使用 Pydantic `BaseModel` 定义，FastAPI 自动解析 JSON 并校验。
- `Field()` 用于添加字段约束：默认值、`gt`/`ge`/`lt`/`le`、`min_length`/`max_length`、`pattern`、`description` 等。
- 模型支持嵌套、列表、字典、可选类型等复杂结构。
- 一个函数可同时接收路径参数、查询参数和请求体，FastAPI 根据类型自动区分。
- `model_config` 配置类可设置额外字段策略（`extra`）、ORM 模式等。
- Pydantic v2 使用 `model_dump()` 序列化模型（v1 是 `dict()`）。
- 请求体校验失败返回 422 错误，错误信息精确到字段级别。

### 第 7 讲 表单数据与文件上传

#### 概念

并非所有请求都以 JSON 格式发送数据。HTML 表单提交使用的是 `application/x-www-form-urlencoded` 或 `multipart/form-data` 编码格式，文件上传则必须使用 `multipart/form-data`。FastAPI 通过 `Form` 和 `File`/`UploadFile` 来处理这两类数据。需要注意的是，不能在同一个请求中同时声明 JSON 请求体和表单数据，因为它们的 Content-Type 不同。表单和文件处理需要安装 `python-multipart` 库（`pip install python-multipart`）。

#### 原理

当函数参数使用 `Form()` 或 `File()`/`UploadFile` 时，FastAPI 会从请求体中按照表单编码格式解析数据，而不是 JSON。`Form` 的工作方式与 `Query` 类似，但数据来源是表单字段。`File` 用于接收文件内容（作为 `bytes`），`UploadFile` 是更高级的封装，提供文件名、内容类型、异步读写方法，适合大文件处理。

`UploadFile` 相比 `File` 的优势在于：它使用 SpooledTemporaryFile 存储，文件超过一定大小（默认 1MB）会自动写入磁盘，避免占用过多内存；它提供 `filename`、`content_type`、`size` 等属性和 `read()`、`write()`、`seek()`、`close()` 方法，操作更方便；它支持异步操作（`await file.read()`），适合异步场景。

`multipart/form-data` 格式允许在一个请求中同时发送表单字段和文件，FastAPI 会自动识别每个部分是普通字段还是文件。

#### 例子

表单数据处理：

```python
from fastapi import FastAPI, Form

app = FastAPI()

@app.post("/login/")
def login(username: str = Form(...), password: str = Form(...)):
    return {"username": username}
```

客户端发送表单：

```bash
curl -X POST "http://127.0.0.1:8000/login/" \
     -d "username=admin&password=123456"
```

单文件上传：

```python
from fastapi import FastAPI, UploadFile, File

app = FastAPI()

@app.post("/uploadfile/")
async def create_upload_file(file: UploadFile = File(...)):
    contents = await file.read()
    return {
        "filename": file.filename,
        "content_type": file.content_type,
        "size": len(contents),
    }
```

多文件上传：

```python
from fastapi import FastAPI, UploadFile
from typing import List

app = FastAPI()

@app.post("/uploadfiles/")
async def create_upload_files(files: list[UploadFile]):
    results = []
    for file in files:
        contents = await file.read()
        results.append({
            "filename": file.filename,
            "size": len(contents),
        })
    return {"uploaded_files": results}

@app.get("/")
def main():
    content = """
    <body>
    <form action="/uploadfiles/" enctype="multipart/form-data" method="post">
    <input name="files" type="file" multiple>
    <input type="submit">
    </form>
    </body>
    """
    return {"html": content}
```

表单与文件混合上传：

```python
@app.post("/items/")
async def create_item(
    name: str = Form(...),
    description: str = Form(None),
    file: UploadFile = File(...),
):
    return {
        "name": name,
        "description": description,
        "filename": file.filename,
    }
```

将上传文件保存到磁盘：

```python
import shutil
from pathlib import Path

@app.post("/save/")
async def save_file(file: UploadFile):
    upload_dir = Path("uploads")
    upload_dir.mkdir(exist_ok=True)
    file_path = upload_dir / file.filename
    with file_path.open("wb") as buffer:
        shutil.copyfileobj(file.file, buffer)
    return {"saved_to": str(file_path)}
```

#### 总结

- 表单数据使用 `Form()` 声明，文件使用 `File()` 或 `UploadFile` 声明。
- 文件上传必须使用 `multipart/form-data` 编码，需安装 `python-multipart`。
- `UploadFile` 优于 `File`：支持大文件、提供文件元信息、支持异步读写。
- 不能在同一个请求中同时使用 JSON 请求体和表单/文件。
- 多文件上传使用 `list[UploadFile]` 类型注解。
- 大文件建议使用 `await file.read()` 分块读取或 `shutil.copyfileobj` 流式保存，避免内存溢出。
- 生产环境应对上传文件的大小、类型、扩展名进行校验，防止安全风险。

## 第三章 响应与错误处理

### 第 8 讲 响应模型与序列化

#### 概念

响应模型（Response Model）是 FastAPI 中用于声明接口返回数据结构的核心机制。通过在路由装饰器上指定 `response_model` 参数，你可以精确控制响应中包含哪些字段、排除哪些字段，以及响应数据的类型。这在实际开发中极为重要：例如，用户创建接口的请求体包含密码字段，但响应中绝不能返回密码；又如，数据库模型包含内部字段，但 API 响应只需暴露部分字段。响应模型实现了"输入模型"与"输出模型"的分离，是构建安全、清晰 API 的关键实践。

#### 原理

当指定 `response_model` 时，FastAPI 会在函数返回后，使用该模型对返回数据进行一次"过滤和转换"。具体过程是：FastAPI 将函数返回值（字典、Pydantic 模型、ORM 对象等）传入 `response_model` 指定的 Pydantic 模型，Pydantic 会按照模型定义的字段进行校验和序列化，未在模型中定义的字段会被丢弃。这一机制确保了响应数据的结构始终与文档一致，同时防止敏感字段泄露。

FastAPI 默认会过滤掉返回值中不在 `response_model` 中的字段。但如果函数返回类型注解与 `response_model` 相同，且设置了 `response_model_exclude_unset=True`，则只会返回客户端实际设置的字段（未设置的字段使用默认值时会被排除），这在 PATCH 等部分更新场景中非常有用。

响应模型还支持 `response_model_exclude`、`response_model_include`、`response_model_by_alias`、`response_model_exclude_none`、`response_model_exclude_defaults` 等参数，提供细粒度的字段控制。

#### 例子

输入输出模型分离的经典场景：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class UserIn(BaseModel):
    username: str
    password: str  # 请求中包含密码
    email: str

class UserOut(BaseModel):
    username: str
    email: str      # 响应中不包含密码

@app.post("/users/", response_model=UserOut)
def create_user(user: UserIn):
    # 即使返回了 user（含 password），响应也只会包含 username 和 email
    return user
```

使用 `response_model_exclude` 排除特定字段：

```python
class Item(BaseModel):
    id: int
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

@app.get("/items/{item_id}", response_model=Item, response_model_exclude={"tax"})
def get_item(item_id: int):
    return {
        "id": item_id,
        "name": "手机",
        "description": "旗舰机",
        "price": 2999.99,
        "tax": 0.15,  # 会被排除
    }
```

部分更新场景使用 `response_model_exclude_unset`：

```python
class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float = 0.1

items = {
    1: {"name": "Foo", "price": 50.2},
    2: {"name": "Bar", "description": "The Bar fighters", "price": 62, "tax": 0.2},
}

@app.get("/items/{item_id}", response_model=Item, response_model_exclude_unset=True)
def read_item(item_id: int):
    return items[item_id]
```

访问 `/items/1` 时，由于 `description` 和 `tax` 未设置（使用默认值），它们不会出现在响应中；访问 `/items/2` 时，由于这两个字段被显式设置，会出现在响应中。

#### 总结

- `response_model` 声明接口返回的数据结构，实现输入输出模型分离。
- FastAPI 会用 `response_model` 过滤返回值，未定义的字段会被丢弃，防止敏感信息泄露。
- `response_model_exclude_unset=True` 只返回显式设置的字段，适合部分更新场景。
- `response_model_exclude`/`response_model_include` 可按字段名精细控制。
- 始终为涉及敏感数据的接口设置 `response_model`，这是安全最佳实践。
- 响应模型同时驱动 OpenAPI 文档中的响应 schema 生成，文档与实际行为一致。

### 第 9 讲 自定义响应与状态码

#### 概念

虽然 FastAPI 默认返回 JSON 响应，但在实际开发中经常需要返回其他类型的响应：HTML 页面、纯文本、XML、二进制文件、重定向、流式响应等。FastAPI 提供了多种响应类型（`Response` 的子类）来满足这些需求，包括 `JSONResponse`、`HTMLResponse`、`PlainTextResponse`、`RedirectResponse`、`StreamingResponse`、`FileResponse` 等。同时，每个 HTTP 响应都附带一个状态码（Status Code），用于告知客户端请求的处理结果，FastAPI 允许在路由装饰器和函数内部灵活设置状态码。

#### 原理

FastAPI 的响应处理基于 Starlette 的 `Response` 类体系。当路径操作函数返回一个 `Response` 实例（或其子类）时，FastAPI 会直接使用该响应，不再进行默认的 JSON 序列化。当函数返回普通 Python 对象（字典、列表、Pydantic 模型）时，FastAPI 会使用默认的 `JSONResponse` 进行序列化。

可以在路由装饰器中通过 `response_class` 参数指定默认响应类型，例如 `response_class=HTMLResponse`。也可以在函数内部动态返回不同类型的响应。

状态码方面，路由装饰器的 `status_code` 参数设置默认成功状态码（如 POST 用 201）。函数内部可以通过 `Response` 参数（`response: Response`）动态设置状态码、响应头、Cookie 等。FastAPI 还提供了 `status` 模块，包含所有 HTTP 状态码常量，避免硬编码数字。

#### 例子

返回不同类型的响应：

```python
from fastapi import FastAPI, Response
from fastapi.responses import HTMLResponse, PlainTextResponse, RedirectResponse

app = FastAPI()

@app.get("/html", response_class=HTMLResponse)
def get_html():
    return "<h1>Hello, World!</h1><p>这是一段 HTML 内容。</p>"

@app.get("/text", response_class=PlainTextResponse)
def get_text():
    return "这是一段纯文本。"

@app.get("/redirect")
def redirect():
    return RedirectResponse(url="https://fastapi.tiangolo.com")
```

动态设置状态码和响应头：

```python
from fastapi import FastAPI, Response, status

app = FastAPI()

@app.post("/items/", status_code=status.HTTP_201_CREATED)
def create_item(item: dict, response: Response):
    response.headers["X-Custom-Header"] = "CustomValue"
    response.status_code = status.HTTP_201_CREATED
    return {"created": item}
```

返回文件：

```python
from fastapi.responses import FileResponse

@app.get("/download")
def download_file():
    return FileResponse(
        path="/path/to/file.pdf",
        media_type="application/pdf",
        filename="report.pdf",  # 浏览器下载时的文件名
    )
```

流式响应（适合大文件或实时数据）：

```python
from fastapi.responses import StreamingResponse

def generate_large_csv():
    for i in range(10000):
        yield f"id,{i},value,{i*10}\n"

@app.get("/stream")
def stream_data():
    return StreamingResponse(
        generate_large_csv(),
        media_type="text/csv",
        headers={"Content-Disposition": "attachment; filename=data.csv"},
    )
```

自定义 JSONResponse（用于全局异常处理等）：

```python
from fastapi.responses import JSONResponse

@app.get("/custom")
def custom_response():
    return JSONResponse(
        status_code=200,
        content={"message": "自定义响应", "code": 0},
        headers={"X-Trace-Id": "abc123"},
    )
```

#### 总结

- FastAPI 提供多种响应类型：`JSONResponse`、`HTMLResponse`、`PlainTextResponse`、`RedirectResponse`、`StreamingResponse`、`FileResponse`。
- 返回 `Response` 实例时，FastAPI 直接使用，不再做 JSON 序列化。
- 通过 `response_class` 参数指定路由的默认响应类型。
- 使用 `status_code` 参数设置默认状态码，推荐用 `status.HTTP_XXX` 常量。
- 通过 `response: Response` 参数可动态设置状态码、响应头、Cookie。
- `StreamingResponse` 适合大文件或实时数据流，使用生成器逐步返回。
- `FileResponse` 适合文件下载，自动处理 Content-Type 和 Content-Disposition。

### 第 10 讲 错误处理与 HTTPException

#### 概念

在 Web 应用中，错误是不可避免的：客户端可能提交了无效数据、请求了不存在的资源、没有权限执行操作，服务器可能遇到内部错误。良好的错误处理机制能让 API 返回清晰、一致的错误信息，帮助客户端开发者快速定位问题。FastAPI 提供了 `HTTPException` 类来主动抛出 HTTP 错误，同时支持自定义异常处理器（Exception Handler）来统一处理各类异常，包括 FastAPI 内置的 `RequestValidationError` 和自定义业务异常。

#### 原理

`HTTPException` 是 FastAPI 提供的标准异常类，它继承自 `Exception`，包含 `status_code`（状态码）、`detail`（错误详情）和 `headers`（响应头）三个主要属性。当在路径操作函数或依赖中抛出 `HTTPException` 时，FastAPI 会捕获它，并将其转换为对应的 HTTP 响应：状态码取自 `status_code`，响应体为 `{"detail": ...}`。

对于其他未捕获的异常，FastAPI 提供了异常处理器机制。通过 `@app.exception_handler(SomeException)` 装饰器注册一个处理函数，当该类型异常被抛出时，FastAPI 会调用对应的处理函数，由处理函数返回自定义响应。这可以用来统一错误响应格式、记录日志、隐藏内部错误细节等。

特别地，FastAPI 内置的请求校验错误 `RequestValidationError` 也可以被自定义处理器接管，从而改变默认的 422 错误响应格式。同样，`Starlette` 的 `HTTPException` 也可以被覆盖处理。

#### 例子

使用 `HTTPException` 抛出错误：

```python
from fastapi import FastAPI, HTTPException, status

app = FastAPI()

items = {"foo": "The Foo Wrestlers"}

@app.get("/items/{item_id}")
def read_item(item_id: str):
    if item_id not in items:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail="Item not found",
            headers={"X-Error": "There goes my error"},
        )
    return {"item": items[item_id]}
```

访问 `/items/bar` 返回：

```json
{
    "detail": "Item not found"
}
```

状态码为 404，并带有自定义响应头。

自定义异常处理器，统一错误响应格式：

```python
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse

class UnicornException(Exception):
    def __init__(self, name: str):
        self.name = name

app = FastAPI()

@app.exception_handler(UnicornException)
async def unicorn_exception_handler(request: Request, exc: UnicornException):
    return JSONResponse(
        status_code=418,
        content={
            "code": 418,
            "message": f"Oops, {exc.name} did it again.",
            "path": str(request.url.path),
        },
    )

@app.get("/unicorns/{name}")
def read_unicorn(name: str):
    if name == "yolo":
        raise UnicornException(name=name)
    return {"unicorn_name": name}
```

覆盖默认的校验错误处理（422 响应）：

```python
from fastapi import FastAPI, Request
from fastapi.exceptions import RequestValidationError
from fastapi.responses import JSONResponse

app = FastAPI()

@app.exception_handler(RequestValidationError)
async def validation_exception_handler(request: Request, exc: RequestValidationError):
    return JSONResponse(
        status_code=422,
        content={
            "code": 422,
            "message": "请求参数校验失败",
            "errors": exc.errors(),
            "path": str(request.url.path),
        },
    )
```

覆盖所有 HTTPException 的响应格式：

```python
from fastapi import FastAPI, HTTPException, Request
from fastapi.responses import JSONResponse

app = FastAPI()

@app.exception_handler(HTTPException)
async def http_exception_handler(request: Request, exc: HTTPException):
    return JSONResponse(
        status_code=exc.status_code,
        content={
            "code": exc.status_code,
            "message": exc.detail,
            "path": str(request.url.path),
        },
    )
```

#### 总结

- `HTTPException` 用于主动抛出 HTTP 错误，包含 `status_code`、`detail`、`headers`。
- 抛出 `HTTPException` 后，FastAPI 自动将其转换为对应的 HTTP 响应。
- 使用 `@app.exception_handler(ExceptionClass)` 注册自定义异常处理器。
- 可覆盖 `RequestValidationError` 处理器，自定义 422 校验错误的响应格式。
- 可覆盖 `HTTPException` 处理器，统一所有 HTTP 错误的响应格式。
- 生产环境应统一错误响应结构（如 `code`/`message`/`detail`），便于客户端处理。
- 异常处理器中避免暴露内部错误堆栈，防止信息泄露。

## 第四章 Pydantic 数据校验进阶

### 第 11 讲 字段约束与类型转换

#### 概念

Pydantic 的强大之处在于它提供了丰富的字段约束和类型转换能力。除了基本的类型注解（`str`、`int`、`float`、`bool`），Pydantic 还支持通过 `Field()` 函数为字段添加数值范围约束、字符串长度约束、正则匹配约束等。同时，Pydantic 在类型不匹配时会尝试进行智能类型转换（Coercion），例如将字符串 `"123"` 转为整数 `123`，将字符串 `"true"` 转为布尔值 `True`。理解这些约束和转换规则，是构建健壮 API 校验逻辑的基础。

#### 原理

Pydantic v2 的核心校验引擎使用 Rust 编写（pydantic-core），性能远超 v1。当一个字段被声明为某种类型时，Pydantic 会按照以下顺序处理输入值：首先尝试严格匹配（值本身就是声明类型），如果匹配则直接使用；如果不匹配，尝试类型转换（字符串转数字、字符串转日期等）；如果转换失败，则抛出 `ValidationError`。

`Field()` 函数是 Pydantic 提供的字段配置工具，主要参数包括：
- 数值约束：`gt`（大于）、`ge`（大于等于）、`lt`（小于）、`le`（小于等于）、`multiple_of`（倍数）
- 字符串约束：`min_length`、`max_length`、`pattern`（正则）
- 集合约束：`min_items`、`max_items`（v2 中已改为 `min_length`/`max_length`）
- 通用：`default`、`default_factory`、`title`、`description`、`examples`、`deprecated`

Pydantic 还支持丰富的类型：`EmailStr`（邮箱）、`HttpUrl`（URL）、`IPvAnyAddress`（IP）、`UUID`、`Decimal`、`datetime`、`date`、`conint`（约束整数）、`constr`（约束字符串）等。这些类型在 `pydantic` 或 `pydantic.types` 模块中。

#### 例子

数值与字符串约束：

```python
from pydantic import BaseModel, Field

class Product(BaseModel):
    name: str = Field(min_length=1, max_length=100, description="商品名称")
    price: float = Field(gt=0, le=100000, description="价格，大于0且不超过10万")
    stock: int = Field(ge=0, default=0, description="库存，非负整数")
    discount: float | None = Field(default=None, ge=0, le=1, description="折扣率0-1")
    code: str = Field(pattern=r"^[A-Z]{3}-\d{4}$", description="商品编码格式ABC-1234")
```

使用特殊类型：

```python
from pydantic import BaseModel, EmailStr, HttpUrl
from datetime import datetime
from uuid import UUID

class User(BaseModel):
    email: EmailStr                          # 自动校验邮箱格式
    website: HttpUrl | None = None           # 自动校验URL
    user_id: UUID                            # 自动解析UUID
    created_at: datetime                     # 自动解析ISO格式时间
    age: int = Field(ge=0, le=150)
```

测试：

```python
user = User(
    email="test@example.com",
    user_id="12345678-1234-1234-1234-123456789012",
    created_at="2024-01-15T10:30:00",
    age=25,
)
print(user.email)        # test@example.com
print(user.user_id)      # UUID('12345678-...')
print(user.created_at)   # 2024-01-15 10:30:00
```

使用 `default_factory` 动态生成默认值：

```python
from pydantic import BaseModel, Field
from datetime import datetime, timezone
import uuid

class Article(BaseModel):
    id: str = Field(default_factory=lambda: str(uuid.uuid4()))
    created_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc))
    tags: list[str] = Field(default_factory=list)  # 注意：不要用 default=[]，会共享引用
    title: str
```

类型转换示例：

```python
class Item(BaseModel):
    quantity: int
    price: float
    in_stock: bool

# 字符串自动转为对应类型
item = Item(quantity="100", price="9.99", in_stock="yes")
print(item.quantity)   # 100 (int)
print(item.price)      # 9.99 (float)
print(item.in_stock)   # True (bool)
```

#### 总结

- `Field()` 提供数值约束（`gt`/`ge`/`lt`/`le`/`multiple_of`）、字符串约束（`min_length`/`max_length`/`pattern`）。
- Pydantic 支持智能类型转换：字符串可转数字、布尔、日期等。
- 特殊类型如 `EmailStr`、`HttpUrl`、`UUID`、`datetime` 提供专用校验。
- 使用 `default_factory` 而非可变默认值（如 `[]`、`{}`），避免共享引用 bug。
- Pydantic v2 性能远超 v1，校验引擎用 Rust 实现。
- `EmailStr` 需要 `pip install email-validator`。
- 约束信息会自动反映到 OpenAPI 文档中，客户端可见。

### 第 12 讲 嵌套模型与模型继承

#### 概念

真实业务中的数据结构往往是复杂的、多层嵌套的：一个订单包含多个商品，一个商品包含多个图片，一个用户有地址信息、有订单列表。Pydantic 支持模型嵌套（一个模型的字段类型是另一个模型）和模型继承（一个模型继承另一个模型），让你能够优雅地表达复杂的数据结构。此外，Pydantic 还支持联合类型（Union）、可选类型（Optional）、字面量类型（Literal）等，进一步增强了数据建模的灵活性。

#### 原理

Pydantic 模型的字段类型可以是任何 Python 类型，包括其他 Pydantic 模型。当字段类型是另一个 `BaseModel` 子类时，Pydantic 会递归地进行校验和转换：将输入的字典转换为对应模型的实例。嵌套可以是任意深度，也可以是列表、字典等容器类型包裹的模型。

模型继承使用标准 Python 类继承语法。子类继承父类的所有字段，并可以添加新字段或覆盖父类字段。这在构建"基础模型 + 扩展模型"的场景中非常有用，例如定义一个 `BaseUser`，然后派生 `CreateUser`、`UpdateUser`、`UserInDB` 等。

联合类型 `Union[A, B]` 或 `A | B` 表示字段可以是多种类型之一，Pydantic 会按顺序尝试每种类型，使用第一个成功的。`Literal` 类型限定字段为特定的几个值之一，类似枚举但更轻量。

#### 例子

模型嵌套：

```python
from pydantic import BaseModel
from typing import Optional

class Image(BaseModel):
    url: str
    name: str

class Item(BaseModel):
    name: str
    description: Optional[str] = None
    price: float
    images: Optional[list[Image]] = None  # 嵌套模型列表

class Offer(BaseModel):
    name: str
    description: Optional[str] = None
    price: float
    items: list[Item]  # 嵌套模型列表

# 使用
offer = Offer(
    name="套餐A",
    price=100.0,
    items=[
        {
            "name": "手机",
            "price": 2999.99,
            "images": [
                {"url": "http://example.com/1.jpg", "name": "正面"},
                {"url": "http://example.com/2.jpg", "name": "背面"},
            ],
        },
        {"name": "耳机", "price": 199.0},
    ],
)
print(offer.items[0].images[0].name)  # 正面
```

模型继承：

```python
from pydantic import BaseModel, Field
from typing import Optional

class UserBase(BaseModel):
    username: str = Field(min_length=3, max_length=20)
    email: str
    full_name: Optional[str] = None

class UserCreate(UserBase):
    password: str = Field(min_length=8)  # 创建时需要密码

class UserInDB(UserBase):
    id: int
    hashed_password: str  # 数据库存储的是哈希密码

class UserOut(UserBase):
    id: int
    # 不包含 password 和 hashed_password

# 使用
user_create = UserCreate(
    username="alice",
    email="alice@example.com",
    password="securepassword",
)
user_in_db = UserInDB(
    id=1,
    username="alice",
    email="alice@example.com",
    hashed_password="hashed...",
)
user_out = UserOut(
    id=1,
    username="alice",
    email="alice@example.com",
)
```

联合类型与 Literal：

```python
from pydantic import BaseModel
from typing import Union, Literal

class Cat(BaseModel):
    pet_type: Literal["cat"]
    meows: int

class Dog(BaseModel):
    pet_type: Literal["dog"]
    barks: float

class Pet(Union[Cat, Dog] if False else BaseModel):
    # 更清晰的写法：使用 discriminated union
    pass

# 使用 discriminated union（判别联合）
from typing import Annotated
from pydantic import Field

Pet = Annotated[Union[Cat, Dog], Field(discriminator="pet_type")]

class Owner(BaseModel):
    name: str
    pet: Pet

owner = Owner(name="Bob", pet={"pet_type": "cat", "meows": 3})
print(owner.pet)  # pet_type='cat' meows=3
```

#### 总结

- Pydantic 支持任意深度的模型嵌套，字段类型可以是另一个 `BaseModel`。
- 嵌套模型可以是单个、列表、字典、可选等多种形式。
- 模型继承使用标准 Python 继承语法，适合构建输入/输出/数据库等多版本模型。
- `Union[A, B]` 或 `A | B` 表示联合类型，Pydantic 按顺序尝试。
- `Literal` 限定字段为特定值，类似轻量枚举。
- 判别联合（discriminated union）通过 `Field(discriminator="field_name")` 优化联合类型校验性能。
- 合理使用继承和嵌套，可以大幅减少重复代码，提升模型可维护性。

### 第 13 讲 自定义校验器

#### 概念

虽然 Pydantic 内置的类型和 `Field()` 约束已经非常丰富，但有些业务校验逻辑无法用简单约束表达：例如密码必须同时包含大小写字母和数字、用户名不能包含敏感词、订单的结束时间必须晚于开始时间、两个字段之间存在依赖关系等。Pydantic 提供了自定义校验器（Validators）机制，允许你编写任意 Python 函数来执行复杂的校验逻辑。Pydantic v2 使用 `@field_validator`（字段级校验）和 `@model_validator`（模型级校验）两个装饰器。

#### 原理

`@field_validator` 用于校验单个字段。它接收字段的值作为参数，可以执行任意校验逻辑：通过则返回该值（可能经过转换），失败则抛出 `ValueError`（Pydantic 会将其转为 `ValidationError`）。装饰器支持 `mode="before"`（在类型转换前执行，接收原始值）和 `mode="after"`（在类型转换后执行，接收已转换的值）两种模式。默认是 `after`。

`@model_validator` 用于校验整个模型，可以访问所有字段的值，适合处理字段间的依赖关系。它支持 `mode="before"`（接收原始字典，在模型实例化前执行）和 `mode="after"`（接收模型实例，在实例化后执行）。

校验器中可以抛出 `ValueError` 或 `AssertionError`，Pydantic 会捕获并转为校验错误。也可以使用 `PydanticCustomError` 抛出更结构化的错误。

#### 例子

字段级校验器：

```python
from pydantic import BaseModel, field_validator

class User(BaseModel):
    username: str
    password: str

    @field_validator("username")
    @classmethod
    def username_must_alphanumeric(cls, v: str) -> str:
        if not v.isalnum():
            raise ValueError("用户名只能包含字母和数字")
        if len(v) < 3:
            raise ValueError("用户名至少3个字符")
        return v

    @field_validator("password")
    @classmethod
    def password_strength(cls, v: str) -> str:
        if len(v) < 8:
            raise ValueError("密码至少8个字符")
        if not any(c.isupper() for c in v):
            raise ValueError("密码必须包含大写字母")
        if not any(c.islower() for c in v):
            raise ValueError("密码必须包含小写字母")
        if not any(c.isdigit() for c in v):
            raise ValueError("密码必须包含数字")
        return v
```

`mode="before"` 校验器（在类型转换前执行）：

```python
from pydantic import BaseModel, field_validator

class Item(BaseModel):
    tags: list[str]

    @field_validator("tags", mode="before")
    @classmethod
    def split_tags(cls, v):
        # 允许客户端传字符串，自动按逗号分割
        if isinstance(v, str):
            return [tag.strip() for tag in v.split(",")]
        return v
```

模型级校验器（处理字段间关系）：

```python
from pydantic import BaseModel, model_validator
from datetime import datetime

class Event(BaseModel):
    start_time: datetime
    end_time: datetime

    @model_validator(mode="after")
    def check_time_range(self) -> "Event":
        if self.end_time <= self.start_time:
            raise ValueError("结束时间必须晚于开始时间")
        return self

class Booking(BaseModel):
    check_in: datetime
    check_out: datetime
    guests: int

    @model_validator(mode="after")
    def validate_booking(self) -> "Booking":
        if self.check_out <= self.check_in:
            raise ValueError("退房时间必须晚于入住时间")
        if self.guests <= 0:
            raise ValueError("入住人数必须大于0")
        # 可以根据入住天数限制人数等
        nights = (self.check_out - self.check_in).days
        if nights > 30 and self.guests > 4:
            raise ValueError("长租超过30天时，人数不能超过4人")
        return self
```

`mode="before"` 模型校验器（接收原始字典）：

```python
from pydantic import BaseModel, model_validator
from typing import Any

class User(BaseModel):
    name: str
    age: int

    @model_validator(mode="before")
    @classmethod
    def remove_id_field(cls, data: Any) -> Any:
        if isinstance(data, dict):
            # 移除客户端可能误传的 id 字段
            data.pop("id", None)
        return data
```

#### 总结

- `@field_validator` 校验单个字段，`@model_validator` 校验整个模型。
- `mode="before"` 在类型转换前执行（接收原始值），`mode="after"` 在转换后执行（接收转换后的值）。
- 校验器中抛出 `ValueError` 或 `AssertionError`，Pydantic 会转为 `ValidationError`。
- 校验通过后必须返回值（可以是转换后的值），否则字段值为 `None`。
- 字段间依赖关系（如时间范围、互斥字段）使用 `@model_validator(mode="after")`。
- `mode="before"` 适合数据预处理，如字符串分割、字段重命名、移除多余字段。
- 校验器中的逻辑会反映到 OpenAPI 文档的描述中，但具体规则需在 docstring 中说明。

## 第五章 依赖注入系统

### 第 14 讲 依赖注入基础

#### 概念

依赖注入（Dependency Injection，DI）是一种设计模式，核心思想是"将组件所依赖的对象由外部提供，而非组件自己创建"。在 FastAPI 中，依赖注入是其最强大、最核心的特性之一。通过依赖注入，你可以将公共逻辑（如数据库会话获取、用户认证、分页参数解析、权限校验等）抽取为可复用的"依赖"，然后在多个路径操作函数中共享。FastAPI 的依赖注入系统基于 Python 的类型提示和函数签名，使用极其简洁优雅，同时支持同步和异步依赖。

#### 原理

FastAPI 的依赖注入通过 `Depends` 类实现。当函数参数声明为 `param: Type = Depends(dependency_callable)` 时，FastAPI 会在请求处理前调用 `dependency_callable`，将其返回值作为参数传入。`dependency_callable` 可以是普通函数、异步函数、类，甚至是另一个带依赖的函数。

FastAPI 会分析依赖函数的签名，递归地解析其参数：如果依赖函数的参数也有 `Depends`，FastAPI 会先解析那些依赖，形成依赖树。同一请求中，相同的依赖只会执行一次，结果会被缓存复用（通过 `use_cache=True` 控制，默认开启），这避免了重复计算。

依赖函数的参数同样支持路径参数、查询参数、请求体等，FastAPI 会按照与路径操作函数相同的规则解析。这意味着依赖函数可以自己声明需要的查询参数（如分页参数），实现参数解析与业务逻辑的解耦。

#### 例子

基本依赖：


子依赖（依赖嵌套）：

```python
from fastapi import FastAPI, Depends

app = FastAPI()

def query_extractor(q: str | None = None):
    return q

def query_checker(q: str = Depends(query_extractor)):
    if q == "admin":
        return "管理员查询"
    return "普通查询"

@app.get("/search/")
def search(result: str = Depends(query_checker)):
    return {"result": result}
```

FastAPI 会先调用 `query_extractor` 获取 `q`，再将其传给 `query_checker`，最后将 `query_checker` 的结果传给 `search`。

#### 总结

- 依赖注入通过 `Depends` 实现，将公共逻辑抽取为可复用的依赖。
- 依赖可以是函数、异步函数、类，FastAPI 自动调用并注入返回值。
- 依赖支持嵌套（子依赖），FastAPI 递归解析依赖树。
- 同一请求中相同依赖默认只执行一次（`use_cache=True`），结果被缓存复用。
- 依赖函数的参数按与路径操作函数相同的规则解析（路径、查询、请求体）。
- 类作为依赖时，`Depends()` 可省略参数，FastAPI 自动实例化注解类型。
- 依赖注入是 FastAPI 实现认证、数据库会话、权限控制等的基础机制。

### 第 15 讲 依赖嵌套与 yield 依赖

#### 概念

FastAPI 的依赖注入系统支持任意深度的嵌套，即一个依赖可以依赖另一个依赖，形成依赖树。这种机制让复杂逻辑可以分解为多层小函数，每层只关注自己的职责。此外，FastAPI 支持使用 `yield` 语法的依赖，这种依赖可以在请求处理完成后执行清理逻辑（如关闭数据库连接、释放资源），类似 Python 的上下文管理器（`with` 语句）。`yield` 依赖是处理需要"获取-使用-释放"模式的资源的标准方式。

#### 原理

当依赖函数使用 `yield` 而非 `return` 时，FastAPI 会将其作为生成器处理：`yield` 之前的代码在请求处理前执行，`yield` 的值作为依赖返回值注入路径操作函数；请求处理完成后，`yield` 之后的代码被执行，用于清理资源。如果 `yield` 之后的代码抛出异常，FastAPI 会捕获并处理。

依赖嵌套时，FastAPI 按照依赖树的拓扑顺序执行：先执行叶子依赖，再逐层向上。对于 `yield` 依赖，清理顺序与获取顺序相反（类似栈的后进先出），确保资源正确释放。

`yield` 依赖可以配合 `try/except/finally` 捕获路径操作函数中抛出的异常，实现错误处理或日志记录。但注意，`yield` 之后的异常如果未被捕获，会被 FastAPI 的异常处理器处理。

#### 例子

`yield` 依赖管理数据库会话：

```python
from fastapi import FastAPI, Depends
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker, Session

app = FastAPI()

engine = create_engine("sqlite:///./test.db")
SessionLocal = sessionmaker(bind=engine)

def get_db():
    db = SessionLocal()
    try:
        yield db  # 将 db 注入路径操作函数
    finally:
        db.close()  # 请求完成后关闭会话

@app.get("/items/")
def read_items(db: Session = Depends(get_db)):
    # 使用 db 查询数据库
    return {"message": "查询成功"}

@app.post("/items/")
def create_item(db: Session = Depends(get_db)):
    # 使用 db 写入数据库
    return {"message": "创建成功"}
```

#### 总结

- 依赖嵌套允许一个依赖依赖另一个依赖，形成依赖树，FastAPI 递归解析。
- `yield` 依赖在 `yield` 前准备资源，`yield` 后清理资源，类似上下文管理器。
- `yield` 依赖的清理顺序与获取顺序相反（后进先出），确保资源正确释放。
- `yield` 依赖中可用 `try/except` 捕获路径操作函数的异常，用于日志或回滚。
- 数据库会话是 `yield` 依赖的典型应用场景：获取会话 → 使用 → 关闭。
- 依赖嵌套让复杂逻辑分层，每层职责单一，便于测试和维护。
- `use_cache=True`（默认）确保同一请求中相同依赖只执行一次。

### 第 16 讲 全局依赖与类依赖

#### 概念

除了在单个路径操作函数上声明依赖，FastAPI 还支持在更高层级声明依赖：可以在 `APIRouter` 级别（一组路由共享依赖）和整个 `FastAPI` 应用级别（所有路由共享依赖）声明。这种全局依赖常用于认证、日志、限流等横切关注点。此外，FastAPI 支持将依赖封装为类，利用类的属性和方法，使依赖更具表达力和可测试性。本讲深入讲解全局依赖和类依赖的高级用法。

#### 原理

在 `APIRouter()` 构造函数中传入 `dependencies=[Depends(...)]`，该路由器下所有路径操作都会执行这些依赖，即使路径操作函数本身没有声明该依赖。同理，`FastAPI()` 构造函数的 `dependencies` 参数应用于整个应用。全局依赖的执行结果不会自动注入函数参数（除非函数也声明了该依赖），它们主要用于"副作用"——如校验、日志、认证拦截。

类依赖利用 Python 类的 `__init__` 方法作为依赖函数。类的实例属性保存依赖数据，方法提供操作。类依赖的优势是：可以封装状态和行为，便于复用和测试；可以通过继承扩展；类型提示更清晰。FastAPI 还支持 `__call__` 方法的类作为依赖，这种类可以接收请求对象，实现更灵活的逻辑。

对于需要访问请求对象（如获取请求头、查询参数、请求体）的依赖，可以使用 `Request` 对象作为依赖参数，FastAPI 会注入当前请求对象。

#### 例子

应用级全局依赖（如 API Key 认证）：

```python
from fastapi import FastAPI, Depends, HTTPException, Header

app = FastAPI()

def verify_api_key(x_api_key: str = Header(...)):
    if x_api_key != "secret-api-key":
        raise HTTPException(status_code=403, detail="无效的 API Key")
    return x_api_key

# 应用级依赖：所有路由都需要 API Key
app = FastAPI(dependencies=[Depends(verify_api_key)])

@app.get("/public/")
def public_endpoint():
    return {"message": "虽然叫 public，但也需要 API Key"}

@app.get("/private/")
def private_endpoint():
    return {"message": "私有接口"}
```


```python
from fastapi import FastAPI, Depends, Query

    def __init__(
        self,
        page: int = Query(1, ge=1, description="页码"),
        size: int = Query(10, ge=1, le=100, description="每页数量"),

        self.page = page
        self.size = size
        self.skip = (page - 1) * size

        return query.offset(self.skip).limit(self.size)
```

带 `__call__` 的类依赖（可访问请求对象）：

```python
from fastapi import FastAPI, Depends, Request, HTTPException

app = FastAPI()

class RateLimiter:
    def __init__(self, max_requests: int = 10):
        self.max_requests = max_requests
        self.requests = {}  # 简化示例，生产环境用 Redis

    def __call__(self, request: Request):
        client_ip = request.client.host
        count = self.requests.get(client_ip, 0)
        if count >= self.max_requests:
            raise HTTPException(status_code=429, detail="请求过于频繁")
        self.requests[client_ip] = count + 1
        return {"ip": client_ip, "count": count + 1}

# 每个实例有独立配置
limiter = RateLimiter(max_requests=5)

@app.get("/limited/")
def limited_endpoint(rate_info = Depends(limiter)):
    return {"rate_info": rate_info}
```

#### 总结

- 全局依赖通过 `FastAPI(dependencies=[...])` 或 `APIRouter(dependencies=[...])` 声明。
- 全局依赖对所有路由生效，主要用于认证、日志、限流等横切关注点。
- 全局依赖的返回值不自动注入函数参数，除非函数也声明了该依赖。
- 类依赖利用 `__init__` 作为依赖函数，封装状态和行为，便于复用和测试。
- 带 `__call__` 方法的类依赖可接收 `Request` 对象，实现灵活逻辑。
- 路由器级依赖适合为一组路由统一添加前置校验（如权限检查）。
- 合理分层使用依赖：函数级（特定接口）、路由器级（模块）、应用级（全局）。

## 第六章 安全与认证

### 第 17 讲 安全机制概览与 OAuth2

#### 概念

Web API 的安全认证是生产级应用的核心需求。FastAPI 在 `fastapi.security` 模块中提供了一套完整的安全工具集，支持多种认证方案：HTTP Basic 认证、HTTP Bearer Token、OAuth2（密码模式、授权码模式）、API Key（Header/Query/Cookie）等。其中 OAuth2 是最常用的授权框架，它定义了一套标准的授权流程。FastAPI 的安全模块与 OpenAPI 规范深度集成，认证方案会自动反映到交互式文档中，开发者可以直接在 `/docs` 界面中登录并测试受保护的接口。本讲先建立安全认证的整体认知，重点讲解 OAuth2 密码模式（Password Flow）。

#### 原理

OAuth2 是一个授权框架（RFC 6749），定义了多种授权流程（Grant Types）。在 API 开发中最常用的是"资源所有者密码凭证模式"（Resource Owner Password Credentials Grant，简称密码模式）：客户端直接将用户名和密码发送给服务器，服务器验证后返回访问令牌（Access Token），客户端后续请求携带该令牌访问受保护资源。这种模式适用于客户端完全可信的场景（如自己的前端应用）。

FastAPI 的 `OAuth2PasswordBearer` 类实现了密码模式的令牌获取端点配置。创建实例时指定 `tokenUrl`（客户端获取令牌的 URL），FastAPI 会在 OpenAPI 文档中注册该认证方案。将实例作为依赖使用时，它会自动从请求的 `Authorization: Bearer <token>` 头中提取令牌，如果没有则返回 401。开发者需要自己实现令牌的验证逻辑（即令牌是否有效、对应哪个用户）。

完整的 OAuth2 密码模式流程：客户端 POST 用户名密码到 `/token` → 服务器验证凭证 → 服务器生成并返回 `{"access_token": "...", "token_type": "bearer"}` → 客户端存储令牌 → 后续请求在 `Authorization` 头携带令牌 → 服务器验证令牌并返回资源。

#### 例子

搭建 OAuth2 密码模式基础结构：

```python
from fastapi import FastAPI, Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer, OAuth2PasswordRequestForm

app = FastAPI()

# 指定获取令牌的 URL
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")

# 模拟用户数据库
fake_users_db = {
    "alice": {
        "username": "alice",
        "hashed_password": "fakehashedsecret",
        "disabled": False,
    }
}

def fake_hash_password(password: str):
    return "fakehashed" + password

# 令牌验证依赖
def get_current_user(token: str = Depends(oauth2_scheme)):
    # 这里简化处理，实际应解析 JWT
    user = fake_users_db.get(token.replace("fakehashed", ""))
    if not user:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="无效的认证凭证",
            headers={"WWW-Authenticate": "Bearer"},
        )
    return user

# 登录端点：验证用户名密码，返回令牌
@app.post("/token")
def login(form_data: OAuth2PasswordRequestForm = Depends()):
    user = fake_users_db.get(form_data.username)
    if not user or user["hashed_password"] != fake_hash_password(form_data.password):
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="用户名或密码错误",
            headers={"WWW-Authenticate": "Bearer"},
        )
    return {"access_token": user["username"], "token_type": "bearer"}

# 受保护的接口
@app.get("/users/me")
def read_users_me(current_user: dict = Depends(get_current_user)):
    return current_user
```

`OAuth2PasswordRequestForm` 是 FastAPI 提供的表单类，自动解析 `username` 和 `password` 字段（表单格式，非 JSON）。登录后，在 `/docs` 界面点击右上角"Authorize"按钮，输入用户名密码即可登录，之后所有受保护接口会自动携带令牌。

测试流程：

```bash
# 1. 登录获取令牌
curl -X POST "http://127.0.0.1:8000/token" \
     -d "username=alice&password=secret"

# 返回：{"access_token":"alice","token_type":"bearer"}

# 2. 携带令牌访问受保护接口
curl -H "Authorization: Bearer alice" \
     http://127.0.0.1:8000/users/me

# 返回：{"username":"alice","hashed_password":"...","disabled":false}
```

#### 总结

- FastAPI 的 `fastapi.security` 模块提供多种认证方案：Basic、Bearer、OAuth2、APIKey。
- OAuth2 密码模式适用于客户端可信场景：用户名密码换令牌，令牌访问资源。
- `OAuth2PasswordBearer(tokenUrl="token")` 配置令牌获取端点，自动从 Authorization 头提取令牌。
- `OAuth2PasswordRequestForm` 自动解析登录表单的 username/password 字段。
- 安全方案自动集成到 OpenAPI 文档，可在 `/docs` 中直接登录测试。
- 本讲的令牌是简化的（直接用用户名），下一讲将使用 JWT 实现真正的安全令牌。
- 401 响应应携带 `WWW-Authenticate: Bearer` 头，符合 HTTP 规范。

### 第 18 讲 JWT Token 认证实现

#### 概念

JWT（JSON Web Token）是一种开放标准（RFC 7519），用于在各方之间安全地传输信息。JWT 是一个紧凑的、URL 安全的字符串，由三部分组成：Header（头部）、Payload（载荷）、Signature（签名），用点号 `.` 连接。在 Web 认证场景中，JWT 常用作访问令牌：服务器在用户登录后签发 JWT，客户端后续请求携带该 JWT，服务器验证签名后提取用户信息。相比传统的 Session 认证，JWT 是无状态的（服务器不需要存储会话），天然适合分布式和微服务架构。本讲实现完整的 JWT 认证流程。

#### 原理

JWT 的三部分：
1. **Header**：声明令牌类型（JWT）和签名算法（如 HS256），经 Base64URL 编码。
2. **Payload**：存放声明（Claims），如 `sub`（主体，通常是用户ID）、`exp`（过期时间）、`iat`（签发时间）、自定义字段。经 Base64URL 编码。注意 Payload 默认不加密，不要放敏感信息。
3. **Signature**：用 Header 中指定的算法，对 `编码后的Header.编码后的Payload` 用密钥签名，确保令牌未被篡改。

JWT 的工作流程：服务器用密钥签发 JWT → 客户端存储并携带 JWT → 服务器收到 JWT 后用同一密钥验证签名 → 验证通过则信任 Payload 中的信息。由于签名涉及密钥，攻击者无法伪造有效的 JWT（除非密钥泄露）。JWT 的过期时间（`exp`）让令牌自动失效，提升安全性。

Python 中常用 `PyJWT` 库（`pip install pyjwt`）生成和验证 JWT。生成时调用 `jwt.encode(payload, secret_key, algorithm)`，验证时调用 `jwt.decode(token, secret_key, algorithms)`。验证时会自动检查 `exp` 等标准声明，过期会抛出 `ExpiredSignatureError`。

#### 例子

完整的 JWT 认证实现：

```python
from datetime import datetime, timedelta, timezone
from typing import Optional
from fastapi import FastAPI, Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer, OAuth2PasswordRequestForm
from jose import JWTError, jwt  # python-jose 库，pip install python-jose[cryptography]
from pydantic import BaseModel

app = FastAPI()

# 配置
SECRET_KEY = "your-secret-key-keep-it-secret"  # 生产环境从环境变量读取
ALGORITHM = "HS256"
ACCESS_TOKEN_EXPIRE_MINUTES = 30

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")

    access_token: str
    token_type: str

    to_encode = data.copy()
    expire = datetime.now(timezone.utc) + (
        expires_delta or timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES)
    )
    to_encode.update({"exp": expire})
    encoded_jwt = jwt.encode(to_encode, SECRET_KEY, algorithm=ALGORITHM)

def get_current_user(token: str = Depends(oauth2_scheme)):
    credentials_exception = HTTPException(

        username: str = payload.get("sub")
        if username is None:
            raise credentials_exception
        token_data = TokenData(username=username)
    except JWTError:
        raise credentials_exception
    # 这里应从数据库查询用户
    user = get_user(username=token_data.username)
    if user is None:
        raise credentials_exception
    return user
```

```text

eyJzdWIiOiJhbGljZSIsImV4cCI6MTcwMDAwMDAwMH0.  # Payload
SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c   # Signature
```

#### 总结

- JWT 由 Header、Payload、Signature 三部分组成，用 `.` 连接，紧凑且 URL 安全。
- JWT 是无状态的，服务器不需要存储会话，适合分布式架构。
- Payload 中的 `sub`（主体）、`exp`（过期时间）是标准声明，`jwt.decode` 会自动校验 `exp`。
- 使用 `python-jose` 或 `PyJWT` 库生成和验证 JWT。
- 密钥（SECRET_KEY）必须保密，生产环境从环境变量或密钥管理服务读取。
- 设置合理的过期时间（如 30 分钟），过期后客户端需重新登录或用刷新令牌。
- Payload 默认只编码不加密，不要存放密码等敏感信息。
- 401 响应携带 `WWW-Authenticate: Bearer` 头，符合 HTTP 规范。

### 第 19 讲 密码哈希与用户管理

#### 概念

在认证系统中，密码的安全存储是重中之重。绝对不能以明文形式存储用户密码——一旦数据库泄露，所有用户密码将直接暴露。正确的做法是使用密码哈希算法（如 bcrypt、Argon2）对密码进行单向哈希后存储。哈希是不可逆的，即使拿到哈希值也无法还原密码。验证密码时，将用户输入的密码哈希后与存储的哈希比较。本讲使用 `passlib` 库实现密码哈希，并构建完整的用户注册、登录、认证流程。同时介绍用户管理的最佳实践。

#### 原理

密码哈希与普通哈希（如 MD5、SHA256）的区别在于：密码哈希算法故意设计得很慢（计算成本可调），且每个密码使用随机盐（Salt）哈希，这使得暴力破解和彩虹表攻击变得不可行。bcrypt 是最常用的密码哈希算法，它内置盐值，计算成本（cost factor）可调，默认为 12 轮（每轮翻倍计算量）。

`passlib` 是 Python 的密码哈希库，支持多种算法，提供统一的 API。使用 `CryptContext(schemes=["bcrypt"])` 创建上下文，调用 `hash(password)` 哈希密码，调用 `verify(password, hashed)` 验证密码。`passlib` 自动处理盐值生成和存储（盐值嵌入在哈希字符串中）。

完整的用户认证流程：注册时哈希密码存入数据库 → 登录时用 `verify` 验证密码 → 验证通过则签发 JWT → 后续请求验证 JWT 获取用户。用户模型通常包含：username、email、hashed_password、disabled（是否禁用）、created_at 等字段。

#### 例子

完整的用户注册与认证系统：

#### 总结

- 密码必须哈希存储，绝不能明文保存，使用 bcrypt 等专用密码哈希算法。
- `passlib` 的 `CryptContext` 提供统一的哈希 API：`hash()` 哈希，`verify()` 验证。
- bcrypt 自动处理盐值，盐值嵌入在哈希字符串中，无需单独存储。

- 密码相关操作（哈希、验证）应使用同步函数，避免在异步上下文中阻塞事件循环。

### 第 20 讲 基于角色的权限控制

#### 概念

认证（Authentication）解决"你是谁"的问题，授权（Authorization）解决"你能做什么"的问题。在真实业务中，不同用户有不同的权限：普通用户只能查看和编辑自己的数据，管理员可以管理所有用户，超级管理员可以配置系统。基于角色的访问控制（Role-Based Access Control，RBAC）是最常用的授权模型：将权限分配给角色，将角色分配给用户，用户通过角色获得权限。FastAPI 通过依赖注入系统可以优雅地实现 RBAC，本讲讲解如何基于 JWT 中的角色声明实现细粒度权限控制。

#### 原理

RBAC 的核心三要素：用户（User）、角色（Role）、权限（Permission）。用户被分配一个或多个角色，角色拥有一组权限。当用户请求访问某资源时，系统检查用户的角色是否包含所需权限。在 JWT 实现中，可以将角色信息放入 JWT 的 Payload（如 `"role": "admin"` 或 `"roles": ["admin", "editor"]`），服务器验证 JWT 后从 Payload 提取角色，与接口要求的角色比较。

FastAPI 实现权限控制的优雅方式是创建权限检查依赖。可以定义一个依赖工厂函数，接收所需角色列表，返回一个依赖函数，该函数从当前用户获取角色并校验。这样在路由上声明 `Depends(require_role("admin"))` 即可限制访问。对于更复杂的场景（如资源所有权检查：用户只能修改自己的文章），可以在依赖中访问路径参数和数据库。

权限控制的层次：接口级（整个接口需要某角色）、对象级（同一接口对不同资源有不同权限）、字段级（不同角色看到不同字段）。本讲重点讲解接口级和对象级。

#### 例子

基于角色的权限控制实现：

```python
from fastapi import FastAPI, Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer
from jose import jwt, JWTError
from pydantic import BaseModel
from typing import Optional

app = FastAPI()
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")
SECRET_KEY = "your-secret-key"
ALGORITHM = "HS256"

class User(BaseModel):
    username: str
    role: str  # "user", "editor", "admin"

# 模拟数据库
users_db = {
    "alice": {"username": "alice", "role": "user"},
    "bob": {"username": "bob", "role": "editor"},
    "admin": {"username": "admin", "role": "admin"},
}

# 模拟文章数据库
articles_db = {
    1: {"id": 1, "title": "文章1", "content": "内容1", "author": "alice"},
    2: {"id": 2, "title": "文章2", "content": "内容2", "author": "bob"},
}

def get_current_user(token: str = Depends(oauth2_scheme)):
    credentials_exception = HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="无法验证凭证",
    )
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        username = payload.get("sub")
        if username is None or username not in users_db:
            raise credentials_exception
        return User(**users_db[username])
    except JWTError:
        raise credentials_exception

# 角色权限依赖工厂
def require_role(*roles: str):
    def role_checker(current_user: User = Depends(get_current_user)):
        if current_user.role not in roles:
            raise HTTPException(
                status_code=status.HTTP_403_FORBIDDEN,
                detail=f"权限不足，需要以下角色之一: {', '.join(roles)}",
            )
        return current_user
    return role_checker

# 所有人可读
@app.get("/articles/")
def list_articles(current_user: User = Depends(get_current_user)):
    return list(articles_db.values())

# 编辑及以上可创建
@app.post("/articles/")
def create_article(
    article: dict,
    current_user: User = Depends(require_role("editor", "admin")),
):
    new_id = max(articles_db.keys()) + 1
    article["id"] = new_id
    article["author"] = current_user.username
    articles_db[new_id] = article
    return article

# 仅管理员可删除
@app.delete("/articles/{article_id}")
def delete_article(
    article_id: int,
    current_user: User = Depends(require_role("admin")),
):
    if article_id not in articles_db:
        raise HTTPException(status_code=404, detail="文章不存在")
    del articles_db[article_id]
    return {"message": "已删除"}

# 对象级权限：作者或管理员可修改
@app.put("/articles/{article_id}")
def update_article(
    article_id: int,
    article: dict,
    current_user: User = Depends(get_current_user),
):
    if article_id not in articles_db:
        raise HTTPException(status_code=404, detail="文章不存在")
    existing = articles_db[article_id]
    # 作者本人或管理员可修改
    if existing["author"] != current_user.username and current_user.role != "admin":
        raise HTTPException(
            status_code=status.HTTP_403_FORBIDDEN,
            detail="只能修改自己的文章",
        )
    existing.update(article)
    return existing
```

使用枚举定义角色更规范：

```python
from enum import Enum

class Role(str, Enum):
    USER = "user"
    EDITOR = "editor"
    ADMIN = "admin"

# 角色层级：admin > editor > user
ROLE_HIERARCHY = {Role.USER: 0, Role.EDITOR: 1, Role.ADMIN: 2}

def require_min_role(min_role: Role):
    def checker(current_user: User = Depends(get_current_user)):
        user_level = ROLE_HIERARCHY.get(Role(current_user.role), -1)
        required_level = ROLE_HIERARCHY[min_role]
        if user_level < required_level:
            raise HTTPException(status_code=403, detail="权限不足")
        return current_user
    return checker

@app.get("/admin/dashboard/")
def admin_dashboard(user = Depends(require_min_role(Role.ADMIN))):
    return {"message": "管理员仪表盘"}
```

#### 总结

- 认证解决"你是谁"，授权解决"你能做什么"，RBAC 是最常用的授权模型。
- RBAC 三要素：用户、角色、权限，权限分配给角色，角色分配给用户。
- JWT 的 Payload 中可携带角色信息（`role` 或 `roles` 字段）。
- 使用依赖工厂 `require_role(*roles)` 实现接口级权限控制，声明式且可复用。
- 对象级权限（如只能修改自己的资源）在依赖中结合路径参数和数据库查询实现。
- 角色层级（admin > editor > user）可简化权限配置，高级角色自动拥有低级权限。
- 权限不足返回 403 Forbidden，未认证返回 401 Unauthorized，两者要区分。
- 复杂权限场景可考虑 Casbin 等专业权限库，支持 ACL、ABAC 等多种模型。

## 第七章 数据库集成

### 第 21 讲 SQLAlchemy 集成基础

#### 概念

绝大多数 Web 应用都需要持久化存储数据，数据库是核心基础设施。在 Python 生态中，SQLAlchemy 是最强大的 ORM（对象关系映射）框架，它将数据库表映射为 Python 类，将表记录映射为对象，让开发者用面向对象的方式操作数据库，无需手写 SQL。FastAPI 与 SQLAlchemy 的结合非常自然：SQLAlchemy 负责数据持久化，FastAPI 负责请求处理和响应序列化，Pydantic 负责数据校验。本讲讲解 SQLAlchemy 的核心概念、模型定义、数据库连接配置，以及与 FastAPI 的集成方式。

#### 原理

SQLAlchemy 分为两层：Core（底层，提供 SQL 表达式语言）和 ORM（高层，提供对象关系映射）。本教程使用 ORM 层。SQLAlchemy 2.0 采用了全新的类型注解风格，与 FastAPI 的类型提示理念一致。

SQLAlchemy ORM 的核心组件：
- **Engine**：数据库连接引擎，管理连接池，是所有数据库操作的入口。通过 `create_engine(url)` 创建。
- **Session**：会话，是数据库操作的工作单元，类似事务。所有增删改查都通过 Session 进行。通过 `sessionmaker(bind=engine)` 创建会话工厂。
- **Base**：所有 ORM 模型的基类，通过 `DeclarativeBase` 创建。模型类继承 Base，定义表结构。
- **Model**：ORM 模型类，类的属性对应表的列。使用 `Mapped` 和 `mapped_column` 进行类型注解（SQLAlchemy 2.0 风格）。

在 FastAPI 中集成 SQLAlchemy 的关键模式是使用 `yield` 依赖管理会话：每个请求获取一个 Session，请求结束后关闭。这确保了会话的隔离性和资源的及时释放。Pydantic 模型与 SQLAlchemy 模型分离：Pydantic 模型（schemas）用于 API 数据校验和序列化，SQLAlchemy 模型（models）用于数据库操作，两者通过 `model_validate` 或手动转换衔接。

### 第 22 讲 CRUD 操作与会话管理

#### 概念

CRUD 是 Create（创建）、Read（读取）、Update（更新）、Delete（删除）四个基本数据库操作的缩写，是几乎所有业务系统的核心。本讲讲解如何使用 SQLAlchemy Session 执行 CRUD 操作，并构建标准的 CRUD 服务层。良好的 CRUD 实现应遵循：业务逻辑与路由分离（CRUD 函数独立模块）、统一错误处理（资源不存在返回 404）、事务管理（写操作需 commit）、输入输出用 Pydantic 模型校验。我们将构建一个完整的文章管理 API，涵盖增删改查的各个方面。

#### 原理

SQLAlchemy Session 的 CRUD 操作：
- **Create**：`db.add(obj)` 将对象加入会话，`db.commit()` 提交事务，`db.refresh(obj)` 刷新获取自增 ID 等数据库生成的字段。
- **Read**：`db.query(Model)` 或 `db.execute(select(Model))`（2.0 风格）查询。支持 `filter_by`、`filter`、`order_by`、`offset`、`limit` 等链式方法。`first()` 返回第一条，`all()` 返回全部，`get(id)` 按主键查询。
- **Update**：修改对象属性后 `db.commit()` 即可。也可用 `update()` 语句批量更新。
- **Delete**：`db.delete(obj)` 删除对象，`db.commit()` 提交。也可用 `delete()` 语句批量删除。

事务管理：Session 默认开启事务，写操作后必须 `commit` 才生效。如果出错，`rollback` 回滚。在 FastAPI 中，通常每个请求一个 Session，请求结束关闭 Session（未 commit 的操作会自动回滚）。

CRUD 层的设计模式：将数据库操作封装在 `crud/` 模块的函数中，路由层调用这些函数。这样路由层只关注 HTTP 逻辑，CRUD 层只关注数据库逻辑，职责清晰，易于测试和复用。

#### 例子

CRUD 服务层：

```python
# app/crud/post.py
from sqlalchemy.orm import Session
from app.models import Post
from app.schemas import PostCreate, PostBase

def get_post(db: Session, post_id: int) -> Post | None:
    return db.get(Post, post_id)

def get_posts(
    db: Session, skip: int = 0, limit: int = 100
) -> list[Post]:
    return db.query(Post).offset(skip).limit(limit).all()

def get_posts_by_author(
    db: Session, author_id: int, skip: int = 0, limit: int = 100
) -> list[Post]:
    return (
        db.query(Post)
        .filter(Post.author_id == author_id)
        .offset(skip)
        .limit(limit)
        .all()
    )

def create_post(db: Session, post: PostCreate, author_id: int) -> Post:
    db_post = Post(**post.model_dump(), author_id=author_id)
    db.add(db_post)
    db.commit()
    db.refresh(db_post)
    return db_post

def update_post(db: Session, post_id: int, post_update: PostBase) -> Post | None:
    db_post = db.get(Post, post_id)
    if not db_post:
        return None
    for field, value in post_update.model_dump().items():
        setattr(db_post, field, value)
    db.commit()
    db.refresh(db_post)
    return db_post

def delete_post(db: Session, post_id: int) -> bool:
    db_post = db.get(Post, post_id)
    if not db_post:
        return False
    db.delete(db_post)
    db.commit()
    return True
```

#### 总结

- CRUD 是 Create、Read、Update、Delete 四个基本数据库操作。
- Create：`db.add()` + `db.commit()` + `db.refresh()`。
- Read：`db.query()` 或 `db.execute(select())`，支持 `filter`、`order_by`、`offset`、`limit`。
- Update：修改属性后 `commit`，或用 `update()` 语句批量更新。
- Delete：`db.delete()` + `commit`，或用 `delete()` 语句批量删除。
- CRUD 逻辑封装在独立模块，路由层调用，职责分离，易于测试。
- 写操作必须 `commit`，出错应 `rollback`，FastAPI 的 `yield` 依赖自动处理关闭。
- SQLAlchemy 2.0 推荐 `select()` 风格，`db.execute(stmt).scalars().all()` 获取结果。
- 资源不存在返回 404，统一错误处理提升 API 一致性。

### 第 23 讲 异步数据库操作

#### 概念

FastAPI 原生支持异步编程，而数据库 I/O 是典型的 I/O 密集型操作。使用同步 SQLAlchemy（如前两讲）时，数据库查询会阻塞事件循环，影响并发性能。为了充分发挥 FastAPI 的异步优势，应使用 SQLAlchemy 的异步扩展（`AsyncSession`、`create_async_engine`）配合异步数据库驱动（如 `asyncpg` for PostgreSQL、`aiomysql` for MySQL）。本讲讲解如何搭建异步数据库层，实现异步 CRUD，以及同步与异步混用的注意事项。

#### 原理

异步 SQLAlchemy 的核心组件：
- **create_async_engine**：异步引擎，使用异步驱动连接数据库。URL 协议不同：PostgreSQL 用 `postgresql+asyncpg://`，MySQL 用 `mysql+aiomysql://`，SQLite 用 `sqlite+aiosqlite://`。
- **async_sessionmaker**：异步会话工厂，创建 `AsyncSession`。
- **AsyncSession**：异步会话，所有方法都是协程：`await db.execute()`、`await db.commit()`、`await db.refresh()` 等。
- **AsyncAttrs**：模型混入，让关系属性的懒加载也支持异步访问。

异步 SQLAlchemy 2.0 的查询风格与同步类似，但所有 I/O 操作都需要 `await`。`db.execute(stmt)` 返回 `Result` 对象，通过 `.scalars().all()` 或 `.scalar_one()` 获取结果。注意，`AsyncSession` 不支持 `db.query()` 旧风格，必须使用 `select()` 语句风格。

关键注意点：异步环境中不能调用同步的阻塞操作（如同步数据库驱动、`time.sleep`），否则会阻塞事件循环。如果必须使用同步库，应通过 `run_in_threadpool` 在线程池中执行。ORM 模型的关系懒加载在异步中需要特殊处理：使用 `selectinload`、`joinedload` 等预加载策略，或使用 `AsyncAttrs` 混入。

#### 例子

异步数据库配置：

```python

    AsyncSession, create_async_engine, async_sessionmaker

    bind=async_engine,

    expire_on_commit=False,  # 异步会话建议关闭，避免访问属性时触发同步查询
)

    pass
```

### 第 24 讲 中间件机制与自定义中间件

#### 概念

中间件（Middleware）是一种在请求到达路由处理函数之前、以及响应返回客户端之前执行逻辑的机制。它就像一个"洋葱"模型：请求从外到内穿过各层中间件，响应从内到外返回。中间件常用于日志记录、请求计时、CORS 处理、GZIP 压缩、认证拦截、限流、请求 ID 追踪等横切关注点。FastAPI 基于 Starlette 的中间件系统，支持使用装饰器风格或类风格定义中间件，并内置了多种常用中间件。理解中间件的执行顺序和编写方式，是构建生产级应用的关键技能。

#### 原理

FastAPI/Starlette 的中间件采用 ASGI 中间件规范。每个中间件接收一个 `call_next` 函数，调用它将请求传递给下一层（可能是下一个中间件，也可能是路由处理函数），`call_next` 返回响应对象，中间件可以在返回响应前后执行逻辑。所有中间件组成一个栈，请求按"先添加的后执行"（栈结构）的顺序穿过。

中间件的两种编写方式：
1. **装饰器风格**：使用 `@app.middleware("http")` 装饰一个异步函数，函数接收 `Request` 和 `call_next` 参数。适合简单逻辑。
2. **类风格**：继承 `BaseHTTPMiddleware`，实现 `async def dispatch(self, request, call_next)` 方法。适合复杂逻辑和复用。

中间件可以修改请求（如添加自定义头）、修改响应（如添加响应头、压缩内容）、短路返回（如认证失败直接返回 401）。注意，中间件中应避免耗时操作，否则会阻塞所有请求。中间件的添加顺序很重要：后添加的中间件先执行（请求方向），先添加的中间件先处理响应。

#### 例子

装饰器风格中间件（请求计时）：

```python
import time
from fastapi import FastAPI, Request

app = FastAPI()

@app.middleware("http")
async def add_process_time_header(request: Request, call_next):
    # 请求处理前
    start_time = time.time()

    # 调用下一层
    response = await call_next(request)

    # 请求处理后
    process_time = time.time() - start_time
    response.headers["X-Process-Time"] = f"{process_time:.4f}"
    return response
```

类风格中间件（请求日志）：

```python
import logging
from fastapi import FastAPI, Request
from starlette.middleware.base import BaseHTTPMiddleware

logger = logging.getLogger("api")

class LoggingMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        # 记录请求信息
        logger.info(
            f"请求: {request.method} {request.url.path} "
            f"来自 {request.client.host if request.client else 'unknown'}"
        )

        try:
            response = await call_next(request)
            logger.info(f"响应: {response.status_code}")
            return response
        except Exception as e:
            logger.error(f"处理异常: {e}")
            raise

app = FastAPI()
app.add_middleware(LoggingMiddleware)
```

请求 ID 追踪中间件（用于日志关联）：

```python
import uuid
from fastapi import FastAPI, Request
from starlette.middleware.base import BaseHTTPMiddleware

class RequestIDMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        # 从请求头获取或生成请求 ID
        request_id = request.headers.get("X-Request-ID", str(uuid.uuid4()))

        # 将 request_id 存入 request.state，供后续使用
        request.state.request_id = request_id

        response = await call_next(request)

        # 在响应头中返回 request_id
        response.headers["X-Request-ID"] = request_id
        return response

app = FastAPI()
app.add_middleware(RequestIDMiddleware)

@app.get("/")
def root(request: Request):
    # 在路由中访问 request_id
    return {"request_id": request.state.request_id}
```

认证拦截中间件（简化示例）：

```python
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse
from starlette.middleware.base import BaseHTTPMiddleware

class SimpleAuthMiddleware(BaseHTTPMiddleware):
    # 不需要认证的路径
    OPEN_PATHS = {"/", "/login", "/docs", "/openapi.json", "/token"}

    async def dispatch(self, request: Request, call_next):
        if request.url.path in self.OPEN_PATHS:
            return await call_next(request)

        token = request.headers.get("Authorization")
        if not token or not token.startswith("Bearer "):
            return JSONResponse(
                status_code=401,
                content={"detail": "未提供有效的认证令牌"},
            )

        # 这里可以验证 token...
        return await call_next(request)

app = FastAPI()
app.add_middleware(SimpleAuthMiddleware)
```

#### 总结

- 中间件是"洋葱"模型，请求从外到内穿过，响应从内到外返回。
- 两种编写方式：`@app.middleware("http")` 装饰器风格、`BaseHTTPMiddleware` 类风格。
- 中间件通过 `call_next` 将请求传递给下一层，可在前后执行逻辑。
- 常见用途：日志、计时、CORS、GZIP、认证、限流、请求 ID 追踪。
- 中间件添加顺序：后添加的先处理请求，先添加的先处理响应。
- 中间件中避免耗时操作，否则阻塞所有请求；耗时任务用后台任务或异步。
- 中间件可修改请求和响应，也可短路返回（如认证失败直接返回 401）。
- 使用 `request.state` 在中间件与路由之间传递数据。

### 第 25 讲 CORS 跨域处理

#### 概念

CORS（Cross-Origin Resource Sharing，跨域资源共享）是浏览器的安全机制：当网页的 JavaScript 向不同源（协议+域名+端口）的服务器发请求时，浏览器会拦截该请求（除非服务器明确允许）。这在前后端分离架构中极为常见：前端运行在 `http://localhost:3000`，后端 API 在 `http://localhost:8000`，属于跨域。FastAPI 内置了 `CORSMiddleware` 中间件，可以方便地配置 CORS 策略，允许指定的源访问 API。正确配置 CORS 是前后端联调的前提，也是 API 安全的重要一环。

#### 原理

CORS 机制涉及两类请求：
1. **简单请求**：使用 GET、HEAD、POST 方法，且 Content-Type 为 `text/plain`、`multipart/form-data`、`application/x-www-form-urlencoded`。浏览器直接发送请求，服务器在响应头中用 `Access-Control-Allow-Origin` 声明允许的源。
2. **预检请求（Preflight）**：不满足简单请求条件的（如自定义头、PUT/DELETE 方法、`application/json`），浏览器先发送一个 OPTIONS 请求询问服务器是否允许。服务器响应 `Access-Control-Allow-*` 系列头。预检通过后，浏览器才发送真实请求。

`CORSMiddleware` 自动处理这两类请求。关键配置项：
- `allow_origins`：允许的源列表，如 `["http://localhost:3000"]`。`["*"]` 表示允许所有源（生产环境不推荐）。
- `allow_methods`：允许的 HTTP 方法，如 `["GET", "POST", "PUT", "DELETE"]`。
- `allow_headers`：允许的请求头，如 `["Authorization", "Content-Type"]`。
- `allow_credentials`：是否允许携带 Cookie，为 `True` 时 `allow_origins` 不能为 `["*"]`。
- `allow_origin_regex`：用正则匹配允许的源，适合通配符场景。
- `max_age`：预检请求缓存时间（秒），减少 OPTIONS 请求。

#### 例子

基本 CORS 配置：

```python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI()

app.add_middleware(
    CORSMiddleware,
    allow_origins=[
        "http://localhost:3000",      # 前端开发服务器
        "http://localhost:8080",      # 另一个前端
        "https://myapp.com",          # 生产环境前端
    ],
    allow_credentials=True,
    allow_methods=["*"],              # 允许所有方法
    allow_headers=["*"],              # 允许所有头
    max_age=600,                      # 预检缓存10分钟
)
```

- CORS 配置应通过环境变量管理，区分开发/测试/生产环境。
- CORS 是浏览器机制，非浏览器客户端（如 curl、移动 App）不受 CORS 限制。

### 第 26 讲 异步编程与并发处理

#### 概念

异步编程是 FastAPI 的核心优势之一。通过 `async`/`await` 语法，FastAPI 能够用单线程处理大量并发 I/O 操作，极大提升吞吐量。本讲深入讲解 Python 异步编程的原理、FastAPI 中的异步使用规范、并发执行多个任务（`asyncio.gather`）、以及同步代码与异步代码的混合处理。理解异步编程的本质，才能写出高性能且正确的 FastAPI 应用，避免常见的阻塞事件循环、死锁等陷阱。

#### 原理

Python 的异步基于协程（Coroutine）和事件循环（Event Loop）。协程是一种可暂停和恢复的函数，用 `async def` 定义，用 `await` 暂停等待。事件循环负责调度协程：当协程 `await` 一个 I/O 操作时，事件循环切换到其他就绪的协程执行，I/O 完成后再恢复原协程。这样单线程就能处理大量并发 I/O，无需多线程的上下文切换开销。

FastAPI 的异步规则：
- 路径操作函数声明为 `async def` 时，FastAPI 在事件循环中直接调用，函数内可使用 `await`。
- 声明为普通 `def` 时，FastAPI 在外部线程池中执行，避免阻塞事件循环。
- 依赖函数同样遵循此规则。

并发执行多个独立任务用 `asyncio.gather(*coroutines)`，它并行运行多个协程，等待全部完成，返回结果列表。相比串行 `await`，`gather` 大幅减少总等待时间。例如三个各需 1 秒的请求，串行需 3 秒，并发只需 1 秒。

关键陷阱：在 `async def` 函数中调用同步阻塞操作（如 `time.sleep`、同步 HTTP 请求、同步数据库查询）会阻塞整个事件循环，所有请求都会卡住。解决方案：用异步版本（`asyncio.sleep`、`httpx.AsyncClient`），或用 `run_in_threadpool`/`run_sync_in_worker_thread` 将阻塞操作放到线程池。

#### 例子

基本异步路径操作：

```python
import asyncio
from fastapi import FastAPI

app = FastAPI()

@app.get("/async")
async def async_endpoint():
    # 模拟异步 I/O 操作（如数据库查询、HTTP 请求）
    await asyncio.sleep(1)
    return {"message": "异步处理完成"}

@app.get("/sync")
def sync_endpoint():
    # 同步函数，FastAPI 自动放到线程池执行
    import time
    time.sleep(1)
    return {"message": "同步处理完成"}
```

并发执行多个任务：

```python
import asyncio
import httpx
from fastapi import FastAPI

app = FastAPI()

async def fetch_user(user_id: int):
    async with httpx.AsyncClient() as client:
        resp = await client.get(f"https://api.example.com/users/{user_id}")
        return resp.json()

async def fetch_posts(user_id: int):
    async with httpx.AsyncClient() as client:
        resp = await client.get(f"https://api.example.com/users/{user_id}/posts")
        return resp.json()

async def fetch_followers(user_id: int):
    async with httpx.AsyncClient() as client:
        resp = await client.get(f"https://api.example.com/users/{user_id}/followers")
        return resp.json()

@app.get("/users/{user_id}/profile")
async def get_user_profile(user_id: int):
    # 串行执行：3次请求，总耗时约3秒
    # user = await fetch_user(user_id)
    # posts = await fetch_posts(user_id)
    # followers = await fetch_followers(user_id)

    # 并发执行：3次请求同时进行，总耗时约1秒
    user, posts, followers = await asyncio.gather(
        fetch_user(user_id),
        fetch_posts(user_id),
        fetch_followers(user_id),
    )
    return {"user": user, "posts": posts, "followers": followers}
```

在异步中调用同步阻塞代码：

```python
import time
from fastapi import FastAPI

    for i in range(n):
        total += i ** 2
    return total

@app.get("/compute")
async def compute():
```

#### 总结

- 异步编程基于协程和事件循环，`async def` 定义协程，`await` 暂停等待 I/O。
- `async def` 路径操作函数在事件循环中执行，`def` 函数在线程池中执行。
- `asyncio.gather(*coros)` 并发执行多个独立任务，大幅减少总等待时间。
- 异步函数中禁止调用同步阻塞操作（`time.sleep`、同步 HTTP/DB），否则阻塞事件循环。
- 必须调用同步阻塞代码时，用 `run_in_threadpool` 放到线程池执行。
- 使用 `asyncio.wait_for(coro, timeout)` 实现超时控制，避免请求无限等待。
- 异步 HTTP 客户端用 `httpx.AsyncClient`，异步数据库用 `AsyncSession`。
- 并发任务之间无依赖时用 `gather`，有依赖时串行 `await`。
- CPU 密集型任务不适合异步，应使用多进程（如 `ProcessPoolExecutor`）。

### 第 27 讲 后台任务与定时任务

#### 概念

在 Web 应用中，有些操作不需要在请求响应周期内完成，如发送邮件通知、生成报表、清理临时文件、推送消息等。如果这些耗时操作在请求处理中同步执行，会显著增加响应时间，影响用户体验。FastAPI 提供了 `BackgroundTasks` 机制，允许在响应返回后异步执行这些任务。此外，许多业务需要定时执行任务（如每天凌晨统计报表、每分钟检查库存），这需要借助第三方库（如 `APScheduler`）实现。本讲讲解后台任务和定时任务的实现方式。

#### 原理

FastAPI 的 `BackgroundTasks` 继承自 Starlette，它将任务加入队列，在响应发送给客户端后执行。`BackgroundTasks` 可以作为依赖注入路径操作函数，调用 `tasks.add_task(func, *args, **kwargs)` 添加任务。任务函数可以是同步或异步的，FastAPI 会自动处理。如果路径操作函数声明了 `background_tasks` 参数，FastAPI 会自动注入 `BackgroundTasks` 实例。

`BackgroundTasks` 适合"触发即忘"的轻量任务，任务与请求绑定。对于更复杂的场景（如任务持久化、重试、定时调度），应使用专业任务队列：Celery（配合 Redis/RabbitMQ）、Dramatiq、ARQ（异步）等。这些工具支持任务持久化、重试机制、定时调度、任务监控等企业级特性。

定时任务推荐 `APScheduler`，它支持多种调度方式：interval（固定间隔）、cron（cron 表达式）、date（一次性）。APScheduler 可以集成到 FastAPI 的生命周期中，随应用启动而启动，随应用关闭而停止。

#### 例子

使用 `BackgroundTasks` 发送邮件：

```python
import time
from fastapi import FastAPI, BackgroundTasks
from pydantic import BaseModel, EmailStr

app = FastAPI()

class Message(BaseModel):
    email: EmailStr
    subject: str
    content: str

def send_email(email: str, subject: str, content: str):
    """模拟发送邮件（耗时操作）"""
    time.sleep(5)  # 模拟 SMTP 发送耗时
    print(f"邮件已发送至 {email}: {subject}")

@app.post("/send-notification")
def send_notification(
    message: Message,
    background_tasks: BackgroundTasks,
):
    # 将邮件发送加入后台任务，立即返回响应
    background_tasks.add_task(
        send_email,
        email=message.email,
        subject=message.subject,
        content=message.content,
    )
    return {"message": "通知已加入发送队列"}
```

```python

from apscheduler.schedulers.asyncio import AsyncIOScheduler
from apscheduler.triggers.interval import IntervalTrigger
from apscheduler.triggers.cron import CronTrigger
from contextlib import asynccontextmanager

@scheduler.scheduled_job(CronTrigger(day_of_week="mon", hour=9))
async def weekly_summary():

async def lifespan(app: FastAPI):

    return [

            "next_run_time": str(job.next_run_time),

        }

    ]
```

- `BackgroundTasks` 适合"触发即忘"的轻量后台任务，在响应返回后执行。

- 多个后台任务按添加顺序串行执行。
- 复杂任务场景（持久化、重试、分布式）使用 Celery、Dramatiq、ARQ 等专业任务队列。
- 定时任务推荐 `APScheduler`，支持 interval、cron、date 三种触发方式。
- APScheduler 通过 `lifespan` 集成到 FastAPI，随应用启停。
- Celery 架构：FastAPI 提交任务 → Redis/RabbitMQ 消息队列 → Celery Worker 执行。
- 后台任务中注意异常处理，未捕获异常会静默失败，建议记录日志。

### 第 28 讲 WebSocket 实时通信

#### 概念

传统的 HTTP 请求-响应模型是单向的：客户端发起请求，服务器响应后连接关闭。这种模型不适合实时通信场景，如聊天室、实时通知、股票行情、协同编辑等。WebSocket 协议解决了这个问题：它在单个 TCP 连接上提供全双工通信，客户端和服务器可以随时互发消息，连接持久保持。FastAPI 内置了对 WebSocket 的支持，可以轻松构建实时通信应用。本讲讲解 WebSocket 的原理、FastAPI 中的 WebSocket 使用方式，以及连接管理。

#### 原理

WebSocket 通信流程：客户端发起 HTTP 请求，带 `Upgrade: websocket` 头，服务器响应 `101 Switching Protocols`，连接升级为 WebSocket。此后双方通过该连接互发消息帧（文本或二进制），直到任一方关闭连接。WebSocket 消息是双向的、实时的，相比 HTTP 轮询（polling）大幅减少延迟和带宽。

FastAPI 的 WebSocket 通过 `@app.websocket("/path")` 装饰器定义。处理函数接收 `WebSocket` 对象，通过 `await websocket.accept()` 接受连接，`await websocket.receive_text()`/`receive_json()`/`receive_bytes()` 接收消息，`await websocket.send_text()`/`send_json()`/`send_bytes()` 发送消息，`await websocket.close()` 关闭连接。

连接管理是 WebSocket 应用的核心难点：服务器需要维护所有活跃连接，实现广播（向所有连接发消息）、点对点（向特定连接发消息）、房间（向一组连接发消息）。通常用一个全局的连接集合或字典管理，配合异步锁保证线程安全。当客户端断开时，需要从集合中移除连接，避免内存泄漏。

#### 例子

基本 WebSocket 端点：

```python
from fastapi import FastAPI, WebSocket, WebSocketDisconnect

app = FastAPI()

@app.websocket("/ws/{client_id}")
```

```python
from fastapi import FastAPI, WebSocket, WebSocketDisconnect
from typing import List

app = FastAPI()

class ConnectionManager:
    def __init__(self):
        self.active_connections: List[WebSocket] = []

    async def connect(self, websocket: WebSocket):
        await websocket.accept()
        self.active_connections.append(websocket)

    def disconnect(self, websocket: WebSocket):
        self.active_connections.remove(websocket)

    async def broadcast(self, message: str):
        # 向所有连接广播消息
        for connection in self.active_connections:
            await connection.send_text(message)

    async def send_personal(self, message: str, websocket: WebSocket):
        await websocket.send_text(message)

manager = ConnectionManager()

@app.websocket("/ws/{client_id}")
async def websocket_endpoint(websocket: WebSocket, client_id: str):
    await manager.connect(websocket)
    await manager.broadcast(f"用户 {client_id} 加入了聊天室")
    try:
        while True:
            data = await websocket.receive_text()
            await manager.broadcast(f"{client_id}: {data}")
    except WebSocketDisconnect:
        manager.disconnect(websocket)
        await manager.broadcast(f"用户 {client_id} 离开了聊天室")
```

```python
from fastapi import FastAPI, WebSocket, WebSocketDisconnect
from collections import defaultdict

app = FastAPI()

class RoomManager:
    def __init__(self):
        # {room_id: {client_id: websocket}}
        self.rooms: dict[str, dict[str, WebSocket]] = defaultdict(dict)

    async def join_room(self, room_id: str, client_id: str, ws: WebSocket):
        await ws.accept()
        self.rooms[room_id][client_id] = ws
        await self.broadcast_to_room(room_id, f"{client_id} 加入了房间", exclude=client_id)

    def leave_room(self, room_id: str, client_id: str):
        if client_id in self.rooms.get(room_id, {}):
            del self.rooms[room_id][client_id]

    async def broadcast_to_room(
        self, room_id: str, message: str, exclude: str = None
    ):
        for cid, ws in self.rooms.get(room_id, {}).items():
            if cid != exclude:
                await ws.send_text(message)

room_manager = RoomManager()

@app.websocket("/ws/room/{room_id}/{client_id}")
async def room_websocket(
    websocket: WebSocket, room_id: str, client_id: str
):
    await room_manager.join_room(room_id, client_id, websocket)
    try:
        while True:
            data = await websocket.receive_text()
            await room_manager.broadcast_to_room(
                room_id, f"{client_id}: {data}"
            )
    except WebSocketDisconnect:
        room_manager.leave_room(room_id, client_id)
        await room_manager.broadcast_to_room(
            room_id, f"{client_id} 离开了房间"
        )
```

### 第 29 讲 生命周期事件与测试

#### 概念

FastAPI 应用有启动和关闭的生命周期。在启动时，常需要初始化资源（数据库连接池、Redis 连接、机器学习模型加载、定时任务启动）；在关闭时，需要释放资源（关闭连接池、停止定时任务、清理临时文件）。FastAPI 提供了 `lifespan` 机制来管理这些生命周期事件。同时，测试是保证代码质量的关键，FastAPI 提供了 `TestClient` 工具，可以方便地对 API 进行集成测试，无需启动真实服务器。本讲讲解生命周期管理和 API 测试的完整方法。

#### 原理

FastAPI 推荐使用 `lifespan` 上下文管理器（基于 `@asynccontextmanager`）管理生命周期。`lifespan` 是一个异步生成器函数，`yield` 之前的代码在应用启动时执行，`yield` 之后的代码在应用关闭时执行。这种方式替代了旧的 `@app.on_event("startup")` 和 `@app.on_event("shutdown")` 装饰器（虽然旧方式仍支持，但官方推荐 `lifespan`）。

`lifespan` 接收一个 `FastAPI` 应用参数，通过 `FastAPI(lifespan=lifespan)` 注册。在 `yield` 前，可以访问 `app.state` 存储全局对象（如数据库连接池），在路由中通过 `request.app.state` 访问。

测试方面，FastAPI 的 `TestClient` 基于 `httpx`，它在不启动真实 HTTP 服务器的情况下模拟请求，直接调用 ASGI 应用。`TestClient` 的 API 类似 `requests`，支持 `get`、`post`、`put`、`delete` 等方法，返回 `Response` 对象。对于异步测试，可以使用 `httpx.AsyncClient` 配合 `pytest-asyncio`。测试时通常需要覆盖依赖（如使用测试数据库），通过 `app.dependency_overrides` 实现。

#### 例子

生命周期管理：

```python
from contextlib import asynccontextmanager
from fastapi import FastAPI, Request
import redis.asyncio as redis

@asynccontextmanager
async def lifespan(app: FastAPI):
    # ===== 启动时执行 =====
    print("应用启动中...")

    # 初始化 Redis 连接池
    app.state.redis = redis.ConnectionPool.from_url("redis://localhost")
    print("Redis 连接池已创建")

    # 加载机器学习模型（示例）
    # app.state.model = load_model("model.pkl")
    print("模型已加载")

    # 启动定时任务等...

    yield  # 应用运行期间

    # ===== 关闭时执行 =====
    print("应用关闭中...")

    # 关闭 Redis 连接池
    await app.state.redis.disconnect()
    print("Redis 连接已关闭")

    # 清理资源...

app = FastAPI(lifespan=lifespan)

@app.get("/cache/{key}")
async def get_cache(key: str, request: Request):
    # 通过 app.state 访问启动时初始化的资源
    r = redis.Redis(connection_pool=request.app.state.redis)
    value = await r.get(key)
    return {"key": key, "value": value}
```

- 测试覆盖率建议达到 80% 以上，关键业务逻辑应 100% 覆盖。

### 第 30 讲 项目部署与最佳实践

#### 概念

经过前 29 讲的学习，你已经掌握了 FastAPI 的核心知识。最后一讲聚焦于将 FastAPI 应用部署到生产环境，以及开发过程中的最佳实践。部署涉及 ASGI 服务器配置（Uvicorn/Gunicorn）、容器化（Docker）、反向代理（Nginx）、环境配置管理、日志收集、监控告警等。最佳实践涵盖项目结构、配置管理、安全加固、性能优化、代码规范等方面。掌握这些内容，才能构建出真正可上线、可维护的生产级 FastAPI 应用。

#### 原理

FastAPI 是一个 ASGI 框架，需要 ASGI 服务器运行。开发环境用 `uvicorn`（单进程），生产环境推荐 `gunicorn` + `uvicorn` worker：Gunicorn 作为进程管理器，管理多个 Uvicorn worker 进程，每个 worker 是独立的 ASGI 应用实例，充分利用多核 CPU。worker 数量一般设为 `CPU 核心数 * 2 + 1`。

容器化部署是现代应用的标准方式。Docker 将应用及其依赖打包成镜像，保证环境一致性。FastAPI 应用的 Dockerfile 通常基于 `python:slim` 镜像，安装依赖，复制代码，启动命令为 `gunicorn` + `uvicorn` worker。

生产架构通常是：客户端 → Nginx（反向代理，处理 TLS、静态文件、负载均衡）→ Gunicorn/Uvicorn（应用服务器）→ FastAPI 应用。Nginx 负责 TLS 终止、请求缓冲、静态文件服务、限流等，Gunicorn 负责进程管理和并发。

配置管理推荐使用 `pydantic-settings`（Pydantic v2 的设置管理库），它支持从环境变量、`.env` 文件读取配置，并提供类型校验和默认值。

1. **实践项目**：选择一个真实需求（如博客系统、电商 API、聊天应用），综合运用所学知识。
2. **深入源码**：阅读 FastAPI 和 Starlette 的源码，理解框架底层机制。
3. **生态拓展**：学习 Alembic（数据库迁移）、Celery（任务队列）、GraphQL（Strawberry）、gRPC 等。
4. **性能优化**：学习性能分析工具（py-spy）、缓存策略（Redis）、数据库优化（索引、查询优化）。
5. **云原生**：学习 Kubernetes、服务网格（Istio）、可观测性（OpenTelemetry）。
