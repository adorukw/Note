# 第一章：Godot 入门基础

## 第 1 讲：Godot 简介与环境搭建

### 概念

Godot（发音类似 "Goh-doh"）是一款免费、开源、跨平台的游戏引擎，由 Juan Linietsky 和 Ariel Manzur 于 2007 年发起，2014 年在 MIT 许可证下正式开源。它采用一体化的设计理念，将 2D 与 3D 引擎、编辑器、脚本语言、动画工具、物理系统等全部打包在一个不到 100MB 的可执行文件中，无需安装即可运行。Godot 支持导出到 Windows、macOS、Linux、Android、iOS、Web 等几乎所有主流平台，是独立游戏开发者和学习者的理想选择。

### 原理

Godot 的架构核心是「节点（Node）」与「场景（Scene）」的组合。每一个游戏元素——无论是精灵、角色、摄像机还是 UI 按钮——都是一个节点；多个节点组合成树状结构就构成场景；场景又可以嵌套，形成复杂的游戏世界。这种设计借鉴了面向对象思想中的组合模式：你不需要写庞大的类继承体系，而是通过组合不同功能的小节点来构建复杂对象。

Godot 内置了多种脚本语言绑定，其中官方主推的 **GDScript** 是专为游戏开发设计的高级语言，语法类似 Python，与引擎 API 深度集成，运行效率在脚本语言中表现优秀。此外还支持通过 GDExtension 使用 C++、Rust 等语言编写高性能模块。

引擎采用场景树驱动的游戏循环：每一帧，引擎从根节点开始，自上而下调用每个节点的 `_process()`（常规帧逻辑）和 `_physics_process()`（物理帧逻辑），再自下而上处理渲染与信号回调，形成完整的帧生命周期。

### 例子

**安装步骤（以 Windows 为例）：**

1. 访问官网 `https://godotengine.org/download`
2. 下载 Godot 4.x 的标准版（Standard 版含 .NET 支持，若不用 C# 可下载普通版）
3. 解压后得到一个单独的可执行文件 `Godot_v4.x-stable_win64.exe`
4. 无需安装，双击即可运行

**验证安装——创建第一个项目：**

打开 Godot 后，你会看到项目管理器。点击「新建项目」，选择一个空文件夹作为项目路径，渲染器选择「Forward+」（默认，适合大多数 3D 游戏；纯 2D 可选「Compatibility」以获得更好兼容性），点击「编辑」即可进入主编辑器。

**第一个 GDScript 脚本（Hello Godot）：**

在场景中创建一个 `Label` 节点，保存场景为 `main.tscn`，然后为根节点附加脚本 `main.gd`：

```gdscript
extends Node2D

func _ready():
    print("Hello, Godot!")
    $Label.text = "欢迎来到 Godot 世界"

func _process(delta):
    # 每帧让 Label 轻微浮动
    $Label.position.y += sin(Time.get_ticks_msec() * 0.003) * 0.5
```

按 `F5` 运行项目，你会看到窗口中显示「欢迎来到 Godot 世界」，并且文字会上下轻微浮动。

### 总结

- Godot 是一款轻量、开源、跨平台的一体化游戏引擎，无需安装，开箱即用
- 核心架构是「节点 + 场景」的组合模式，强调组合优于继承
- 官方主推 GDScript 脚本语言，语法简洁，与引擎深度集成
- 安装只需下载一个可执行文件，适合快速上手和教学
- **注意事项**：务必从官网下载，避免第三方修改版；初学者建议使用 Godot 4.x 标准版；渲染器选择上，2D 项目可选 Compatibility，3D 项目默认 Forward+

## 第 2 讲：编辑器界面与项目结构

### 概念

Godot 编辑器是一个集成式开发环境，集场景编辑、脚本编写、资源管理、调试预览于一体。理解编辑器的布局和项目目录结构，是高效开发的基础。一个 Godot 项目由「项目文件（`.godot/` 配置目录）+ 资源文件（场景、脚本、图片、音频等）+ 项目配置（`project.godot`）」三部分组成。

### 原理

Godot 编辑器采用四区布局：

1. **场景面板（左上）**：显示当前场景的节点树，可在此添加、删除、重排节点
2. **文件系统面板（左下）**：以树形结构展示项目 `res://` 目录下的所有资源文件
3. **中央视口**：2D/3D 场景的可视化编辑区域，支持拖拽、缩放、对齐
4. **检查器面板（右侧）**：显示并编辑当前选中节点或资源的属性
5. **底部面板**：可切换显示输出、调试器、动画编辑器、音频混音器等

Godot 的资源路径以 `res://` 开头，代表项目根目录。所有资源（图片、场景、脚本）都通过 `res://` 路径引用，这使得项目具有完全的可移植性——把整个项目文件夹复制到另一台电脑，路径不会失效。

项目配置文件 `project.godot` 是一个 INI 格式的文本文件，记录了项目名称、主场景、输入映射、显示设置、渲染选项等所有项目级配置。理解这个文件有助于版本控制和团队协作。

### 例子

**推荐的项目目录结构：**

```
my_game/
├── project.godot          # 项目配置文件
├── icon.svg               # 默认图标
├── scenes/                # 场景文件
│   ├── main.tscn
│   ├── player.tscn
│   └── enemy.tscn
├── scripts/               # 脚本文件
│   ├── player.gd
│   └── enemy.gd
├── assets/                # 美术与音频资源
│   ├── sprites/
│   ├── audio/
│   └── fonts/
└── .godot/                # 引擎自动生成的配置缓存（勿手动修改）
```

**在代码中引用资源：**

```gdscript
# 加载图片纹理
var texture = load("res://assets/sprites/player.png")

# 实例化另一个场景
var enemy_scene = preload("res://scenes/enemy.tscn")
var enemy = enemy_scene.instantiate()
add_child(enemy)
```

**`preload` 与 `load` 的区别：**

- `preload`：编译时加载，资源路径必须是常量字符串，加载发生在脚本解析阶段
- `load`：运行时加载，路径可以是变量，适合动态加载

**设置主场景：**

在菜单「项目 → 项目设置 → 应用 → 运行 → 主场景」中选择 `main.tscn`，这样按 `F5` 运行时就会自动加载该场景作为游戏入口。

### 总结

- 编辑器采用四区布局：场景面板、文件系统、视口、检查器，底部为多功能面板
- 项目资源以 `res://` 为根路径引用，保证项目可移植性
- `project.godot` 是核心配置文件，记录所有项目级设置
- 推荐按 `scenes/`、`scripts/`、`assets/` 分类组织文件，保持项目整洁
- **注意事项**：`.godot/` 目录是引擎自动生成的，不要手动修改或提交到版本控制；`preload` 比 `load` 更高效，能用 `preload` 就优先使用

## 第 3 讲：场景与节点系统

### 概念

**节点（Node）** 是 Godot 中最基本的构建单元，每个节点代表一个具体功能：显示图片（`Sprite2D`）、播放音效（`AudioStreamPlayer`）、检测碰撞（`Area2D`）等。**场景（Scene）** 是节点的有序集合，以树状结构组织，拥有一个根节点和若干子节点。场景可以保存为 `.tscn` 文件，也可以被其他场景实例化引用——这是 Godot 最强大的特性之一：**场景即预制体（Prefab）**。

### 原理

Godot 的节点系统遵循几个核心原则：

1. **树状结构**：每个节点只能有一个父节点，但可以有多个子节点。整个游戏世界就是一棵以 `SceneTree` 为根的节点树。
2. **生命周期回调**：引擎在特定时机自动调用节点的回调函数：
   - `_ready()`：节点进入场景树后调用一次，用于初始化
   - `_process(delta)`：每帧调用，用于常规逻辑（如移动、动画）
   - `_physics_process(delta)`：物理帧调用（默认 60 次/秒），用于物理相关逻辑
   - `_input(event)`：收到输入事件时调用
3. **继承与组合**：节点通过类继承获得功能（如 `CharacterBody2D` 继承自 `CollisionObject2D`），通过组合（添加子节点）扩展能力。
4. **场景嵌套**：一个场景可以作为另一个场景的子节点实例化，形成「场景中的场景」，实现模块化复用。

节点的名称（`name`）在同级中必须唯一，可以通过 `$NodeName` 或 `get_node("NodeName")` 访问子节点。`$` 是 `get_node` 的语法糖，`$Player/Sprite` 等价于 `get_node("Player/Sprite")`。

### 例子

**创建一个玩家场景：**

1. 新建场景，根节点选择 `CharacterBody2D`，命名为 `Player`
2. 添加子节点 `Sprite2D`（用于显示角色图片）
3. 添加子节点 `CollisionShape2D`（用于碰撞检测，形状选矩形）
4. 添加子节点 `Camera2D`（跟随玩家的摄像机）
5. 保存为 `player.tscn`

节点树结构：
```
Player (CharacterBody2D)
├── Sprite2D
├── CollisionShape2D
└── Camera2D
```

**在主场景中实例化玩家：**

```gdscript
extends Node2D

var player_scene = preload("res://player.tscn")

func _ready():
    var player = player_scene.instantiate()
    player.position = Vector2(400, 300)
    add_child(player)
    print("玩家已生成于：", player.position)
```

**节点访问与生命周期演示：**

```gdscript
extends Node2D

func _ready():
    # 访问子节点
    var sprite = $Sprite2D
    sprite.modulate = Color.RED  # 将精灵染红
    
    # 访问父节点
    var parent = get_parent()
    print("父节点：", parent.name)
    
    # 延迟调用
    call_deferred("delayed_action")

func _process(delta):
    # 每帧旋转 1 弧度/秒
    rotation += delta

func delayed_action():
    print("延迟执行的动作")
```

### 总结

- 节点是 Godot 的基本单元，场景是节点的树状集合，场景可嵌套实例化
- 核心生命周期回调：`_ready()`、`_process()`、`_physics_process()`、`_input()`
- 通过 `$NodeName` 语法糖快速访问子节点，路径用 `/` 分隔
- 场景即预制体，是 Godot 模块化开发的核心思想
- **注意事项**：节点名在同级必须唯一；`_ready()` 中访问子节点是安全的（子节点先于父节点 ready）；避免在 `_process()` 中做重计算，会影响帧率

## 第 4 讲：GDScript 基础语法

### 概念

**GDScript** 是 Godot 专属的高级脚本语言，专为游戏开发设计。它采用类似 Python 的缩进式语法，去掉了分号和大括号，同时保留了静态类型提示、面向对象特性与信号机制。GDScript 与引擎 API 无缝集成，无需额外绑定层，运行效率在脚本语言中表现优秀，是 Godot 开发的首选语言。

### 原理

GDScript 的设计哲学是「简洁但不简陋」：

1. **缩进即作用域**：使用 Tab 或空格缩进（推荐 Tab）表示代码块，无需 `{}`
2. **动态类型 + 可选静态类型**：默认动态类型，可添加类型提示提升性能与可读性
3. **信号是一等公民**：内置 `signal` 关键字声明自定义信号，支持观察者模式
4. **工具脚本（@tool）**：可在编辑器中运行脚本，实时预览效果
5. **协程与 await**：通过 `await` 实现异步等待，简化异步逻辑

GDScript 的变量作用域清晰：函数内声明的变量是局部变量，类级变量（在函数外声明）是成员变量。`@onready` 修饰符用于在 `_ready()` 前延迟初始化节点引用，`@export` 用于在检查器中暴露变量。

### 例子

**变量与数据类型：**

```gdscript
extends Node

# 动态类型变量
var score = 0
var player_name = "Hero"

# 静态类型变量（推荐）
var health: int = 100
var speed: float = 250.0
var is_alive: bool = true
var position: Vector2 = Vector2.ZERO

# 常量
const MAX_HEALTH = 100
const GRAVITY = 980.0

# 在检查器中暴露
@export var jump_force: float = 400.0
@export var move_speed: float = 200.0

# 延迟初始化节点引用
@onready var sprite = $Sprite2D
```

**函数与控制流：**

```gdscript
func _ready():
    var result = calculate_damage(50, 0.5)
    print("造成伤害：", result)
    
    # 条件语句
    if health <= 0:
        die()
    elif health < 30:
        print("危险！")
    else:
        print("状态良好")
    
    # 循环
    for i in range(5):
        print("第", i, "次循环")
    
    var enemies = ["goblin", "orc", "troll"]
    for enemy in enemies:
        attack(enemy)

# 带类型提示与默认值的函数
func calculate_damage(base: int, multiplier: float = 1.0) -> int:
    return int(base * multiplier)

func die() -> void:
    is_alive = false
    queue_free()  # 从场景树中删除该节点
```

**类与继承：**

```gdscript
# enemy.gd
class_name Enemy
extends CharacterBody2D

@export var max_health: int = 50
var current_health: int

func _ready():
    current_health = max_health

func take_damage(amount: int) -> void:
    current_health -= amount
    if current_health <= 0:
        die()

func die() -> void:
    queue_free()
```

```gdscript
# boss.gd —— 继承自 Enemy
extends Enemy

@export var phase: int = 1

func take_damage(amount: int) -> void:
    # 调用父类方法
    super.take_damage(amount)
    if current_health < max_health * 0.5 and phase == 1:
        phase = 2
        print("Boss 进入第二阶段！")
```

**信号与 await：**

```gdscript
extends Node

signal health_changed(new_value: int)
signal died

var health: int = 100

func _ready():
    # 连接信号
    health_changed.connect(_on_health_changed)
    died.connect(_on_died)

func take_damage(amount: int):
    health -= amount
    health_changed.emit(health)
    if health <= 0:
        died.emit()

func _on_health_changed(new_value: int):
    print("血量变化：", new_value)

func _on_died():
    print("角色死亡")

# await 异步等待
async func delayed_print():
    await get_tree().create_timer(2.0).timeout
    print("2秒后打印")
```

### 总结

- GDScript 语法类似 Python，缩进表示作用域，无需分号和大括号
- 支持动态类型与可选静态类型，推荐使用类型提示提升性能与可读性
- `@export` 暴露变量到检查器，`@onready` 延迟初始化节点引用
- 信号机制实现观察者模式，`await` 简化异步逻辑
- `class_name` 声明全局类，`extends` 实现继承，`super` 调用父类方法
- **注意事项**：缩进必须统一（Tab 或空格不能混用）；`queue_free()` 是安全删除节点的方式；类型提示不会强制运行时检查，但能优化性能；`@tool` 脚本会在编辑器中运行，注意副作用

# 第二章：核心系统

## 第 5 讲：节点与场景树深入

### 概念

在上一讲中我们初步接触了节点与场景。本讲将深入探讨 **场景树（SceneTree）** 的运行机制、节点的分组管理、节点间通信的最佳实践，以及 `SceneTree` 单例的常用功能。理解这些内容，才能编写出结构清晰、易于维护的游戏代码。

### 原理

**场景树的生命周期顺序**是一个关键知识点。当节点被添加到场景树时，引擎按以下顺序执行：

1. **子节点先于父节点**调用 `_enter_tree()` 和 `_ready()`
2. `_enter_tree()`：节点刚进入场景树时调用（可能在 `_ready()` 之前多次调用，如果节点被移除再添加）
3. `_ready()`：节点及其所有子节点都进入场景树后调用一次
4. `_process(delta)` / `_physics_process(delta)`：每帧/物理帧调用
5. `_exit_tree()`：节点即将离开场景树时调用

**节点分组（Groups）** 是一种广播机制。你可以给节点添加标签（如 `"enemies"`、`"collectibles"`），然后通过 `get_tree().call_group("enemies", "take_damage", 50)` 一次性调用组内所有节点的方法。这比手动遍历子节点更高效。

**节点间通信的三种方式**：
1. **直接引用**：通过 `$` 或 `get_node()` 访问——耦合度高，不推荐跨层级使用
2. **信号**：松耦合，发送方不需要知道接收方是谁——推荐方式
3. **事件总线 / 单例**：全局通信，适合跨场景传递数据

**SceneTree 单例**提供了全局功能：暂停游戏（`paused`）、切换场景（`change_scene_to_file()`）、创建定时器（`create_timer()`）、获取节点组等。

### 例子

**生命周期演示：**

```gdscript
extends Node2D

func _enter_tree():
    print(name, "：进入场景树")

func _ready():
    print(name, "：准备就绪")
    # 此时所有子节点已 ready

func _exit_tree():
    print(name, "：离开场景树")

func _process(delta):
    pass  # 每帧调用
```

**节点分组管理：**

```gdscript
# 在编辑器中或代码中添加节点到分组
func _ready():
    add_to_group("enemies")
    add_to_group("destructible")

# 全局调用组内方法
func explode_all():
    get_tree().call_group("enemies", "take_damage", 100)
    
# 获取组内所有节点
func count_enemies() -> int:
    return get_tree().get_nodes_in_group("enemies").size()
```

**单例（Autoload）实现全局事件总线：**

首先在「项目设置 → Autoload」中注册脚本 `globals.gd`，类名为 `EventBus`：

```gdscript
# globals.gd
extends Node

signal player_died
signal score_changed(new_score: int)

var player_score: int = 0

func add_score(amount: int):
    player_score += amount
    score_changed.emit(player_score)
```

在任何脚本中都可以直接使用：

```gdscript
# player.gd
func die():
    EventBus.player_died.emit()
    queue_free()

# ui.gd
func _ready():
    EventBus.score_changed.connect(_update_score_label)
    EventBus.player_died.connect(_show_game_over)

func _update_score_label(new_score):
    $ScoreLabel.text = "分数：" + str(new_score)
```

**场景切换：**

```gdscript
func _on_level_completed():
    # 切换到下一关
    get_tree().change_scene_to_file("res://scenes/level_2.tscn")

func _on_quit_pressed():
    get_tree().quit()

func _pause_game():
    get_tree().paused = true  # 暂停所有节点的 _process

func _resume_game():
    get_tree().paused = false
```

### 总结

- 场景树生命周期：子节点先 ready，`_enter_tree()` → `_ready()` → `_process()` → `_exit_tree()`
- 节点分组实现广播通信，`call_group()` 批量调用组内方法
- 节点间通信优先使用信号（松耦合），跨场景通信使用 Autoload 单例
- `SceneTree` 单例提供场景切换、暂停、定时器等全局功能
- **注意事项**：`_ready()` 只调用一次，但 `_enter_tree()` 可能多次调用；暂停游戏时设置 `process_mode` 为 `PROCESS_MODE_WHEN_PAUSED` 的节点仍会运行；Autoload 单例在游戏启动时自动创建，适合做全局管理器

## 第 6 讲：信号系统（Signal）

### 概念

**信号（Signal）** 是 Godot 实现观察者模式的核心机制。一个节点可以「发出（emit）」信号，其他节点可以「连接（connect）」到该信号并响应。信号实现了发送方与接收方的解耦——发送方不需要知道谁在监听，接收方也不需要轮询状态变化。这是 Godot 推荐的节点间通信方式，也是 UI 系统的基础。

### 原理

信号的工作原理基于「发布-订阅」模式：

1. **声明信号**：在脚本中用 `signal` 关键字声明，可带参数
2. **发出信号**：用 `signal_name.emit(args)` 触发，所有连接的回调都会被调用
3. **连接信号**：用 `signal_name.connect(callable)` 注册回调函数
4. **断开连接**：用 `signal_name.disconnect(callable)` 移除回调

Godot 4 对信号系统做了重大改进：
- 信号现在是一等对象，可以直接用 `.connect()` 和 `.emit()` 操作
- 连接时传入 `Callable` 对象，支持绑定参数（`bind()`）
- 支持一次性连接（`CONNECT_ONE_SHOT`）和延迟连接（`CONNECT_DEFERRED`）

所有节点都内置了一些常用信号，如 `Button.pressed`、`Area2D.body_entered`、`Timer.timeout` 等。在编辑器中，节点的「节点」标签页会列出所有可用信号，可以可视化连接到目标方法。

### 例子

**自定义信号：**

```gdscript
extends Node2D

# 声明信号（可带参数）
signal health_changed(new_health: int, max_health: int)
signal died

var health: int = 100
var max_health: int = 100

func take_damage(amount: int):
    health = max(0, health - amount)
    # 发出信号
    health_changed.emit(health, max_health)
    if health == 0:
        died.emit()

func heal(amount: int):
    health = min(max_health, health + amount)
    health_changed.emit(health, max_health)
```

**连接信号（代码方式）：**

```gdscript
extends Node2D

@onready var player = $Player

func _ready():
    # 方式1：连接到本对象的方法
    player.health_changed.connect(_on_player_health_changed)
    player.died.connect(_on_player_died)
    
    # 方式2：带绑定参数
    player.died.connect(_log_event.bind("玩家阵亡"))

func _on_player_health_changed(new_hp: int, max_hp: int):
    print("血量：", new_hp, "/", max_hp)
    $UI/HealthBar.value = float(new_hp) / max_hp * 100

func _on_player_died():
    print("游戏结束")
    get_tree().reload_current_scene()

func _log_event(message: String):
    print("[事件] ", message)
```

**连接内置信号（编辑器方式）：**

在编辑器中选中 `Button` 节点，切换到「节点」面板 →「信号」，双击 `pressed()` 信号，选择目标节点和方法，编辑器会自动生成：

```gdscript
func _on_button_pressed():
    print("按钮被点击了！")
```

**一次性连接与延迟连接：**

```gdscript
func _ready():
    # 一次性连接：触发一次后自动断开
    $TutorialBanner.closed.connect(_start_game, CONNECT_ONE_SHOT)
    
    # 延迟连接：在帧末尾触发，避免在物理回调中修改场景树
    $EnemySpawner.spawned.connect(_on_enemy_spawned, CONNECT_DEFERRED)

func _start_game():
    print("教程结束，游戏开始")

func _on_enemy_spawned(enemy):
    print("敌人生成：", enemy.name)
```

**信号链示例——UI 按钮触发场景切换：**

```gdscript
# main_menu.gd
extends Control

signal start_game_requested

func _ready():
    $VBoxContainer/StartButton.pressed.connect(_on_start_pressed)
    $VBoxContainer/QuitButton.pressed.connect(_on_quit_pressed)

func _on_start_pressed():
    start_game_requested.emit()

func _on_quit_pressed():
    get_tree().quit()
```

```gdscript
# main.gd
extends Node2D

func _ready():
    var menu = preload("res://scenes/main_menu.tscn").instantiate()
    add_child(menu)
    menu.start_game_requested.connect(_start_game)

func _start_game():
    get_tree().change_scene_to_file("res://scenes/level_1.tscn")
```

### 总结

- 信号是 Godot 的观察者模式实现，实现发送方与接收方解耦
- 声明用 `signal`，发出用 `.emit()`，连接用 `.connect(Callable)`
- Godot 4 中信号是一等对象，支持绑定参数、一次性连接、延迟连接
- 所有节点都有内置信号（如 `Button.pressed`、`Area2D.body_entered`）
- **注意事项**：信号连接不需要手动断开——当节点被 `queue_free()` 时，相关连接自动清除；避免在信号回调中直接 `queue_free()` 发送方节点，可能导致后续回调出错，可用 `call_deferred()` 包装；编辑器连接信号会自动生成 `_on_节点名_信号名` 格式的方法

## 第 7 讲：输入系统

### 概念

Godot 的输入系统支持键盘、鼠标、手柄、触摸等多种输入设备，并通过「输入动作（Input Action）」抽象层将物理输入映射为游戏逻辑动作。开发者定义 `move_left`、`jump` 等动作，绑定具体的按键，代码中只检测动作状态，无需关心具体按键。这种设计让游戏天然支持多设备和自定义按键。

### 原理

Godot 输入系统分为两层：

1. **底层输入事件（InputEvent）**：每次按键、移动鼠标都会产生一个 `InputEvent` 对象，通过 `_input(event)` 或 `_unhandled_input(event)` 回调接收
2. **高层输入动作（Input Action）**：在项目设置中定义动作名，绑定一个或多个物理输入，通过 `Input.is_action_pressed()` 等方法查询

**输入回调的执行顺序**（从先到后）：
1. `_input(event)`：所有节点都会收到，适合全局处理
2. `_gui_input(event)`：UI 控件专用
3. `_shortcut_input(event)`：快捷键处理
4. `_unhandled_input(event)`：未被前面消费的事件，适合游戏逻辑

**输入状态查询方法**：
- `Input.is_action_pressed("jump")`：当前是否按住
- `Input.is_action_just_pressed("jump")`：本帧刚按下（边沿触发）
- `Input.is_action_just_released("jump")`：本帧刚释放
- `Input.get_vector("move_left", "move_right", "move_up", "move_down")`：获取方向向量（已归一化）

**输入动作定义**：在「项目设置 → 输入映射」中添加动作，绑定按键/手柄按钮/鼠标按键。一个动作可绑定多个输入，实现「WASD 和方向键都能移动」。

### 例子

**定义输入动作（项目设置中）：**

| 动作名 | 绑定按键 |
|--------|---------|
| `move_left` | A, ← |
| `move_right` | D, → |
| `move_up` | W, ↑ |
| `move_down` | S, ↓ |
| `jump` | Space |
| `attack` | 鼠标左键, J |

**2D 角色移动（CharacterBody2D）：**

```gdscript
extends CharacterBody2D

@export var speed: float = 300.0

func _physics_process(delta):
    # 获取方向向量（自动归一化）
    var direction = Input.get_vector(
        "move_left", "move_right", "move_up", "move_down"
    )
    velocity = direction * speed
    move_and_slide()

func _unhandled_input(event):
    if event.is_action_pressed("jump"):
        jump()
    if event.is_action_pressed("attack"):
        attack()

func jump():
    print("跳跃！")

func attack():
    print("攻击！")
```

**`_input` 与 `_unhandled_input` 的区别：**

```gdscript
extends Node2D

# _input：所有输入都会触发，包括 UI 已处理的
func _input(event):
    if event is InputEventMouseButton and event.pressed:
        print("鼠标点击（_input）")

# _unhandled_input：只有未被 UI 消费的输入才触发
func _unhandled_input(event):
    if event is InputEventMouseButton and event.pressed:
        print("鼠标点击（_unhandled_input）")
        # 适合处理游戏世界点击，UI 点击不会到达这里
```

**处理鼠标位置与拖拽：**

```gdscript
extends Node2D

var dragging = false
var offset = Vector2.ZERO

@onready var sprite = $Sprite2D

func _unhandled_input(event):
    if event is InputEventMouseButton:
        if event.pressed and sprite.get_rect().has_point(to_local(event.position)):
            dragging = true
            offset = sprite.position - to_local(event.position)
        elif not event.pressed:
            dragging = false
    
    elif event is InputEventMouseMotion and dragging:
        sprite.position = to_local(event.position) + offset

func to_local(global_pos: Vector2) -> Vector2:
    return global_pos - global_position
```

**手柄输入检测：**

```gdscript
func _process(delta):
    # 检测手柄左摇杆
    var joy_vector = Input.get_vector(
        "joy_left", "joy_right", "joy_up", "joy_down"
    )
    if joy_vector.length() > 0.1:
        print("摇杆方向：", joy_vector)
    
    # 检测手柄震动
    Input.start_joy_vibration(0, 0.5, 0.5, 0.3)  # 设备0，弱震0.5，强震0.5，持续0.3秒
```

### 总结

- 输入系统分两层：底层 `InputEvent` 事件 + 高层 `Input Action` 动作抽象
- 输入回调顺序：`_input` → `_gui_input` → `_unhandled_input`，游戏逻辑优先用 `_unhandled_input`
- `Input.get_vector()` 一次获取四方向输入并自动归一化，是移动控制的推荐方式
- 在项目设置中定义动作并绑定多设备输入，实现跨设备支持
- **注意事项**：`is_action_just_pressed()` 在 `_physics_process` 中检测更可靠；UI 按钮会自动消费输入，不会传递到 `_unhandled_input`；手柄索引从 0 开始，多手柄需遍历 `Input.get_connected_joypads()`

## 第 8 讲：资源系统（Resource）

### 概念

**资源（Resource）** 是 Godot 中用于存储数据的对象，与节点（Node）不同，资源不参与场景树，而是被节点引用。图片纹理、音频流、字体、材质、动画、自定义配置等都是资源。资源可以被保存为 `.tres`（文本格式）或 `.res`（二进制格式）文件，在多个场景间共享复用。理解资源系统是构建数据驱动游戏的关键。

### 原理

Resource 的核心特性：

1. **数据容器**：Resource 继承自 `RefCounted`，采用引用计数管理内存，无需手动释放
2. **序列化**：Resource 可保存为文件，下次加载时自动反序列化，支持嵌套引用
3. **共享引用**：多个节点引用同一个 Resource 实例时，修改会影响所有引用者（除非 `duplicate()`）
4. **@export 暴露**：Resource 的属性可通过 `@export` 暴露到检查器，实现可视化编辑

**加载方式**：
- `preload("res://path.tres")`：编译时加载，路径必须是常量
- `load("res://path.tres")`：运行时加载，路径可以是变量
- `ResourceLoader.load_threaded()`：异步加载，适合大资源避免卡顿

**自定义 Resource** 是数据驱动设计的核心。例如，定义一个 `ItemData` 资源类存储道具信息，策划可以在检查器中创建和编辑道具数据，无需修改代码。

### 例子

**自定义 Resource 类（道具数据）：**

```gdscript
# item_data.gd
class_name ItemData
extends Resource

@export var name: String = "未知道具"
@export var icon: Texture2D
@export var description: String = ""
@export var stackable: bool = false
@export var max_stack: int = 99
@export var value: int = 0
@export var rarity: String = "common"

func use(player) -> bool:
    print("使用了：", name)
    return true
```

**在编辑器中创建 Resource 实例：**

1. 在文件系统面板右键 →「新建 Resource」
2. 选择 `ItemData` 类型
3. 保存为 `sword.tres`
4. 在检查器中编辑属性（名称、图标、描述等）

**在代码中加载和使用 Resource：**

```gdscript
extends Node2D

# 预加载道具资源
var sword_data = preload("res://resources/items/sword.tres")
var potion_data = preload("res://resources/items/potion.tres")

var inventory: Array[ItemData] = []

func _ready():
    inventory.append(sword_data)
    inventory.append(potion_data)
    inventory.append(potion_data.duplicate())  # 复制一份，避免共享引用
    
    print_inventory()

func print_inventory():
    for item in inventory:
        print("- ", item.name, " (价值：", item.value, ")")
```

**动态创建 Resource：**

```gdscript
func create_random_loot() -> ItemData:
    var loot = ItemData.new()
    loot.name = "随机宝箱"
    loot.value = randi_range(10, 100)

    return loot

func _ready():

```

**异步加载大资源：**

```gdscript

    ResourceLoader.load_threaded_request(path)

func _process(delta):
    var status = ResourceLoader.load_threaded_get_status("res://scenes/level_2.tscn")
    if status == ResourceLoader.THREAD_LOAD_LOADED:

        get_tree().change_scene_to_packed(level)

```

**Resource 作为配置文件：**

```gdscript
# game_config.gd
class_name GameConfig
extends Resource

@export var master_volume: float = 1.0
@export var music_volume: float = 0.8
@export var sfx_volume: float = 1.0
@export var fullscreen: bool = false
@export var language: String = "zh_CN"
```

```gdscript
    ResourceSaver.save(config, "user://config.tres")

```

> **提示**：`user://` 路径指向用户数据目录（不同于 `res://` 项目目录），适合保存玩家存档和配置，导出后仍可读写。

### 总结

- Resource 是数据容器，不参与场景树，被节点引用，采用引用计数管理内存
- 可序列化为 `.tres`（文本）或 `.res`（二进制）文件，在多场景间共享
- `preload` 编译时加载，`load` 运行时加载，`ResourceLoader.load_threaded` 异步加载
- 自定义 Resource 配合 `@export` 实现数据驱动设计，策划可在检查器编辑数据
- `user://` 路径用于保存玩家数据（存档、配置），导出后可读写
- **注意事项**：Resource 是共享引用，修改会影响所有引用者，需要独立副本时用 `duplicate()`；`preload` 只能用于常量路径；大资源（如大场景、大纹理）建议异步加载避免卡顿；`ResourceSaver.save()` 保存到 `res://` 在导出后会失败，只能保存到 `user://`

# 第三章：2D 游戏开发

## 第 9 讲：2D 节点与精灵

### 概念

Godot 的 2D 系统提供了一整套节点用于构建 2D 游戏：`Sprite2D`（精灵）、`AnimatedSprite2D`（动画精灵）、`CharacterBody2D`（角色物理体）、`RigidBody2D`（刚体）、`StaticBody2D`（静态体）、`Area2D`（区域检测）等。本讲聚焦于最基础的视觉节点——精灵，以及 2D 坐标系、变换（Transform）等核心概念，这是所有 2D 游戏的视觉基础。

### 原理

**2D 坐标系**：Godot 的 2D 坐标系以屏幕左上角为原点（0,0），X 轴向右为正，Y 轴向下为正（注意与数学坐标系不同）。每个 2D 节点都有 `position`（位置）、`rotation`（旋转，弧度制）、`scale`（缩放）三个基本变换属性，组合成 `transform`（变换矩阵）。

**节点继承体系**：
```
Node2D（2D 基类，提供变换）
├── Sprite2D（显示单张图片）
├── AnimatedSprite2D（播放帧动画）
├── Camera2D（2D 摄像机）
├── CollisionObject2D（可碰撞物体基类）
│   ├── Area2D（区域检测，无物理响应）
│   ├── StaticBody2D（静态物体，如墙壁）
│   ├── RigidBody2D（受物理力影响的刚体）
│   └── CharacterBody2D（角色控制器，手动控制移动）
└── ...
```

**Sprite2D 工作原理**：`Sprite2D` 通过 `texture` 属性引用一张图片纹理，可选 `region_enabled` 裁剪显示区域，或 `hframes`/`vframes` 将精灵图集（Sprite Sheet）切分为多帧。`centered` 控制是否以图片中心为锚点，`offset` 微调偏移。

**AnimatedSprite2D** 通过 `SpriteFrames` 资源管理多个动画，每个动画包含若干帧和帧率，适合角色行走、攻击等帧动画。

### 例子

**Sprite2D 基本使用：**

```gdscript
extends Sprite2D

func _ready():
    # 加载纹理（也可在检查器中拖入）
    texture = load("res://assets/sprites/player.png")
    centered = true
    # 切分精灵图集（4列3行）
    hframes = 4
    vframes = 3
    frame = 0  # 显示第一帧

func _process(delta):
```

## 第 10 讲：动画系统（AnimationPlayer）

### 概念

Godot 提供了强大的动画系统，核心节点是 `AnimationPlayer`。它可以动画化几乎所有属性：节点位置、旋转、缩放、颜色、纹理、甚至调用函数。与 `AnimatedSprite2D`（仅限帧动画）不同，`AnimationPlayer` 是通用动画工具，支持关键帧、补间、动画混合、状态机等高级功能。Godot 4 还引入了 `AnimationTree` 用于复杂动画状态管理。

### 原理

**AnimationPlayer 工作原理**：

1. **动画（Animation）** 是一个 Resource，包含多条轨道（Track）
2. **轨道（Track）** 分为属性轨道（动画化属性值）、方法轨道（在特定时间调用函数）、音频轨道（播放音效）等
3. **关键帧（Key）** 定义某时间点的值，引擎自动在关键帧间插值
4. **播放控制**：`play("name")`、`play_backwards("name")`、`stop()`、`pause()`

**插值模式**：
- `INTERPOLATION_LINEAR`：线性插值（默认）
- `INTERPOLATION_NEAREST`：无插值，直接跳变
- `INTERPOLATION_CUBIC`：三次贝塞尔，更平滑

**动画过渡**：`play("attack", 0.2)` 的第二个参数是淡入淡出时间（秒），实现动画间平滑过渡。

**AnimationTree** 在 AnimationPlayer 之上提供状态机（State Machine）和混合树（Blend Tree），适合角色动画的复杂状态切换（如走→跑→跳的平滑过渡）。

**Tween（补间动画）** 是轻量级动画工具，适合一次性动画（如 UI 弹出、物体移动），无需创建 Animation 资源。

### 例子

**创建 AnimationPlayer 动画（编辑器方式）：**

1. 添加 `AnimationPlayer` 节点
2. 点击「动画」→「新建」，命名为 `bounce`
3. 时长设为 1 秒，开启循环
4. 选中 `Sprite2D`，在检查器右键 `position` →「插入关键帧」
5. 在 0 秒处设置 position 为 (400, 300)，0.5 秒处设为 (400, 200)，1 秒处回到 (400, 300)

**代码控制 AnimationPlayer：**

```gdscript

func _physics_process(delta):

        else:
            play_animation("idle")
    else:

            play_animation("jump")
        else:
            play_animation("fall")

func play_animation(anim_name: String):
    if anim_player.current_animation != anim_name:
        # 0.15秒过渡时间
        anim_player.play(anim_name, 0.15)

func attack():
    anim_player.play("attack")
    # 等待动画播放完毕
    await anim_player.animation_finished
    anim_player.play("idle")
```

**AnimationTree 状态机（角色动画）：**

1. 添加 `AnimationTree` 节点
2. 设置 `anim_player` 属性指向 AnimationPlayer
3. `tree_root` 选择 `AnimationNodeStateMachine`
4. 添加状态节点（对应 AnimationPlayer 中的动画）
5. 连接状态，设置过渡条件

```gdscript

    anim_tree.set("parameters/conditions/is_moving", direction != 0)

        state_machine.travel("idle")
```

### 总结

- `AnimationPlayer` 是通用动画工具，支持属性、方法、音频等多类型轨道
- 动画由关键帧组成，引擎自动插值，支持线性、最近邻、三次贝塞尔插值
- `play(name, fade_time)` 实现动画间平滑过渡
- `AnimationTree` 提供状态机和混合树，适合复杂角色动画
- `Tween` 是轻量级补间动画，适合一次性效果（UI 弹出、移动等）
- **注意事项**：`await animation_finished` 需确保动画非循环；Tween 默认顺序执行，`set_parallel(true)` 可并行；AnimationTree 的 `travel()` 会自动寻找最短路径过渡；动画轨道路径格式为 `NodePath:property`，如 `.:position` 表示自身位置

## 第 11 讲：物理引擎与碰撞

### 概念

Godot 2D 物理引擎基于自研的物理系统，提供刚体模拟、碰撞检测、射线检测等功能。物理节点分为四类：`StaticBody2D`（静态体，如墙壁地板）、`RigidBody2D`（刚体，受力和重力影响）、`CharacterBody2D`（角色体，手动控制移动）、`Area2D`（区域，仅检测不阻挡）。每个物理体都需要 `CollisionShape2D` 子节点定义碰撞形状。

### 原理

**碰撞层与掩码（Layer & Mask）**：Godot 支持 32 个物理层。每个物体设置自己所在的层（Layer），以及它会与哪些层碰撞（Mask）。例如：玩家在层 1，敌人在层 2，子弹在层 3；玩家掩码设为 2（与敌人碰撞），子弹掩码设为 2（击中敌人），但子弹层 3 不与玩家层 1 碰撞。

**碰撞形状（CollisionShape2D）**：
- `RectangleShape2D`：矩形，最常用，性能最好
- `CircleShape2D`：圆形，适合球类
- `CapsuleShape2D`：胶囊形，适合角色
- `ConvexPolygonShape2D`：凸多边形
- `ConcavePolygonShape2D`：凹多边形（仅静态体）

**CharacterBody2D 移动原理**：不同于 RigidBody2D 受物理力驱动，CharacterBody2D 通过设置 `velocity` 并调用 `move_and_slide()` 或 `move_and_collide()` 手动移动。`move_and_slide()` 会自动处理斜坡滑动和碰撞响应，是角色控制的首选。

**Area2D 检测信号**：
- `body_entered(body)`：物理体进入区域
- `body_exited(body)`：物理体离开区域
- `area_entered(area)`：另一个 Area2D 进入
- `area_exited(area)`：另一个 Area2D 离开

**射线检测（RayCast2D）**：从一点向某方向发射射线，返回第一个击中的物体，常用于视线检测、地面检测、瞄准等。

### 例子

**CharacterBody2D 平台跳跃角色：**

- `Area2D` 通过 `body_entered`/`body_exited` 信号检测物体进出
- `RayCast2D` 用于射线检测，适合视线、地面、瞄准检测
- **注意事项**：碰撞形状要略小于视觉精灵，避免「卡边」；`move_and_slide()` 自动应用 delta，不要手动乘；RigidBody2D 不要直接设置 `position`，用 `linear_velocity` 或 `apply_impulse()`；Area2D 的 `monitoring` 必须开启才能检测

## 第 12 讲：摄像机与视差背景

### 概念

`Camera2D` 是 2D 游戏的摄像机节点，控制玩家看到的视野范围。它支持跟随目标、平滑移动、缩放、限制边界等功能。视差背景（Parallax Background）则通过多层背景以不同速度滚动，营造空间纵深感，是横版游戏的标配技术。本讲讲解摄像机配置与视差背景的实现。

### 原理

**Camera2D 工作原理**：场景中可以有多个 Camera2D，但同一时刻只有一个「当前摄像机」（`current = true`）生效。摄像机跟随自身位置移动，因此通常将 Camera2D 作为角色子节点，或通过代码同步位置。`Camera2D` 的关键属性：

- `position_smoothing_enabled` + `position_smoothing_speed`：平滑跟随
- `zoom`：缩放（大于 1 放大，小于 1 缩小）
- `limit_left/right/top/bottom`：限制摄像机移动边界
- `offset`：偏移量（如让角色偏左，给右侧更多视野）
- `drag_horizontal_enabled` / `drag_vertical_enabled`：边缘拖拽（角色不动时摄像机才移动）

**视差背景原理**：`ParallaxBackground` 节点包含一个或多个 `ParallaxLayer`。每个层设置 `motion_scale`（滚动速度比例）：远景层 scale 小（如 0.2，移动慢），近景层 scale 大（如 1.0，与摄像机同步）。层还可以设置 `motion_mirroring` 实现无限平铺重复。

**摄像机震动**：通过 Tween 或随机偏移实现，增强打击感和爆炸效果。

### 例子

**基础跟随摄像机：**

```gdscript
# player.gd
extends CharacterBody2D

func _ready():
    $Camera2D.make_current()  # 设为当前摄像机
    $Camera2D.position_smoothing_enabled = true
    $Camera2D.position_smoothing_speed = 5.0
    $Camera2D.zoom = Vector2(2, 2)  # 放大2倍（像素风游戏常用）
```

**限制摄像机边界（防止看到地图外）：**

```gdscript
    limit_top = 0
    limit_right = 2000
```

**摄像机震动效果：**

```gdscript
extends Camera2D

var shake_amount: float = 0.0
var original_offset: Vector2

func _ready():
    original_offset = offset

func shake(intensity: float, duration: float):
    shake_amount = intensity
    var tween = create_tween()

    if shake_amount > 0:
```

**视差背景实现：**

节点结构：
```
ParallaxBackground
├── ParallaxLayer (远景天空)
│   └── Sprite2D (天空图)
├── ParallaxLayer (中景山脉)
│   └── Sprite2D (山脉图)
└── ParallaxLayer (近景树木)
    └── Sprite2D (树木图)
```

每个 `ParallaxLayer` 的属性设置：

| 层 | motion_scale | motion_mirroring |
|----|-------------|------------------|
| 远景天空 | (0.1, 0.1) | (0, 0) 不重复 |
| 中景山脉 | (0.3, 0.3) | (1024, 0) 水平重复 |
| 近景树木 | (0.6, 0.6) | (512, 0) 水平重复 |

```gdscript
# 代码设置视差层
extends ParallaxBackground

func _ready():
    var far_layer = $FarLayer
    far_layer.motion_scale = Vector2(0.1, 0.1)
    # 无限水平重复
    far_layer.motion_mirroring = Vector2(1920, 0)
    
    var near_layer = $NearLayer
    near_layer.motion_scale = Vector2(0.6, 0.6)
    near_layer.motion_mirroring = Vector2(512, 0)
```

**摄像机跟随带前瞻偏移（角色面朝方向多给视野）：**

```gdscript
extends Camera2D

@onready var player = get_parent()
var look_ahead: float = 0.0
var target_offset: float = 0.0

func _process(delta):
    # 根据角色朝向调整偏移
    var direction = sign(player.velocity.x)
    if direction != 0:
        target_offset = direction * 100  # 朝向方向偏移100像素
    
    # 平滑过渡
    look_ahead = lerp(look_ahead, target_offset, delta * 3)
    offset.x = look_ahead
```

### 总结

- `Camera2D` 控制 2D 视野，`make_current()` 设为当前摄像机，`position_smoothing` 实现平滑跟随
- `limit_*` 属性限制摄像机边界，防止看到地图外区域
- `zoom` 大于 1 放大画面（像素风常用），小于 1 缩小
- `ParallaxBackground` + `ParallaxLayer` 实现视差滚动，`motion_scale` 控制滚动速度，`motion_mirroring` 实现无限平铺
- 摄像机震动通过随机偏移实现，增强打击感
- **注意事项**：像素风游戏建议设置 `Project Settings → Rendering → Texture → Canvas Textures → Default Texture Filter` 为 Nearest，避免缩放模糊；`Camera2D` 作为角色子节点时，角色旋转会导致画面旋转，可设置 `rotating = false`；视差层的 `motion_mirroring` 值应等于背景图宽度

# 第四章：3D 游戏开发

## 第 13 讲：3D 节点与模型导入

### 概念

Godot 的 3D 系统与 2D 类似，但引入了三维空间坐标、网格（Mesh）、材质（Material）、骨骼动画等概念。核心 3D 节点包括 `Node3D`（3D 基类）、`MeshInstance3D`（网格实例）、`Camera3D`（3D 摄像机）、`DirectionalLight3D`（方向光）、`CharacterBody3D`（3D 角色控制器）等。Godot 支持导入 glTF 2.0（推荐）、OBJ、FBX 等主流 3D 模型格式，glTF 是 Web 时代的 3D 模型标准，Godot 对其支持最为完善。

### 原理

**3D 坐标系**：Godot 3D 使用右手坐标系——X 轴向右，Y 轴向上，Z 轴向外（朝向观察者）。这与许多引擎（如 Unity 的左手系）不同，需特别注意。`Vector3` 用于表示 3D 向量，`Transform3D` 表示 3D 变换（位置 + 旋转 + 缩放）。

**3D 节点继承体系**：
```
Node3D（3D 基类，提供变换）
├── MeshInstance3D（渲染网格）
├── Camera3D（3D 摄像机）
├── Light3D（灯光基类）
│   ├── DirectionalLight3D（方向光，模拟太阳）
│   ├── OmniLight3D（点光源）
│   └── SpotLight3D（聚光灯）
├── CollisionObject3D（可碰撞物体基类）
│   ├── Area3D（区域检测）
│   ├── StaticBody3D（静态体）
│   ├── RigidBody3D（刚体）
│   └── CharacterBody3D（角色控制器）
└── ...
```

**网格与材质**：`MeshInstance3D` 通过 `mesh` 属性引用网格资源。网格定义几何形状（顶点、三角形），材质定义外观（颜色、纹理、着色器）。Godot 4 默认使用 `StandardMaterial3D`，支持 PBR（基于物理的渲染）工作流：反照率（Albedo）、金属度（Metallic）、粗糙度（Roughness）、法线贴图（Normal）等。

**模型导入流程**：将 `.gltf`/`.glb` 文件拖入项目目录，Godot 自动生成 `.import` 配置和导入资源。可在「导入」面板中配置动画、材质、网格选项，然后重新导入。

### 例子

**创建基础 3D 场景：**

1. 新建场景，根节点选 `Node3D`
2. 添加 `Camera3D`，位置设为 (0, 2, 5)，旋转 X 设为 -15 度
3. 添加 `DirectionalLight3D`，旋转设为 (-45, -30, 0)
4. 添加 `MeshInstance3D`，网格选 `New BoxMesh`，大小 (2, 2, 2)

**3D 角色移动（CharacterBody3D）：**

```gdscript
extends CharacterBody3D

@export var speed: float = 5.0
@export var jump_velocity: float = 4.5
@export var gravity: float = 9.8

func _physics_process(delta):
    # 重力
    if not is_on_floor():
        velocity.y -= gravity * delta
    
    # 跳跃
    if Input.is_action_just_pressed("jump") and is_on_floor():
        velocity.y = jump_velocity
    
    # 获取输入方向（基于摄像机方向）
    var input_dir = Input.get_vector("move_left", "move_right", "move_forward", "move_back")
    var direction = (transform.basis * Vector3(input_dir.x, 0, input_dir.y)).normalized()
    
    if direction:
        velocity.x = direction.x * speed
        velocity.z = direction.z * speed
        # 角色朝向移动方向
        var look_pos = global_position + direction
        look_at(Vector3(look_pos.x, global_position.y, look_pos.z))
    else:
        velocity.x = move_toward(velocity.x, 0, speed)
        velocity.z = move_toward(velocity.z, 0, speed)
    
    move_and_slide()
```

### 总结

- Godot 3D 使用右手坐标系：X 右、Y 上、Z 外（朝向观察者）
- `Node3D` 是 3D 基类，`MeshInstance3D` 渲染网格，`Camera3D` 是摄像机
- 推荐 glTF 2.0 格式导入模型，Godot 自动生成场景和网格资源
- `StandardMaterial3D` 支持 PBR 工作流：反照率、金属度、粗糙度、法线贴图
- `CharacterBody3D` 配合 `move_and_slide()` 实现 3D 角色控制
- **注意事项**：3D 模型面数过多会影响性能，注意 LOD（细节层次）优化；导入 FBX 可能需要先转为 glTF；`SurfaceTool` 用于程序化生成网格，`ImmediateMesh` 适合动态调试绘制

## 第 14 讲：3D 物理与碰撞

### 概念

3D 物理系统与 2D 类似，提供 `StaticBody3D`、`RigidBody3D`、`CharacterBody3D`、`Area3D` 四类物理体，以及 `CollisionShape3D` 定义碰撞形状。3D 碰撞形状包括 `BoxShape3D`、`SphereShape3D`、`CapsuleShape3D`、`CylinderShape3D`、`ConvexPolygonShape3D`、`ConcavePolygonShape3D` 和 `HeightMapShape3D`（地形）。本讲讲解 3D 物理体的使用、碰撞层配置与射线检测。

### 原理

**3D 碰撞形状选择原则**：
- `BoxShape3D`：盒子，性能最好，适合简单物体
- `SphereShape3D`：球体，适合球类，碰撞响应最平滑
- `CapsuleShape3D`：胶囊，适合人形角色（站立时）
- `CylinderShape3D`：圆柱，适合柱子、桶
- `ConvexPolygonShape3D`：凸多边形，适合复杂但凸的物体
- `ConcavePolygonShape3D`：凹多边形，仅用于静态体（如地形、建筑），性能较差
- `HeightMapShape3D`：高度图，用于地形

**CharacterBody3D 与 RigidBody3D 的区别**：
- `CharacterBody3D`：不受物理力驱动，通过 `velocity` + `move_and_slide()` 手动控制，适合玩家角色
- `RigidBody3D`：受重力、力、冲量驱动，适合可推动的物体、投掷物

**3D 射线检测**：`RayCast3D` 节点持续检测一条射线，`PhysicsRayQueryParameters3D` 用于一次性查询。3D 还支持 `ShapeCast3D`（形状射线）和 `Area3D`（区域检测）。

**碰撞信号**：
- `body_entered(body)` / `body_exited(body)`：物理体进出
- `area_entered(area)` / `area_exited(area)`：Area3D 进出

### 例子

**3D 角色控制器（含跳跃和地面检测）：**

```gdscript
@export var jump_velocity: float = 4.5

    if Input.is_action_just_pressed("jump") and is_on_floor():
        velocity.y = jump_velocity
```

**地形碰撞（HeightMapShape3D）：**

```gdscript
extends StaticBody3D

func _ready():
    # 从高度图生成碰撞形状
    var heightmap_shape = HeightMapShape3D.new()
    var width = 128
    var depth = 128
    
    # 生成高度数据（示例：正弦波地形）
    var heights = PackedFloat32Array()
    heights.resize(width * depth)
    for z in range(depth):
        for x in range(width):
            var h = sin(x * 0.1) * cos(z * 0.1) * 5.0
            heights[z * width + x] = h
    
    heightmap_shape.map_width = width
    heightmap_shape.map_depth = depth
    heightmap_shape.map_data = heights
    
    var collision_shape = CollisionShape3D.new()
    collision_shape.shape = heightmap_shape
    add_child(collision_shape)
```

- 3D 物理体四类：`StaticBody3D`、`RigidBody3D`、`CharacterBody3D`、`Area3D`
- 碰撞形状按需选择：简单用 Box/Sphere，角色用 Capsule，地形用 HeightMap
- `CharacterBody3D` 手动控制移动，`RigidBody3D` 受物理力驱动
- `RayCast3D` 持续检测，`intersect_ray()` 一次性查询，适合点击检测、视线检测
- `Area3D` 作为触发器，检测物体进出，适合拾取、区域事件
- **注意事项**：凹多边形形状只能用于静态体；`move_and_slide()` 在 3D 中默认包含地面检测，`is_on_floor()` 可判断是否着地；RigidBody3D 不要直接设置 `position`，用 `linear_velocity` 或 `apply_impulse()`；射线检测的 `exclude` 参数可排除自身避免误检

## 第 15 讲：光照与材质

### 概念

光照与材质是 3D 游戏视觉表现的核心。Godot 4 的 Forward+ 渲染器支持实时全局光照（GI）、阴影、PBR 材质、HDR、泛光（Bloom）等高级效果。光照类型包括方向光（模拟太阳）、点光源（灯泡）、聚光灯（手电筒）。材质系统基于 PBR（基于物理的渲染），通过反照率、金属度、粗糙度等参数模拟真实世界材质外观。

### 原理

**光照类型**：
- `DirectionalLight3D`：方向光，模拟无限远的平行光（太阳），所有光线方向一致，无衰减
- `OmniLight3D`：点光源，从一点向四面八方发射，有距离衰减
- `SpotLight3D`：聚光灯，锥形光束，有范围和角度限制

**阴影**：光源开启 `shadow_enabled` 后，物体会投射阴影。阴影质量通过 `directional_shadow_mode`（方向光）或 `shadow_normal_bias` 调整。阴影是性能开销大户，需谨慎使用。

**全局光照（GI）**：
- `VoxelGI`：体素 GI，实时动态 GI，适合中小场景
- `SDFGI`：有符号距离场 GI，半实时，适合户外大场景
- `BakedLightmap`：烘焙光照贴图，离线计算，性能最好但无法动态变化

**PBR 材质参数**（`StandardMaterial3D`）：
- `albedo_color` / `albedo_texture`：基础颜色
- `metallic`：金属度（0=非金属，1=纯金属）
- `roughness`：粗糙度（0=镜面光滑，1=完全粗糙）
- `emission`：自发光（不受光照影响）
- `normal_texture`：法线贴图（模拟表面凹凸）
- `orm_texture`：AO（环境光遮蔽）/粗糙度/金属度合一贴图

**环境光（Environment）**：通过 `WorldEnvironment` 节点配置，包含天空、雾、泛光、色调映射、SSAO（屏幕空间环境光遮蔽）等全局效果。

- `WorldEnvironment` 配置天空、雾、泛光、色调映射等全局效果
- 阴影是性能开销大户，按需开启，调整 `shadow_max_distance` 控制范围
- **注意事项**：移动端建议用烘焙光照，避免实时阴影；`Forward+` 渲染器支持最多 8 个实时阴影投射光源；`Compatibility` 渲染器功能受限但兼容性好；法线贴图能极大提升细节但增加显存；`emission` 不受光照影响，适合做发光物体

## 第 16 讲：3D 摄像机控制

### 概念

3D 游戏的摄像机比 2D 复杂得多，涉及视角控制（第一人称/第三人称）、碰撞处理、平滑跟随等。`Camera3D` 提供 `fov`（视场角）、`near`/`far`（裁剪面）、`projection`（透视/正交）等属性。本讲讲解三种常见摄像机模式：第一人称、第三人称跟随、自由观察，以及摄像机碰撞处理。

### 原理

**摄像机投影模式**：
- `PROJECTION_PERSPECTIVE`：透视投影（默认），近大远小，适合 3D 游戏
- `PROJECTION_ORTHOGONAL`：正交投影，无透视变形，适合 2.5D 或等距视角

**FOV（视场角）**：默认 75 度。增大 FOV（如 90）视野更广但边缘变形，适合 FPS；减小 FOV（如 45）视野窄但压缩感强，适合远景展示。

**摄像机跟随策略**：
1. **直接跟随**：摄像机位置 = 目标位置 + 偏移，简单但生硬
2. **平滑跟随**：用 `lerp()` 或 `position_smoothing` 平滑过渡
3. **弹簧臂（SpringArm）**：`SpringArm3D` 节点自动处理摄像机碰撞，第三人称游戏首选

**摄像机碰撞**：第三人称摄像机可能穿墙，需要检测摄像机与墙壁的碰撞，将摄像机拉近角色。`SpringArm3D` 内置此功能。

**鼠标控制视角**：捕获鼠标（`Input.mouse_mode = MOUSE_MODE_CAPTURED`），根据鼠标移动旋转摄像机，按 ESC 释放鼠标。

### 例子

```gdscript
        spring_arm.rotation.x -= event.relative.y * mouse_sensitivity
        spring_arm.rotation.x = clamp(spring_arm.rotation.x, -PI/3, PI/3)
        rotation.y -= event.relative.x * mouse_sensitivity

func _physics_process(delta):
    # 基于摄像机方向移动
    var input_dir = Input.get_vector("move_left", "move_right", "move_forward", "move_back")
    var direction = (spring_arm.transform.basis * Vector3(input_dir.x, 0, input_dir.y)).normalized()
    direction.y = 0

    velocity.z = direction.z * speed

        # 角色朝向移动方向
```

**自由观察摄像机（策略游戏/编辑器风格）：**

```gdscript
extends Camera3D

@export var move_speed: float = 20.0
@export var rotate_speed: float = 0.005
@export var zoom_speed: float = 5.0

func _unhandled_input(event):
    # 鼠标右键拖拽旋转
    if event is InputEventMouseMotion and Input.is_mouse_button_pressed(MOUSE_BUTTON_RIGHT):
        rotate_y(-event.relative.x * rotate_speed)
        rotate_x(-event.relative.y * rotate_speed)
        rotation.x = clamp(rotation.x, -PI/2, PI/2)

func _process(delta):
    # WASD 移动
    var input_dir = Input.get_vector("move_left", "move_right", "move_back", "move_forward")
    var direction = (transform.basis * Vector3(input_dir.x, 0, input_dir.y)).normalized()
    global_position += direction * move_speed * delta
    
    # QE 上下移动
    if Input.is_action_pressed("move_up"):
        global_position.y += move_speed * delta
    if Input.is_action_pressed("move_down"):
        global_position.y -= move_speed * delta
    
    # 滚轮缩放（调整 FOV）
    var wheel = Input.get_axis("zoom_in", "zoom_out")
    if wheel != 0:
        fov = clamp(fov + wheel * zoom_speed, 20, 120)

func _input(event):
    if event is InputEventMouseButton:
        if event.button_index == MOUSE_BUTTON_WHEEL_UP:
            fov = clamp(fov - zoom_speed, 20, 120)
        elif event.button_index == MOUSE_BUTTON_WHEEL_DOWN:
            fov = clamp(fov + zoom_speed, 20, 120)
```

- `Camera3D` 支持 `fov`（视场角）、`near`/`far`（裁剪面）、透视/正交投影
- 第一人称：摄像机在角色头部，鼠标控制视角，限制俯仰角
- 第三人称：用 `SpringArm3D` 自动处理摄像机碰撞，避免穿墙
- 自由观察：WASD 移动 + 鼠标旋转 + 滚轮缩放，适合策略游戏
- `Input.mouse_mode = MOUSE_MODE_CAPTURED` 捕获鼠标，`MOUSE_MODE_VISIBLE` 释放
- **注意事项**：FOV 过大会导致边缘变形，FPS 建议 75-90，TPS 建议 60-75；`SpringArm3D` 的 `collision_mask` 需正确设置才能检测墙壁；摄像机脚本建议用 `_unhandled_input` 而非 `_input`，避免与 UI 冲突；3D 摄像机震动用 3D 随机偏移

## 第 17 讲：UI 系统（Control 节点）

### 概念

Godot 的 UI 系统基于 `Control` 节点家族，提供按钮、标签、文本框、滚动条、容器等丰富的界面控件。与 2D/3D 节点不同，Control 节点拥有「锚点（Anchor）」和「边距（Margin）」系统，能根据屏幕尺寸自动调整布局，实现响应式 UI。本讲讲解常用 UI 控件、布局容器、主题系统，以及如何构建游戏菜单、HUD、对话框等界面。

### 原理

**Control 节点的布局系统**：

1. **锚点（Anchor）**：定义控件四个边相对于父容器的参考位置（0~1）。例如左上角锚点 (0,0,0,0) 表示控件相对于父容器左上角；全屏锚点 (0,0,1,1) 表示控件随父容器拉伸
2. **边距（Offset/Margin）**：控件四边与锚点的距离（像素）。锚点+边距共同决定控件位置和大小
3. **容器（Container）**：自动排列子控件的 Control 节点，如 `HBoxContainer`（水平排列）、`VBoxContainer`（垂直排列）、`GridContainer`（网格）、`MarginContainer`（留边距）

**常用 Control 节点**：
- `Label`：文本标签
- `Button`：按钮，发出 `pressed` 信号
- `TextureButton`：图片按钮
- `LineEdit`：单行输入框
- `TextEdit`：多行文本编辑
- `ProgressBar`：进度条
- `TextureProgressBar`：图片进度条（血条常用）
- `OptionButton`：下拉选择框
- `CheckBox` / `CheckButton`：复选框
- `Slider`（`HSlider`/`VSlider`）：滑块

**主题（Theme）**：`Theme` 资源统一管理 UI 的字体、颜色、样式。可设置全局默认主题，也可为单个控件覆盖。主题让 UI 风格保持一致，便于换肤。

**UI 信号**：Control 节点有丰富的内置信号，如 `Button.pressed`、`LineEdit.text_changed`、`Slider.value_changed`，通过信号连接实现交互逻辑。

## 第 18 讲：音频系统

### 概念

Godot 的音频系统通过 `AudioStreamPlayer`（非空间音频）、`AudioStreamPlayer2D`（2D 空间音频）、`AudioStreamPlayer3D`（3D 空间音频）三种节点播放声音。音频资源（AudioStream）支持 `.wav`（无损，适合短音效）、`.ogg`（压缩，适合背景音乐）、`.mp3`（压缩）等格式。音频总线（Bus）系统提供音量控制、效果链（混响、均衡器等）和分组管理。

### 原理

**三种音频播放器**：
- `AudioStreamPlayer`：非空间音频，全场景均匀播放，适合 BGM、UI 音效
- `AudioStreamPlayer2D`：2D 空间音频，根据距离屏幕中心衰减，适合 2D 游戏环境音
- `AudioStreamPlayer3D`：3D 空间音频，根据距离和方向衰减，支持多普勒效应，适合 3D 游戏

**音频总线（Bus）**：每个总线是一个音频通道，可挂载效果（如 Reverb、EQ、Compressor）。默认有 `Master` 总线，可自定义 `Music`、`SFX`、`Voice` 等总线，分别控制音量。播放器通过 `bus` 属性指定输出总线。

**AudioStream 类型**：
- `AudioStreamWAV`：WAV 格式，无压缩，加载快，适合频繁播放的短音效
- `AudioStreamOggVorbis`：OGG 格式，压缩，适合长背景音乐，支持流式播放
- `AudioStreamMP3`：MP3 格式，压缩
- `AudioStreamRandomPitch`：包装其他流，随机变调，避免音效重复单调

**音量单位**：Godot 使用分贝（dB）表示音量，`0 dB` 为原始音量，`-6 dB` 约为一半音量，`-80 dB` 几乎静音。`linear_to_db()` 和 `db_to_linear()` 可在线性值（0~1）和分贝间转换。

```gdscript

    if bus_idx >= 0:
        AudioServer.set_bus_volume_db(bus_idx, linear_to_db(linear_volume))

        return db_to_linear(AudioServer.get_bus_volume_db(bus_idx))
    return 0.0

func mute_bus(bus_name: String, muted: bool):
    var bus_idx = AudioServer.get_bus_index(bus_name)
    if bus_idx >= 0:
        AudioServer.set_bus_mute(bus_idx, muted)

# 使用示例
func _on_volume_slider_changed(value):
    AudioManager.set_bus_volume("Master", value)
```

**淡入淡出音乐切换：**

```gdscript
extends Node

@onready var music_player = $MusicPlayer

func play_music_with_fade(stream: AudioStream, fade_duration: float = 1.0):
    # 淡出当前音乐
    var fade_out = create_tween()
    fade_out.tween_property(music_player, "volume_db", -40, fade_duration)
    
    # 淡出完成后切换并淡入
    fade_out.tween_callback(func():
        music_player.stream = stream
        music_player.volume_db = -40
        music_player.play()
    )
    
    var fade_in = create_tween()
    fade_in.tween_interval(fade_duration)  # 等待淡出完成
    fade_in.tween_property(music_player, "volume_db", 0, fade_duration)
```

### 总结

- 三种音频播放器：`AudioStreamPlayer`（非空间）、`AudioStreamPlayer2D`（2D）、`AudioStreamPlayer3D`（3D）
- WAV 适合短音效，OGG 适合背景音乐，MP3 兼容性好
- 音频总线（Bus）分组管理音量和效果，默认有 `Master` 总线
- 音量用分贝（dB），`linear_to_db()` / `db_to_linear()` 转换
- 音效池避免频繁播放中断，随机变调避免单调
- **注意事项**：3D 音频需设置 `max_distance` 和衰减参数；`AudioStreamPlayer3D` 需要监听者（Camera3D）才能听到空间效果；总线效果在「音频」面板配置；移动端注意音频格式兼容性，OGG 通用性最好

## 第 19 讲：粒子系统

### 概念

粒子系统用于模拟火焰、烟雾、爆炸、雨雪、魔法特效等大量小颗粒组成的视觉效果。Godot 提供 `GPUParticles2D`（2D GPU 粒子）、`GPUParticles3D`（3D GPU 粒子）和对应的 CPU 版本（`CPUParticles2D`/`CPUParticles3D`）。GPU 粒子利用显卡并行计算，性能远超 CPU 粒子，是首选。粒子通过 `ParticleProcessMaterial` 材质配置各种参数，实现丰富的视觉效果。

### 原理

**GPU vs CPU 粒子**：
- `GPUParticles2D/3D`：使用着色器在 GPU 上计算，可同时渲染数万粒子，性能极佳
- `CPUParticles2D/3D`：在 CPU 上计算，兼容性好但粒子数受限（建议 <1000），适合低端设备

**粒子生命周期**：每个粒子从「发射」到「消亡」经历：发射 → 运动 → 衰减 → 死亡。`lifetime` 属性控制单次发射周期时长，`amount` 控制最大粒子数。

**ParticleProcessMaterial 核心参数**：
- **发射形状（Emission Shape）**：点、球体、盒子、线段等，决定粒子初始位置
- **方向与速度（Direction & Spread）**：发射方向和扩散角度
- **重力（Gravity）**：粒子受重力影响（可设为负值模拟上升烟雾）
- **初始速度（Initial Velocity）**：粒子发射时的速度
- **角速度（Angular Velocity）**：粒子旋转速度
- **线性加速度（Linear Accel）**：速度变化率
- **阻尼（Damping）**：速度衰减
- **缩放（Scale）**：粒子大小随时间变化
- **颜色（Color）**：粒子颜色，支持渐变（Color Ramp）
- **透明度（Alpha Ramp）**：淡入淡出

**一次性 vs 循环**：`emitting = true` 持续发射；设置 `one_shot = true` 则只发射一次（适合爆炸特效），配合 `finished` 信号自动删除节点。

### 例子

**3D 火焰特效：**

```gdscript
extends GPUParticles3D

func _ready():
    amount = 50
    lifetime = 1.0
    explosiveness = 0.0  # 均匀发射
    
    var material = ParticleProcessMaterial.new()
    
    # 发射形状：球体
    material.emission_shape = ParticleProcessMaterial.EMISSION_SHAPE_SPHERE
    material.emission_sphere_radius = 0.3
    
    # 方向：向上
    material.direction = Vector3(0, 1, 0)
    material.spread = 15.0  # 扩散角度
    
    # 速度与加速度
    material.initial_velocity_min = 1.0
    material.initial_velocity_max = 2.0
    material.gravity = Vector3(0, -2, 0)  # 轻微向下（火焰上升后下落）
    material.linear_accel_min = 1.0
    material.linear_accel_max = 2.0
    
    # 缩放：从大到小
    material.scale_min = 0.5
    material.scale_max = 1.0
    
    # 颜色渐变：红→橙→黄→透明
    var color_ramp = Gradient.new()
    color_ramp.add_point(0.0, Color(1, 0.2, 0, 1))  # 红
    color_ramp.add_point(0.3, Color(1, 0.5, 0, 1))  # 橙
    color_ramp.add_point(0.6, Color(1, 1, 0, 0.8))  # 黄
    color_ramp.add_point(1.0, Color(1, 1, 0.5, 0))  # 透明
    
    var gradient_texture = GradientTexture1D.new()
    gradient_texture.gradient = color_ramp
    material.color_ramp = gradient_texture
    
    process_material = material
    
    # 粒子贴图（火焰用发光球体）
    var mesh = QuadMesh.new()
    mesh.size = Vector2(0.5, 0.5)
    draw_pass_1 = mesh
```

### 总结

- `GPUParticles2D/3D` 是首选，性能远超 CPU 版本；低端设备用 `CPUParticles` 兼容

## 第 20 讲：游戏发布与导出

### 概念

完成游戏开发后，最后一步是导出为可执行文件并发布到目标平台。Godot 支持导出到 Windows、macOS、Linux、Android、iOS、Web 等平台。导出前需要配置导出模板（Export Template）、设置导出预设（Export Preset）、处理平台特定需求（如图标、权限、签名）。本讲讲解完整导出流程、跨平台注意事项，以及优化建议。

### 原理

**导出模板（Export Template）**：Godot 编辑器本身不含各平台的运行时，需单独下载导出模板。模板分「debug」（调试，含开发工具）和「release」（发布，优化性能）版本。在「编辑器 → 管理导出模板」中下载安装。

**导出预设（Export Preset）**：每个平台一个预设，配置：
- 平台特定选项（如 Android 的包名、权限）
- 资源过滤（包含/排除哪些文件）
- 脚本加密（可选，保护 GDScript 源码）
- 图标与启动画面

**PCK 与嵌入式导出**：
- **PCK 文件**：游戏资源打包为 `.pck` 文件，与可执行文件分离，便于更新
- **嵌入式**：资源嵌入可执行文件，单文件分发，适合小型游戏

**平台特定注意事项**：
- **Windows**：`.exe` + `.pck`（或嵌入式），需考虑 32/64 位
- **macOS**：`.app` 应用包，需签名和公证才能分发，注意 Apple Silicon 与 Intel 架构
- **Linux**：可执行文件 + `.pck`，注意不同发行版库依赖
- **Android**：`.apk` 或 `.aab`，需配置 SDK、签名、权限、最低 API 版本
- **iOS**：`.ipa`，需 Xcode、开发者账号、签名
- **Web**：HTML5 + WASM + `.pck`，注意跨域、全屏、文件系统限制

**代码签名与公证**：
- macOS：需 Developer ID 证书签名 + `xcrun notarytool` 公证
- Windows：可选代码签名（避免 SmartScreen 警告）
- Android：需 keystore 签名
- iOS：需 Apple 开发者证书 + Provisioning Profile

### 例子

**配置导出预设（以 Windows 为例）：**

   - 嵌入 PCK：勾选（单文件分发）

**获取用户数据路径（跨平台存档）：**

```gdscript
extends Node

func get_save_path() -> String:
    # user:// 自动映射到各平台用户数据目录
    # Windows: %APPDATA%/Godot/app_userdata/项目名
    # macOS: ~/Library/Application Support/Godot/app_userdata/项目名
    # Linux: ~/.local/share/godot/app_userdata/项目名
    # Android: /data/data/包名/files
    # iOS: App 的 Documents 目录
    # Web: localStorage（受限）
    return "user://savegame.json"

func save_game(data: Dictionary):
    var file = FileAccess.open(get_save_path(), FileAccess.WRITE)
    if file:
        file.store_string(JSON.stringify(data))
        file.close()

func load_game() -> Dictionary:
    if not FileAccess.file_exists(get_save_path()):
        return {}
    var file = FileAccess.open(get_save_path(), FileAccess.READ)
    if file:
        var text = file.get_as_text()
        file.close()
        var result = JSON.parse_string(text)
        if result is Dictionary:
            return result
    return {}
```
