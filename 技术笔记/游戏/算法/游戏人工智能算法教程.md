# 第1章 游戏AI基础

## 第1讲 游戏AI概述与发展史

### 概念

游戏人工智能（Game AI）是指在电子游戏中，用于驱动非玩家角色（NPC）、敌人、盟友、环境系统等表现出"智能"或"类智能"行为的算法与技术的总称。与学术意义上的强人工智能不同，游戏AI追求的不是真正的自我意识或通用智能，而是**在有限的计算预算内，让游戏世界看起来"活"起来，并为玩家提供有趣、有挑战性、有沉浸感的体验**。游戏AI的核心目标可以概括为三点：可信（Believable）、有趣（Fun）、可控（Controllable）。

游戏AI与学术AI的关键差异在于"目的性"。学术AI追求最优解、最高准确率；而游戏AI常常**故意"装傻"**——一个完美的FPS敌人会瞬间爆头玩家，但这毫无乐趣可言。优秀的游戏AI设计师会让NPC表现出"可被击败的智能"，例如暴露破绽、做出错误决策、表现出情绪反应，这些"不完美"恰恰是游戏体验的精髓。

### 原理

游戏AI的发展史可以划分为几个明显阶段，每个阶段都受到当时硬件能力、游戏类型演变和AI理论突破的共同推动：

**第一阶段：规则驱动时代（1970s-1980s）**。早期游戏如《Pac-Man》（1980）的幽灵AI完全基于硬编码规则——红色Blinky直接追击玩家，粉色Pinky试图绕到玩家前方，青色Inky和橙色Clyde各有不同的目标点计算逻辑。这种"目标点+寻路"的极简架构至今仍是许多休闲游戏AI的基础。这一时期的AI本质上是**有限状态机+预设规则**的组合，计算开销极低，但表现力有限。

**第二阶段：脚本与状态机时代（1990s）**。随着3D游戏兴起，《Quake》《Half-Life》等FPS游戏引入了更复杂的状态机驱动敌人AI。Half-Life的HGrunt士兵能协同作战、投掷手雷、呼叫支援，标志着"战术AI"概念的诞生。同时期RTS游戏如《Age of Empires》开始使用资源管理AI，但本质上仍是脚本化的决策树。这一阶段确立了**FSM（有限状态机）作为游戏AI工业标准**的地位。

**第三阶段：行为树与规划时代（2000s-2010s）**。Halo 2首次大规模采用行为树（Behavior Tree），彻底改变了游戏AI的工程实践。行为树相比FSM具有更好的模块化、可复用性和可扩展性，迅速成为业界主流。同时，F.E.A.R.（2005）引入了GOAP（目标导向行动规划），让NPC能根据目标动态规划行动序列，被誉为"游戏AI的里程碑"。这一阶段的核心思想是**从"反应式"AI走向"规划式"AI**。

**第四阶段：数据驱动与学习时代（2010s至今）**。随着深度学习革命，游戏AI开始引入机器学习技术。AlphaGo（2016）击败李世石标志着强化学习在棋类游戏中的统治地位；OpenAI Five（2018）在Dota 2中战胜人类冠军，展示了多智能体强化学习的潜力。然而，**商业游戏对ML的采用仍然谨慎**，主要原因是不可预测性、调试困难和性能开销。当前主流商业游戏仍以行为树+效用系统为主，ML多用于NPC动画、内容生成（PCG）等辅助领域。

### 例子

下面是一个还原《Pac-Man》幽灵AI的Python简化示例，展示了"目标点+追击"的经典模式：

```python
import numpy as np
from enum import Enum

class GhostType(Enum):
    BLINKY = "red"      # 直接追击
    PINKY = "pink"      # 追击玩家前方4格
    INKY = "cyan"       # 复杂目标点
    CLYDE = "orange"    # 远距离时随机

class Ghost:
    def __init__(self, ghost_type, start_pos):
        self.type = ghost_type
        self.pos = np.array(start_pos, dtype=float)
    
    def compute_target(self, player_pos, player_dir, blinky_pos):
        """每种幽灵有不同的目标点计算逻辑"""
        if self.type == GhostType.BLINKY:
            return player_pos.copy()
        elif self.type == GhostType.PINKY:
            # 试图绕到玩家前方4格
            return player_pos + player_dir * 4
        elif self.type == GhostType.INKY:
            # 以Blinky和玩家前方点的中点翻转
            front = player_pos + player_dir * 2
            return 2 * front - blinky_pos
        elif self.type == GhostType.CLYDE:
            dist = np.linalg.norm(self.pos - player_pos)
            if dist > 8:
                return player_pos.copy()
            else:
                return np.array([0, 0])  # 散开到角落
    
    def update(self, player_pos, player_dir, blinky_pos, maze):
        target = self.compute_target(player_pos, player_dir, blinky_pos)
        # 在4个方向中选择最接近目标点的可行方向
        best_dir = None
        best_dist = float('inf')
        for d in [(0,1),(0,-1),(1,0),(-1,0)]:
            next_pos = self.pos + np.array(d)
            if maze.is_walkable(next_pos):
                dist = np.linalg.norm(next_pos - target)
                if dist < best_dist:
                    best_dist = dist
                    best_dir = d
        if best_dir:
            self.pos += np.array(best_dir) * 0.1  # 按速度移动
```

这个例子虽然简单，但揭示了游戏AI的一个核心设计哲学：**不同的"性格"可以通过不同的目标函数实现，而不需要复杂的算法**。四个幽灵共用同一套寻路逻辑，仅目标点计算不同，就产生了截然不同的行为模式，这是"以小博大"的经典案例。

### 总结

本讲重点回顾：
- 游戏AI的目标是**可信、有趣、可控**，而非追求最优解或通用智能
- 游戏AI发展经历了**规则→状态机→行为树/规划→机器学习**四个阶段
- 经典设计哲学：**用简单的算法+差异化的参数/目标，制造丰富的行为表现**
- 商业游戏对ML的采用仍谨慎，**行为树+效用系统**是当前工业主流
- 学习游戏AI时，要始终牢记"玩家体验"是最终评价标准，而非算法的"先进性"

常见误区：初学者容易陷入"越复杂的算法越好"的陷阱，实际上一个调校良好的FSM往往比一个粗糙的神经网络提供更好的游戏体验。算法选择应匹配游戏类型、性能预算和团队能力。

## 第2讲 游戏AI的核心范式与架构

### 概念

游戏AI的"范式"指的是设计和组织AI系统的根本方法论。理解范式比掌握具体算法更重要，因为它决定了你如何思考问题、如何拆分模块、如何应对需求变化。本讲介绍游戏AI的三大核心范式：**反应式范式（Reactive）**、**审议式范式（Deliberative）** 和 **混合范式（Hybrid）**，以及支撑这些范式的典型架构模式。

一个完整的游戏AI系统通常由以下子系统组成：**感知（Perception）** 负责从游戏世界获取信息；**决策（Decision Making）** 负责根据感知信息选择行动；**运动（Movement）** 负责执行移动相关指令；**动画（Animation）** 负责将抽象行动转化为可视表现。这四个子系统通过**黑板（Blackboard）** 或 **工作记忆（Working Memory）** 共享状态，形成完整的AI闭环。

### 原理

**反应式范式**源于Rodney Brooks的"包容架构"（Subsumption Architecture），核心思想是"**不需要思考，直接反应**"。AI不维护复杂的世界模型，不进行长远规划，而是根据当前感知直接触发行为。经典的反应式系统如Braitenberg车辆，仅用简单的传感器-电机连接就能产生看似"智能"的行为。在游戏中，反应式AI常用于低级敌人、动物NPC、群体单位等。其优点是**计算开销低、响应迅速、实现简单**；缺点是**缺乏前瞻性、难以处理复杂目标、容易出现行为僵化**。

**审议式范式**则相反，强调"**先思考，再行动**"。AI维护内部世界模型，能够进行符号推理、目标规划、行动序列生成。GOAP、HTN、MCTS都属于审议式范式。审议式AI能处理复杂任务（如"潜入敌营、窃取情报、安全撤离"），但**计算开销大、调试困难、对感知准确性敏感**。在游戏中，审议式AI常用于Boss、关键剧情NPC、RTS对手等需要"显得聪明"的角色。

**混合范式（Hybrid / Three-Layer Architecture）** 是工业界的主流选择，结合两者优点。经典的三层架构包括：
- **反应层（Reactive Layer）**：处理紧急情况，如躲避子弹、闪避车辆，延迟极低
- **审议层（Deliberative Layer）**：进行战术规划、目标选择，延迟较高
- **协调层（Sequencer Layer / Executive Layer）**：管理两者切换，处理行为优先级

这种分层设计让AI既能快速反应，又能进行长远规划。例如一个FPS士兵：反应层让他被射击时立即寻找掩护；审议层让他规划"绕到玩家侧翼发起攻击"；协调层确保两者不冲突。

**架构模式**方面，现代游戏AI常用以下几种组织方式：
1. **黑板模式（Blackboard）**：所有子系统共享一个数据结构，松耦合，便于扩展
2. **事件驱动模式**：感知系统发布事件，决策系统订阅响应，适合异步处理
3. **组件化模式（ECS）**：将AI拆分为PerceptionComponent、DecisionComponent等，符合现代引擎架构
4. **服务模式（Service）**：将寻路、视线检测等通用功能封装为服务，供多个AI共享

### 例子

下面展示一个基于黑板模式的三层混合AI架构骨架（Python伪代码）：

```python
from dataclasses import dataclass, field
from typing import List, Callable
import time

@dataclass
class Blackboard:
    """共享记忆，所有AI子系统读写"""
    # 感知信息
    enemies_in_sight: List[dict] = field(default_factory=list)
    nearest_threat: dict = None
    health: float = 100.0
    ammo: int = 30
    # 决策信息
    current_goal: str = "patrol"
    planned_actions: List[str] = field(default_factory=list)
    # 运动信息
    position: tuple = (0, 0, 0)
    velocity: tuple = (0, 0, 0)

class PerceptionSystem:
    """感知层：从游戏世界获取信息"""
    def __init__(self, blackboard: Blackboard, world):
        self.bb = blackboard
        self.world = world
    
    def update(self, dt):
        # 视线检测、听觉检测、记忆更新
        self.bb.enemies_in_sight = self.world.query_visible_enemies(self.bb.position)
        self.bb.nearest_threat = min(
            self.bb.enemies_in_sight, 
            key=lambda e: e['distance'], 
            default=None
        )
        # 健康值、弹药等由游戏系统同步

class ReactiveLayer:
    """反应层：处理紧急情况，低延迟"""
    def __init__(self, blackboard: Blackboard):
        self.bb = blackboard
        self.rules = [
            # (条件, 行动, 优先级)
            (lambda: self.bb.health < 20, "flee", 100),
            (lambda: self.bb.nearest_threat and 
                    self.bb.nearest_threat['distance'] < 5, "melee_dodge", 90),
            (lambda: self.bb.ammo == 0, "reload", 80),
        ]
    
    def evaluate(self):
        """返回最高优先级的紧急行动，或None"""
        for condition, action, priority in sorted(
            self.rules, key=lambda r: -r[2]
        ):
            if condition():
                return action
        return None

class DeliberativeLayer:
    """审议层：进行战术规划"""
    def __init__(self, blackboard: Blackboard):
        self.bb = blackboard
    
    def plan(self):
        """根据当前目标生成行动序列"""
        if self.bb.current_goal == "patrol":
            return ["move_to_waypoint", "look_around", "advance"]
        elif self.bb.current_goal == "attack":
            return ["find_cover", "suppressing_fire", "flank"]
        elif self.bb.current_goal == "defend":
            return ["hold_position", "watch_chokepoint"]
        return ["idle"]

class ExecutiveLayer:
    """协调层：管理反应与审议的切换"""
    def __init__(self, blackboard, reactive, deliberative):
        self.bb = blackboard
        self.reactive = reactive
        self.deliberative = deliberative
        self.current_plan = []
        self.plan_index = 0
    
    def update(self, dt):
        # 1. 先检查反应层是否有紧急行动
        urgent = self.reactive.evaluate()
        if urgent:
            self.execute(urgent)
            return  # 紧急行动打断规划
        
        # 2. 若规划已耗尽，重新规划
        if self.plan_index >= len(self.current_plan):
            self.current_plan = self.deliberative.plan()
            self.plan_index = 0
        
        # 3. 执行当前规划步骤
        if self.current_plan:
            action = self.current_plan[self.plan_index]
            if self.execute(action):
                self.plan_index += 1
    
    def execute(self, action):
        print(f"[AI] 执行行动: {action}")
        return True  # 实际中调用运动/动画系统

# 组装完整AI
bb = Blackboard()
ai = ExecutiveLayer(bb, ReactiveLayer(bb), DeliberativeLayer(bb))

# 游戏主循环
for frame in range(100):
    ai.update(dt=0.016)
```

这个架构的关键设计点：**反应层优先级高于审议层**，确保紧急情况能立即打断规划；**黑板作为唯一数据源**，避免子系统间紧耦合；**协调层负责调度**，让两层协作而非冲突。这种模式在《Half-Life 2》《Far Cry》等游戏中都有体现。

### 总结

本讲重点回顾：
- 游戏AI三大范式：**反应式（快但浅）、审议式（深但慢）、混合式（工业主流）**
- 完整AI系统由**感知→决策→运动→动画**四层组成，通过黑板共享状态
- 三层混合架构：**反应层处理紧急、审议层处理规划、协调层管理切换**
- 常用架构模式：**黑板、事件驱动、ECS组件化、服务模式**
- 范式选择应匹配角色定位：杂兵用反应式、Boss用审议式、关键NPC用混合式

常见误区：初学者常把所有逻辑塞进决策层，导致系统臃肿、性能下降。正确做法是**让感知层做"过滤"，决策层只做"选择"**，运动层负责"执行"，各司其职。

## 第3讲 AI与游戏引擎集成

### 概念

游戏AI不是孤立运行的算法，而是嵌入在游戏引擎（Game Engine）这一庞大软件系统中的一个子系统。理解AI如何与引擎集成，是从"会写AI算法"到"能做出游戏AI"的关键一步。本讲讨论AI系统在引擎中的位置、与其它子系统的交互方式、性能优化策略，以及主流引擎（Unity、Unreal）的AI框架。

游戏引擎通常包含以下核心子系统：**渲染（Rendering）**、**物理（Physics）**、**音频（Audio）**、**动画（Animation）**、**输入（Input）**、**资源管理（Resource）**、**场景管理（Scene）** 和 **脚本（Scripting）**。AI系统需要与其中大部分交互：从场景管理获取可见物体、从物理系统获取碰撞信息、向动画系统发送动作指令、向音频系统触发音效。理解这些交互的时序和数据流，是设计高效AI的前提。

### 原理

**AI在引擎更新循环中的位置**至关重要。典型引擎每帧执行顺序为：输入处理 → 物理模拟 → AI更新 → 动画更新 → 渲染。AI放在物理之后，是因为AI需要基于最新物理状态决策；放在动画之前，是因为动画需要根据AI决策播放。但这个顺序并非绝对——某些游戏会让AI以更低频率更新（如每3帧一次），以节省性能。

**AI更新的频率优化**是性能关键。一个开放世界游戏可能有数百个NPC，如果每个NPC每帧都跑完整AI，性能将崩溃。常用策略包括：
1. **LOD-AI（Level of Detail for AI）**：远处NPC用简化AI，近处用完整AI
2. **时间分片（Time Slicing）**：将NPC分成N组，每帧只更新1/N
3. **事件触发更新**：NPC平时休眠，被感知事件唤醒后才更新
4. **层级调度**：群体级AI（如RTS）每秒更新几次，单位级AI每帧更新

**AI与动画系统的交互**通过"动作"抽象完成。AI决策输出的是抽象动作（如"攻击"、"reload"），动画系统负责将其映射到具体动画片段。现代引擎使用**动画状态机（ASM）** 或 **动画蓝图（Animation Blueprint）** 管理动画过渡。AI与动画的解耦让两者可以独立迭代——AI设计师调整决策逻辑，动画师调整表现，互不干扰。

**AI与物理系统的交互**主要体现在两方面：一是**运动执行**，AI输出的目标位置需要通过物理系统验证（避免穿墙）；二是**感知获取**，AI的视线检测、听觉检测依赖物理系统的射线检测（Raycast）。性能敏感的场景常用**简化的感知几何**（如球体碰撞）替代精确射线检测。

**主流引擎AI框架**：
- **Unity**：提供NavMesh寻路、Animator状态机、NavMesh Agent组件；第三方插件如 Behavior Designer、NodeCanvas 提供行为树
- **Unreal Engine**：内置AI Controller、Behavior Tree、Blackboard、Environment Query System（EQS）、NavMesh，是商业引擎中AI功能最完整的
- **自研引擎**：通常基于ECS架构，AI作为组件集合实现，灵活性最高但开发量大

**调试与可视化**是AI开发的命脉。优秀引擎都提供AI调试工具：行为树可视化、感知锥显示、NavMesh可视化、决策日志等。Unreal的Gameplay Debugger、Unity的Debug.DrawRay都是必备工具。**没有可视化的AI系统是无法调试的**，这是初学者常忽视的工程要点。

# 第2章 决策系统基础

## 第4讲 有限状态机（FSM）

### 概念

有限状态机（Finite State Machine, FSM）是游戏AI中最古老、最广泛使用的决策模型。它将AI的行为建模为一组**互斥的状态（State）**，AI在任一时刻只处于其中一个状态，并通过**转移（Transition）** 在状态间切换。每个状态定义了"进入时做什么"、"更新时做什么"、"退出时做什么"，转移则定义了"在什么条件下从状态A切换到状态B"。FSM的核心优势在于**直观、可预测、易调试**，是初学者入门游戏AI的最佳起点。

FSM的数学定义是一个五元组 `(Q, Σ, δ, q0, F)`：Q是有限状态集合，Σ是输入事件集合，δ是转移函数（Q×Σ→Q），q0是初始状态，F是终止状态集合。在游戏AI中，我们通常简化为三元组：**状态集合 + 转移规则 + 当前状态**。理解FSM的关键是"互斥性"——AI同一时刻只能在一个状态，这既是优点（行为清晰可预测）也是限制（难以表达并发行为）。

### 原理

FSM的工作机制可以概括为"**事件驱动的状态切换 + 状态内的持续行为**"。每个游戏帧，FSM执行两步操作：① 调用当前状态的`Update()`方法，执行该状态的持续行为（如巡逻时移动）；② 检查当前状态的所有转移条件，若某条件满足则触发转移，依次调用旧状态的`Exit()`、新状态的`Enter()`，并将当前状态切换为新状态。

**状态设计**是FSM的核心艺术。好的状态划分应遵循**MECE原则（Mutually Exclusive, Collectively Exhaustive）**——状态间互不重叠，合起来覆盖所有可能行为。常见的设计陷阱包括：状态过细（导致状态爆炸）、状态过粗（导致逻辑混杂）、状态间隐式依赖（破坏封装）。一个经验法则是：**每个状态应该能用一句话描述其目的**，如果描述不清，说明状态划分有问题。

**转移设计**有两种主要风格：① **状态内转移**——转移条件写在状态内部，状态自己决定何时退出（高内聚但耦合其他状态）；② **外部转移表**——转移规则集中管理，状态本身不知道后续状态（解耦但可读性差）。工业实践常用**混合方案**：状态提供"是否应该退出"的查询接口，外部转移表决定退出后去哪里。

**FSM的变体**包括：
- **Moore型**：输出仅依赖当前状态（行为在状态内定义）
- **Mealy型**：输出依赖状态和输入（转移时触发行为）
- **带栈的FSM**：允许"挂起"当前状态、执行子状态后恢复（HFSM的雏形）

游戏AI多用Moore型，因为行为与状态绑定更直观。

**FSM的局限性**：① **状态爆炸**——状态数随行为复杂度指数增长；② **难以复用**——状态间转移硬编码，无法跨角色复用；③ **缺乏并发**——同一时刻只能一个状态，难以表达"边移动边射击"；④ **扩展困难**——新增行为可能需要修改多个状态的转移逻辑。这些局限催生了HFSM、行为树等更高级的架构。

### 例子

下面是一个完整的FSM实现，模拟一个FPS敌人的行为（巡逻→警戒→追击→攻击→逃跑）：

```python
from abc import ABC, abstractmethod
from typing import List, Callable

class State(ABC):
    """状态基类"""
    def __init__(self, name: str):
        self.name = name
    
    @abstractmethod
    def enter(self, agent): pass
    
    @abstractmethod
    def update(self, agent, dt: float) -> str:
        """返回下一个状态名，或None表示保持当前状态"""
        pass
    
    @abstractmethod
    def exit(self, agent): pass
    
    def __repr__(self):
        return f"State({self.name})"

class PatrolState(State):
    def __init__(self):
        super().__init__("patrol")
        self.waypoints = [(0,0), (10,0), (10,10), (0,10)]
        self.current_wp = 0
    
    def enter(self, agent):
        print(f"[{agent.name}] 开始巡逻")
        agent.move_to(self.waypoints[self.current_wp])
    
    def update(self, agent, dt):
        # 到达当前路径点后切换下一个
        if agent.at_target():
            self.current_wp = (self.current_wp + 1) % len(self.waypoints)
            agent.move_to(self.waypoints[self.current_wp])
        
        # 检查转移条件
        if agent.can_see_enemy():
            return "chase"
        if agent.heard_noise():
            return "alert"
        return None
    
    def exit(self, agent):
        print(f"[{agent.name}] 停止巡逻")

class AlertState(State):
    def __init__(self):
        super().__init__("alert")
        self.timer = 0
    
    def enter(self, agent):
        print(f"[{agent.name}] 进入警戒，调查噪音")
        self.timer = 0
        agent.look_around()
    
    def update(self, agent, dt):
        self.timer += dt
        if agent.can_see_enemy():
            return "chase"
        if self.timer > 5.0:  # 5秒后恢复巡逻
            return "patrol"
        return None
    
    def exit(self, agent):
        pass

class ChaseState(State):
    def __init__(self):
        super().__init__("chase")
    
    def enter(self, agent):
        print(f"[{agent.name}] 追击敌人！")
    
    def update(self, agent, dt):
        agent.move_to(agent.enemy_position)
        
        if agent.distance_to_enemy() < agent.attack_range:
            return "attack"
        if not agent.can_see_enemy() and agent.lost_sight_timer > 3.0:
            return "alert"
        if agent.health < 20:
            return "flee"
        return None
    
    def exit(self, agent):
        pass

class AttackState(State):
    def __init__(self):
        super().__init__("attack")
        self.fire_timer = 0
    
    def enter(self, agent):
        print(f"[{agent.name}] 开火！")
        agent.stop_moving()
    
    def update(self, agent, dt):
        self.fire_timer += dt
        if self.fire_timer > 0.3:  # 每0.3秒射击一次
            agent.fire()
            self.fire_timer = 0
        
        if agent.distance_to_enemy() > agent.attack_range:
            return "chase"
        if agent.health < 20:
            return "flee"
        return None
    
    def exit(self, agent):
        pass

class FleeState(State):
    def __init__(self):
        super().__init__("flee")
    
    def enter(self, agent):
        print(f"[{agent.name}] 撤退！")
        # 朝远离敌人的方向逃跑
        agent.flee_from(agent.enemy_position)
    
    def update(self, agent, dt):
        if agent.health > 50:  # 恢复后重新参战
            return "patrol"
        if agent.distance_to_enemy() < 5:
            agent.flee_from(agent.enemy_position)
        return None
    
    def exit(self, agent):
        pass

class FSM:
    """有限状态机"""
    def __init__(self, initial_state: State):
        self.states = {initial_state.name: initial_state}
        self.current_state = initial_state
        self.current_state.enter(None)  # 假设agent稍后传入
    
    def add_state(self, state: State):
        self.states[state.name] = state
    
    def update(self, agent, dt):
        next_state_name = self.current_state.update(agent, dt)
        if next_state_name and next_state_name != self.current_state.name:
            self.transition_to(next_state_name, agent)
    
    def transition_to(self, state_name, agent):
        old_state = self.current_state
        new_state = self.states[state_name]
        old_state.exit(agent)
        self.current_state = new_state
        new_state.enter(agent)
        print(f"[{agent.name}] {old_state.name} -> {new_state.name}")

# 组装FSM
fsm = FSM(PatrolState())
fsm.add_state(AlertState())
fsm.add_state(ChaseState())
fsm.add_state(AttackState())
fsm.add_state(FleeState())

# 游戏主循环
# for frame in range(1000):
#     fsm.update(agent, dt=0.016)
```

这个FSM清晰地表达了五种行为模式及其切换条件。注意每个状态的`update`方法只关心"何时退出"和"退出后去哪"，状态内的具体行为（移动、射击）委托给agent执行，实现了**决策与执行的分离**。

### 总结

本讲重点回顾：
- FSM = **状态集合 + 转移规则 + 当前状态**，AI任一时刻只在一个状态
- 状态设计遵循**MECE原则**，每个状态能用一句话描述目的
- 转移设计两种风格：**状态内转移（高内聚）** 和 **外部转移表（解耦）**
- FSM优势：**直观、可预测、易调试、性能好**
- FSM局限：**状态爆炸、难复用、无并发、扩展难**

适用场景：**行为简单的敌人、动物NPC、UI流程、游戏模式切换**。当行为复杂度超过7-10个状态时，应考虑升级到HFSM或行为树。常见误区是把所有逻辑塞进状态，导致状态臃肿——应保持状态"小而专注"，复杂逻辑拆分为子状态或委托给其他系统。

## 第5讲 分层状态机（HFSM）

### 概念

分层状态机（Hierarchical Finite State Machine, HFSM）是FSM的扩展，允许**状态嵌套**——一个状态可以包含子状态机，形成树状结构。HFSM的核心动机是解决FSM的"状态爆炸"问题：当行为复杂时，扁平FSM的状态数和转移数会指数增长，难以维护。HFSM通过**将相关状态分组为高层状态**，让转移在合适的层级发生，大幅降低复杂度。

HFSM的关键概念包括：**父状态（Parent State）** 包含子状态机；**子状态（Child State）** 是父状态内的具体状态；**历史状态（History State）** 记住子状态机上次激活的子状态，便于恢复；**进入/退出动作层级传播**——进入父状态时先执行父状态进入动作，再进入初始子状态。这种层级结构让AI能表达"在战斗状态下，可以是近战或远程子状态"这样的语义。

### 原理

HFSM的核心机制是**状态的层级化进入/退出**。当从状态A转移到状态B时，系统会找到A和B的**最近公共祖先（LCA）**，然后依次：① 从A向上退出到LCA（执行沿途所有退出动作）；② 从LCA向下进入到B（执行沿途所有进入动作）。这种"上下楼梯"式的转移确保了状态变更的语义正确性——例如从"战斗.近战"切换到"巡逻"时，会先退出"近战"、再退出"战斗"、最后进入"巡逻"。

**层级转移的优势**体现在复用性上。考虑一个有"巡逻"和"战斗"两个高层状态的士兵AI，"战斗"下有"近战"、"远程"、"防御"三个子状态。如果用扁平FSM，每个子状态都需要写"血量低时逃跑"的转移，共3条；用HFSM，只需在"战斗"父状态写一条转移，所有子状态自动继承。这种**转移的层级继承**是HFSM的核心价值。

**历史状态**解决"中断恢复"问题。假设士兵在"战斗.远程"状态时被呼叫支援，进入"支援"状态；支援完成后，应该回到"战斗.远程"而非"战斗.近战"。历史状态记住子状态机上次的位置，让恢复自然。这在游戏AI中极为常见——任何"打断-恢复"模式都需要历史状态。

**HFSM vs FSM 的选择标准**：
- 行为简单、状态数<8：用FSM
- 行为有明确层级、状态数8-20：用HFSM
- 行为需要复杂组合、复用：用行为树（下一讲）

HFSM在工业界的典型应用包括：Quake III的bot AI、Half-Life的士兵AI、许多RTS的单位AI。它至今仍是许多游戏的首选，因为相比行为树，HFSM的"状态互斥"语义更易推理，调试更直观。

### 例子

下面实现一个分层状态机，模拟一个有"和平"和"战斗"两个高层模式的士兵AI，每个模式下有子状态：

```python
from typing import Dict, List, Optional, Callable

class HState:
    """分层状态基类"""
    def __init__(self, name: str, parent: Optional['HState'] = None):
        self.name = name
        self.parent = parent
        self.children: Dict[str, 'HState'] = {}
        self.initial_child: Optional[str] = None
        self.history: Optional[str] = None  # 历史状态
        
        if parent:
            parent.children[name] = self
    
    def add_child(self, child: 'HState', is_initial: bool = False) -> 'HState':
        child.parent = self
        self.children[child.name] = child
        if is_initial:
            self.initial_child = child.name
        return child
    
    # 钩子方法，子类重写
    def on_enter(self, agent): pass
    def on_update(self, agent, dt) -> Optional[str]: return None
    def on_exit(self, agent): pass
    
    def is_composite(self):
        return len(self.children) > 0

class HFSM:
    def __init__(self, root: HState):
        self.root = root
        self.current_path: List[str] = []  # 从root到当前状态的路径
        self._enter_state(root.name)
    
    def _find_state(self, path: List[str]) -> HState:
        state = self.root
        for name in path[1:]:
            state = state.children[name]
        return state
    
    def _enter_state(self, name: str, from_history: bool = False):
        """进入状态，递归进入初始子状态"""
        # 构建新路径
        state = self.root
        new_path = [state.name]
        for n in self.current_path[1:]:
            state = state.children[n]
            new_path.append(state.name)
            if n == name:
                break
        
        # 简化：直接处理名称查找
        target = self._find_state_by_name(name)
        new_path = self._get_path(target)
        
        # 找到LCA
        lca_idx = 0
        for i, (a, b) in enumerate(zip(self.current_path, new_path)):
            if a != b:
                break
            lca_idx = i + 1
        
        # 退出旧路径（从深到浅）
        for i in range(len(self.current_path) - 1, lca_idx - 1, -1):
            old_state = self._find_state(self.current_path[:i+1])
            # 如果是组合状态，记录历史
            if old_state.is_composite() and i < len(self.current_path):
                old_state.history = self.current_path[i+1] if i+1 < len(self.current_path) else old_state.initial_child
            old_state.on_exit(agent_ref)
        
        # 进入新路径（从浅到深）
        for i in range(lca_idx, len(new_path)):
            new_state = self._find_state(new_path[:i+1])
            new_state.on_enter(agent_ref)
        
        self.current_path = new_path
        
        # 如果是组合状态，递归进入初始/历史子状态
        current = self._find_state(self.current_path)
        if current.is_composite():
            child_name = current.history if from_history and current.history else current.initial_child
            if child_name:
                self._enter_state(child_name, from_history)
    
    def _find_state_by_name(self, name: str) -> HState:
        """BFS查找状态"""
        queue = [self.root]
        while queue:
            s = queue.pop(0)
            if s.name == name:
                return s
            queue.extend(s.children.values())
        raise ValueError(f"State {name} not found")
    
    def _get_path(self, state: HState) -> List[str]:
        path = []
        while state:
            path.insert(0, state.name)
            state = state.parent
        return path
    
    def update(self, agent, dt):
        # 从深到浅调用update，最深的状态优先返回转移
        for i in range(len(self.current_path) - 1, -1, -1):
            state = self._find_state(self.current_path[:i+1])
            next_name = state.on_update(agent, dt)
            if next_name:
                self.transition_to(next_name)
                break
    
    def transition_to(self, name: str):
        self._enter_state(name)

# 全局变量简化示例（实际应封装）
```

### 总结

本讲重点回顾：
- HFSM通过**状态嵌套**解决FSM的状态爆炸问题
- 核心机制：**LCA查找 + 层级进入/退出**，确保状态变更语义正确
- **转移层级继承**：父状态转移对所有子状态生效，大幅减少重复代码
- **历史状态**：支持"中断-恢复"模式，记住子状态机上次位置

## 第6讲 行为树（Behavior Tree）

### 概念

行为树（Behavior Tree, BT）是现代游戏AI的工业标准决策架构，由Halo 2（2004）首次大规模采用，随后在Unreal Engine、CryEngine等主流引擎中成为内置功能。行为树是一种**树形结构的决策模型**，通过组合节点（Composite）、装饰节点（Decorator）、叶节点（Leaf）的层级组合，实现复杂行为的模块化、可复用、可扩展表达。相比FSM/HFSM，行为树的核心优势在于**无状态转移、节点可复用、行为可组合**。

行为树与FSM的根本差异在于"**控制流模型**"：FSM是"状态+转移"的有向图，行为树是"自顶向下遍历"的树。FSM的转移是显式的、双向的（A→B意味着A知道B的存在）；行为树的节点是**无状态的**（大部分情况），每次遍历从根开始，根据节点返回状态决定走向。这种"无状态遍历"让行为树节点可以**任意复用**——同一个"攻击"节点可以出现在树的不同位置，而FSM的状态转移硬编码导致难以复用。

### 原理

行为树由四类节点组成，每类节点有明确的职责：

**1. 叶节点（Leaf Node）**：行为树的执行单元，分为**动作节点（Action）** 和 **条件节点（Condition）**。动作节点执行具体行为（移动、攻击、播放动画），返回`Success`/`Failure`/`Running`三种状态。条件节点检查某条件是否满足，返回`Success`/`Failure`。叶节点是行为树的"叶子"，不再有子节点。

**2. 组合节点（Composite Node）**：管理子节点的执行策略，是行为树的"分支"。三种经典组合：
- **Sequence（序列）**：依次执行子节点，全部成功才返回成功，任一失败立即返回失败。相当于逻辑"AND"。
- **Selector（选择）/ Fallback（回退）**：依次执行子节点，任一成功立即返回成功，全部失败才返回失败。相当于逻辑"OR"。
- **Parallel（并行）**：同时执行所有子节点，根据策略（全部成功/任一成功）决定返回。用于并发行为。

**3. 装饰节点（Decorator Node）**：修饰单个子节点的行为，类似函数装饰器。常见装饰器：`Inverter`（反转结果）、`Repeat`（重复执行）、`Retry`（失败重试）、`Timeout`（超时限制）、`Cooldown`（冷却时间）。装饰器让行为树具备"元编程"能力。

**4. 根节点（Root Node）**：树的入口，每帧（或按频率）从根开始遍历。

**遍历机制**是行为树的核心。每次`Tick()`从根开始，深度优先遍历：
- 组合节点根据自身策略决定执行哪些子节点、何时停止
- 叶节点执行行为并返回状态
- 装饰节点包装子节点的返回状态
- `Running`状态表示行为进行中（如移动到目标点），下一帧继续从该节点执行

**行为树的状态记忆**通过"**活动节点**"实现。当某叶节点返回`Running`，行为树记住这个节点，下一帧直接从该节点继续（而非从根重新遍历）。这种"**记忆式遍历**"让行为树能处理持续行为，同时保持无状态优势——活动节点是运行时状态，不影响树结构本身。

**行为树 vs HFSM 的对比**：
| 维度 | HFSM | 行为树 |
|------|------|--------|
| 控制流 | 状态转移图 | 树遍历 |
| 复用性 | 差（转移硬编码） | 好（节点无状态） |
| 可读性 | 状态路径清晰 | 树结构直观 |
| 并发 | 难（互斥状态） | 易（Parallel节点） |
| 调试 | 状态切换日志 | 节点遍历日志 |
| 适用 | 简单-中等复杂 | 中等-高度复杂 |

工业实践：**简单AI用FSM，中等复杂用HFSM，高度复杂用行为树**。Unreal Engine的Behavior Tree是当前最成熟的工业实现。

### 例子

下面实现一个完整的行为树框架，并构建一个"守卫NPC"的行为树（巡逻→发现敌人→追击→攻击）：

```python
from enum import Enum
from abc import ABC, abstractmethod
from typing import List, Optional

class Status(Enum):
    SUCCESS = "success"
    FAILURE = "failure"
    RUNNING = "running"

class Node(ABC):
    """行为树节点基类"""
    def __init__(self, name: str = ""):
        self.name = name or self.__class__.__name__
        self.parent: Optional['Node'] = None
    
    @abstractmethod
    def tick(self, agent) -> Status:
        pass
    
    def reset(self):
        """重置节点状态（用于重新开始）"""
        pass

# === 叶节点 ===
class ActionNode(Node):
    """动作节点基类"""
    pass

class ConditionNode(Node):
    """条件节点基类"""
    pass

# 具体动作节点
class MoveToWaypoint(ActionNode):
    def __init__(self):
        super().__init__("MoveToWaypoint")
    
    def tick(self, agent):
        if not agent.has_target():
            agent.next_waypoint()
        agent.move_to_target()
        if agent.at_target():
            return Status.SUCCESS
        return Status.RUNNING

class ChaseEnemy(ActionNode):
    def tick(self, agent):
        if not agent.can_see_enemy():
            return Status.FAILURE
        agent.move_to(agent.enemy_position)
        if agent.distance_to_enemy() < agent.attack_range:
            return Status.SUCCESS
        return Status.RUNNING

class AttackEnemy(ActionNode):
    def __init__(self):
        self.fire_cooldown = 0
    
    def tick(self, agent):
        if not agent.can_see_enemy():
            return Status.FAILURE
        if agent.distance_to_enemy() > agent.attack_range:
            return Status.FAILURE
        if self.fire_cooldown <= 0:
            agent.fire()
            self.fire_cooldown = 0.3
        return Status.RUNNING
    
    def reset(self):
        self.fire_cooldown = 0

# 具体条件节点
class CanSeeEnemy(ConditionNode):
    def tick(self, agent):
        return Status.SUCCESS if agent.can_see_enemy() else Status.FAILURE

class IsHealthy(ConditionNode):
    def __init__(self, threshold=30):
        super().__init__("IsHealthy")
        self.threshold = threshold
    
    def tick(self, agent):
        return Status.SUCCESS if agent.health > self.threshold else Status.FAILURE

# === 组合节点 ===
class Sequence(Node):
    """序列：全部成功才成功"""
    def __init__(self, children: List[Node], name: str = "Sequence"):
        super().__init__(name)
        self.children = children
        self.current_idx = 0
        for c in children:
            c.parent = self
    
    def tick(self, agent):
        while self.current_idx < len(self.children):
            status = self.children[self.current_idx].tick(agent)
            if status == Status.RUNNING:
                return Status.RUNNING
            if status == Status.FAILURE:
                self.current_idx = 0  # 重置，下次从头开始
                return Status.FAILURE
            self.current_idx += 1
        self.current_idx = 0
        return Status.SUCCESS
    
    def reset(self):
        self.current_idx = 0
        for c in self.children:
            c.reset()

class Selector(Node):
    """选择：任一成功就成功"""
    def __init__(self, children: List[Node], name: str = "Selector"):
        super().__init__(name)
        self.children = children
        self.current_idx = 0
        for c in children:
            c.parent = self
    
    def tick(self, agent):
        while self.current_idx < len(self.children):
            status = self.children[self.current_idx].tick(agent)
            if status == Status.RUNNING:
                return Status.RUNNING
            if status == Status.SUCCESS:
                self.current_idx = 0
                return Status.SUCCESS
            self.current_idx += 1
        self.current_idx = 0
        return Status.FAILURE
    
    def reset(self):
        self.current_idx = 0
        for c in children:
            c.reset()

# === 装饰节点 ===
class Inverter(Node):
    """反转结果"""
    def __init__(self, child: Node):
        super().__init__("Inverter")
        self.child = child
        self.child.parent = self
    
    def tick(self, agent):
        status = self.child.tick(agent)
        if status == Status.SUCCESS:
            return Status.FAILURE
        if status == Status.FAILURE:
            return Status.SUCCESS
        return Status.RUNNING

class Cooldown(Node):
    """冷却装饰器"""
    def __init__(self, child: Node, cooldown: float):
        super().__init__("Cooldown")
        self.child = child
        self.cooldown = cooldown
        self.timer = 0
        self.child.parent = self
    
    def tick(self, agent):
        if self.timer > 0:
            self.timer -= 0.016  # 假设dt=0.016
            return Status.FAILURE
        status = self.child.tick(agent)
        if status == Status.FAILURE or status == Status.SUCCESS:
            self.timer = self.cooldown
        return status

# === 行为树 ===
class BehaviorTree:
    def __init__(self, root: Node):
        self.root = root
    
    def tick(self, agent):
        return self.root.tick(agent)

# === 构建守卫NPC的行为树 ===
def build_guard_bt():
    """
    行为树结构：
    Selector (尝试以下行为，任一成功即可)
    ├── Sequence (战斗序列：健康且能看到敌人)
    │   ├── IsHealthy(30)
    │   └── Selector
    │       ├── Sequence (近战攻击)
    │       │   ├── ChaseEnemy
    │       │   └── AttackEnemy
    │       └── ChaseEnemy (仅追击)
    └── MoveToWaypoint (巡逻)
    """
    combat_seq = Sequence([
        IsHealthy(30),
        Selector([
            Sequence([
                ChaseEnemy(),
                AttackEnemy(),
            ], name="ChaseAndAttack"),
            ChaseEnemy(),
        ], name="CombatChoice"),
    ], name="Combat")
    
    patrol = MoveToWaypoint()
    
    root = Selector([combat_seq, patrol], name="Root")
    return BehaviorTree(root)

# 使用
bt = build_guard_bt()
# 游戏主循环
# for frame in range(1000):
#     bt.tick(agent)
```

这个行为树表达了清晰的优先级：**先尝试战斗（如果健康且能看到敌人），否则巡逻**。战斗内部又有优先级：**先尝试追击+攻击，若攻击失败则仅追击**。这种"**优先级+组合**"的表达力是FSM难以企及的。注意`MoveToWaypoint`节点可以复用到其他行为树中，无需修改——这是行为树的核心优势。

### 总结

本讲重点回顾：
- 行为树 = **叶节点（动作/条件）+ 组合节点（序列/选择/并行）+ 装饰节点** 的树形结构
- 三种核心组合：**Sequence（AND）、Selector（OR）、Parallel（并发）**
- 遍历机制：**自顶向下深度优先 + Running状态记忆**
- 核心优势：**节点无状态可复用、行为可组合、并发支持好**
- 工业地位：**Unreal Engine内置，现代游戏AI事实标准**

适用场景：**中高复杂度AI、需要模块化和复用、需要并发行为**。常见误区：① 行为树过深——超过5-6层会显著降低性能和可读性，应拆分；② 滥用Running——过多Running节点导致行为树"卡住"，应合理设计中断条件；③ 忽视黑板——行为树应通过黑板共享状态，而非节点间直接通信。

# 第3章 移动与导航

## 第7讲 转向行为（Steering Behaviors）

### 概念

转向行为（Steering Behaviors）是Craig Reynolds在1999年提出的运动控制模型，用于让NPC表现出**自然、流畅、有"生命感"的移动**。它解决的不是"如何从A到B"（这是寻路问题），而是"**如何以自然的方式移动**"——包括加速、减速、转弯、避让、聚集等。转向行为是游戏AI运动层的基础，从《模拟人生》的市民到《GTA》的行人，从鸟群到鱼群，都依赖这套技术。

转向行为的核心思想是"**力模型**"：每个行为计算一个"转向力"（Steering Force），作用于NPC的速度向量，改变其运动方向和速率。多个行为可以**加权混合**，产生复杂运动。例如一只鸟同时受"分离力"（避免碰撞）、"对齐力"（与邻居同向）、"聚集力"（向群体中心移动）三种力作用，就形成了著名的Boids鸟群算法。

### 原理

转向行为的物理基础是**牛顿运动学**：位置、速度、加速度。每个NPC维护`position`、`velocity`两个向量，每帧根据`steering_force`更新：

```
acceleration = steering_force / mass
velocity += acceleration * dt
velocity = truncate(velocity, max_speed)  # 限制最大速度
position += velocity * dt
```

`mass`参数让不同体型的NPC有不同"惯性"——重型敌人转向慢，轻型敌人灵活。`truncate`操作确保速度不超过上限，模拟现实中的物理限制。

**Reynolds定义的经典转向行为**包括三大类：

**1. 寻路类（Seeking）**：
- **Seek（寻找）**：朝目标加速移动。`steering = normalize(target - position) * max_speed - velocity`
- **Flee（逃跑）**：远离目标。`steering = normalize(position - target) * max_speed - velocity`
- **Arrive（到达）**：接近目标时减速，避免冲过头。根据距离调整目标速度。
- **Pursuit（追击）**：预测目标未来位置后Seek。基于目标当前速度外推。
- **Evade（躲避）**：预测追击者未来位置后Flee。

**2. 操控类（Wandering）**：
- **Wander（漫游）**：在NPC前方画一个圆，每帧在圆上随机选一点作为目标，产生"看似有目的但实际随机"的运动。
- **Path Following（路径跟随）**：沿预定路径移动，结合Seek和预测。

**3. 群体类（Flocking）**：
- **Separation（分离）**：远离过近的邻居，避免碰撞
- **Alignment（对齐）**：与邻居平均速度方向一致
- **Cohesion（聚集）**：向邻居中心移动

**力的混合策略**是转向行为的关键。多个行为产生的力需要合并，常见方法：
- **加权求和**：每个力乘以权重后相加，简单但可能冲突
- **优先级仲裁**：高优先级力先满足，剩余预算给低优先级
- **行为抑制**：某行为激活时抑制其他行为（如紧急避障抑制漫游）

**避障（Obstacle Avoidance）**是转向行为的重要应用。Reynolds的方法是：从NPC向前投射一根"触须"（whisker），若触须碰到障碍物，则产生一个垂直于触须的避让力。更精确的方法是用**射线检测+障碍物几何**计算避让方向。

### 例子

下面实现核心转向行为，并展示一个综合应用（巡逻+避障+边界）：

```python
import numpy as np
import math

class Vehicle:
    """转向行为的载体"""
    def __init__(self, x, y):
        self.position = np.array([x, y], dtype=float)
        self.velocity = np.array([0.0, 0.0])
        self.acceleration = np.array([0.0, 0.0])
        self.max_speed = 4.0
        self.max_force = 0.5
        self.mass = 1.0
        self.radius = 5.0
    
    def apply_force(self, force):
        """施加转向力（考虑质量）"""
        self.acceleration += force / self.mass
    
    def update(self, dt):
        self.velocity += self.acceleration * dt
        self._truncate(self.velocity, self.max_speed)
        self.position += self.velocity * dt
        self.acceleration *= 0  # 重置加速度
    
    def _truncate(self, vec, max_val):
        mag = np.linalg.norm(vec)
        if mag > max_val:
            vec *= max_val / mag

# === 转向行为函数 ===
def seek(vehicle, target, max_speed=None):
    """寻找目标"""
    max_speed = max_speed or vehicle.max_speed
    desired = target - vehicle.position
    desired = desired / (np.linalg.norm(desired) + 1e-9) * max_speed
    steering = desired - vehicle.velocity
    return steering

def flee(vehicle, target, panic_distance=100):
    """逃离目标"""
    distance = np.linalg.norm(target - vehicle.position)
    if distance > panic_distance:
        return np.array([0.0, 0.0])
    desired = vehicle.position - target
    desired = desired / (np.linalg.norm(desired) + 1e-9) * vehicle.max_speed
    return desired - vehicle.velocity

def arrive(vehicle, target, slow_radius=50):
    """到达目标（接近时减速）"""
    to_target = target - vehicle.position
    distance = np.linalg.norm(to_target)
    if distance < 1:
        return np.array([0.0, 0.0])
    # 距离越近，速度越低
    if distance < slow_radius:
        speed = vehicle.max_speed * (distance / slow_radius)
    else:
        speed = vehicle.max_speed
    desired = to_target / (distance + 1e-9) * speed
    return desired - vehicle.velocity

def pursuit(vehicle, evader):
    """追击（预测目标未来位置）"""
    to_evader = evader.position - vehicle.position
    relative_heading = np.dot(vehicle.velocity, evader.velocity)
    
    # 如果朝向目标且目标朝向我们，直接Seek
    if (np.dot(to_evader, vehicle.velocity) > 0 and 
        relative_heading < -0.95):
        return seek(vehicle, evader.position)
    
    # 否则预测未来位置
    look_ahead = np.linalg.norm(to_evader) / vehicle.max_speed
    predicted = evader.position + evader.velocity * look_ahead
    return seek(vehicle, predicted)

def wander(vehicle, wander_radius=20, wander_distance=50, wander_jitter=10):
    """漫游行为"""
    if not hasattr(vehicle, '_wander_angle'):
        vehicle._wander_angle = 0
    
    # 随机扰动角度
    vehicle._wander_angle += np.random.uniform(-1, 1) * wander_jitter * 0.01
    
    # 计算圆上的目标点
    circle_center = vehicle.velocity / (np.linalg.norm(vehicle.velocity) + 1e-9) * wander_distance
    displacement = np.array([
        math.cos(vehicle._wander_angle) * wander_radius,
        math.sin(vehicle._wander_angle) * wander_radius
    ])
    target = vehicle.position + circle_center + displacement
    return seek(vehicle, target)

def obstacle_avoidance(vehicle, obstacles):
    """障碍物避让"""
    ahead = vehicle.position + vehicle.velocity / (np.linalg.norm(vehicle.velocity) + 1e-9) * 50
    ahead2 = vehicle.position + vehicle.velocity / (np.linalg.norm(vehicle.velocity) + 1e-9) * 25
    
    most_threatening = None
    closest = float('inf')
    for obs in obstacles:
        # 检测障碍物是否在前方触须上
        d1 = np.linalg.norm(ahead - obs['pos'])
        d2 = np.linalg.norm(ahead2 - obs['pos'])
        d3 = np.linalg.norm(vehicle.position - obs['pos'])
        if min(d1, d2, d3) < obs['radius'] + vehicle.radius:
            d = np.linalg.norm(vehicle.position - obs['pos'])
            if d < closest:
                closest = d
                most_threatening = obs
    
    if most_threatening:
        avoidance = ahead - most_threatening['pos']
        avoidance = avoidance / (np.linalg.norm(avoidance) + 1e-9) * vehicle.max_force
        return avoidance
    return np.array([0.0, 0.0])

def separation(vehicle, neighbors):
    """分离力（避免与邻居碰撞）"""
    steering = np.array([0.0, 0.0])
    count = 0
    for n in neighbors:
        d = np.linalg.norm(vehicle.position - n.position)
        if 0 < d < vehicle.radius * 3:
            diff = vehicle.position - n.position
            diff = diff / (d * d + 1e-9)  # 距离越远，力越小
            steering += diff
            count += 1
    if count > 0:
        steering /= count
        steering = steering / (np.linalg.norm(steering) + 1e-9) * vehicle.max_speed
        steering -= vehicle.velocity
    return steering

# === 综合应用：巡逻NPC ===
class PatrolNPC:
    def __init__(self, x, y, waypoints):
        self.vehicle = Vehicle(x, y)
        self.waypoints = waypoints
        self.current_wp = 0
        self.obstacles = []
    
    def update(self, dt, neighbors):
        target = self.waypoints[self.current_wp]
        
        # 加权混合多种行为
        force_arrive = arrive(self.vehicle, target, slow_radius=30) * 1.0
        force_avoid = obstacle_avoidance(self.vehicle, self.obstacles) * 2.0  # 高优先级
        force_sep = separation(self.vehicle, neighbors) * 1.5
        
        total = force_arrive + force_avoid + force_sep
        # 限制总力
        mag = np.linalg.norm(total)
        if mag > self.vehicle.max_force:
            total = total / mag * self.vehicle.max_force
        
        self.vehicle.apply_force(total)
        self.vehicle.update(dt)
        
        # 到达路径点后切换
        if np.linalg.norm(target - self.vehicle.position) < 10:
            self.current_wp = (self.current_wp + 1) % len(self.waypoints)
```

这个示例展示了转向行为的**组合艺术**：巡逻NPC同时受"到达力"（朝路径点移动）、"避障力"（避开障碍物）、"分离力"（避开其他NPC）三种力作用，权重反映优先级。避障力权重最高（2.0），确保安全；分离力次之（1.5），避免拥挤；到达力基础权重（1.0）。这种加权混合是工业实践的标准做法。

### 总结

本讲重点回顾：
- 转向行为基于**牛顿运动学**，通过转向力改变NPC速度
- 三大类行为：**寻路类（Seek/Flee/Arrive/Pursuit）、操控类（Wander/PathFollow）、群体类（Separation/Alignment/Cohesion）**
- 力的混合策略：**加权求和、优先级仲裁、行为抑制**
- 避障核心：**前方触须检测 + 垂直避让力**
- 应用场景：**动物运动、人群模拟、车辆AI、鸟群鱼群**

常见误区：① 忽视`max_force`限制——不限制力的大小会导致NPC瞬移；② 力的权重未调优——权重不当会导致行为"打架"或"漂移"；③ 直接用Seek而非Arrive——Seek会让NPC在目标点附近反复冲过头。调试技巧：在编辑器中绘制每个力的向量，直观观察力的平衡。

## 第8讲 寻路算法：Dijkstra与A*

### 概念

寻路（Pathfinding）是游戏AI最经典的算法领域，解决"**从起点到终点找一条最优路径**"的问题。本讲介绍两种基础且重要的寻路算法：**Dijkstra算法**（1959）和**A*算法**（1968）。Dijkstra算法保证找到最短路径，但搜索范围大；A*算法通过启发式函数大幅提升效率，是游戏工业的事实标准。理解这两种算法的原理和差异，是掌握游戏AI导航的基础。

寻路问题在游戏中的表现形式多样：网格地图上的角色移动、RTS中单位的长距离行军、RPG中NPC的城镇巡逻、MOBA中的小兵路线。尽管场景不同，底层算法高度统一——都是**图搜索算法**的应用。游戏地图被抽象为"图"（Graph）：节点（Node）表示可站立位置，边（Edge）表示可通行连接，边权重表示通行成本（距离、地形难度等）。

### 原理

**Dijkstra算法**的核心思想是"**广度优先 + 最小成本优先**"。算法维护两个集合：已确定最短路径的节点集合`S`，待处理的节点集合`Q`（优先队列）。初始时起点距离为0，其他节点距离为无穷大。每轮从`Q`中取出距离最小的节点`u`，将其加入`S`，然后松弛`u`的所有邻居——若经过`u`到邻居`v`的距离比当前已知距离短，则更新。重复直到目标节点被加入`S`或`Q`为空。

Dijkstra的正确性基于"**非负权边**"假设——若边权为负，算法可能给出错误结果。在游戏中边权通常为正（距离、时间），所以Dijkstra适用。其时间复杂度为`O((V+E)logV)`（用优先队列），空间复杂度`O(V)`。

Dijkstra的**关键缺陷**是"无方向性"——它向所有方向均匀扩展，像水波纹一样。这意味着即使目标在东方，它也会向西方搜索，浪费大量计算。在大型地图上，这种"盲目搜索"会导致明显卡顿。

**A*算法**通过引入**启发式函数（Heuristic Function）** 解决Dijkstra的方向性问题。A*的核心公式：

```
f(n) = g(n) + h(n)
```

其中`g(n)`是从起点到节点`n`的实际成本，`h(n)`是从`n`到目标的估计成本（启发式）。A*每轮选择`f(n)`最小的节点扩展，**既考虑已花费成本（g），又考虑预估剩余成本（h）**，从而朝目标方向优先搜索。

**启发式函数的设计**是A*的关键。`h(n)`必须满足**可采纳性（Admissibility）**——不能高估实际成本，否则不保证最优解。常见启发式：
- **曼哈顿距离**（Manhattan）：`|dx| + |dy|`，适用于4方向网格移动
- **欧几里得距离**（Euclidean）：`sqrt(dx² + dy²)`，适用于任意方向移动
- **切比雪夫距离**（Chebyshev）：`max(|dx|, |dy|)`，适用于8方向网格移动

**A*的最优性**：当`h(n)`可采纳时，A*保证找到最短路径。当`h(n)=0`时，A*退化为Dijkstra。当`h(n)`恰好等于实际成本时，A*只搜索最优路径上的节点，效率最高。

**A*的性能调优**：
- **权重A*（Weighted A*）**：使用`f(n) = g(n) + w*h(n)`，`w>1`时优先朝目标搜索，牺牲最优性换取速度
- **迭代加深A*（IDA*）**：用深度优先+阈值限制，节省内存
- **双向A*（Bidirectional A*）**：从起点和终点同时搜索，相遇时合并
- **跳点搜索（JPS）**：在网格地图上利用对称性剪枝，比A*快10倍以上

**数据结构**对A*性能影响巨大。开放列表（Open Set）通常用**二叉堆**或**配对堆**实现，保证O(logV)的插入和删除最小值。封闭列表（Closed Set）用哈希表实现，O(1)查找。在大型地图上，数据结构优化能带来数倍性能提升。

### 例子

下面实现完整的A*算法，支持网格地图和多种启发式：

```python
import heapq
import math
from enum import Enum
from typing import List, Tuple, Set, Dict, Optional

class CellType(Enum):
    WALKABLE = 0
    WALL = 1
    WATER = 2  # 高成本地形
    ROAD = 3   # 低成本地形

class GridMap:
    """网格地图"""
    def __init__(self, width, height):
        self.width = width
        self.height = height
        self.cells = [[CellType.WALKABLE] * width for _ in range(height)]
        # 地形成本
        self.terrain_cost = {
            CellType.WALKABLE: 1.0,
            CellType.WALL: float('inf'),
            CellType.WATER: 3.0,
            CellType.ROAD: 0.5,
        }
    
    def set_cell(self, x, y, cell_type):
        self.cells[y][x] = cell_type
    
    def is_walkable(self, x, y):
        if 0 <= x < self.width and 0 <= y < self.height:
            return self.cells[y][x] != CellType.WALL
        return False
    
    def get_cost(self, x, y):
        return self.terrain_cost[self.cells[y][x]]
    
    def get_neighbors(self, x, y, allow_diagonal=True):
        """获取邻居（4方向或8方向）"""
        neighbors = []
        directions = [(0,1),(0,-1),(1,0),(-1,0)]
        if allow_diagonal:
            directions += [(1,1),(1,-1),(-1,1),(-1,-1)]
        for dx, dy in directions:
            nx, ny = x+dx, y+dy
            if self.is_walkable(nx, ny):
                # 对角移动时检查是否穿墙
                if dx != 0 and dy != 0:
                    if not self.is_walkable(x+dx, y) or not self.is_walkable(x, y+dy):
                        continue
                neighbors.append((nx, ny, dx, dy))
        return neighbors

def heuristic(a, b, mode='manhattan'):
    """启发式函数"""
    dx, dy = abs(a[0]-b[0]), abs(a[1]-b[1])
    if mode == 'manhattan':
        return dx + dy
    elif mode == 'euclidean':
        return math.sqrt(dx*dx + dy*dy)
    elif mode == 'chebyshev':
        return max(dx, dy)
    elif mode == 'octile':  # 8方向网格的最优启发式
        return max(dx, dy) + (math.sqrt(2)-1) * min(dx, dy)
    return dx + dy

class AStar:
    def __init__(self, grid: GridMap, allow_diagonal=True, heuristic_mode='octile'):
        self.grid = grid
        self.allow_diagonal = allow_diagonal
        self.heuristic_mode = heuristic_mode
    
    def find_path(self, start, goal) -> Tuple[List, float]:
        """寻找从start到goal的最短路径"""
        open_heap = []  # 优先队列：(f_score, counter, node)
        open_set = {}   # node -> g_score
        closed_set: Set = set()
        came_from: Dict = {}
        g_score = {start: 0}
        f_score = {start: heuristic(start, goal, self.heuristic_mode)}
        counter = 0  # 防止f_score相同时比较node
        
        heapq.heappush(open_heap, (f_score[start], counter, start))
        open_set[start] = 0
        counter += 1
        
        while open_heap:
            _, _, current = heapq.heappop(open_heap)
            
            # 跳过已处理的过时条目
            if current in closed_set:
                continue
            if current not in open_set:
                continue
            
            if current == goal:
                return self._reconstruct_path(came_from, current), g_score[current]
            
            del open_set[current]
            closed_set.add(current)
            
            for nx, ny, dx, dy in self.grid.get_neighbors(current[0], current[1], self.allow_diagonal):
                neighbor = (nx, ny)
                if neighbor in closed_set:
                    continue
                
                # 计算移动成本（对角线成本为sqrt(2)）
                move_cost = self.grid.get_cost(nx, ny)
                if dx != 0 and dy != 0:
                    move_cost *= math.sqrt(2)
                
                tentative_g = g_score[current] + move_cost
                
                if neighbor not in g_score or tentative_g < g_score[neighbor]:
                    came_from[neighbor] = current
                    g_score[neighbor] = tentative_g
                    f_score[neighbor] = tentative_g + heuristic(neighbor, goal, self.heuristic_mode)
                    heapq.heappush(open_heap, (f_score[neighbor], counter, neighbor))
                    open_set[neighbor] = tentative_g
                    counter += 1
        
        return [], float('inf')  # 无路径
    
    def _reconstruct_path(self, came_from, current):
        path = [current]
        while current in came_from:
            current = came_from[current]
            path.append(current)
        path.reverse()
        return path

# === 测试 ===
def demo():
    # 创建20x20地图
    grid = GridMap(20, 20)
    # 设置一些墙
    for y in range(5, 15):

    for x in range(5, 10):
        grid.set_cell(x, 10, CellType.WALL)

        grid.set_cell(x, 0, CellType.ROAD)

            elif grid.cells[y][x] == CellType.WATER:
                line += "~"
            elif grid.cells[y][x] == CellType.ROAD:
                line += "."
            else:
                line += " "
        print(line)

demo()
```

### 总结

本讲重点回顾：
- Dijkstra：**广度优先 + 最小成本**，保证最优但搜索范围大
- A*：`f(n) = g(n) + h(n)`，**启发式引导方向**，效率高且最优
- 启发式必须**可采纳**（不高估实际成本），常用：曼哈顿、欧几里得、切比雪夫、Octile
- 性能优化：**权重A*、IDA*、双向A*、JPS、二叉堆**
- 数据结构：**开放列表用堆，封闭列表用哈希表**

适用场景：**静态地图、单次寻路、需要最优路径**。常见误区：① 启发式高估——导致非最优路径；② 忽视地形成本——所有地形同等对待，路径不自然；③ 每帧重新寻路——应缓存路径或使用增量算法。工业实践：大型游戏常用**NavMesh + A***（下一讲）替代纯网格A*，大幅减少节点数。

## 第9讲 导航网格（NavMesh）

### 概念

导航网格（Navigation Mesh, NavMesh）是现代游戏工业的标准寻路表示方法，解决网格地图（Grid）在大规模场景下的性能和表现力问题。NavMesh将可行走区域表示为**多边形网格**（通常是三角形或凸多边形），每个多边形是一个"可站立区域"，多边形之间的邻接关系表示可通行连接。相比网格地图的"每格一节点"，NavMesh用少量多边形覆盖大片区域，**节点数减少1-2个数量级**，寻路速度大幅提升。

NavMesh的另一个核心优势是**支持任意方向移动**。网格地图的角色只能沿8方向移动，路径呈"锯齿状"；NavMesh的角色可以在多边形内任意位置移动，路径平滑自然。此外，NavMesh能自然表达**不同体型的通行能力**——大型角色只能通过宽通道，小型角色可穿越窄缝，只需为不同体型生成不同NavMesh。

### 原理

**NavMesh的生成**是一个复杂的几何处理过程，主流引擎（Unity、Unreal）都提供自动生成工具。核心步骤：
1. **碰撞几何采集**：从场景的碰撞体（Collider）中提取可行走区域
2. **体素化（Voxelization）**：将3D空间划分为体素网格，标记每个体素为"可行走"或"障碍"
3. **区域生成（Region Generation）**：将相邻可行走体素合并为区域，去除小孤岛
4. **轮廓提取（Contour Extraction）**：沿区域边界提取多边形轮廓
5. **多边形细分（Polygon Subdivision）**：将轮廓三角化为凸多边形
6. **邻接关系建立**：计算多边形之间的共享边，建立导航图

**NavMesh上的A*** 与网格A*原理相同，但节点是"多边形"而非"格子"。关键差异在于：
- **节点**：多边形（用中心点或任意代表点表示）
- **边**：多边形间的共享边
- **成本**：通常用多边形中心点间的距离，或更精确的"漏斗算法"路径长度

**Funnel Algorithm（漏斗算法）** 是NavMesh路径平滑的核心。A*找到的是多边形序列，角色若沿多边形中心移动，路径会呈"之字形"。漏斗算法将相邻多边形的共享边视为"通道"，在通道内寻找最短路径——就像水在漏斗中流动，沿通道的一侧或另一侧走，遇到拐角时切换。算法复杂度O(n)，效果极佳。

**NavMesh的查询操作**：
- **FindClosestPoint**：找到NavMesh上离查询点最近的点（用于将任意点"吸附"到NavMesh）
- **Raycast**：在NavMesh上投射射线，检测是否可达（用于视线检测）
- **ProjectPoint**：将3D点投影到NavMesh表面
- **FindRandomPoint**：在NavMesh上随机采样点（用于NPC出生、漫游目标）

**NavMesh的高级特性**：
- **NavMesh Link / Off-Mesh Link**：连接两个不相连NavMesh区域的"传送边"，用于跳跃、攀爬、传送门
- **动态NavMesh**：支持运行时修改（如门开关、桥梁建造），但性能开销大
- **NavMesh Modifier**：标记区域为"高成本"或"禁止通行"，实现"避开火区"、"只走道路"
- **多层NavMesh**：为飞行、游泳、地面分别生成NavMesh

**NavMesh vs Grid 对比**：
| 维度 | Grid | NavMesh |
|------|------|---------|
| 节点数 | 多（每格一节点） | 少（每多边形一节点） |
| 路径质量 | 锯齿状 | 平滑 |
| 内存占用 | 高 | 低 |
| 生成难度 | 简单 | 复杂（需工具） |
| 动态修改 | 容易 | 困难 |
| 任意方向 | 不支持 | 支持 |
| 适用场景 | 小型、规则地图 | 大型、复杂3D场景 |

### 例子

下面实现一个简化的NavMesh寻路系统，包含多边形表示、A*搜索和漏斗算法平滑：

```python
import numpy as np
import heapq
import math
from typing import List, Tuple, Dict, Set
from dataclasses import dataclass

@dataclass
class Polygon:
    """NavMesh多边形"""
    id: int
    vertices: List[Tuple[float, float]]  # 顶点（顺时针或逆时针）
    center: Tuple[float, float]
    neighbors: List[int] = None  # 邻接多边形ID
    
    def __post_init__(self):
        if self.neighbors is None:
            self.neighbors = []
        if self.center is None:
            cx = sum(v[0] for v in self.vertices) / len(self.vertices)
            cy = sum(v[1] for v in self.vertices) / len(self.vertices)
            self.center = (cx, cy)
    
    def contains(self, point) -> bool:
        """点是否在多边形内（射线法）"""
        x, y = point
        n = len(self.vertices)
        inside = False
        j = n - 1
        for i in range(n):
            xi, yi = self.vertices[i]
            xj, yj = self.vertices[j]
            if ((yi > y) != (yj > y)) and \
               (x < (xj - xi) * (y - yi) / (yj - yi + 1e-9) + xi):
                inside = not inside
            j = i
        return inside
    
    def shared_edge(self, other):
        """与另一多边形的共享边"""
        shared = []
        for v in self.vertices:
            if v in other.vertices:
                shared.append(v)
        return shared if len(shared) == 2 else None

class NavMesh:
    def __init__(self):
        self.polygons: Dict[int, Polygon] = {}
    
    def add_polygon(self, poly: Polygon):
        self.polygons[poly.id] = poly
    
    def build_neighbors(self):
        """建立邻接关系"""
        ids = list(self.polygons.keys())
        for i, id1 in enumerate(ids):
            for id2 in ids[i+1:]:
                if self.polygons[id1].shared_edge(self.polygons[id2]):
                    self.polygons[id1].neighbors.append(id2)
                    self.polygons[id2].neighbors.append(id1)
    
    def find_polygon(self, point) -> int:
        """找到包含点的多边形"""
        for pid, poly in self.polygons.items():
            if poly.contains(point):
                return pid
        return -1
    
    def find_path(self, start, goal) -> List[Tuple[float, float]]:
        """A*寻路 + 漏斗平滑"""
        start_poly = self.find_polygon(start)
        goal_poly = self.find_polygon(goal)
        if start_poly == -1 or goal_poly == -1:
            return []
        if start_poly == goal_poly:
            return [start, goal]
        
        # A*搜索多边形序列
        poly_path = self._astar(start_poly, goal_poly)
        if not poly_path:
            return []
        
        # 收集通道（共享边）
        portals = []
        for i in range(len(poly_path) - 1):
            edge = self.polygons[poly_path[i]].shared_edge(self.polygons[poly_path[i+1]])
            if edge:
                # 确保边的方向一致（左、右）
                portals.append((edge[0], edge[1]))
        
        # 漏斗算法平滑
        path = self._funnel(start, portals, goal)
        return path
    
    def _astar(self, start_id, goal_id):
        open_heap = [(0, 0, start_id)]
        came_from = {}
        g_score = {start_id: 0}
        counter = 0
        
        while open_heap:
            _, _, current = heapq.heappop(open_heap)
            if current == goal_id:
                path = [current]
                while current in came_from:
                    current = came_from[current]
                    path.append(current)
                path.reverse()
                return path
            
            for neighbor in self.polygons[current].neighbors:
                # 用多边形中心距离作为成本
                c1 = self.polygons[current].center
                c2 = self.polygons[neighbor].center
                cost = math.dist(c1, c2)
                tentative = g_score[current] + cost
                
                if neighbor not in g_score or tentative < g_score[neighbor]:
                    came_from[neighbor] = current
                    g_score[neighbor] = tentative
                    h = math.dist(c2, self.polygons[goal_id].center)
                    heapq.heappush(open_heap, (tentative + h, counter, neighbor))
                    counter += 1
        return []
    
    def _funnel(self, start, portals, goal):
        """漏斗算法：在通道序列中找最短路径"""
        # 简化版：依次连接共享边中点
        # 完整版见论文"The Funnel Algorithm"
        path = [start]
        for left, right in portals:
            mid = ((left[0]+right[0])/2, (left[1]+right[1])/2)
            path.append(mid)
        path.append(goal)
        return path

# === 构建示例NavMesh ===
def build_demo_navmesh():
    """构建一个简单的NavMesh（4个相邻四边形）"""
    navmesh = NavMesh()
    
    # 4个2x2的正方形多边形，拼成4x4的大正方形
    polys = [
        Polygon(0, [(0,0),(2,0),(2,2),(0,2)], None),
        Polygon(1, [(2,0),(4,0),(4,2),(2,2)], None),
        Polygon(2, [(0,2),(2,2),(2,4),(0,4)], None),
        Polygon(3, [(2,2),(4,2),(4,4),(2,4)], None),
    ]
    for p in polys:
        navmesh.add_polygon(p)
    navmesh.build_neighbors()
    
    return navmesh

navmesh = build_demo_navmesh()
path = navmesh.find_path((0.5, 0.5), (3.5, 3.5))
print(f"路径: {path}")
# 输出: 路径: [(0.5, 0.5), (2.0, 2.0), (3.5, 3.5)]
```

这个简化示例展示了NavMesh寻路的核心流程：**多边形A* + 漏斗平滑**。实际引擎中的NavMesh更复杂——多边形可能是任意凸多边形，漏斗算法需要精确处理顶点顺序和拐角判断。但核心思想一致：用少量多边形表示可行走区域，在多边形级别寻路，再用漏斗算法生成平滑路径。

### 总结

本讲重点回顾：
- NavMesh用**多边形网格**表示可行走区域，节点数比Grid少1-2个数量级
- 生成流程：**体素化 → 区域生成 → 轮廓提取 → 多边形细分 → 邻接建立**
- 寻路流程：**多边形A* → 漏斗算法平滑**
- 高级特性：**Off-Mesh Link、动态NavMesh、NavMesh Modifier、多层NavMesh**
- 工业地位：**Unity、Unreal内置，3D游戏事实标准**

适用场景：**3D游戏、大型开放世界、需要平滑路径**。常见误区：① NavMesh生成参数不当——单元大小、斜坡角度设置错误导致NavMesh破碎或缺失；② 忽视Off-Mesh Link——跳跃、攀爬等行为需要手动添加Link；③ 动态NavMesh滥用——运行时修改NavMesh开销大，应尽量用NavMesh Modifier替代。调试技巧：在编辑器中可视化NavMesh，检查是否有"孤岛"或"断连"区域。

## 第10讲 群体行为与Flocking

### 概念

群体行为（Flocking / Crowd Simulation）是游戏AI中模拟**大量个体协同运动**的技术，典型应用包括鸟群、鱼群、人群、丧尸潮、RTS单位群。本讲聚焦经典的**Boids算法**（Craig Reynolds, 1987）及其扩展。Boids通过三条简单规则——**分离、对齐、聚集**——让大量个体涌现出复杂的群体行为，是"涌现式AI"的典范。

群体行为的挑战在于**规模**：一只鸟的AI简单，但1000只鸟同时模拟就涉及大量邻居查询和力计算。直接实现Boids的复杂度是O(n²)（每只鸟检查所有其他鸟），在1000只鸟时需要100万次计算，难以实时。因此，群体行为的核心不仅是算法本身，更是**空间加速结构和性能优化**。

### 原理

**Boids三规则**是群体行为的基础：

**1. 分离（Separation）**：避免与邻居过近。对每个邻居计算一个"远离"向量，距离越近力越大，所有力求和。这模拟了生物的"个人空间"本能——鸟不会撞到彼此。数学上，分离力 = Σ (position_self - position_neighbor) / distance²。

**2. 对齐（Alignment）**：与邻居速度方向一致。计算邻居的平均速度向量，作为个体的"期望速度"，转向力 = 期望速度 - 当前速度。这模拟了羊群效应——个体倾向于跟随群体方向。

**3. 聚集（Cohesion）**：向邻居中心移动。计算邻居的质心位置，产生一个朝向质心的Seek力。这模拟了"不想掉队"的本能——个体倾向于留在群体中。

三条规则的**加权组合**产生群体行为：分离力防止碰撞，对齐力产生方向一致，聚集力维持群体完整。权重的微妙调整能产生截然不同的群体风格——高分离权重产生"松散群体"，高聚集权重产生"密集群体"，高对齐权重产生"整齐队列"。

**邻居查询优化**是群体行为性能的关键。O(n²)的暴力查询在n>500时不可行，常用加速结构：
- **空间哈希（Spatial Hashing）**：将空间划分为网格，每个格子维护一个个体列表。查询邻居时只检查当前格子及周围8个格子。复杂度降至O(n·k)，k是每格平均个体数。
- **四叉树/八叉树（Quadtree/Octree）**：层次化空间划分，适合密度不均的场景。
- **KD树**：高维空间查询，但动态更新成本高。
- **网格 + 并行**：GPU实现，可模拟数万个体。

**群体行为的高级扩展**：
- **目标导向（Goal-Driven）**：在Boids基础上加入"朝目标移动"的力，让群体有目的地迁徙
- **领导跟随（Leadership）**：部分个体作为"领导"，其他个体跟随领导
- **障碍避让**：加入障碍物避让力，让群体绕开障碍
- **捕食者-猎物**：引入"捕食者"个体，触发群体的"逃跑"行为
- **路径跟随**：群体沿预定路径移动，结合Boids维持队形

**人群模拟（Crowd Simulation）**是群体行为在游戏中的高级应用，模拟大量人类角色。相比鸟群，人群模拟需要考虑：
- **个体差异**：不同人有不同目标、速度、避让策略
- **社会力**：除了物理力，还有"社会力"（如避免穿越他人私人空间）
- **路径规划**：每个个体可能有自己的全局路径，Boids只负责局部避让
- **连续避让（ORCA / RVO）**：基于速度障碍的精确避让算法，保证无碰撞

**ORCA（Optimal Reciprocal Collision Avoidance）** 是当前最先进的人群避让算法，由Jur van den Berg等人提出。它基于"速度障碍"概念——每个个体计算与其他个体的"碰撞速度集合"，然后选择集合外的最优速度。ORCA保证无碰撞，且计算高效，是Unity、Unreal人群系统的核心算法。

### 例子

下面实现完整的Boids算法，包含空间哈希加速：

```python
import numpy as np
import math
from dataclasses import dataclass
from typing import List, Tuple, Dict

@dataclass
class Boid:
    position: np.ndarray
    velocity: np.ndarray
    acceleration: np.ndarray = None
    
    def __post_init__(self):
        if self.acceleration is None:
            self.acceleration = np.zeros(2)

class SpatialHash:
    """空间哈希加速结构"""
    def __init__(self, cell_size: float):
        self.cell_size = cell_size
        self.cells: Dict[Tuple[int, int], List[int]] = {}
    
    def _hash(self, pos) -> Tuple[int, int]:
        return (int(pos[0] // self.cell_size), 
                int(pos[1] // self.cell_size))
    
    def insert(self, idx: int, pos):
        key = self._hash(pos)
        if key not in self.cells:
            self.cells[key] = []
        self.cells[key].append(idx)
    
    def query_neighbors(self, pos, radius) -> List[int]:
        """查询半径内的所有个体索引"""
        result = []
        min_x = int((pos[0] - radius) // self.cell_size)
        max_x = int((pos[0] + radius) // self.cell_size)
        min_y = int((pos[1] - radius) // self.cell_size)
        max_y = int((pos[1] + radius) // self.cell_size)
        
        for cx in range(min_x, max_x + 1):
            for cy in range(min_y, max_y + 1):
                if (cx, cy) in self.cells:
                    result.extend(self.cells[(cx, cy)])
        return result
    
    def clear(self):
        self.cells.clear()

class BoidsSystem:
    def __init__(self, width, height, num_boids=200):
        self.width = width
        self.height = height
        self.boids: List[Boid] = []
        self.spatial_hash = SpatialHash(cell_size=30)
        
        # 参数
        self.perception_radius = 25
        self.separation_radius = 15
        self.max_speed = 4.0
        self.max_force = 0.2
        
        # 权重
        self.weight_sep = 1.5
        self.weight_align = 1.0
        self.weight_cohesion = 1.0
        
        # 初始化
        for _ in range(num_boids):
            pos = np.array([np.random.uniform(0, width), 
                           np.random.uniform(0, height)])
            vel = np.array([np.random.uniform(-2, 2), 
                           np.random.uniform(-2, 2)])
            self.boids.append(Boid(pos, vel))
    
    def update(self, dt):
        # 1. 重建空间哈希
        self.spatial_hash.clear()
        for i, b in enumerate(self.boids):
            self.spatial_hash.insert(i, b.position)
        
        # 2. 对每个boid计算三力
        for i, boid in enumerate(self.boids):
            sep = self._separation(i, boid)
            align = self._alignment(i, boid)
            coh = self._cohesion(i, boid)
            
            boid.acceleration = (sep * self.weight_sep + 
                                align * self.weight_align + 
                                coh * self.weight_cohesion)
        
        # 3. 更新运动学
        for boid in self.boids:
            boid.velocity += boid.acceleration * dt * 60  # 缩放
            self._limit(boid.velocity, self.max_speed)
            boid.position += boid.velocity * dt * 60
            
            # 边界处理：环绕
            if boid.position[0] < 0: boid.position[0] += self.width
            if boid.position[0] > self.width: boid.position[0] -= self.width
            if boid.position[1] < 0: boid.position[1] += self.height
            if boid.position[1] > self.height: boid.position[1] -= self.height
    
    def _separation(self, idx, boid):
        """分离力"""
        steering = np.zeros(2)
        count = 0
        neighbors = self.spatial_hash.query_neighbors(boid.position, self.separation_radius)
        for j in neighbors:
            if j == idx: continue
            other = self.boids[j]
            d = np.linalg.norm(boid.position - other.position)
            if 0 < d < self.separation_radius:
                diff = (boid.position - other.position) / (d * d)  # 距离越远力越小
                steering += diff
                count += 1
        if count > 0:
            steering /= count
            steering = self._steer(boid, steering)
        return steering
    
    def _alignment(self, idx, boid):
        """对齐力"""
        avg_velocity = np.zeros(2)
        count = 0
        neighbors = self.spatial_hash.query_neighbors(boid.position, self.perception_radius)
        for j in neighbors:
            if j == idx: continue
            other = self.boids[j]
            d = np.linalg.norm(boid.position - other.position)
            if d < self.perception_radius:
                avg_velocity += other.velocity
                count += 1
        if count > 0:
            avg_velocity /= count
            return self._steer(boid, avg_velocity)
        return np.zeros(2)
    
    def _cohesion(self, idx, boid):
        """聚集力"""
        center = np.zeros(2)
        count = 0
        neighbors = self.spatial_hash.query_neighbors(boid.position, self.perception_radius)
        for j in neighbors:
            if j == idx: continue
            other = self.boids[j]
            d = np.linalg.norm(boid.position - other.position)
            if d < self.perception_radius:
                center += other.position
                count += 1
        if count > 0:
            center /= count
            return self._seek(boid, center)
        return np.zeros(2)
    
    def _steer(self, boid, desired):
        """计算转向力"""
        mag = np.linalg.norm(desired)
        if mag > 0:
            desired = desired / mag * self.max_speed
            steering = desired - boid.velocity
            self._limit(steering, self.max_force)
            return steering
        return np.zeros(2)
    
    def _seek(self, boid, target):
        desired = target - boid.position
        return self._steer(boid, desired)
    
    def _limit(self, vec, max_val):
        mag = np.linalg.norm(vec)
        if mag > max_val:
            vec *= max_val / mag

# === 测试 ===
boids = BoidsSystem(width=800, height=600, num_boids=300)
for frame in range(100):
    boids.update(dt=0.016)
    if frame % 20 == 0:
        avg_pos = np.mean([b.position for b in boids.boids], axis=0)
        avg_vel = np.mean([b.velocity for b in boids.boids], axis=0)
        print(f"帧 {frame}: 平均位置=({avg_pos[0]:.0f},{avg_pos[1]:.0f}), "
              f"平均速度=({avg_vel[0]:.2f},{avg_vel[1]:.2f})")
```

这个实现的关键优化是**空间哈希**——将O(n²)的邻居查询降为接近O(n)。300只boids每帧只需约9000次距离计算（每只查询约30个邻居），而非90000次。注意三条力的权重差异：分离力权重最高（1.5），因为避免碰撞是首要目标；对齐和聚集权重相同（1.0），维持群体一致性。

### 总结

本讲重点回顾：
- Boids三规则：**分离（避免碰撞）、对齐（速度一致）、聚集（向中心移动）**
- 性能关键：**空间哈希、四叉树、GPU并行**，将O(n²)降为O(n)
- 高级扩展：**目标导向、领导跟随、障碍避让、捕食者-猎物**
- 人群模拟：**ORCA/RVO**提供精确无碰撞避让
- 应用场景：**鸟群、鱼群、人群、丧尸潮、RTS单位群**

常见误区：① 忽视邻居查询优化——直接O(n²)导致帧率暴跌；② 权重未调优——三力权重失衡导致群体行为不自然（如全部挤成一团或全部散开）；③ 边界处理粗暴——硬边界会让群体"撞墙"，应使用环绕或软排斥。调试技巧：可视化每个boid的三力向量，观察力的平衡；可视化空间哈希网格，检查密度分布。

# 第4章 战术与战斗AI

## 第11讲 效用系统（Utility System）

### 概念

效用系统（Utility System）是一种基于**评分决策**的AI架构，核心思想是"**为每个候选行为计算一个效用分数，选择分数最高的执行**"。与FSM的"条件触发"和行为树的"树遍历"不同，效用系统不预设行为优先级或转移路径，而是让所有行为**平等竞争**，由分数动态决定胜者。这种"涌现式决策"让AI表现出更自然、更灵活的行为，特别适合需要权衡多因素的复杂决策场景。

效用系统在游戏中的经典应用包括《模拟人生》（The Sims）系列——市民的需求（饥饿、社交、精力等）驱动行为选择；《辐射》系列的NPC决策；以及许多RTS的AI对手。效用系统的优势在于**自然处理多目标权衡**：一个NPC同时考虑"饥饿度高"、"附近有食物"、"敌人威胁大"等多个因素，综合评分后选择最优行为，而非硬编码的"如果饥饿则吃饭"。

### 原理

效用系统的核心机制是**评分函数（Scoring Function）**。每个行为关联一个评分函数，输入是当前世界状态，输出是0-1之间的效用分数。系统每帧（或按频率）计算所有可执行行为的分数，选择最高分行为执行。评分函数的设计是效用系统的艺术所在——好的函数能让AI表现出"智能权衡"，差的函数则导致AI行为混乱。

**评分函数的构建**通常基于**考虑因素（Considerations）**。每个考虑因素是一个输入变量（如"距离敌人的距离"、"自身血量"），通过**响应曲线（Response Curve）** 映射到0-1分数。多个考虑因素通过**组合方式**（乘法、加法、最大值等）合并为行为总分。这种"考虑因素 + 响应曲线 + 组合"的模块化设计，让评分逻辑可复用、可调试、可平衡。

**响应曲线（Response Curve）** 是将原始输入（如距离=15米）映射到效用分数（如0.7）的函数。常见曲线类型：
- **线性（Linear）**：`y = (x - min) / (max - min)`，简单直接
- **对数（Logistic）**：S形曲线，适合"中间敏感、两端平缓"的场景
- **指数（Exponential）**：`y = x^k`，k>1时强调高值，k<1时强调低值
- **阈值（Threshold）**：阶梯函数，超过阈值得1，否则得0
- **自定义（Custom）**：分段函数或样条曲线，精确控制

响应曲线的选择反映AI的"性格"——一个胆小的NPC对"敌人距离"用指数衰减曲线（远距离就害怕），一个勇敢的NPC用线性曲线（只有很近才在意）。

**考虑因素的组合方式**：
- **乘法（Product）**：所有因素都重要，任一为0则总分为0。适合"必要条件"组合。
- **加法（Sum）**：因素独立贡献，可互相补偿。适合"加分项"组合。
- **最大值（Max）**：取最高分因素。适合"任一满足即可"。
- **加权平均（Weighted Average）**：考虑因素重要性差异。

**惯性（Inertia）与迟滞（Hysteresis）** 是效用系统的重要优化。若每帧都选最高分行为，AI可能在两个相近分数的行为间频繁切换，表现"犹豫不决"。解决方案：① **执行阈值**——当前行为分数低于某阈值才考虑切换；② **迟滞**——切换到新行为需要其分数比当前行为高出一定裕度；③ **执行冷却**——行为执行后强制持续一段时间。

**效用系统的变体**：
- **无限效用系统（Infinite Utility System）**：分数无上限，更灵活但难平衡
- **复合效用（Composite Utility）**：行为本身是子效用系统，形成层级
- **效用行为树（Utility Behavior Tree）**：在行为树节点上应用效用评分

### 例子

下面实现一个完整的效用系统，模拟一个RPG角色的日常决策（吃饭、睡觉、社交、战斗、探索）：

```python
import math
from dataclasses import dataclass
from typing import List, Callable, Dict
from enum import Enum

class ActionType(Enum):
    EAT = "eat"
    SLEEP = "sleep"
    SOCIALIZE = "socialize"
    FIGHT = "fight"
    EXPLORE = "explore"
    FLEE = "flee"

# === 响应曲线 ===
def linear(x, min_val=0, max_val=1, slope=1, intercept=0):
    """线性曲线"""
    t = (x - min_val) / (max_val - min_val + 1e-9)
    t = max(0, min(1, t))
    return max(0, min(1, slope * t + intercept))

def logistic(x, midpoint=0.5, steepness=10):
    """逻辑斯蒂曲线（S形）"""
    t = (x - min_val) / (max_val - min_val + 1e-9) if 'min_val' in dir() else x
    return 1 / (1 + math.exp(-steepness * (x - midpoint)))

def exponential(x, k=2):
    """指数曲线"""
    return min(1, x ** k)

def inverse(x, min_val=0.1):
    """倒数曲线（距离越近分数越高）"""
    return min_val / (x + min_val)

# === 考虑因素 ===
@dataclass
class Consideration:
    name: str
    input_func: Callable
    response_curve: Callable
    weight: float = 1.0
    
    def score(self, context) -> float:
        raw = self.input_func(context)
        return self.response_curve(raw) * self.weight

# === 行为 ===
@dataclass
class UtilityAction:
    name: str
    action_type: ActionType
    considerations: List[Consideration]
    combo_method: str = "product"  # product / sum / max
    
    def score(self, context) -> float:
        scores = [c.score(context) for c in self.considerations]
        if not scores:
            return 0
        if self.combo_method == "product":
            result = 1.0
            for s in scores:
                result *= max(s, 0.01)  # 避免0导致全0
            return result
        elif self.combo_method == "sum":
            return sum(scores) / len(scores)
        elif self.combo_method == "max":
            return max(scores)
        return 0
    
    def execute(self, agent):
        print(f"  [{agent.name}] 执行: {self.name}")

# === 上下文（AI状态） ===
@dataclass
class Context:
    health: float = 100
    hunger: float = 0      # 0-100, 越高越饿
    energy: float = 100    # 0-100, 越低越累
    social: float = 50     # 0-100, 越低越想社交
    enemy_distance: float = 100  # 距离敌人
    enemy_threat: float = 0  # 0-1
    food_available: bool = True
    bed_available: bool = True
    friend_nearby: bool = False

# === 构建行为库 ===
def build_actions():
    actions = []
    
    # 吃饭：饥饿度高且有食物
    actions.append(UtilityAction(
        name="去吃饭",
        action_type=ActionType.EAT,
        considerations=[
            Consideration("hunger", lambda c: c.hunger/100, linear),
            Consideration("food", lambda c: 1.0 if c.food_available else 0.0, linear),
            Consideration("energy_cost", lambda c: 1.0 - c.enemy_threat, linear),  # 战斗时不想吃
        ],
        combo_method="product"
    ))
    
    # 睡觉：精力低且安全
    actions.append(UtilityAction(
        name="去睡觉",
        action_type=ActionType.SLEEP,
        considerations=[
            Consideration("tiredness", lambda c: (100-c.energy)/100, linear),
            Consideration("bed", lambda c: 1.0 if c.bed_available else 0.0, linear),
            Consideration("safety", lambda c: 1.0 - c.enemy_threat, exponential),
        ],
        combo_method="product"
    ))
    
    # 社交：社交需求高且有朋友
    actions.append(UtilityAction(
        name="找朋友聊天",
        action_type=ActionType.SOCIALIZE,
        considerations=[
            Consideration("social_need", lambda c: (100-c.social)/100, linear),
            Consideration("friend", lambda c: 1.0 if c.friend_nearby else 0.0, linear),
            Consideration("safety", lambda c: 1.0 - c.enemy_threat, linear),
        ],
        combo_method="product"
    ))
    
    # 战斗：敌人近且威胁大且自身健康
    actions.append(UtilityAction(
        name="迎战",
        action_type=ActionType.FIGHT,
        considerations=[
            Consideration("enemy_close", lambda c: inverse(c.enemy_distance, 10), linear),
            Consideration("threat", lambda c: c.enemy_threat, linear),
            Consideration("health", lambda c: c.health/100, linear),
            Consideration("courage", lambda c: 0.7, linear),  # 性格因素
        ],
        combo_method="product"
    ))
    
    # 逃跑：敌人威胁大但自身虚弱
    actions.append(UtilityAction(
        name="逃跑",
        action_type=ActionType.FLEE,
        considerations=[
            Consideration("threat", lambda c: c.enemy_threat, linear),
            Consideration("weakness", lambda c: (100-c.health)/100, linear),
        ],
        combo_method="product"
    ))
    
    # 探索：默认行为，分数较低
    actions.append(UtilityAction(
        name="四处探索",
        action_type=ActionType.EXPLORE,
        considerations=[
            Consideration("curiosity", lambda c: 0.3, linear),
            Consideration("safety", lambda c: 1.0 - c.enemy_threat, linear),
        ],
        combo_method="product"
    ))
    
    return actions

# === 效用系统 ===
class UtilitySystem:
    def __init__(self, actions: List[UtilityAction]):
        self.actions = actions
        self.current_action: UtilityAction = None
        self.hysteresis = 0.1  # 切换阈值
    
    def update(self, agent, context: Context):
        # 计算所有行为分数
        scored = [(a, a.score(context)) for a in self.actions]
        scored.sort(key=lambda x: -x[1])
        
        # 迟滞：新行为分数需比当前高hysteresis才切换
        best_action, best_score = scored[0]
        if self.current_action is None:
            self.current_action = best_action
        elif best_action != self.current_action:
            current_score = next(s for a, s in scored if a == self.current_action)
            if best_score > current_score + self.hysteresis:
                self.current_action = best_action
        
        # 执行
        self.current_action.execute(agent)
        
        # 调试输出
        return scored

# === 测试 ===
class Agent:
    def __init__(self, name):
        self.name = name

agent = Agent("Hero")
system = UtilitySystem(build_actions())

# 场景1：日常状态
print("=== 场景1: 日常状态 ===")
ctx = Context(health=100, hunger=30, energy=80, social=70, 
              enemy_distance=100, enemy_threat=0)
scored = system.update(agent, ctx)
for a, s in scored[:3]:
    print(f"  {a.name}: {s:.3f}")

# 场景2：饥饿且疲惫
print("\n=== 场景2: 饥饿且疲惫 ===")
ctx = Context(health=100, hunger=85, energy=20, social=70,
              enemy_distance=100, enemy_threat=0)
scored = system.update(agent, ctx)
for a, s in scored[:3]:
    print(f"  {a.name}: {s:.3f}")

# 场景3：敌人出现，自身虚弱
print("\n=== 场景3: 敌人出现，自身虚弱 ===")
ctx = Context(health=30, hunger=50, energy=50, social=50,
              enemy_distance=5, enemy_threat=0.8)
scored = system.update(agent, ctx)
for a, s in scored[:3]:
    print(f"  {a.name}: {s:.3f}")
```

### 总结

本讲重点回顾：
- 效用系统 = **评分函数 + 最高分选择**，行为平等竞争
- 核心组件：**考虑因素 + 响应曲线 + 组合方式**
- 响应曲线类型：**线性、对数、指数、阈值、自定义**
- 组合方式：**乘法（必要条件）、加法（加分项）、最大值（任一满足）**
- 优化：**惯性、迟滞、执行冷却**，避免行为频繁切换

适用场景：**多目标权衡、模拟生活类游戏、复杂NPC决策**。常见误区：① 评分函数过于复杂——难以调试和平衡，应保持简单；② 忽视迟滞——导致AI"精神分裂"般频繁切换行为；③ 用乘法组合所有因素——一个因素为0导致总分0，可能掩盖其他高分因素。调试技巧：可视化所有行为分数，观察分数变化趋势。

## 第12讲 模糊逻辑与决策

### 概念

模糊逻辑（Fuzzy Logic）由Lotfi Zadeh于1965年提出，是对经典布尔逻辑的扩展，允许**真值在0到1之间连续变化**。在游戏中，模糊逻辑用于处理**模糊、不确定、渐进式**的决策——例如"敌人距离近"不是非黑即白（近/远），而是"很近、较近、中等、较远、很远"的连续光谱。模糊逻辑让AI能像人类一样处理模糊概念，做出更自然的决策。

模糊逻辑在游戏中的典型应用包括：**模糊状态机（FuSM）**——状态不是互斥的，AI可以同时"部分"处于多个状态；**模糊控制**——如车辆AI根据"距离前车远近"和"速度差"模糊控制油门和刹车；**模糊战术评估**——评估"局势有利程度"等模糊概念。相比二元逻辑，模糊逻辑的输出更平滑，避免"硬切换"带来的不自然。

### 原理

模糊逻辑的核心概念包括：

**1. 模糊集合（Fuzzy Set）**：经典集合中元素要么属于（1）要么不属于（0）；模糊集合中元素以**隶属度（Membership Degree）** 0-1表示属于程度。例如"距离近"的模糊集合：5米隶属度0.9，10米隶属度0.5，20米隶属度0.1，30米隶属度0。

**2. 隶属函数（Membership Function）**：将输入映射到隶属度的函数。常见形状：
- **三角形（Triangular）**：`μ(x) = max(0, 1 - |x - c| / w)`，简单高效
- **梯形（Trapezoidal）**：三角形顶部扩展为平台
- **高斯型（Gaussian）**：`μ(x) = exp(-(x-c)²/(2σ²))`，平滑
- **S形（Sigmoid）**：`μ(x) = 1/(1+exp(-k(x-c)))`，适合"大于某值"的模糊集

**3. 模糊化（Fuzzification）**：将精确输入（如距离=15米）通过隶属函数转换为模糊隶属度（如"近"=0.3, "中"=0.7, "远"=0.1）。

**4. 模糊规则（Fuzzy Rules）**：IF-THEN规则，前提和结论都是模糊的。例如"IF 距离近 AND 速度快 THEN 刹车力度大"。规则前提通过模糊逻辑运算（AND用min，OR用max，NOT用1-μ）组合。

**5. 模糊推理（Fuzzy Inference）**：根据规则计算输出模糊集合。常用方法：
- **Mamdani推理**：规则结论的隶属度被前提真值"截断"，形成输出模糊集
- **Sugeno推理**：规则结论是精确函数（如线性组合），输出是加权平均

**6. 去模糊化（Defuzzification）**：将输出模糊集合转换为精确值。常用方法：
- **重心法（Centroid）**：取模糊集的重心，最常用
- **最大隶属度法（Max Membership）**：取隶属度最大的点
- **加权平均法（Weighted Average）**：各规则输出加权平均

**完整模糊控制流程**：精确输入 → 模糊化 → 模糊规则匹配 → 模糊推理 → 去模糊化 → 精确输出。

**模糊状态机（FuSM）** 是模糊逻辑在状态机上的应用。传统FSM中AI只在一个状态；FuSM中AI可以**同时以不同隶属度处于多个状态**。例如AI可以"70%巡逻 + 30%警戒"，行为是两种状态动作的加权混合。FuSM适合需要平滑过渡的场景，如车辆驾驶AI。

### 例子

下面实现一个模糊逻辑控制器，模拟赛车AI根据"距离前车"和"当前速度"决定"油门/刹车"力度：

```python
import numpy as np
import math
from typing import Dict, List, Tuple, Callable
from dataclasses import dataclass

# === 隶属函数 ===
def triangular(x, a, b, c):
    """三角形隶属函数：a=左脚, b=顶点, c=右脚"""
    if x <= a or x >= c:
        return 0.0
    elif x == b:
        return 1.0
    elif x < b:
        return (x - a) / (b - a)
    else:
        return (c - x) / (c - b)

def trapezoidal(x, a, b, c, d):
    """梯形隶属函数"""
    if x <= a or x >= d:
        return 0.0
    elif b <= x <= c:
        return 1.0
    elif x < b:
        return (x - a) / (b - a)
    else:
        return (d - x) / (d - c)

def sigmoid(x, c, k):
    """S形隶属函数"""
    return 1.0 / (1.0 + math.exp(-k * (x - c)))

# === 模糊集合定义 ===
# 输入1：距离前车（0-100米）
distance_sets = {
    "very_close": lambda x: trapezoidal(x, 0, 0, 5, 15),
    "close": lambda x: triangular(x, 10, 20, 30),
    "medium": lambda x: triangular(x, 25, 40, 55),
    "far": lambda x: triangular(x, 50, 70, 90),
    "very_far": lambda x: trapezoidal(x, 85, 100, 100, 100),
}

# 输入2：当前速度（0-200 km/h）
speed_sets = {
    "slow": lambda x: trapezoidal(x, 0, 0, 30, 60),
    "medium": lambda x: triangular(x, 50, 90, 130),
    "fast": lambda x: trapezoidal(x, 110, 150, 200, 200),
}

# 输出：油门力度（0-1）
throttle_sets = {
    "none": lambda x: trapezoidal(x, 0, 0, 0.1, 0.2),
    "light": lambda x: triangular(x, 0.1, 0.3, 0.5),
    "moderate": lambda x: triangular(x, 0.4, 0.6, 0.8),
    "full": lambda x: trapezoidal(x, 0.7, 0.9, 1.0, 1.0),
}

# === 模糊规则 ===
# (距离集合, 速度集合) -> 油门集合
rules = [
    ("very_close", "slow", "none"),
    ("very_close", "medium", "none"),
    ("very_close", "fast", "none"),
    ("close", "slow", "light"),
    ("close", "medium", "none"),
    ("close", "fast", "none"),
    ("medium", "slow", "moderate"),
    ("medium", "medium", "light"),
    ("medium", "fast", "light"),
    ("far", "slow", "full"),
    ("far", "medium", "moderate"),
    ("far", "fast", "light"),
    ("very_far", "slow", "full"),
    ("very_far", "medium", "full"),
    ("very_far", "fast", "moderate"),
]

class FuzzyController:
    def __init__(self, input_sets, output_sets, rules):
        self.input_sets = input_sets
        self.output_sets = output_sets
        self.rules = rules
    
    def fuzzify(self, value, sets) -> Dict[str, float]:
        """模糊化：精确值 -> 各集合隶属度"""
        return {name: func(value) for name, func in sets.items()}
    
    def apply_rules(self, distance_membership, speed_membership) -> Dict[str, float]:
        """应用规则：返回每个输出集合的激活强度"""
        output_activation = {name: 0.0 for name in self.output_sets}
        
        for dist_set, spd_set, out_set in self.rules:
            # AND用min
            activation = min(
                distance_membership[dist_set],
                speed_membership[spd_set]
            )
            # OR用max（同一输出集合可能被多条规则激活）
            output_activation[out_set] = max(
                output_activation[out_set],
                activation
            )
        
        return output_activation
    
    def defuzzify_centroid(self, activation, output_sets, 
                          x_min=0, x_max=1, steps=100) -> float:
        """重心法去模糊化"""
        xs = np.linspace(x_min, x_max, steps)
        # 计算聚合后的模糊集（各输出集合的min截断后取max）
        aggregated = np.zeros(steps)
        for name, act in activation.items():
            if act > 0:
                for i, x in enumerate(xs):
                    # Mamdani推理：min(激活强度, 隶属度)
                    aggregated[i] = max(aggregated[i], 
                                       min(act, output_sets[name](x)))
        
        # 重心法
        numerator = np.sum(xs * aggregated)
        denominator = np.sum(aggregated)
        if denominator == 0:
            return 0.0
        return numerator / denominator
    
    def evaluate(self, distance, speed) -> float:
        """完整模糊控制流程"""
        # 1. 模糊化
        dist_mem = self.fuzzify(distance, distance_sets)
        spd_mem = self.fuzzify(speed, speed_sets)
        
        # 2. 应用规则
        activation = self.apply_rules(dist_mem, spd_mem)
        
        # 3. 去模糊化
        output = self.defuzzify_centroid(activation, throttle_sets)
        return output
```

- 模糊逻辑允许**真值在0-1连续变化**，处理模糊、渐进概念
- 核心流程：**模糊化 → 规则匹配 → 模糊推理 → 去模糊化**
- 隶属函数：**三角形、梯形、高斯、S形**
- 推理方法：**Mamdani（截断）、Sugeno（函数）**
- 去模糊化：**重心法（最常用）、最大隶属度、加权平均**
- 模糊状态机（FuSM）：AI可同时以不同隶属度处于多状态

## 第13讲 战术评估与掩护系统

### 概念

战术评估（Tactical Evaluation）和掩护系统（Cover System）是FPS、TPS、战术游戏AI的核心技术，让NPC表现出**军事化的智能行为**——寻找掩护、侧翼包抄、火力压制、协同进攻。本讲聚焦两个关键问题：① 如何评估地图上的战术位置价值（战术点评估）；② 如何让NPC智能利用掩护进行战斗。

战术点（Tactical Point）是地图上具有战术价值的位置，如掩护点、狙击点、伏击点。战术评估系统为每个候选位置计算综合分数，考虑**掩护质量、视野范围、敌人威胁、可达性、与队友协同**等因素。掩护系统则让NPC在战斗中动态选择、利用、转移掩护点，形成"打-躲-移动-打"的战斗节奏。

### 原理

**战术点评估**的核心是**多因素加权评分**。每个候选位置根据多个"考虑因素"评分，因素包括：
- **掩护质量（Cover Quality）**：位置能阻挡多少方向来的火力？通常用"被多少面墙包围"或"到最近障碍物的距离"衡量
- **视野范围（Field of View）**：从该位置能看到多少区域？用视线检测计算可见格子数
- **威胁暴露（Threat Exposure）**：该位置暴露在多少敌人火力下？用"到敌人的距离"和"是否有视线"衡量
- **可达性（Accessibility）**：NPC能否快速到达？用寻路距离衡量
- **战术优势（Tactical Advantage）**：是否高地？是否侧翼？是否扼守要道？

**Unreal Engine的EQS（Environment Query System）** 是工业级战术评估系统的典范。EQS通过**生成器（Generator）** 产生候选点集合，通过**测试（Test）** 评分，通过**上下文（Context）** 提供参考信息（如"所有敌人位置"），最终返回最优点。这种"生成-测试-选择"的架构高度灵活，是现代游戏AI的标准实践。

**掩护系统的核心机制**：

**1. 掩护点生成**：在场景中自动或手动标记掩护点。自动方法：沿墙壁每隔1-2米采样一个点，检查该点是否能提供掩护（前方有可遮挡的障碍物）。手动方法：关卡设计师在编辑器中放置掩护点标记。

**2. 掩护点分类**：
- **硬掩护（Hard Cover）**：完全阻挡视线和子弹（如混凝土墙）
- **软掩护（Soft Cover）**：阻挡视线但不完全阻挡子弹（如灌木丛、薄板）
- **部分掩护（Partial Cover）**：仅阻挡特定方向（如墙角）

**3. 掩护点状态**：每个掩护点维护状态——空闲、被占用、被压制（敌人火力覆盖）、已失效（被破坏）。NPC选择掩护点时排除已占用或失效的点。

**4. 掩护行为**：
- **进入掩护**：移动到掩护点，进入蹲伏/靠墙姿势
- **观察掩护**：从掩护边缘探头观察敌人
- **盲射**：不探头朝敌人方向射击（精度低但安全）
- **精准射击**：探头射击（精度高但暴露）
- **转移掩护**：当前掩护被压制或失效时，转移到新掩护

**5. 火力压制（Suppression）** 是掩护战斗的关键机制。当某区域被密集火力覆盖时，该区域的掩护点被标记为"被压制"，NPC不会选择进入。这模拟了真实战斗中"火力压制让敌人不敢露头"的战术。游戏《 Brothers in Arms》《Red Orchestra》深度实现了这一机制。

**侧翼包抄（Flanking）** 是高级战术行为。NPC不直接朝敌人前进，而是绕到敌人侧翼或后方攻击。实现方法：在敌人周围生成"侧翼候选点"（敌人侧后方一定距离），评估这些点的可达性和隐蔽性，选择最优点作为移动目标。这要求NPC有"敌人朝向"的感知能力。

**协同战术（Coordinated Tactics）** 让多个NPC配合行动。经典模式：
- **压制+侧翼**：一组NPC火力压制敌人，另一组侧翼包抄
- **交替掩护前进**：A组射击时B组移动，然后交换
- **包围**：多组NPC从不同方向接近敌人

实现协同需要**通信机制**——NPC共享战术状态（"我在压制"、"我需要掩护"），通常通过黑板或事件系统完成。

### 例子

下面实现一个战术评估与掩护系统，模拟FPS战斗中的掩护选择：

```python
import numpy as np
import math
from dataclasses import dataclass, field
from typing import List, Dict, Tuple, Optional
from enum import Enum

class CoverType(Enum):
    HARD = "hard"      # 硬掩护
    SOFT = "soft"      # 软掩护
    PARTIAL = "partial"  # 部分掩护

@dataclass
class CoverPoint:
    id: int
    position: Tuple[float, float, float]
    cover_type: CoverType
    cover_direction: Tuple[float, float]  # 掩护朝向（朝向敌人的反方向）
    height: float = 1.0  # 掩护高度
    
    # 运行时状态
    occupied_by: Optional[int] = None  # 占用者ID
    suppressed: float = 0.0  # 压制程度 0-1
    validity: float = 1.0  # 有效性 0-1
    
    def is_available(self) -> bool:
        return (self.occupied_by is None and 
                self.suppressed < 0.7 and 
                self.validity > 0.3)

@dataclass
class Enemy:
    id: int
    position: Tuple[float, float, float]
    facing: Tuple[float, float]
    threat_level: float = 1.0

class TacticalEvaluator:
    """战术点评估器"""
    
    def __init__(self, cover_points: List[CoverPoint]):
        self.cover_points = cover_points
        # 评分权重
        self.weights = {
            'cover_quality': 1.5,
            'threat_exposure': 1.0,
            'accessibility': 0.8,
            'flanking': 1.2,
            'suppression_penalty': 2.0,
        }
    
    def evaluate_cover(self, cover: CoverPoint, npc_pos, enemies: List[Enemy],
                      allies: List[int] = None) -> float:
        """评估单个掩护点的综合分数"""
        # 1. 掩护质量：硬掩护 > 软掩护 > 部分掩护
        cover_quality = {
            CoverType.HARD: 1.0,
            CoverType.SOFT: 0.5,
            CoverType.PARTIAL: 0.7
        }[cover.cover_type]
        
        # 2. 威胁暴露：暴露在多少敌人火力下
        threat_exposure = 0
        for enemy in enemies:
            if self._has_line_of_sight(cover.position, enemy.position):
                # 检查掩护是否朝向敌人
                to_enemy = np.array(enemy.position) - np.array(cover.position)
                cover_dir = np.array(cover.cover_direction)
                alignment = np.dot(to_enemy[:2], cover_dir) / (
                    np.linalg.norm(to_enemy[:2]) * np.linalg.norm(cover_dir) + 1e-9)
                # 掩护方向与敌人方向越对齐，掩护效果越好
                cover_effectiveness = max(0, alignment)
                threat_exposure += enemy.threat_level * (1 - cover_effectiveness)
        threat_exposure = min(1.0, threat_exposure / max(len(enemies), 1))
        
        # 3. 可达性：到NPC的距离
        dist = np.linalg.norm(np.array(cover.position) - np.array(npc_pos))
        accessibility = 1.0 / (1.0 + dist / 20.0)  # 距离越近分数越高
        
        # 4. 侧翼优势：是否在敌人侧翼
        flanking_score = 0
        for enemy in enemies:
            to_cover = np.array(cover.position) - np.array(enemy.position)
            enemy_facing = np.array(enemy.facing)
            # 与敌人朝向的夹角
            angle = np.dot(to_cover[:2], enemy_facing) / (
                np.linalg.norm(to_cover[:2]) * np.linalg.norm(enemy_facing) + 1e-9)
            # 在敌人后方（angle < -0.5）得分最高
            if angle < -0.5:
                flanking_score = max(flanking_score, 1.0)
            elif angle < 0:
                flanking_score = max(flanking_score, 0.5)
        
        # 5. 压制惩罚
        suppression_penalty = cover.suppressed
        
        # 综合评分
        score = (
            cover_quality * self.weights['cover_quality'] +
            (1 - threat_exposure) * self.weights['threat_exposure'] +
            accessibility * self.weights['accessibility'] +
            flanking_score * self.weights['flanking'] -
            suppression_penalty * self.weights['suppression_penalty']
        )
        
        return score
    
    def find_best_cover(self, npc_pos, enemies, exclude_ids=None) -> Optional[CoverPoint]:
        """寻找最佳掩护点"""
        exclude_ids = exclude_ids or set()
        best_cover = None
        best_score = -float('inf')
        
        for cover in self.cover_points:
            if cover.id in exclude_ids:
                continue
            if not cover.is_available():
                continue
            score = self.evaluate_cover(cover, npc_pos, enemies)
            if score > best_score:
                best_score = score
                best_cover = cover
        
        return best_cover
    
    def _has_line_of_sight(self, pos_a, pos_b) -> bool:
        """简化视线检测（实际中用射线检测）"""
        # 假设无障碍物，简化为True
        return True

class CoverCombatAI:
    """掩护战斗AI"""
    
    def __init__(self, npc_id, evaluator: TacticalEvaluator):
        self.npc_id = npc_id
        self.evaluator = evaluator
        self.current_cover: Optional[CoverPoint] = None
        self.state = "advancing"  # advancing / in_cover / shooting / relocating
        self.state_timer = 0
        self.shoot_duration = 1.5
        self.hide_duration = 2.0
    
    def update(self, npc_pos, enemies, dt):
        self.state_timer += dt
        
        if self.state == "advancing":
            # 寻找掩护
            cover = self.evaluator.find_best_cover(
                npc_pos, enemies, 
                exclude_ids={self.current_cover.id} if self.current_cover else set()
            )
            if cover:
                self.current_cover = cover
                cover.occupied_by = self.npc_id
                self._move_to(cover.position)
                if self._at_position(cover.position, npc_pos):
                    self.state = "in_cover"
                    self.state_timer = 0
        
        elif self.state == "in_cover":
            # 在掩护中观察，准备射击
            if self.state_timer > self.hide_duration:
                self.state = "shooting"
                self.state_timer = 0
                self._pop_out_and_shoot(enemies)
        
        elif self.state == "shooting":
            # 探头射击
            if self.state_timer > self.shoot_duration:
                self.state = "in_cover"
                self.state_timer = 0
                self._pop_back()
            
            # 检查是否需要转移（被压制或掩护失效）
            if self.current_cover and self.current_cover.suppressed > 0.7:
                self._release_current_cover()
                self.state = "advancing"
                self.state_timer = 0
        
        elif self.state == "relocating":
            if self._at_position(self.current_cover.position, npc_pos):
                self.state = "in_cover"
                self.state_timer = 0
    
    def _release_current_cover(self):
        if self.current_cover:
            self.current_cover.occupied_by = None
            self.current_cover = None
    
    def _move_to(self, position):
        print(f"  [NPC {self.npc_id}] 移动到 {position}")
    
    def _at_position(self, target, current, threshold=1.0):
        return np.linalg.norm(np.array(target) - np.array(current)) < threshold
    
    def _pop_out_and_shoot(self, enemies):
        if enemies:
            target = enemies[0]
            print(f"  [NPC {self.npc_id}] 探头射击敌人 {target.id}")
    
    def _pop_back(self):
        print(f"  [NPC {self.npc_id}] 缩回掩护")

cover_points = [

    CoverPoint(3, (20, 0, 0), CoverType.HARD, (1, 0)),

]
```

- 工业标准：**Unreal EQS** 的"生成-测试-选择"架构

# 第5章 高级决策架构

## 第14讲 分层任务网络（HTN）

### 概念

分层任务网络（Hierarchical Task Network, HTN）是一种基于**任务分解**的AI规划架构，起源于AI规划研究，在《Transformers: Fall of Cybertron》《Guerrilla Games的Killzone》等游戏中得到工业应用。HTN的核心思想是：AI有一个"目标任务"，通过**递归分解**为更小的子任务，直到分解为可直接执行的"原子任务"。与行为树的"反应式选择"不同，HTN是**前瞻式规划**——一次性规划出完整的任务序列，再依次执行。

HTN与行为树的根本差异在于"**规划 vs 反应**"。行为树每帧重新评估，根据当前状态选择行为，是"走一步看一步"的反应式决策；HTN在决策时一次性规划出未来多步的行为序列，是"谋定而后动"的前瞻式规划。这种差异让HTN特别适合需要**长程规划**的场景——如RTS的建造序列、RPG的剧情推进、战术游戏的多人协同。

### 原理

HTN的核心概念包括：

**1. 任务（Task）**：HTN的基本单元，分为两类：
- **复合任务（Compound Task）**：可分解为子任务的高层任务，定义了"如何完成"的方法
- **原子任务（Primitive Task）**：不可分解的底层任务，直接执行（如"移动到"、"攻击"）

**2. 方法（Method）**：复合任务的分解方案。一个复合任务可以有多个方法，每个方法定义了"在什么条件下，分解为哪些子任务"。方法包含**前提条件（Precondition）** 和**子任务列表（Subtasks）**。规划器根据当前世界状态选择满足前提的方法。

**3. 世界状态（World State）**：HTN维护一个世界状态（键值对），任务执行会修改状态。规划器在规划时**模拟**任务执行，预测状态变化，确保后续任务的前提满足。

**4. 规划过程**：
- 输入：目标任务 + 当前世界状态
- 过程：递归分解复合任务，选择满足前提的方法，将子任务加入计划
- 输出：原子任务序列（计划）

**HTN规划算法**（基本版本）：
```
function HTNPlan(task, state):
    if task 是原子任务:
        if task.前提满足(state):
            return [task]
        else:
            return 失败
    
    for method in task.方法列表:
        if method.前提满足(state):
            new_state = state.copy()
            subplan = []
            for subtask in method.子任务:
                result = HTNPlan(subtask, new_state)
                if result == 失败:
                    break  # 尝试下一个方法
                subplan.extend(result)
                # 模拟执行，更新状态
                for t in result:
                    new_state = t.效果(new_state)
            else:
                return subplan  # 所有子任务成功
    return 失败  # 所有方法都失败
```

**HTN vs 行为树 vs GOAP 对比**：
| 维度 | 行为树 | HTN | GOAP |
|------|--------|-----|------|
| 决策方式 | 反应式 | 前瞻式规划 | 前瞻式规划 |
| 知识表示 | 树结构 | 任务分解规则 | 目标+动作 |
| 规划深度 | 1步 | 多步 | 多步 |
| 表达力 | 中 | 高 | 高 |
| 性能 | 高 | 中 | 低 |
| 调试 | 直观 | 较复杂 | 复杂 |

**HTN的优势**：
- **长程规划**：能规划出多步行为序列，适合复杂任务
- **领域知识编码**：设计师通过方法定义"如何完成任务"，将专家知识编码进AI
- **可预测**：规划结果明确，调试相对容易
- **性能可控**：相比GOAP的全局搜索，HTN的搜索空间受方法约束

**HTN的局限**：
- **知识工程量大**：需要设计师手动编写大量方法和分解规则
- **灵活性低**：方法的前提是硬编码的，难以应对未预见情况
- **重规划成本**：世界状态变化时需要重新规划，可能卡顿

下面实现一个HTN框架，模拟一个RPG角色的"打怪升级"任务规划：

```python
from dataclasses import dataclass, field
from typing import List, Dict, Callable, Optional, Any
from enum import Enum

class TaskType(Enum):
    PRIMITIVE = "primitive"
    COMPOUND = "compound"

@dataclass
class WorldState:
    """世界状态（键值对）"""
    state: Dict[str, Any] = field(default_factory=dict)
    
    def copy(self):
        return WorldState(self.state.copy())
    
    def get(self, key, default=None):
        return self.state.get(key, default)
    
    def set(self, key, value):
        self.state[key] = value
    
    def has(self, key):
        return key in self.state

@dataclass
class PrimitiveTask:
    name: str
    precondition: Callable[[WorldState], bool]
    effect: Callable[[WorldState], WorldState]
    execute: Callable[[Any], None] = None
    
    @property
    def type(self):
        return TaskType.PRIMITIVE

@dataclass
class Method:
    name: str
    precondition: Callable[[WorldState], bool]
    subtasks: List[str]  # 子任务名（引用任务库）

@dataclass
class CompoundTask:
    name: str
    methods: List[Method]
    
    @property
    def type(self):
        return TaskType.COMPOUND

class HTNDomain:
    """HTN领域定义"""
    def __init__(self):
        self.tasks: Dict[str, Any] = {}
    
    def add_primitive(self, task: PrimitiveTask):
        self.tasks[task.name] = task
    
    def add_compound(self, task: CompoundTask):
        self.tasks[task.name] = task

class HTNPlanner:
    def __init__(self, domain: HTNDomain):
        self.domain = domain
    
    def plan(self, root_task: str, world_state: WorldState) -> Optional[List[PrimitiveTask]]:
        """规划：返回原子任务序列，或None表示失败"""
        result = self._decompose(root_task, world_state)
        if result is None:
            return None
        return [t for t in result if isinstance(t, PrimitiveTask)]
    
    def _decompose(self, task_name: str, world_state: WorldState) -> Optional[List]:
        task = self.domain.tasks.get(task_name)
        if task is None:
            return None
        
        if isinstance(task, PrimitiveTask):
            if task.precondition(world_state):
                # 模拟执行效果
                new_state = task.effect(world_state.copy())
                return [(task, new_state)]
            return None
        
        elif isinstance(task, CompoundTask):
            # 尝试每个方法
            for method in task.methods:
                if not method.precondition(world_state):
                    continue
                
                # 尝试分解这个方法的所有子任务
                current_state = world_state.copy()
                subplan = []
                success = True
                
                for subtask_name in method.subtasks:
                    result = self._decompose(subtask_name, current_state)
                    if result is None:
                        success = False
                        break
                    # 更新状态（取最后一个任务后的状态）
                    for t, s in result:
                        subplan.append((t, s))
                        current_state = s
                
                if success:
                    return subplan
            
            return None  # 所有方法都失败

# === 定义RPG领域 ===
def build_rpg_domain():
    domain = HTNDomain()
    
    # === 原子任务 ===
    domain.add_primitive(PrimitiveTask(
        name="MoveToEnemy",
        precondition=lambda ws: ws.has("enemy_position") and not ws.get("at_enemy", False),
        effect=lambda ws: (ws.set("at_enemy", True), ws.set("at_town", False), ws)[2],
        execute=lambda agent: print("  -> 移动到敌人位置")
    ))
    
    domain.add_primitive(PrimitiveTask(
        name="AttackEnemy",
        precondition=lambda ws: ws.get("at_enemy", False) and ws.get("enemy_alive", True),
        effect=lambda ws: (ws.set("enemy_alive", False), ws.set("exp", ws.get("exp", 0) + 100), ws)[2],
        execute=lambda agent: print("  -> 攻击并击败敌人")
    ))
    
    domain.add_primitive(PrimitiveTask(
        name="LootEnemy",
        precondition=lambda ws: not ws.get("enemy_alive", True) and ws.get("at_enemy", False),
        effect=lambda ws: (ws.set("gold", ws.get("gold", 0) + 50), ws)[2],
        execute=lambda agent: print("  -> 拾取战利品")
    ))
    
    domain.add_primitive(PrimitiveTask(
        name="MoveToTown",
        precondition=lambda ws: not ws.get("at_town", False),
        effect=lambda ws: (ws.set("at_town", True), ws.set("at_enemy", False), ws)[2],
        execute=lambda agent: print("  -> 返回城镇")
    ))
    
    domain.add_primitive(PrimitiveTask(
        name="BuyPotion",
        precondition=lambda ws: ws.get("at_town", False) and ws.get("gold", 0) >= 20,
        effect=lambda ws: (ws.set("potions", ws.get("potions", 0) + 1), 
                          ws.set("gold", ws.get("gold", 0) - 20), ws)[2],
        execute=lambda agent: print("  -> 购买药水")
    ))
    
    domain.add_primitive(PrimitiveTask(
        name="LevelUp",
        precondition=lambda ws: ws.get("exp", 0) >= 100,
        effect=lambda ws: (ws.set("level", ws.get("level", 1) + 1),
                          ws.set("exp", ws.get("exp", 0) - 100), ws)[2],

    ))
    
    # === 复合任务 ===
    domain.add_compound(CompoundTask(
        name="DefeatEnemy",
        methods=[
            Method(
                name="StandardBattle",

                subtasks=["MoveToEnemy", "AttackEnemy", "LootEnemy"]

        name="ShopAndRest",
        methods=[
            Method(
                name="BuySupplies",
                precondition=lambda ws: ws.get("gold", 0) >= 20 and ws.get("potions", 0) < 3,
                subtasks=["MoveToTown", "BuyPotion"]
            ),
        ]
    ))
    
    domain.add_compound(CompoundTask(
        name="Adventure",
        methods=[
            Method(
                name="FullAdventure",
                precondition=lambda ws: True,  # 总是可用
                subtasks=["DefeatEnemy", "ShopAndRest", "LevelUp"]

        ]
```

### 总结

本讲重点回顾：
- HTN基于**任务递归分解**，复合任务通过方法分解为子任务
- 核心组件：**复合任务、原子任务、方法、世界状态**
- 规划过程：**递归分解 + 状态模拟**，一次性生成完整计划
- 与行为树差异：**前瞻式规划 vs 反应式选择**
- 优势：**长程规划、领域知识编码、可预测**
- 局限：**知识工程量大、灵活性低、重规划成本**

适用场景：**RTS建造序列、RPG剧情推进、战术协同、需要连贯行为序列的AI**。常见误区：① 方法前提过于严格——导致规划频繁失败；② 任务层次过深——规划性能下降，应控制在3-4层；③ 忽视重规划——世界状态变化时未重新规划，导致行为脱节。调试技巧：打印规划过程和状态变化，理解AI的"思考"过程。

## 第15讲 目标导向行动规划（GOAP）

### 概念

目标导向行动规划（Goal-Oriented Action Planning, GOAP）是Jeff Orkin在《F.E.A.R.》（2005）中工业化的AI规划架构，基于经典AI的STRIPS规划。GOAP的核心思想是：AI有一个**目标（Goal）**，通过**搜索**一组**动作（Action）** 序列，使世界状态从当前状态转变为目标状态。与HTN的"任务分解"不同，GOAP是"**目标驱动的前向/反向搜索**"——设计师只定义动作和目标，AI自己搜索如何达成目标。

GOAP与HTN的关键差异在于"**知识表示**"。HTN需要设计师编写"如何完成任务"的方法（分解规则），知识工程量大但搜索空间小；GOAP只需定义"动作的效果"和"目标条件"，AI通过搜索自动发现动作序列，知识工程量小但搜索空间大。GOAP更"智能"但也更难控制——AI可能规划出设计师未预见的行为序列，这既是优势（涌现性）也是风险（不可预测）。

### 原理

**GOAP的核心组件**：

**1. 世界状态（World State）**：键值对表示，如`{has_weapon: true, enemy_visible: true, health: 50}`。GOAP的所有推理基于世界状态。

**2. 动作（Action）**：每个动作定义：
- **前提条件（Precondition）**：执行前世界状态必须满足的条件
- **效果（Effect）**：执行后世界状态的变化
- **成本（Cost）**：执行代价，规划器寻找总成本最小的计划

**3. 目标（Goal）**：期望的世界状态，如`{enemy_dead: true}`。目标可以是硬性（必须满足）或软性（优先满足）。

**4. 规划器（Planner）**：搜索从当前状态到目标状态的动作序列。常用算法：
- **A***：将"状态差异"作为启发式，搜索成本最小的动作序列
- **前向搜索**：从当前状态开始，尝试所有可执行动作，直到达到目标
- **反向搜索**：从目标状态开始，反向寻找能产生目标状态的动作

**A*规划算法**（GOAP常用）：
```
function GOAPPlan(current_state, goal):
    open_set = 优先队列
    open_set.add(Node(state=current_state, g=0, h=heuristic(current_state, goal)))
    closed_set = {}
    
    while open_set 非空:
        current = open_set.pop()  # f = g + h 最小
        
        if goal.满足(current.state):
            return 重建路径(current)
        
        closed_set.add(current.state)
        
        for action in 可执行动作(current.state):
            new_state = action.效果(current.state)
            if new_state in closed_set:
                continue
            g = current.g + action.cost
            h = heuristic(new_state, goal)
            open_set.add(Node(state=new_state, g=g, h=h, parent=current, action=action))
    
    return 失败
```

**启发式函数**：通常用"当前状态与目标状态的差异"——即目标中未满足的条件数。这是可采纳的（不高估实际成本），保证A*找到最优解。

**GOAP的优势**：
- **涌现性**：AI能规划出设计师未预见的动作序列
- **知识工程量小**：只需定义动作，无需编写分解规则
- **灵活性强**：新增动作自动融入规划，无需修改现有逻辑
- **目标驱动**：AI行为有明确目的，表现"有意图"

**GOAP的局限**：
- **性能开销**：搜索空间大，规划耗时，需控制动作数量
- **不可预测**：AI可能规划出意外行为，调试困难
- **成本平衡**：动作成本设计不当会导致AI选择次优路径
- **状态表示**：世界状态需要离散化，连续值难以处理

**GOAP的优化**：
- **动作预过滤**：规划前过滤掉前提不满足的动作，减少搜索空间
- **目标优先级**：多个目标时按优先级规划
- **计划缓存**：相似状态复用之前的计划
- **增量规划**：世界状态变化小时，修补现有计划而非重新规划

**GOAP vs HTN 的选择**：
- 需要涌现性、动作组合灵活：选GOAP
- 需要可控性、设计师主导：选HTN
- 实际项目常**混合使用**：HTN处理高层任务分解，GOAP处理具体目标规划

### 例子

下面实现一个GOAP规划器，模拟一个FPS敌人的战斗规划：

```python
from dataclasses import dataclass, field
from typing import List, Dict, Set, Callable, Optional, Any
import heapq

@dataclass
class WorldState:
    """世界状态：键值对，值是布尔或数字"""
    state: Dict[str, Any] = field(default_factory=dict)
    
    def copy(self):
        return WorldState(self.state.copy())
    
    def get(self, key, default=None):
        return self.state.get(key, default)
    
    def set(self, key, value):
        self.state[key] = value
        return self
    
    def matches(self, goal_state: Dict[str, Any]) -> bool:
        """检查是否满足目标条件"""
        for k, v in goal_state.items():
            if self.state.get(k) != v:
                return False
        return True
    
    def apply_effect(self, effect: Dict[str, Any]):
        """应用效果"""
        for k, v in effect.items():
            self.state[k] = v
        return self
    
    def __hash__(self):
        return hash(frozenset(self.state.items()))
    
    def __eq__(self, other):
        return self.state == other.state

@dataclass
class GOAPAction:
    name: str
    cost: float
    precondition: Dict[str, Any]
    effect: Dict[str, Any]
    execute: Optional[Callable] = None
    
    def is_precondition_satisfied(self, ws: WorldState) -> bool:
        for k, v in self.precondition.items():
            if ws.get(k) != v:
                return False
        return True
    
    def apply(self, ws: WorldState) -> WorldState:
        new_ws = ws.copy()
        return new_ws.apply_effect(self.effect)

@dataclass
class GOAPGoal:
    name: str
    condition: Dict[str, Any]
    priority: int = 1

class GOAPPlanner:
    def __init__(self, actions: List[GOAPAction]):
        self.actions = actions
    
    def plan(self, current_state: WorldState, goal: GOAPGoal) -> Optional[List[GOAPAction]]:
        """A*规划"""
        start = current_state.copy()
        
        # 检查是否已满足目标
        if start.matches(goal.condition):
            return []
        
        # A*搜索
        open_heap = []
        counter = 0
        heapq.heappush(open_heap, (0, counter, start, []))
        closed_set: Set = set()
        
        while open_heap:
            f, _, state, path = heapq.heappop(open_heap)
            
            state_hash = hash(frozenset(state.state.items()))
            if state_hash in closed_set:
                continue
            closed_set.add(state_hash)
            
            if state.matches(goal.condition):
                return path
            
            for action in self.actions:
                if not action.is_precondition_satisfied(state):
                    continue
                new_state = action.apply(state)
                new_state_hash = hash(frozenset(new_state.state.items()))
                if new_state_hash in closed_set:
                    continue
                
                g = sum(a.cost for a in path) + action.cost
                h = self._heuristic(new_state, goal.condition)
                f_new = g + h
                
                counter += 1
                heapq.heappush(open_heap, (f_new, counter, new_state, path + [action]))
        
        return None
    
    def _heuristic(self, state: WorldState, goal: Dict[str, Any]) -> float:
        """启发式：未满足的目标条件数"""
        count = 0
        for k, v in goal.items():
            if state.get(k) != v:
                count += 1
        return count

# === 定义FPS敌人的GOAP领域 ===
def build_fps_domain():
    actions = [
        GOAPAction(
            name="PickUpWeapon",
            cost=2.0,
            precondition={"weapon_available": True, "armed": False},
            effect={"armed": True},
            execute=lambda: print("  -> 拾取武器")
        ),
        GOAPAction(
            name="Reload",
            cost=1.0,
            precondition={"armed": True, "has_ammo": True},
            effect={"loaded": True},
            execute=lambda: print("  -> 装弹")
        ),
        GOAPAction(
            name="MoveToEnemy",
            cost=3.0,
            precondition={"enemy_visible": True},
            effect={"in_attack_range": True},
            execute=lambda: print("  -> 接近敌人")
        ),
        GOAPAction(
            name="Shoot",
            cost=1.0,
            precondition={"armed": True, "loaded": True, "in_attack_range": True, "enemy_alive": True},
            effect={"enemy_alive": False},
            execute=lambda: print("  -> 射击敌人")
        ),
        GOAPAction(
            name="MeleeAttack",
            cost=2.0,
            precondition={"in_attack_range": True, "enemy_alive": True},
            effect={"enemy_alive": False},
            execute=lambda: print("  -> 近战攻击")
        ),
        GOAPAction(
            name="CallReinforcement",
            cost=5.0,
            precondition={"enemy_visible": True, "reinforcement_available": True},
            effect={"reinforcement_called": True},
            execute=lambda: print("  -> 呼叫支援")
        ),
    ]
    
    goals = [
        GOAPGoal("KillEnemy", {"enemy_alive": False}, priority=2),
        GOAPGoal("GetReinforcement", {"reinforcement_called": True}, priority=1),
    ]
    
    return actions, goals

# === 测试 ===
actions, goals = build_fps_domain()
planner = GOAPPlanner(actions)

# 场景1：有武器有弹药，看到敌人
print("=== 场景1: 武装状态，发现敌人 ===")
state1 = WorldState({
    "armed": True,
```

## 第16讲 蒙特卡洛树搜索（MCTS）

### 概念

蒙特卡洛树搜索（Monte Carlo Tree Search, MCTS）是一种基于**随机模拟**的搜索算法，在棋类游戏AI中取得突破性成果——AlphaGo、AlphaZero的核心技术之一。MCTS通过**随机模拟（Rollout）** 评估局面价值，通过**树搜索**积累统计信息，逐步聚焦于有前途的动作。与传统的minimax搜索（需要评估函数）不同，MCTS**不需要领域特定的评估函数**，只需能模拟游戏到结束。

MCTS在游戏AI中的应用包括：**棋类游戏**（围棋、国际象棋、五子棋）、**卡牌游戏**（炉石传说AI）、**回合制策略游戏**（文明系列AI）、**实时策略游戏的战术决策**。MCTS的优势在于能处理**大状态空间、不完全信息、复杂评估**的场景，是传统搜索算法难以应对的。

### 原理

**MCTS的核心流程**（每次迭代4步）：

**1. 选择（Selection）**：从根节点开始，根据选择策略（通常UCB1）递归选择子节点，直到到达"未完全展开"的节点（即还有未尝试的动作）。UCB1公式：

```
UCB1 = (wins / visits) + C * sqrt(ln(parent_visits) / visits)
```

第一项是" exploitation"（利用已知好动作），第二项是" exploration"（探索未充分尝试的动作），C是探索常数（通常√2）。UCB1平衡了利用与探索，是MCTS的关键。

**2. 扩展（Expansion）**：在选中的节点上，选择一个未尝试的动作，创建新子节点。

**3. 模拟（Simulation / Rollout）**：从新节点开始，**随机**或用**启发式策略**模拟游戏到结束，得到胜负结果。这一步是MCTS的"评估函数"——通过随机模拟估计局面价值。

**4. 回传（Backpropagation）**：将模拟结果沿路径回传到根，更新每个节点的`wins`和`visits`统计。

经过多次迭代后，选择根节点下**访问次数最多**（或胜率最高）的子节点作为最佳动作。

**MCTS的优势**：
- **无需评估函数**：通过模拟自动评估，适合难以设计评估函数的游戏
- ** anytime算法**：随时可停止，返回当前最佳结果
- **不对称搜索**：聚焦于有前途的分支，不浪费计算资源
- **处理大状态空间**：不需要枚举所有状态

**MCTS的局限**：
- **计算密集**：需要大量模拟，实时性挑战大
- **模拟质量依赖**：纯随机模拟可能不准，需启发式引导
- **不完全信息处理**：需特殊处理（如PIMC - Perfect Information Monte Carlo）

**MCTS的增强技术**：
- **启发式Rollout**：模拟时用启发式策略而非纯随机，提高模拟质量
- **Progressive Bias**：用领域知识引导选择，逐渐淡化
- **RAVE（Rapid Action Value Estimation）**：利用动作相关性加速收敛
- **神经网络评估**：AlphaGo用神经网络替代部分模拟，大幅提升性能
- **并行化**：根并行、树并行、叶并行，利用多核

**MCTS在实时游戏中的应用挑战**：
- **时间限制**：实时游戏每帧只有毫秒级决策时间，需控制模拟次数
- **状态空间大**：RTS游戏状态远比棋类复杂，需抽象化
- **不完全信息**：战争迷雾、对手手牌等，需PIMC或信念状态

### 例子

下面实现一个完整的MCTS算法，应用于井字棋（Tic-Tac-Toe）：

```python
import math
import random
from typing import List, Optional, Tuple
from dataclasses import dataclass
import copy

class TicTacToe:
    """井字棋游戏"""
    def __init__(self):
        self.board = [[' ' for _ in range(3)] for _ in range(3)]
        self.current_player = 'X'  # X先手
        self.winner = None
    
    def get_valid_moves(self) -> List[Tuple[int, int]]:
        if self.winner is not None:
            return []
        return [(r, c) for r in range(3) for c in range(3) if self.board[r][c] == ' ']
    
    def make_move(self, move: Tuple[int, int]):
        r, c = move
        self.board[r][c] = self.current_player
        self._check_winner()
        self.current_player = 'O' if self.current_player == 'X' else 'X'
    
    def _check_winner(self):
        lines = []
        # 行
        lines.extend(self.board)
        # 列
        lines.extend([[self.board[r][c] for r in range(3)] for c in range(3)])
        # 对角线
        lines.append([self.board[i][i] for i in range(3)])
        lines.append([self.board[i][2-i] for i in range(3)])
        
        for line in lines:
            if line[0] != ' ' and line.count(line[0]) == 3:
                self.winner = line[0]
                return
        
        # 平局
        if all(self.board[r][c] != ' ' for r in range(3) for c in range(3)):
            self.winner = 'draw'
    
    def is_game_over(self) -> bool:
        return self.winner is not None
    
    def clone(self):
        new_game = TicTacToe()
        new_game.board = [row[:] for row in self.board]
        new_game.current_player = self.current_player
        new_game.winner = self.winner
        return new_game

@dataclass
class MCTSNode:
    game_state: TicTacToe
    parent: Optional['MCTSNode']
    move: Optional[Tuple[int, int]]  # 导致此节点的动作
    children: List['MCTSNode']
    visits: int = 0
    wins: float = 0  # 从parent视角的胜利数
    untried_moves: List[Tuple[int, int]] = None
    
    def __post_init__(self):
        if self.untried_moves is None:
            self.untried_moves = self.game_state.get_valid_moves()
    
    def is_fully_expanded(self) -> bool:
        return len(self.untried_moves) == 0
    
    def is_terminal(self) -> bool:
        return self.game_state.is_game_over()

class MCTS:
    def __init__(self, exploration_constant: float = math.sqrt(2)):
        self.c = exploration_constant
    
    def search(self, root_state: TicTacToe, iterations: int) -> Optional[Tuple[int, int]]:
        root = MCTSNode(game_state=root_state.clone(), parent=None, move=None, children=[])
        
        for _ in range(iterations):
            node = self._select(root)
            if not node.is_terminal():
                node = self._expand(node)
            result = self._simulate(node.game_state)
            self._backpropagate(node, result)
        
        # 选择访问次数最多的子节点
        if not root.children:
            return None
        best_child = max(root.children, key=lambda c: c.visits)
        return best_child.move
    
    def _select(self, node: MCTSNode) -> MCTSNode:
        """选择：用UCB1递归选择直到未完全展开或终端节点"""
        while node.is_fully_expanded() and not node.is_terminal():
            node = self._ucb1_select(node)
        return node
    
    def _ucb1_select(self, node: MCTSNode) -> MCTSNode:
        """UCB1选择子节点"""
        log_parent_visits = math.log(node.visits)
        best_score = -float('inf')
        best_child = None
        for child in node.children:
            if child.visits == 0:
                return child  # 未访问的优先
            # UCB1: wins/visits + C * sqrt(ln(parent_visits) / visits)
            exploit = child.wins / child.visits
            explore = self.c * math.sqrt(log_parent_visits / child.visits)
            score = exploit + explore
            if score > best_score:
                best_score = score
                best_child = child
        return best_child
    
    def _expand(self, node: MCTSNode) -> MCTSNode:
        """扩展：选择一个未尝试的动作，创建新子节点"""
        if not node.untried_moves:
            return node
        move = node.untried_moves.pop(random.randint(0, len(node.untried_moves) - 1))
        new_state = node.game_state.clone()
        new_state.make_move(move)
        child = MCTSNode(
            game_state=new_state,
            parent=node,
            move=move,
            children=[]
        )
        node.children.append(child)
        return child
    
    def _simulate(self, state: TicTacToe) -> str:
        """模拟：随机走子到游戏结束"""
        state = state.clone()
        while not state.is_game_over():
            moves = state.get_valid_moves()
            move = random.choice(moves)
            state.make_move(move)
        return state.winner
    
    def _backpropagate(self, node: MCTSNode, result: str):
        """回传：沿路径更新统计"""
        while node is not None:
            node.visits += 1
            # 从parent视角计算胜负
            if node.parent is not None:
                parent_player = node.parent.game_state.current_player
                if result == 'draw':
                    node.wins += 0.5
                elif result == parent_player:
                    node.wins += 1
            node = node.parent

# === 测试：MCTS vs 随机AI ===
def play_game(mcts_iterations=1000):
    game = TicTacToe()
    mcts = MCTS()
    
    while not game.is_game_over():
        if game.current_player == 'X':
            # MCTS下棋
            move = mcts.search(game, mcts_iterations)
            print(f"MCTS (X) 下在 {move}")
        else:
            # 随机AI下棋
            moves = game.get_valid_moves()
            move = random.choice(moves)
            print(f"随机 (O) 下在 {move}")
        game.make_move(move)
        
        # 打印棋盘
        for row in game.board:
            print(' '.join(row))
        print()
    
    print(f"结果: {game.winner}")
    return game.winner

print("=== MCTS vs 随机AI ===")
play_game(mcts_iterations=500)
```

```

MCTS (X) 下在 (1, 1)
    
  X 
    
随机 (O) 下在 (0, 0)
O   X
    
MCTS (X) 下在 (2, 0)
O   X
    X
O   X
...
结果: X
```

MCTS通过500次模拟，能稳定击败随机AI。在井字棋这种小游戏中，MCTS甚至能找到最优策略（保证不输）。在更复杂的游戏中（如五子棋、围棋），MCTS的优势更明显——它能处理传统搜索无法应对的状态空间。

### 总结

本讲重点回顾：
- MCTS通过**随机模拟**评估局面，**树搜索**积累统计
- 四步流程：**选择（UCB1）→ 扩展 → 模拟 → 回传**
- UCB1公式平衡**利用与探索**：`wins/visits + C*sqrt(ln(N)/n)`
- 优势：**无需评估函数、anytime、不对称搜索、处理大状态空间**
- 局限：**计算密集、模拟质量依赖、不完全信息处理复杂**
- 增强技术：**启发式Rollout、RAVE、神经网络评估（AlphaGo）、并行化**

适用场景：**棋类游戏、卡牌游戏、回合制策略、需要长程规划的游戏**。常见误区：① 模拟次数不足——MCTS需要足够模拟才能收敛，实时场景需平衡；② 纯随机模拟——复杂游戏中模拟质量差，需启发式引导；③ 忽视并行化——MCTS天然可并行，单线程浪费性能。调试技巧：可视化搜索树，观察节点访问分布和胜率。

# 第6章 机器学习与游戏AI

## 第17讲 神经网络基础与游戏应用

### 概念

神经网络（Neural Network）是机器学习的核心技术，模拟生物神经元的连接方式，通过**学习数据中的模式**来完成预测、分类、决策等任务。在游戏AI中，神经网络的应用从早期的**神经进化**（用遗传算法训练神经网络控制角色）到现代的**深度强化学习**（AlphaGo、OpenAI Five），已成为前沿游戏AI的核心技术。

与前面章节的"**手工设计**"AI不同，神经网络是"**数据驱动**"的——设计师不直接编写行为规则，而是提供训练数据或训练环境，让神经网络自己学习。这种范式转变让AI能处理**人类难以手工设计规则**的复杂任务，如视觉感知、自然语言、复杂策略。但神经网络的"黑盒"特性也带来调试困难、不可预测等挑战，在游戏中的应用需要谨慎。

### 原理

**神经网络的基本结构**：

**1. 神经元（Neuron）**：网络的基本单元，接收输入，计算加权和，通过激活函数输出。数学表达：`y = activation(Σ(w_i * x_i) + b)`，其中`w_i`是权重，`b`是偏置，`activation`是激活函数。

**2. 激活函数（Activation Function）**：引入非线性，让网络能学习复杂模式。常见激活函数：
- **Sigmoid**：`1/(1+e^(-x))`，输出0-1，适合二分类
- **Tanh**：`(e^x - e^(-x))/(e^x + e^(-x))`，输出-1到1
- **ReLU**：`max(0, x)`，简单高效，深度网络首选
- **Leaky ReLU**：`max(0.01x, x)`，避免ReLU的"死神经元"问题

**3. 网络结构**：神经元按层组织：
- **输入层（Input Layer）**：接收原始特征
- **隐藏层（Hidden Layer）**：中间层，提取抽象特征
- **输出层（Output Layer）**：产生最终预测

层数越多，网络表达能力越强，但训练越困难（梯度消失、过拟合）。"深度学习"指有多个隐藏层的网络。

**4. 前向传播（Forward Propagation）**：输入从输入层逐层计算到输出层，得到预测结果。

**5. 反向传播（Backpropagation）**：训练算法。计算预测误差，通过链式法则将误差反向传播，更新权重。核心公式：`w_new = w_old - learning_rate * ∂Loss/∂w`。

**6. 损失函数（Loss Function）**：衡量预测与真实值的差距。常见：
- **MSE（均方误差）**：回归任务
- **交叉熵（Cross-Entropy）**：分类任务

**神经网络在游戏中的应用模式**：

**1. 感知（Perception）**：神经网络处理原始传感器数据（图像、声音），提取高级特征。例如用CNN从游戏画面识别敌人位置、用RNN处理语音指令。

**2. 决策（Decision Making）**：神经网络直接输出动作决策。输入游戏状态，输出动作概率或Q值。这是强化学习的核心模式。

**3. 内容生成（Content Generation）**：用GAN、VAE等生成游戏内容——地图、角色、音乐、对话。例如《无人深空》的程序生成。

**4. 玩家建模（Player Modeling）**：分析玩家行为，预测偏好、难度适应。用于动态难度调整、个性化推荐。

**5. 动画与物理**：用神经网络生成自然动画（如强化学习驱动的角色运动）、模拟复杂物理（流体、布料）。

**游戏AI中神经网络的特殊挑战**：
- **实时性**：游戏每帧16ms，神经网络推理必须快速
- **确定性**：游戏需要可复现，神经网络需固定随机种子
- **可解释性**：设计师需理解AI行为，神经网络黑盒难调试
- **训练数据**：游戏场景多样，数据采集成本高
- **部署体积**：移动游戏对模型大小敏感

### 例子

下面用纯Python实现一个简单的多层感知机（MLP），并应用于游戏AI的"敌人类型识别"任务：

```python
import numpy as np
from typing import List, Tuple, Callable

class NeuralNetwork:
    """简单的前馈神经网络"""
    def __init__(self, layer_sizes: List[int], 
                 activation: str = 'relu', output_activation: str = 'sigmoid'):
        self.layer_sizes = layer_sizes
        self.activation = self._get_activation(activation)
        self.output_activation = self._get_activation(output_activation)
        self.activation_deriv = self._get_activation_deriv(activation)
        
        # 初始化权重和偏置
        self.weights = []
        self.biases = []
        for i in range(len(layer_sizes) - 1):
            # He初始化（适合ReLU）
            w = np.random.randn(layer_sizes[i], layer_sizes[i+1]) * np.sqrt(2.0 / layer_sizes[i])
            b = np.zeros((1, layer_sizes[i+1]))
            self.weights.append(w)
            self.biases.append(b)
    
    def _get_activation(self, name) -> Callable:
        activations = {
            'relu': lambda x: np.maximum(0, x),
            'sigmoid': lambda x: 1 / (1 + np.exp(-np.clip(x, -500, 500))),
            'tanh': lambda x: np.tanh(x),
            'softmax': lambda x: np.exp(x - np.max(x, axis=1, keepdims=True)) / 
                                np.sum(np.exp(x - np.max(x, axis=1, keepdims=True)), axis=1, keepdims=True),
            'linear': lambda x: x
        }
        return activations[name]
    
    def _get_activation_deriv(self, name) -> Callable:
        derivs = {
            'relu': lambda x: (x > 0).astype(float),
            'sigmoid': lambda x: x * (1 - x),
            'tanh': lambda x: 1 - x**2,
        }
        return derivs[name]
    
    def forward(self, X: np.ndarray) -> Tuple[np.ndarray, List[np.ndarray]]:
        """前向传播，返回输出和各层激活值"""
        activations = [X]
        a = X
        for i, (w, b) in enumerate(zip(self.weights, self.biases)):
            z = np.dot(a, w) + b
            if i == len(self.weights) - 1:
                a = self.output_activation(z)
            else:
                a = self.activation(z)
            activations.append(a)
        return a, activations
    
    def backward(self, X: np.ndarray, y: np.ndarray, 
                 activations: List[np.ndarray], learning_rate: float):
        """反向传播"""
        m = X.shape[0]
        L = len(self.weights)
        
        # 输出层误差
        delta = activations[-1] - y  # 交叉熵+sigmoid的简化梯度
        
        # 反向传播
        for i in range(L - 1, -1, -1):
            dW = np.dot(activations[i].T, delta) / m
            db = np.sum(delta, axis=0, keepdims=True) / m
            
            if i > 0:
                delta = np.dot(delta, self.weights[i].T) * self.activation_deriv(activations[i])
            
            self.weights[i] -= learning_rate * dW
            self.biases[i] -= learning_rate * db
    
    def train(self, X: np.ndarray, y: np.ndarray, epochs: int = 1000, 
              learning_rate: float = 0.1, verbose: bool = True):
        """训练网络"""
        for epoch in range(epochs):
            output, activations = self.forward(X)
            self.backward(X, y, activations, learning_rate)
            
            if verbose and epoch % 200 == 0:
                loss = np.mean(-(y * np.log(output + 1e-9) + (1-y) * np.log(1-output + 1e-9)))
                print(f"Epoch {epoch}, Loss: {loss:.4f}")
    
    def predict(self, X: np.ndarray) -> np.ndarray:
        """预测"""
        output, _ = self.forward(X)
        return output

# === 游戏应用：敌人类型识别 ===
# 输入：敌人的特征（体型、速度、攻击力、防御力）
```

## 第18讲 强化学习与游戏AI

### 概念

强化学习（Reinforcement Learning, RL）是机器学习的三大范式之一（监督学习、无监督学习、强化学习），通过**智能体（Agent）与环境交互**，从**奖励（Reward）** 中学习最优策略。强化学习是当前游戏AI最前沿的方向——AlphaGo击败李世石、OpenAI Five击败Dota 2世界冠军、AlphaStar在星际争霸2中达到大师级水平，都是强化学习的成果。

强化学习与监督学习的根本差异在于"**学习信号**"。监督学习有标注数据（输入→正确输出），强化学习只有奖励信号（动作的好坏），智能体需要自己探索发现好动作。这种"试错学习"让强化学习能处理**没有标准答案**的复杂决策问题——如围棋的最优走法、Dota的团队策略。但强化学习的训练成本极高，样本效率低，是当前研究的热点。

### 原理

**强化学习的基本框架**（MDP - 马尔可夫决策过程）：

**1. 核心要素**：
- **状态（State, S）**：环境的描述，如游戏画面、单位位置
- **动作（Action, A）**：智能体可执行的操作，如移动、攻击
- **奖励（Reward, R）**：动作的即时反馈，如击杀敌人+10、死亡-100
- **策略（Policy, π）**：状态到动作的映射，`π(a|s)`是在状态s下选择动作a的概率
- **价值函数（Value Function, V/Q）**：评估状态或状态-动作对的长期价值

**2. 目标**：最大化**累积折扣奖励**：`E[Σ γ^t * R_t]`，其中`γ`是折扣因子（0-1），平衡即时与长期奖励。

**3. 核心方程——Bellman方程**：
- 状态价值：`V(s) = E[R + γV(s')]`
- 动作价值：`Q(s,a) = E[R + γ max_a' Q(s',a')]`

Bellman方程是强化学习的理论基础，定义了价值的递归关系。

**强化学习的主要方法**：

**1. 基于价值（Value-Based）**：学习Q函数，选择Q值最大的动作。代表算法：**Q-Learning, DQN**。
- **Q-Learning**：`Q(s,a) ← Q(s,a) + α[r + γ max_a' Q(s',a') - Q(s,a)]`
- **DQN（Deep Q-Network）**：用神经网络近似Q函数，引入经验回放和目标网络稳定训练

**2. 基于策略（Policy-Based）**：直接学习策略函数`π(a|s)`。代表算法：**REINFORCE, PPO**。
- **REINFORCE**：`∇J = E[∇log π(a|s) * G]`，G是回报
- **PPO（Proximal Policy Optimization）**：限制策略更新幅度，训练稳定，是当前工业首选

**3. Actor-Critic**：结合价值和策略，Actor学策略，Critic学价值。代表算法：**A2C, A3C, SAC**。

**4. 模型-based（Model-Based）**：学习环境模型（状态转移），用模型规划。样本效率高但模型误差累积。

**强化学习的关键技术**：

**1. 探索与利用（Exploration vs Exploitation）**：
- **ε-greedy**：以ε概率随机探索，否则利用当前最优
- **Softmax**：按Q值的softmax概率选择
- **UCB**：置信上界，平衡探索与利用
- **好奇心驱动**：对新颖状态给予内在奖励

**2. 经验回放（Experience Replay）**：存储转移`(s,a,r,s')`，随机采样训练，打破数据相关性，提高样本效率。

**3. 目标网络（Target Network）**：用延迟更新的网络计算目标Q值，稳定训练。

**4. 奖励塑造（Reward Shaping）**：设计密集的中间奖励，引导智能体学习。如"靠近目标+小奖励"，避免稀疏奖励导致学习困难。

**强化学习在游戏中的挑战**：
- **样本效率低**：需要海量游戏局数，AlphaGo用了数百万局
- **稀疏奖励**：很多游戏只在结束时给奖励（胜负），学习困难
- **大状态空间**：复杂游戏状态空间巨大，需函数近似
- **不完全信息**：战争迷雾、对手手牌，需特殊处理
- **多智能体**：团队协作、对手适应，训练复杂
- **sim-to-real gap**：训练环境与真实游戏的差异

```python
import numpy as np
import random
from typing import Tuple, List
from dataclasses import dataclass

class GridWorld:
    """网格世界环境"""
    def __init__(self, size=5):
        self.size = size
        self.reset()
        # 陷阱和宝藏位置
        self.traps = [(1, 1), (3, 3), (2, 4)]
        self.treasure = (4, 4)
    
    def reset(self) -> Tuple[int, int]:
        self.agent_pos = (0, 0)
        return self.agent_pos
    
    def step(self, action: int) -> Tuple[Tuple[int, int], float, bool]:
        """执行动作，返回(新状态, 奖励, 是否结束)"""
        # 0:上 1:下 2:左 3:右
        moves = [(0, -1), (0, 1), (-1, 0), (1, 0)]
        dx, dy = moves[action]
        x, y = self.agent_pos
        new_x = max(0, min(self.size - 1, x + dx))
        new_y = max(0, min(self.size - 1, y + dy))
        self.agent_pos = (new_x, new_y)
        
        # 计算奖励
        if self.agent_pos in self.traps:
            return self.agent_pos, -10.0, True  # 陷阱，游戏结束
        elif self.agent_pos == self.treasure:
            return self.agent_pos, 10.0, True  # 找到宝藏
        else:
            # 小惩罚鼓励快速到达
            return self.agent_pos, -0.1, False

class QLearningAgent:
    """Q-Learning智能体"""
    def __init__(self, state_size: int, action_size: int, 
                 learning_rate: float = 0.1, discount: float = 0.95,
                 epsilon: float = 1.0, epsilon_min: float = 0.01,
                 epsilon_decay: float = 0.995):
        self.q_table = np.zeros((state_size, state_size, action_size))
        self.lr = learning_rate
        self.gamma = discount
        self.epsilon = epsilon
        self.epsilon_min = epsilon_min
        self.epsilon_decay = epsilon_decay
        self.action_size = action_size
    
    def choose_action(self, state: Tuple[int, int]) -> int:
        """ε-greedy选择动作"""
        if random.random() < self.epsilon:
            return random.randint(0, self.action_size - 1)
        return np.argmax(self.q_table[state[0], state[1]])
    
    def learn(self, state, action, reward, next_state, done):
        """Q-Learning更新"""
        current_q = self.q_table[state[0], state[1], action]
        
        if done:
            target = reward
        else:
            target = reward + self.gamma * np.max(self.q_table[next_state[0], next_state[1]])
        
        # Q更新公式
        self.q_table[state[0], state[1], action] += self.lr * (target - current_q)
        
        # 衰减探索率
        if done:
            self.epsilon = max(self.epsilon_min, self.epsilon * self.epsilon_decay)

# === 训练 ===
def train_q_learning(episodes=1000):
    env = GridWorld(size=5)
    agent = QLearningAgent(state_size=5, action_size=4)
    
    rewards_history = []
    
    for episode in range(episodes):
        state = env.reset()
        total_reward = 0
        steps = 0
        done = False
        
        while not done and steps < 100:  # 最多100步
            action = agent.choose_action(state)
            next_state, reward, done = env.step(action)
            agent.learn(state, action, reward, next_state, done)
            state = next_state
            total_reward += reward
            steps += 1
        
        rewards_history.append(total_reward)
        
        if (episode + 1) % 100 == 0:
            avg_reward = np.mean(rewards_history[-100:])
            print(f"Episode {episode+1}, 平均奖励: {avg_reward:.2f}, "
                  f"探索率: {agent.epsilon:.3f}")
    
    return agent

print("=== Q-Learning训练 ===")
agent = train_q_learning(episodes=500)

# === 测试学到的策略 ===
print("\n=== 测试策略 ===")

state = env.reset()
path = [state]

    state = next_state
    steps += 1

print(f"路径: {path}")
print(f"总奖励: {total_reward}, 步数: {steps}")
print(f"结果: {'找到宝藏!' if state == env.treasure else '掉入陷阱' if state in env.traps else '超时'}")

# 可视化Q表
print("\n=== Q表（每个状态的最优动作价值）===")
action_names = ['↑', '↓', '←', '→']
for y in range(5):
    for x in range(5):
        if (x, y) == env.treasure:
            print(' T ', end='')
        elif (x, y) in env.traps:
            print(' X ', end='')
        else:
            best_action = np.argmax(agent.q_table[x, y])
            print(f' {action_names[best_action]} ', end='')
    print()
```

## 第19讲 遗传算法与神经进化

### 概念

遗传算法（Genetic Algorithm, GA）是受生物进化启发的优化算法，通过**选择、交叉、变异**等机制在解空间中搜索最优解。神经进化（Neuroevolution）是遗传算法与神经网络的结合——用遗传算法优化神经网络的权重或结构，而非传统的梯度下降。在游戏AI中，遗传算法和神经进化适用于**没有梯度信息、奖励稀疏、需要探索多样解**的场景，如车辆控制、角色运动、关卡生成。

遗传算法与强化学习的差异在于"**优化信号**"。强化学习基于梯度（通过奖励的导数），需要可微的策略；遗传算法基于适应度（无梯度），只需评估解的好坏。这让遗传算法能优化**不可微**的目标——如游戏胜负、关卡趣味性。但遗传算法的样本效率通常低于梯度方法，适合问题规模适中、评估快速的场景。

### 原理

**遗传算法的核心流程**：

**1. 编码（Encoding）**：将解表示为"染色体"（Chromosome）。常见编码：
- **二进制编码**：解表示为0/1串，适合离散问题
- **实数编码**：解表示为实数向量，适合连续优化
- **树编码**：解表示为语法树，适合程序生成（遗传编程）

**2. 初始化（Initialization）**：随机生成初始种群（Population），通常几十到几百个个体。

**3. 适应度评估（Fitness Evaluation）**：用问题特定的适应度函数评估每个个体。在游戏AI中，适应度可能是"游戏得分"、"生存时间"、"击败敌人数"。

**4. 选择（Selection）**：根据适应度选择父代，适应度高的更可能被选。常见方法：
- **轮盘赌选择**：按适应度比例选择
- **锦标赛选择**：随机选k个，选最优的
- **精英保留**：直接保留最优的几个个体到下一代

**5. 交叉（Crossover）**：父代交换基因产生子代。常见方法：
- **单点交叉**：随机选一点，交换后半部分
- **多点交叉**：多个交换点
- **均匀交叉**：每个基因独立按概率交换

**6. 变异（Mutation）**：以小概率随机改变基因，维持种群多样性。如二进制编码的翻位、实数编码的随机扰动。

**7. 替换（Replacement）**：用子代替换部分或全部父代，形成新一代。

**8. 终止条件**：达到最大代数、适应度收敛、找到满意解。

**神经进化（Neuroevolution）** 是遗传算法在神经网络优化上的应用：

**1. NEAT（NeuroEvolution of Augmenting Topologies）**：经典神经进化算法，同时优化权重和网络结构。从简单网络开始，通过添加节点和连接逐步复杂化。NEAT的三个关键创新：
- **结构创新编号**：追踪基因的历史，便于交叉
- **物种形成**：相似网络归为同一物种，保护创新
- **增量复杂化**：从简单开始逐步增加复杂度

**2. CMA-ES（协方差矩阵适应进化策略）**：实数编码的高级进化策略，自适应调整搜索方向和步长，适合连续优化。

**3. 深度神经进化**：用遗传算法训练深度神经网络，OpenAI的研究表明在Atari游戏上能与强化学习媲美。

**遗传算法在游戏中的应用**：

**1. NPC行为优化**：用GA优化NPC的参数（如FSM的转移条件、行为树的权重），适应度是"对战胜率"或"玩家满意度"。

**2. 关卡生成**：用GA生成满足设计约束的关卡，适应度包括"可通关性"、"难度曲线"、"趣味性"。

**3. 角色运动**：用神经进化学习角色运动控制，如四足生物的步态、车辆的驾驶策略。

**4. 游戏平衡**：用GA寻找游戏中的"最强策略"，帮助设计师发现不平衡点。

**5. 程序生成内容**：用GA生成武器、角色外观、音乐等。

### 例子

下面实现一个遗传算法，优化一个"赛车AI"的神经网络控制器：

```python
import numpy as np
import random
from typing import List, Tuple, Callable
from dataclasses import dataclass, field

@dataclass
class Individual:
    """个体：神经网络权重"""
    weights: np.ndarray  # 展平的权重
    fitness: float = 0.0

class GeneticAlgorithm:
    def __init__(self, population_size: int, gene_size: int,
                 crossover_rate: float = 0.8, mutation_rate: float = 0.1,
                 mutation_strength: float = 0.5, elite_count: int = 2):
        self.population_size = population_size
        self.gene_size = gene_size
        self.crossover_rate = crossover_rate
        self.mutation_rate = mutation_rate
        self.mutation_strength = mutation_strength
        self.elite_count = elite_count
        self.population: List[Individual] = []
        self.generation = 0
        self.best_fitness_history = []
        
        # 初始化种群
        for _ in range(population_size):
            weights = np.random.randn(gene_size) * 0.5
            self.population.append(Individual(weights=weights))
    
    def evolve(self, fitness_func: Callable[[np.ndarray], float]) -> Individual:
        """进化一代"""
        # 1. 评估适应度
        for ind in self.population:
            if ind.fitness == 0.0:  # 未评估的
                ind.fitness = fitness_func(ind.weights)
        
        # 2. 排序
        self.population.sort(key=lambda x: -x.fitness)
        best = self.population[0]
        self.best_fitness_history.append(best.fitness)
        
        # 3. 精英保留
        new_population = self.population[:self.elite_count]
        
        # 4. 生成子代
        while len(new_population) < self.population_size:
            parent1 = self._tournament_select()
            parent2 = self._tournament_select()
            
            # 交叉
            if random.random() < self.crossover_rate:
                child1, child2 = self._crossover(parent1, parent2)
            else:
                child1, child2 = Individual(weights=parent1.weights.copy()), \
                                Individual(weights=parent2.weights.copy())
            
            # 变异
            self._mutate(child1)
            self._mutate(child2)
            
            new_population.append(child1)
            if len(new_population) < self.population_size:
                new_population.append(child2)
        
        self.population = new_population
        self.generation += 1
        return best
    
    def _tournament_select(self, k: int = 3) -> Individual:
        """锦标赛选择"""
        contestants = random.sample(self.population, min(k, len(self.population)))
        return max(contestants, key=lambda x: x.fitness)
    
    def _crossover(self, p1: Individual, p2: Individual) -> Tuple[Individual, Individual]:
        """均匀交叉"""
        mask = np.random.rand(self.gene_size) < 0.5
        c1_weights = np.where(mask, p1.weights, p2.weights)
        c2_weights = np.where(mask, p2.weights, p1.weights)
        return Individual(weights=c1_weights), Individual(weights=c2_weights)
    
    def _mutate(self, ind: Individual):
        """高斯变异"""
        mutation_mask = np.random.rand(self.gene_size) < self.mutation_rate
        noise = np.random.randn(self.gene_size) * self.mutation_strength
        ind.weights = np.where(mutation_mask, ind.weights + noise, ind.weights)
        ind.fitness = 0.0  # 标记需要重新评估

# === 简单神经网络控制器 ===
class SimpleNN:
    """简单的2层神经网络"""
    def __init__(self, input_size, hidden_size, output_size):
        self.input_size = input_size
        self.hidden_size = hidden_size
        self.output_size = output_size
        self.gene_size = (input_size * hidden_size + hidden_size + 
                         hidden_size * output_size + output_size)
    
    def set_weights(self, genes: np.ndarray):
        idx = 0
        self.W1 = genes[idx:idx+self.input_size*self.hidden_size].reshape(
            self.input_size, self.hidden_size)
        idx += self.input_size * self.hidden_size
        self.b1 = genes[idx:idx+self.hidden_size]
        idx += self.hidden_size
        self.W2 = genes[idx:idx+self.hidden_size*self.output_size].reshape(
            self.hidden_size, self.output_size)
        idx += self.hidden_size * self.output_size
        self.b2 = genes[idx:idx+self.output_size]
    
    def forward(self, X):
        h = np.tanh(X @ self.W1 + self.b1)
        return h @ self.W2 + self.b2

# === 赛车模拟环境（简化）===
class CarSimulator:
    """简化赛车环境：控制赛车在赛道上行驶"""
    def __init__(self):
        self.track_length = 100
        self.reset()
    
    def reset(self):
        self.position = 0.0
        self.speed = 0.0
        self.time = 0
        self.crashed = False
    
    def step(self, action: np.ndarray) -> float:
        """action: [throttle, brake]，返回奖励"""
        if self.crashed:
            return 0
        
        throttle = np.clip(action[0], 0, 1)
        brake = np.clip(action[1], 0, 1)
        
        # 简化物理
        self.speed += throttle * 0.5 - brake * 0.8 - 0.05  # 摩擦
        self.speed = max(0, min(self.speed, 5))
        self.position += self.speed
        self.time += 1
        
        # 简化碰撞检测：速度过快且转弯（这里简化为随机）
        if self.speed > 4.5 and random.random() < 0.1:
            self.crashed = True
            return -10
        
        # 到达终点
        if self.position >= self.track_length:
            return 100 - self.time * 0.1  # 越快奖励越高
        
        # 即时奖励：前进距离
        return self.speed * 0.1
    
    def is_done(self):
        return self.crashed or self.position >= self.track_length

# === 适应度函数 ===
def evaluate_car(genes: np.ndarray) -> float:
    """评估赛车AI的适应度"""
    nn = SimpleNN(input_size=3, hidden_size=8, output_size=2)
    nn.set_weights(genes)
    
    sim = CarSimulator()
    total_reward = 0
    
    while not sim.is_done() and sim.time < 200:
        # 输入：当前位置、速度、剩余距离
        state = np.array([sim.position / 100, sim.speed / 5, 
                         (100 - sim.position) / 100])
        action = nn.forward(state)
        reward = sim.step(action)
        total_reward += reward
    
    return total_reward

# === 训练 ===
print("=== 遗传算法训练赛车AI ===")
nn_arch = SimpleNN(3, 8, 2)
ga = GeneticAlgorithm(population_size=30, gene_size=nn_arch.gene_size,
                     crossover_rate=0.8, mutation_rate=0.1)

for gen in range(50):
    best = ga.evolve(evaluate_car)
    if (gen + 1) % 10 == 0:
        avg_fitness = np.mean([ind.fitness for ind in ga.population[:10]])
        print(f"Generation {gen+1}: 最佳适应度={best.fitness:.2f}, "
              f"前10平均={avg_fitness:.2f}")

# 测试最佳个体
print("\n=== 测试最佳赛车AI ===")
best_weights = ga.population[0].weights
nn = SimpleNN(3, 8, 2)
nn.set_weights(best_weights)

sim = CarSimulator()
print(f"初始状态: 位置={sim.position:.1f}, 速度={sim.speed:.1f}")

while not sim.is_done() and sim.time < 200:
    state = np.array([sim.position / 100, sim.speed / 5, (100 - sim.position) / 100])
    action = nn.forward(state)
    sim.step(action)
    if sim.time % 20 == 0:
        print(f"  时间={sim.time}, 位置={sim.position:.1f}, 速度={sim.speed:.1f}, "
              f"油门={action[0]:.2f}, 刹车={action[1]:.2f}")

print(f"最终: 位置={sim.position:.1f}, 时间={sim.time}, "
      f"{'完成!' if sim.position >= 100 else '失败'}")
```

### 总结

本讲重点回顾：
- 遗传算法通过**选择、交叉、变异**在解空间搜索
- 核心流程：**编码 → 初始化 → 评估 → 选择 → 交叉 → 变异 → 替换**
- 神经进化：用GA优化神经网络，代表算法**NEAT、CMA-ES**
- 与强化学习差异：**无梯度、适合不可微目标、样本效率较低**
- 游戏应用：**NPC优化、关卡生成、角色运动、游戏平衡、内容生成**

适用场景：**无梯度优化、奖励稀疏、需要多样解、问题规模适中**。常见误区：① 种群过小——多样性不足，易陷入局部最优；② 变异率过高——破坏优秀解，应自适应衰减；③ 适应度函数设计不当——导致进化方向错误。调试技巧：监控适应度曲线，可视化最优个体行为，分析种群多样性。

# 第7章 前沿与实战

## 第20讲 多智能体协作与博弈论

### 概念

多智能体系统（Multi-Agent Systems, MAS）研究**多个智能体在共享环境中交互**的AI问题，是游戏AI的高级话题。从RTS的多单位协同、MOBA的团队配合，到体育游戏的队伍战术、社交游戏的NPC互动，多智能体场景无处不在。本讲聚焦两个核心问题：① 多个智能体如何**协作**达成共同目标；② 智能体间如何**博弈**（竞争或合作）。

博弈论（Game Theory）为多智能体交互提供了数学框架，分析理性决策者如何在策略互动中做选择。从冯·诺依曼的《博弈论与经济行为》（1944）到纳什均衡（1950），再到现代的算法博弈论，博弈论深刻影响了经济学、政治学、生物学和人工智能。在游戏AI中，博弈论用于设计**平衡的游戏规则**、分析**最优策略**、训练**多智能体强化学习**。

### 原理

**多智能体协作的核心机制**：

**1. 通信（Communication）**：智能体间交换信息，协调行动。通信方式：
- **黑板模式（Blackboard）**：共享数据结构，智能体读写
- **消息传递（Message Passing）**：点对点或广播消息
- **信号传递（Signaling）**：通过环境间接通信（如留下痕迹）

**2. 协调（Coordination）**：避免冲突，分配任务。方法：
- **角色分配**：每个智能体承担固定角色（坦克、治疗、输出）
- **市场拍卖**：任务作为"商品"，智能体竞价
- **共享计划**：共同规划多智能体行动序列
- **涌现协调**：通过局部规则涌现全局协调（如Flocking）

**3. 组织结构（Organization）**：
- **层级结构**：指挥官→小队→成员，命令自上而下
- **扁平结构**：智能体平等，通过协商决策
- **动态结构**：根据情境调整组织

**博弈论的核心概念**：

**1. 博弈的表示**：
- **标准式（Normal Form）**：收益矩阵，适合同时博弈
- **扩展式（Extensive Form）**：博弈树，适合序贯博弈

**2. 策略类型**：
- **纯策略（Pure Strategy）**：确定性地选择一个动作
- **混合策略（Mixed Strategy）**：以概率分布选择动作

**3. 纳什均衡（Nash Equilibrium）**：所有玩家都不愿单方面改变策略的状态。在纳什均衡下，给定其他玩家策略，每个玩家的策略都是最优响应。纳什证明任何有限博弈都存在至少一个纳什均衡（可能混合）。

**4. 帕累托最优（Pareto Optimality）**：不存在"在不损害他人的前提下让某人更好"的状态。帕累托最优是效率的衡量，纳什均衡是稳定的衡量，两者可能不一致。

**5. 经典博弈模型**：
- **囚徒困境（Prisoner's Dilemma）**：个人理性导致集体非理性
- **协调博弈（Coordination Game）**：多个均衡，需协调选择
- **零和博弈（Zero-Sum Game）**：一方收益等于另一方损失
- **雪堆博弈（Chicken Game）**：谁先退让谁输，但都不退让双输

**多智能体强化学习（MARL）** 是当前研究热点：

**1. 独立学习（Independent Learning）**：每个智能体独立学习，把其他智能体视为环境。简单但环境非平稳（其他智能体也在学习）。

**2. 集中训练分散执行（CTDE）**：训练时共享信息，执行时独立决策。代表算法：**MAPPO, QMIX, MADDPG**。

**3. 自博弈（Self-Play）**：智能体与自己博弈，逐步进化。AlphaGo、AlphaZero的核心技术。

**4. 对抗训练（Adversarial Training）**：智能体互相对抗，提升鲁棒性。GAN的思想在多智能体的应用。

**5. 种群训练（Population-Based Training）**：维护多个智能体种群，避免过拟合单一对手。AlphaStar用此方法达到星际争霸大师级。

### 例子

下面实现一个多智能体协作系统（简化版黑板模式）和一个博弈论分析（囚徒困境）：

```python
import numpy as np
import random
from typing import List, Dict, Tuple, Optional
from dataclasses import dataclass, field
from enum import Enum

# === 多智能体协作：黑板模式 ===
class Blackboard:
    """共享黑板"""
    def __init__(self):
        self.data: Dict[str, any] = {}
        self.messages: List[Dict] = []
    
    def set(self, key, value):
        self.data[key] = value
    
    def get(self, key, default=None):
        return self.data.get(key, default)
    
    def post_message(self, sender: int, msg_type: str, content: any):
        self.messages.append({
            'sender': sender,
            'type': msg_type,
            'content': content,
            'timestamp': len(self.messages)
        })
    
    def get_messages(self, msg_type: str = None) -> List[Dict]:
        if msg_type:
            return [m for m in self.messages if m['type'] == msg_type]
        return self.messages

class Role(Enum):
    TANK = "tank"        # 坦克：吸引火力
    HEALER = "healer"    # 治疗：恢复队友
    DPS = "dps"          # 输出：造成伤害

@dataclass
class CombatAgent:
    agent_id: int
    role: Role
    health: float = 100
    position: Tuple[float, float] = (0, 0)
    target_enemy: Optional[int] = None
    
    def decide(self, blackboard: Blackboard, allies: List['CombatAgent'], 
               enemies: List[Dict]) -> Dict:
        """决策：基于黑板和队友状态"""
        action = {'agent_id': self.agent_id, 'type': None, 'target': None}
        
        # 1. 检查紧急消息
        urgent_msgs = blackboard.get_messages('need_heal')
        for msg in urgent_msgs:
            if msg['sender'] != self.agent_id:
                ally = next((a for a in allies if a.agent_id == msg['sender']), None)
                if ally and self.role == Role.HEALER and ally.health < 30:
                    action['type'] = 'heal'
                    action['target'] = ally.agent_id
                    return action
        
        # 2. 角色特定行为
        if self.role == Role.TANK:
            # 坦克：吸引最强敌人
            if enemies:
                strongest = max(enemies, key=lambda e: e['threat'])
                action['type'] = 'taunt'
                action['target'] = strongest['id']
                # 广播吸引的敌人
                blackboard.post_message(self.agent_id, 'tanking', strongest['id'])
        
        elif self.role == Role.HEALER:
            # 治疗：优先治疗血量最低的队友
            wounded = [a for a in allies if a.health < 70 and a.agent_id != self.agent_id]
            if wounded:
                target = min(wounded, key=lambda a: a.health)
                action['type'] = 'heal'
                action['target'] = target.agent_id
            else:
                action['type'] = 'support'  # 辅助输出
        
        elif self.role == Role.DPS:
            # 输出：攻击坦克吸引的敌人，或攻击最弱敌人
            tank_msgs = blackboard.get_messages('tanking')
            if tank_msgs:
                action['target'] = tank_msgs[-1]['content']  # 攻击坦克吸引的敌人
            elif enemies:
                weakest = min(enemies, key=lambda e: e['health'])
                action['target'] = weakest['id']
            action['type'] = 'attack'
            
            # 血量低时请求治疗
            if self.health < 30:
                blackboard.post_message(self.agent_id, 'need_heal', self.health)
        
        return action

class MultiAgentSystem:
    """多智能体系统"""
    def __init__(self):
        self.blackboard = Blackboard()
        self.agents: List[CombatAgent] = []
    
    def add_agent(self, agent: CombatAgent):
        self.agents.append(agent)
    
    def update(self, enemies: List[Dict]) -> List[Dict]:
        """所有智能体决策"""
        actions = []
        for agent in self.agents:
            action = agent.decide(self.blackboard, self.agents, enemies)
            actions.append(action)
        return actions

# === 博弈论：囚徒困境 ===
class PrisonersDilemma:
    """囚徒困境"""
    # 收益矩阵：(A的收益, B的收益)
    #          B沉默    B背叛
    # A沉默   (-1,-1) (-3, 0)
    # A背叛   (0,-3)  (-2,-2)
    payoff_matrix = {
        ('cooperate', 'cooperate'): (-1, -1),   # 都沉默：各1年
        ('cooperate', 'defect'): (-3, 0),        # A沉默B背叛：A3年B无罪
        ('defect', 'cooperate'): (0, -3),        # A背叛B沉默：A无罪B3年
        ('defect', 'defect'): (-2, -2),          # 都背叛：各2年
    }
    
    @classmethod
    def get_payoff(cls, action_a: str, action_b: str) -> Tuple[float, float]:
        return cls.payoff_matrix[(action_a, action_b)]
    
    @classmethod
    def find_nash_equilibrium(cls) -> List[Tuple[str, str]]:
        """寻找纳什均衡"""
        equilibria = []
        actions = ['cooperate', 'defect']
        
        for a in actions:
            for b in actions:
                payoff_a, payoff_b = cls.get_payoff(a, b)
                
                # 检查A是否有动机偏离
                a_best = True
                for a_alt in actions:
                    if a_alt != a:
                        payoff_a_alt, _ = cls.get_payoff(a_alt, b)
                        if payoff_a_alt > payoff_a:
                            a_best = False
                            break
                
                # 检查B是否有动机偏离
                b_best = True
                for b_alt in actions:
                    if b_alt != b:
                        _, payoff_b_alt = cls.get_payoff(a, b_alt)
                        if payoff_b_alt > payoff_b:
                            b_best = False
                            break
                
                if a_best and b_best:
                    equilibria.append((a, b))
        
        return equilibria

def repeated_prisoners_dilemma(strategy_a, strategy_b, rounds=10):
    """重复囚徒困境"""
    history_a, history_b = [], []
    total_a, total_b = 0, 0
    
    for r in range(rounds):
        # 获取动作（策略可以参考历史）
        action_a = strategy_a(history_a, history_b)
        action_b = strategy_b(history_b, history_a)
        
        payoff_a, payoff_b = PrisonersDilemma.get_payoff(action_a, action_b)
        total_a += payoff_a
        total_b += payoff_b
        
        history_a.append(action_a)
        history_b.append(action_b)
    
    return total_a, total_b

def tit_for_tat(my_history, opp_history):
    """以牙还牙：第一轮合作，之后复制对手上一轮的动作"""
    if not opp_history:
        return 'cooperate'
    return opp_history[-1]

def always_defect(my_history, opp_history):
    return 'defect'
```

## 第21讲 现代游戏AI实战案例与未来趋势

### 概念

本讲作为课程的收官，通过分析**现代游戏AI的实战案例**，将前面20讲的知识融会贯通，并展望游戏AI的未来趋势。我们将深入剖析几款里程碑游戏的AI架构——《最后生还者》的NPC情感系统、《异形：隔离》的AI导演、《荒野大镖客2》的生态AI、《F.E.A.R.》的GOAP实战，理解工业级游戏AI如何综合运用多种技术。最后讨论游戏AI的前沿方向：大语言模型在游戏中的应用、神经渲染与AI生成内容、玩家建模与个性化等。

通过这些案例，读者将看到游戏AI不是单一技术的应用，而是**多种技术的有机融合**——一个优秀的NPC可能同时使用行为树做决策、NavMesh做导航、效用系统做战术评估、神经网络做感知。游戏AI工程师的核心能力，是理解各种技术的优劣，根据需求**选择和组合**合适的方案。

### 原理

**案例1：《F.E.A.R.》的GOAP实战**

《F.E.A.R.》（2005）是GOAP的工业里程碑，Jeff Orkin将学术规划算法成功应用于商业FPS。其AI架构核心：
- **GOAP规划器**：敌人根据目标（如"杀死玩家"）自动规划动作序列
- **工作记忆（Working Memory）**：黑板系统存储感知到的世界状态
- **感知系统**：视觉、听觉感知，结果写入工作记忆
- **动作执行**：规划出的原子动作（移动、射击、翻越）由底层执行

F.E.A.R.的AI表现出**涌现的战术行为**——敌人会侧翼包抄、压制射击、呼叫支援，这些行为并非硬编码，而是GOAP根据动作效果自动规划的结果。这证明了GOAP的"涌现性"价值。

**案例2：《最后生还者》的NPC情感系统**

《最后生还者》的同伴AI（Ellie、Tess等）以"情感真实"著称。其技术要点：
- **情感状态机**：NPC有恐惧、愤怒、信任等情感状态，影响行为
- **关系建模**：NPC对玩家的态度随互动变化
- **情境感知**：NPC根据环境（弹药充足？敌人数量？）调整行为
- **对话驱动**：NPC通过对话表达情感，增强沉浸感

关键设计：**NPC的"不完美"是刻意的**——Ellie会犯错、会害怕、会需要帮助，这些"弱点"让她显得真实。这与传统"全能AI"的设计哲学截然不同。

**案例3：《异形：隔离》的AI导演**

《异形：隔离》的异形AI被誉为"最恐怖的AI"，其核心是**双脑架构**：
- **导演AI（Director AI）**：宏观控制，了解玩家位置，决定异形的"大致区域"和"强度"
- **异形AI（Alien AI）**：微观行为，在导演指定的区域内搜索，**不知道玩家位置**

这种设计让异形既"总能找到玩家"（导演引导），又"显得在搜索"（异形AI无知），创造了恐怖的"猫鼠游戏"体验。异形AI还使用**学习机制**——会记住玩家常用的躲藏点，下次优先搜索。

**案例4：《荒野大镖客2》的生态AI**

《荒野大镖客2》的开放世界以"活的"著称，其AI生态包括：
- **动物AI**：每种动物有独特行为（狼群狩猎、鹿群逃跑、熊领地巡逻）
- **NPC日程**：NPC有日常作息，工作、休息、社交
- **事件系统**：随机事件（遇险、冲突、偶遇）动态生成
- **关系网络**：NPC间有社会关系，互动影响声誉

技术核心是**大量简单AI的涌现**——每个NPC的AI并不复杂，但数千个NPC同时运作，加上精心设计的事件触发，创造了"活的世界"的错觉。

**案例5：《黑帝斯》的对话系统**

《黑帝斯》的对话系统以"永远不会重复"著称，其技术：
- **条件对话树**：对话根据玩家进度、关系、历史选择动态分支
- **记忆系统**：NPC记住玩家的每次互动
- **优先级排序**：重要剧情对话优先于闲聊
- **变体池**：每句台词有多个变体，避免重复

**未来趋势**：

**1. 大语言模型（LLM）在游戏中的应用**：
- **动态对话**：NPC用LLM生成自然对话，摆脱预设台词
- **玩家意图理解**：LLM解析玩家自由输入（语音/文本）
- **内容生成**：LLM生成任务、剧情、角色背景
- **挑战**：实时性、成本、一致性、可控性

**2. 神经渲染与AI生成内容**：
- **神经纹理**：用神经网络生成高质量纹理
- **AI动画**：强化学习生成自然动画
- **程序生成+AI**：用ML增强PCG，生成更丰富的关卡

**3. 玩家建模与个性化**：
- **难度自适应**：根据玩家表现动态调整难度
- **内容推荐**：推荐玩家可能喜欢的任务/装备
- **行为预测**：预测玩家下一步行动，预加载资源

**4. 多模态AI**：
- **视觉+语言+动作**：NPC同时理解画面、对话、动作
- **情感识别**：通过玩家语音、表情识别情绪，调整NPC反应

**5. AI辅助开发**：
- **AI测试**：用AI自动测试游戏，发现bug
- **AI平衡**：用AI分析游戏平衡性，建议调整
- **AI美术**：用AI生成概念图、贴图、动画

### 例子

下面实现一个简化的"AI导演"系统，模拟《异形：隔离》的双脑架构：

```python
import numpy as np
import random
from typing import Tuple, List, Optional
from dataclasses import dataclass, field
from enum import Enum

class DirectorState(Enum):
    CALM = "calm"           # 平静：异形远离
    HUNTING = "hunting"     # 狩猎：异形接近
    STALKING = "stalking"   # 潜行：异形在附近搜索
    COMBAT = "combat"       # 战斗：异形发现玩家

@dataclass
class Player:
    position: Tuple[float, float]
    health: float = 100
    noise_level: float = 0  # 玩家发出的噪音
    hiding: bool = False

@dataclass
class Alien:
    position: Tuple[float, float]
    state: str = "patrol"  # patrol / search / attack
    target_area: Optional[Tuple[float, float]] = None
    known_player_pos: Optional[Tuple[float, float]] = None  # 异形"认为"的玩家位置
    search_points: List[Tuple[float, float]] = field(default_factory=list)

class AIDirector:
    """AI导演：宏观控制，知道玩家位置"""
    def __init__(self, map_size: Tuple[float, float]):
        self.map_size = map_size
        self.state = DirectorState.CALM
        self.intensity = 0.0  # 紧张度 0-1
        self.tension_timer = 0
    
    def update(self, player: Player, alien: Alien, dt: float):
        """导演更新：根据玩家状态调整异形行为"""
        # 1. 计算紧张度
        dist_to_alien = np.linalg.norm(
            np.array(player.position) - np.array(alien.position))
        
        # 玩家噪音吸引异形
        if player.noise_level > 0.5:
            self.intensity = min(1.0, self.intensity + 0.3 * dt)
        else:
            self.intensity = max(0.0, self.intensity - 0.1 * dt)
        
        # 距离影响
        if dist_to_alien < 5:
            self.intensity = min(1.0, self.intensity + 0.5 * dt)
        
        # 2. 状态转换
        old_state = self.state
        if self.intensity > 0.8:
            self.state = DirectorState.COMBAT
        elif self.intensity > 0.6:
            self.state = DirectorState.STALKING
        elif self.intensity > 0.3:
            self.state = DirectorState.HUNTING
        else:
            self.state = DirectorState.CALM
        
        if old_state != self.state:
            print(f"  [导演] 状态转换: {old_state.value} -> {self.state.value}")
        
        # 3. 引导异形（导演知道玩家位置，但异形不知道）
        if self.state == DirectorState.CALM:
            # 平静：异形随机巡逻
            if random.random() < 0.01:
                alien.target_area = self._random_point()
                alien.state = "patrol"
        
        elif self.state == DirectorState.HUNTING:
            # 狩猎：引导异形到玩家附近的大区域（不精确）
            if random.random() < 0.1:
                # 在玩家周围10-20米生成搜索区域
                angle = random.uniform(0, 2 * np.pi)
                dist = random.uniform(10, 20)
                target = (player.position[0] + np.cos(angle) * dist,
                         player.position[1] + np.sin(angle) * dist)
                alien.target_area = self._clamp_to_map(target)
                alien.state = "search"
        
        elif self.state == DirectorState.STALKING:
            # 潜行：引导异形更接近玩家
            if random.random() < 0.2:
                angle = random.uniform(0, 2 * np.pi)
                dist = random.uniform(5, 10)
                target = (player.position[0] + np.cos(angle) * dist,
                         player.position[1] + np.sin(angle) * dist)
                alien.target_area = self._clamp_to_map(target)
                alien.state = "search"
        
        elif self.state == DirectorState.COMBAT:
            # 战斗：异形直接知道玩家位置（被发现）
            alien.known_player_pos = player.position
            alien.state = "attack"
        
        # 4. 防止过度挫败：玩家躲藏时降低强度
        if player.hiding and self.state != DirectorState.COMBAT:
            self.intensity = max(0.0, self.intensity - 0.2 * dt)
    
    def _random_point(self):
        return (random.uniform(0, self.map_size[0]),
                random.uniform(0, self.map_size[1]))
    
    def _clamp_to_map(self, pos):
        return (max(0, min(self.map_size[0], pos[0])),
                max(0, min(self.map_size[1], pos[1])))

class AlienAI:
    """异形AI：微观行为，不知道玩家精确位置（除非导演告知）"""
    def __init__(self):
        self.search_memory: List[Tuple[float, float]] = []  # 记住搜索过的点
    
    def update(self, alien: Alien, player: Player, dt: float):
        """异形行为更新"""
        if alien.state == "patrol":
            # 巡逻：朝目标区域移动
            if alien.target_area:
                self._move_towards(alien, alien.target_area, speed=2, dt=dt)
        
        elif alien.state == "search":
            # 搜索：在目标区域附近搜索
            if alien.target_area:
                # 检查是否到达目标区域
                dist = np.linalg.norm(
                    np.array(alien.position) - np.array(alien.target_area))
                if dist < 2:
                    # 到达后，在附近搜索
                    if not alien.search_points:
                        # 生成搜索点（在目标区域周围）
                        for _ in range(5):
                            angle = random.uniform(0, 2 * np.pi)
                            r = random.uniform(2, 5)
                            sp = (alien.target_area[0] + np.cos(angle) * r,
                                  alien.target_area[1] + np.sin(angle) * r)
                            alien.search_points.append(sp)
                    
                    # 依次搜索各点
                    if alien.search_points:
                        target = alien.search_points[0]
                        self._move_towards(alien, target, speed=1.5, dt=dt)
                        if np.linalg.norm(
                            np.array(alien.position) - np.array(target)) < 1:
                            self.search_memory.append(alien.search_points.pop(0))
                else:
                    self._move_towards(alien, alien.target_area, speed=2, dt=dt)
        
        elif alien.state == "attack":
            # 攻击：朝已知玩家位置移动
            if alien.known_player_pos:
                self._move_towards(alien, alien.known_player_pos, speed=3, dt=dt)
                dist = np.linalg.norm(
                    np.array(alien.position) - np.array(alien.known_player_pos))
                if dist < 1:
                    print("  [异形] 抓住玩家！")
                    player.health -= 50
                    alien.known_player_pos = None
                    alien.state = "search"
    
    def _move_towards(self, alien, target, speed, dt):
        direction = np.array(target) - np.array(alien.position)
        dist = np.linalg.norm(direction)
        if dist > 0:
            direction = direction / dist
            alien.position = (
                alien.position[0] + direction[0] * speed * dt,
                alien.position[1] + direction[1] * speed * dt
            )

# === 模拟游戏 ===

        player.noise_level = 0.2  # 中期潜行
        player.hiding = True
    else:
        player.noise_level = 0.5
        player.hiding = False
    
    # 导演更新
    director.update(player, alien, dt)
    
    # 异形AI更新
    alien_ai.update(alien, player, dt)
    
    # 输出关键事件
    if tick % 10 == 0:
        dist = np.linalg.norm(
            np.array(player.position) - np.array(alien.position))
        print(f"  [Tick {tick}] 玩家=({player.position[0]:.0f},"

              f"{alien.position[1]:.0f}) 距离={dist:.1f} "
              f"异形状态={alien.state} 紧张度={director.intensity:.2f}")

print(f"\n最终玩家血量: {player.health}")
```

### 总结

本讲重点回顾：
- **F.E.A.R.**：GOAP实现涌现战术行为，工作记忆+感知+规划的经典架构
