# 借用组件全替换方案：把 DE 碎片从 niri 中彻底清除

> 生成时间：2026-08-01
> 环境：Arch Linux + niri 26.04（ThinkPad T480，Intel 核显，Wayland）
> 目标：把从 Sway / GNOME / XFCE / KDE / PulseAudio 借用的全部组件，替换为**完全独立的软件**，实现"niri + 全独立软件栈"，尽量不装任何 DE 的零件。
> 对应文档：`niri桌面环境组件分类分析.md`（分类来源）· `DE组件平替分析.md`（部分单项分析）

---

## 〇、先说结论

- **可完全替换**：swaybg、swaylock、mako、swayidle、gnome-keyring、gnome-power-manager、network-manager-applet、gvfs、file-roller、thunar 全家桶、sddm、pavucontrol —— 全部有独立替代品。
- **不可替换（硬依赖，保留）**：`xdg-desktop-portal-gtk`（gtk4 强制依赖）、`xdg-desktop-portal-wlr`（niri 强制依赖，连带 grim/slurp）、NetworkManager（已成通用标准，不算"借用"）。
- **替换后直接消失**：整套 XFCE 库（exo / libxfce4ui / libxfce4util / xfconf）、Qt5 运行时（sddm-sugar-dark 的依赖）、gsettings-desktop-schemas 的部分残留。

---

## 一、必须保留的（硬依赖，不算"借用"）

这 3 项不是"主动借用 DE 组件"，而是**系统/GTK 的强制依赖**，删掉会导致核心功能损坏：

| 保留项 | 原因 |
|--------|------|
| `xdg-desktop-portal-gtk` | **gtk4 的硬依赖**（已查证）。所有 GTK 应用依赖它做文件选择/屏幕共享。删除即破坏 GTK 栈。 |
| `xdg-desktop-portal-wlr` | **niri 的硬依赖**（`niri` 包声明 `xdg-desktop-portal-impl` 由它提供）。它负责 Wayland 屏幕录制/共享。 |
| `grim` + `slurp` | **xdg-desktop-portal-wlr 的硬依赖**（portal 内部用它们抓屏）。niri 自带截图功能，但 portal 仍需要 grim/slurp。 |
| `NetworkManager` | 起源 GNOME，但已演变为**跨 DE 通用网络服务**，niri 生态无替代。保留即可，不算借用。 |
| adwaita 图标/光标/字体、libadwaita | GTK3/GTK4 应用的**主题资源依赖**，非主动借用，保留。 |

> 结论：这 5 项中真正"不可去 GNOME 化"的只有 portal-gtk 和 grim/slurp，但它们是**依赖**而非**主动选择**，性质与 swaybg/sddm 不同。

## 二、Sway 生态替换（7 项）

### 1. swaybg → **swww**（动画壁纸）或 **wbg**（静态）

- **swww**（AUR）：独立项目，支持动图/模糊/渐变，现代 Wayland 壁纸工具。
- **wbg**（AUR）：极简静态壁纸，依赖最小。
- niri 自身**没有壁纸功能**，必须靠外部程序。

```bash
yay -S swww          # 推荐
```

niri 配置中把：
```
spawn-at-startup "swaybg" "--mode" "fill" "--image" ".../bg.png"
```
替换为：
```
spawn-at-startup "swww-daemon"
spawn-at-startup "swww" "img" "/home/adorukw/Pictures/Wallpaper/bg.png"
```

---

### 2. swaylock → **waylock**（extra 官方仓库，独立）

- **waylock**（`ifreund` 开发，官方仓库）：纯 C 的 Wayland 锁屏，**完全独立**，可配置认证界面。

```bash
sudo pacman -S waylock
yay -Rsw swaylock
```

waylock 无配置文件，用命令行参数：
- `waylock -init-color 0x1e1e2e -input-color 0x7fc8ff -ring-color 0x505050`
- 或加 `-screenshot-path` 让锁屏模糊壁纸。

**必须同步修改 3 个地方**（现在都写死了 swaylock）：
1. `~/.config/swayidle/config`：`swaylock -f` → `waylock -f`
2. `~/.config/waybar/scripts/power.sh`：`swaylock -f -c 1e1e2e` → `waylock -f -init-color 0x1e1e2e`
3. niri 键盘绑定若绑定过 `swaylock` 则改掉（当前配置没绑，跳过）

---

### 3. mako → **fnott**（extra 官方仓库，独立）

- **fnott**（`dnkl` 开发，官方仓库）：键盘驱动的 Wayland 通知守护，**完全独立**（foot 作者出品）。

```bash
sudo pacman -S fnott
yay -Rsw mako
```

- mako 配置在 `~/.config/mako/`，fnott 配置在 `~/.config/fnott/fnott.ini`，需手写重排。
- niri 的 `spawn-at-startup` 不需要额外加 fnott——它有 systemd user service（`fnott.service`）自启，且 mako.service 已由 `systemctl --user enable fnott` 接管。

```bash
systemctl --user enable --now fnott
```

---

### 4. swayidle → **systemd 用户计时器**（零第三方依赖）

- swayidle 属于 sway 项目。idle 管理其实不需要第三方守护：niri 自带 `niri msg action power-off-monitors` 和 `power-on-monitors`，锁屏交给 waylock。

**方案 A（推荐，零依赖）**：用 systemd user timer + 脚本实现"5 分钟锁屏、10 分钟关屏"。

创建 `~/.local/bin/lock-and-off.sh`：
```bash
#!/usr/bin/env bash
waylock -f &
sleep 2
niri msg action power-off-monitors
```

systemd user unit 触发：
```bash
systemctl --user start niri-lock.timer   # 需要先写 unit，见下
```

创建 `~/.config/systemd/user/niri-idle.service`：
```ini
[Unit]
Description=Lock and power off monitors
[Service]
ExecStart=/home/adorukw/.local/bin/lock-and-off.sh
Type=oneshot
```

创建 `~/.config/systemd/user/niri-idle.timer`：
```ini
[Unit]
Description=Lock after 5 min
[Timer]
OnBootSec=5min
OnUnitActiveSec=5min
[Install]
WantedBy=timers.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now niri-idle.timer
yay -Rsw swayidle
```

删除 `~/.config/swayidle/config`，并去掉 niri 配置里的 `spawn-at-startup "swayidle" "-w"`。

> **方案 B**：`hypridle`（Hyprland 生态）——不推荐，因为它属于另一个 WM（Hyprland），仍是"借用"，违背目标。

---

### 5. grim + slurp → **niri 自带截图**（官方功能，免费升级）

- niri **内置截图**：`niri msg action screenshot / screenshot-screen / screenshot-window`，且配置里已设 `screenshot-path`。
- 默认键位：`Print`=全屏、`Ctrl+Print`=屏幕、`Alt+Print`=窗口，截图 UI 自动出现。

```bash
yay -Rsw grim slurp
```

> 注意：grim/slurp 会被 `xdg-desktop-portal-wlr` 拉回来（硬依赖），所以装回后它们仍在。**不影响**，它们成了 portal 内部组件而非你主动用的工具。若想真正删除，需要同时换掉 portal-wlr——不可行，故不折腾。

## 三、GNOME 生态替换（6 项）

### 7. gnome-keyring → **KeePassXC**（extra 官方仓库，独立）

- KeePassXC 自带 `org.freedesktop.secrets` 服务，可完全接管密钥环，且是**独立项目**。

```bash
sudo pacman -S keepassxc
yay -Rsw gnome-keyring
```

niri 配置中删除：
```
spawn-at-startup "gnome-keyring-daemon" "--start" "--components=secrets,ssh"
```

之后：
- 在 KeePassXC 设置中**启用"集成 → 开启 Secret Service 集成"**，首次使用时要解锁数据库。
- Edge/Zed 等应用存密码时会弹 KeePassXC 授权请求（可选"总是允许"）。
- 注意：`niri` 包的 `org.freedesktop.secrets` 建议依赖仍满足（KeePassXC 提供）。

---

### 8. gnome-power-manager → **直接删除**（不需要替代）

- niri 自带 `niri msg action power-off-monitors`（DPMS 关屏）+ 已装的 `brightnessctl` 控亮度。
- 电池状态：waybar 的 battery.sh 已直接读 `/sys/class/power_supply/BAT*`，不依赖它。
- 电源操作：power.sh 已用 `systemctl poweroff/reboot/suspend`。

```bash
sudo pacman -R gnome-power-manager
```

---

### 9. network-manager-applet → **networkmanager-dmenu**（extra 官方仓库，独立）

- **networkmanager-dmenu**（firecat53 开发，官方仓库）：纯 dmenu/rofi 风格网络菜单，**独立项目**，替代 GNOME 托盘。
- 或 **nm-tray**（AUR）：Qt 托盘，独立项目。

```bash
sudo pacman -S networkmanager-dmenu
yay -Rsw network-manager-applet
```

- nm-applet 现在由 systemd user 服务 `app-nm-applet@autostart.service` 拉起，卸载后自动消失。
- waybar 的 network 模块 `on-click` 目前是 `nm-connection-editor`（GNOME），改成：
```jsonc
"on-click": "networkmanager_dmenu",
```
- NetworkManager 本体**保留**（通用服务）。

---

### 10. gvfs → **随 Thunar 一起删**（换终端文件管理器则不需要）

- gvfs 的回收站/网络浏览/SMB 功能只被 Thunar 这类 GUI 文件管理器使用。
- 若按第 13 节把 Thunar 换成 **yazi**，gvfs 无用途，直接删。

```bash
sudo pacman -Rns gvfs
```

> 风险提示：部分 GTK 应用（如某些下载器、文件对话框的"最近"列表）可能依赖 gvfs 的 trash 后端。若发现异常再装回 `gvfs`。

---

### 11. file-roller → **xarchiver**（extra 官方仓库，独立）或 **atool**（终端）

```bash
sudo pacman -S xarchiver
yay -Rsw file-roller
```

- 若同时弃用 Thunar 和 thunar-archive-plugin，file-roller 本身就是 Thunar 插件的调用目标，随插件一起删。
- 终端派：`atool`（aunpack/apack）。

---

### 12. xdg-desktop-portal-gtk → **保留**（gtk4 硬依赖）

## 四、XFCE 生态替换（thunar 全家桶，6 项）

### 13. thunar → **yazi**（extra 官方仓库，独立 Rust 终端文件管理器）

- **yazi**（sxyazi 开发，官方仓库）：异步终端文件管理器，内置图片/视频预览、归档解压、文件操作，Wayland 全屏窗口下体验极佳。

```bash
sudo pacman -S yazi
yay -Rns thunar thunar-archive-plugin thunar-volman tumbler xfconf exo
```

替换后：
- Thunar 的图形右键菜单/拖拽/缩略图网格会失去，换来极快的终端体验。
- 若必须保留 GUI 文件管理器且要求独立：可用 **Double Commander**（官方仓库，独立）或 **pcmanfm**（LXDE 生态，不符合"完全独立"，不推荐）。

### 14. tumbler → **yazi 内置预览**（chafa/ueberzug 依赖）

- yazi 自带预览插件，需要装 `chafa`（官方仓库）做图片预览：

```bash
sudo pacman -S chafa
```
- tumbler 随第 13 条删除。

### 15. thunar-archive-plugin → **yazi 内置归档支持** + **atool**

```bash
sudo pacman -S atool
```
- yazi 内置 `a --` 解压操作（调用系统解压工具），无需插件。

### 16. thunar-volman → **udisks2 udev 规则**（udisks2 已装）

- U 盘自动挂载：写 `/etc/udev/rules.d/99-udisks2.rules` 或直接靠 `udisksctl mount`（yazi 配置里可绑定）。
- 简单方案：yazi 配置 `[open]` 绑定 `udisksctl`。

## 五、KDE 生态替换（2 项）

### 17. sddm + sddm-sugar-dark → **greetd + tuigreet**（greetd 官方仓库独立）

- **greetd**（kennylevinsen 开发，官方仓库）：极简登录守护，**完全独立**，可配合任意 greeter。
- **tuigreet**（AUR）：文本 greeter，极简。

```bash
sudo pacman -S greetd
yay -S tuigreet
sudo systemctl disable sddm
sudo systemctl enable greetd
yay -Rsw sddm sddm-sugar-dark
```

配置 `/etc/greetd/config.toml`：
```toml
[terminal]
vt = 1

[default_session]
command = "tuigreet --time --cmd niri"
user = "greeter"
```

> 注意：卸载 sddm 会连带移除 **Qt5 运行时**（qt5-graphicaleffects、qt5-quickcontrols2、qt5-svg 等约 15 个包），系统更精简。
> 若更喜欢图形登录界面，可选 `ly`（官方仓库，独立 TUI 登录器）替代 greetd。

### 18. 备选：**ly**（extra 官方仓库，独立 TUI 登录器）

```bash
sudo pacman -S ly
sudo systemctl disable sddm
sudo systemctl enable ly
yay -Rsw sddm sddm-sugar-dark
```

## 六、PulseAudio 生态替换（1 项）

### 19. pavucontrol → **pwvucontrol**（AUR，独立，PipeWire 原生）或 **pulsemixer**（官方仓库）

- **pwvucontrol**（AUR）：专为 PipeWire 写的 GTK 音量控制，功能对标 pavucontrol。
- **pulsemixer**（官方仓库，独立）：ncurses 音量工具，零 GUI。

```bash
yay -S pwvucontrol      # 或 sudo pacman -S pulsemixer
yay -Rsw pavucontrol
```

waybar 的 pulseaudio 模块 `on-click-right` 目前是 `pavucontrol`，改成：
```jsonc
"on-click-right": "pwvucontrol"
```

## 八、执行顺序（安全操作顺序）

```bash
# 1. 先装好所有替代品，避免中途无锁屏/无登录
sudo pacman -S waylock fnott yazi xarchiver atool chafa keepassxc \
    networkmanager-dmenu greetd pulsemixer
yay -S swww pwvucontrol
yay -S tuigreet

# 2. 登录管理器（最先换，否则重启进不去）
sudo systemctl disable sddm && sudo systemctl enable greetd

# 3. 配置 niri（改壁纸、删旧 spawn）
# 4. 配置 systemd idle timer + 删 swayidle/swaylock 配置
# 5. 配置 KeePassXC secrets 集成
# 6. 卸载全部借用组件
yay -Rsw swaybg swaylock mako swayidle gnome-keyring gnome-power-manager \
    network-manager-applet file-roller \
    thunar thunar-archive-plugin thunar-volman tumbler xfconf \
    sddm sddm-sugar-dark pavucontrol gvfs grim slurp

# 7. 清理孤儿依赖
yay -Yc
```

> 注意：grim/slurp 会被 portal-wlr 自动装回，属正常现象（见第 5 节）。

## 十、风险与回滚

| 风险 | 说明 | 对策 |
|------|------|------|
| 锁屏失效 | swaylock→waylock 参数不同 | 先测 `waylock -f` 能锁住再删 swaylock |
| 登录进不去 | sddm→greetd 配置错误 | 切换前**先 enable greetd 再 disable sddm**；grub 菜单可进 TTY 回滚 |
| 密码存储丢失 | gnome-keyring→KeePassXC 未配置 secrets | 先开 KeePassXC 集成并解锁一次，再删 gnome-keyring |
| GTK 应用"最近文件"异常 | gvfs 被删 | 如异常则 `sudo pacman -S gvfs` 装回 |
| 通知不显示 | mako→fnott 配置未迁移 | 对照 mako 配置逐条改写 fnott.ini |

**回滚命令**：
```bash
sudo pacman -S sddm swaybg swaylock mako swayidle gnome-keyring thunar pavucontrol
sudo systemctl disable greetd && sudo systemctl enable sddm
# 恢复 niri config.kdl 备份即可
```

## 十一、最终结论

1. **19 个借用组件中 16 个可以彻底替换**，只剩 portal-gtk、portal-wlr（+连带 grim/slurp）是 gtk4/niri 的硬依赖，且它们本质是"库依赖"而非"主动借用的桌面组件"。
2. **替换后系统更精简**：预计卸载约 40~50 个包（含整套 XFCE 库和 Qt5 运行时）。
3. **核心亮点**：锁屏/壁纸/通知全部换成独立项目（waylock/swww/fnott），idle 甚至零依赖（systemd timer），登录器换成 greetd——除了 portal 依赖，niri 桌面真正做到"零 DE 组件"。
4. 建议分**两步**执行：先做低风险项（swaybg/swaylock/mako/pavucontrol/file-roller），稳定后做高风险项（sddm、gnome-keyring、thunar 全家桶）。
