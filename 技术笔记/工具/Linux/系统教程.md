## 第1章 Linux 基础入门

### 第1讲 Linux 概述与发展历史

#### 概念

**Linux** 是一个开源的、类 Unix 的操作系统内核，由芬兰人 Linus Torvalds 于 1991 年创建。严格来说，"Linux"只是内核（kernel）的名字，但日常语境中我们用"Linux"指代基于该内核的完整操作系统（即 Linux 发行版）。Linux 是自由软件（Free Software）和开源软件（Open Source Software）的典范，其内核代码遵循 GPL 协议发布，任何人都可以自由使用、修改和分发。

Linux 与 Windows、macOS 并列为三大主流操作系统，但它有一个独特之处：你日常说的"Linux"实际上是由 Linux 内核 + GNU 工具链 + 各种应用软件组合而成的**发行版**（Distribution，简称 Distro）。这种"内核 + 组件"的模块化设计是 Unix 哲学的体现，也是 Linux 灵活强大的根源。

#### 原理

Linux 的诞生有三个关键背景：① 1983 年 Richard Stallman 发起 **GNU 计划**（GNU's Not Unix），目标是创建一个自由的 Unix 类操作系统，到 1990 年代初 GNU 已经完成了大部分组件（编译器 GCC、文本编辑器 Emacs、Shell 等），但缺少一个可用的内核；② 1991 年 Linus Torvalds 在赫尔辛基大学读书时，因为对 Minix（一个教学用 Unix）的限制不满，自己写了一个终端模拟器，逐渐发展成内核原型，并在 1991 年 8 月 25 日在 Usenet 上发布了著名的帖子，宣告 Linux 诞生；③ GNU 的工具 + Linux 内核，恰好补齐了彼此的缺口，形成了完整的 GNU/Linux 操作系统。

Linux 内核采用**宏内核**（Monolithic Kernel）架构，与 Windows NT 的**混合内核**和 Mach 的**微内核**（Microkernel）不同。宏内核将进程管理、内存管理、文件系统、设备驱动等都运行在内核态，性能高但耦合度大；微内核只把最核心功能放内核态，其他作为用户态服务，更模块化但通信开销大。Linux 通过**可加载内核模块**（LKM）机制在宏内核基础上实现了动态扩展能力，兼顾了性能和灵活性。Linux 的开发模式是独特的"分布式协作"——全球数千名开发者通过邮件列表提交补丁，Linus 担任最终维护者，这是开源协作的奇迹。

#### 例子

Linux 发展的关键时间节点：

```

1989  GPL v1 发布
1991  Linus 发布 Linux 0.01（10月）

1993  Slackware、Debian 等首批发行版出现
1994  Linux 1.0 发布，Red Hat 成立
1996  Tux 企鹅成为官方吉祥物
2000  Linux 2.4，支持 SMP 多处理器
2003  Linux 2.6，企业级特性完善

```

```bash

```

#### 总结

- Linux 是 1991 年 Linus Torvalds 创建的开源类 Unix 内核，与 GNU 工具结合形成完整系统
- 采用宏内核架构，通过可加载模块实现动态扩展，兼顾性能和灵活性
- Linux 本身只是内核，"Linux 系统"实际是发行版（内核 + GNU 工具 + 应用）
- Linux 开发模式是分布式协作的典范，通过 Git 和邮件列表协作
- Linux 主导了服务器、超算、移动、嵌入式等领域，是现代互联网的基石

### 第2讲 Linux 发行版选型与安装

#### 概念

**Linux 发行版**（Linux Distribution）是基于 Linux 内核，搭配 GNU 工具链、桌面环境、包管理器、应用软件等打包而成的完整操作系统。不同发行版在包管理、软件版本、更新策略、目标用户上各有侧重。主流发行版可分为三大家族：**Red Hat 系**（RHEL/CentOS/Rocky/AlmaLinux/Fedora）、**Debian 系**（Debian/Ubuntu/Linux Mint）、**独立系**（Arch/Gentoo/SUSE/Alpine）。选对发行版是 Linux 学习的第一步。

#### 原理

发行版的差异主要体现在四个维度：① **包管理系统**——Red Hat 系用 RPM + YUM/DNF，Debian 系用 DEB + APT，Arch 用 Pacman，这是最直观的区别；② **发布策略**——滚动发布（Rolling，如 Arch/Manjaro，永远最新）vs 点发布（如 Ubuntu 每 6 个月一版，Debian 两年一版）；③ **稳定性 vs 新鲜度**——服务器优先稳定（Debian Stable、RHEL），桌面优先新鲜（Fedora、Arch）；④ **支持模式**——商业支持（RHEL、SUSE）、社区维护（Debian、CentOS）。

选型原则：① **服务器/生产环境**首选 RHEL 系（Rocky/AlmaLinux 替代 CentOS）或 Ubuntu LTS，因为有长期支持和广泛文档；② **桌面学习**首选 Ubuntu 或 Linux Mint，对新手友好；③ **进阶玩家**用 Arch 或 Fedora 尝鲜；④ **容器/精简场景**用 Alpine（5MB 大小）。安装方式主要有：图形安装器（最简单）、最小安装（服务器常用）、PXE 网络安装（批量部署）、云镜像（云服务器常用）。

#### 例子

主流发行版对比：

| 发行版 | 包管理 | 发布周期 | 适用场景 | 特点 |
|--------|--------|----------|----------|------|
| Ubuntu | apt/dpkg | 6个月/2年LTS | 桌面、服务器、云 | 新手友好，文档丰富 |
| Debian | apt/dpkg | 2年 | 服务器 | 极致稳定，Ubuntu 之父 |
| RHEL | dnf/rpm | 3-10年 | 企业服务器 | 商业支持，认证齐全 |
| Rocky/Alma | dnf/rpm | 跟随RHEL | 企业服务器 | CentOS 替代品 |
| Fedora | dnf/rpm | 6个月 | 桌面、开发 | 新技术试验田 |
| CentOS Stream | dnf/rpm | 滚动 | 开发测试 | RHEL 上游 |
| Arch | pacman | 滚动 | 进阶桌面 | 极简，DIY |
| Alpine | apk | 滚动 | 容器 | 5MB，安全 |
| openSUSE | zypper/rpm | 8个月/滚动 | 桌面、服务器 | YaST 管理工具 |

### 第3讲 Linux 目录结构与文件系统层次标准

#### 概念

Linux 采用**单根树形目录结构**，所有文件和设备都从根目录 `/` 开始，没有 Windows 的 C/D/E 盘概念。这种结构由 **FHS**（Filesystem Hierarchy Standard，文件系统层次标准）规范，定义了各目录的用途和内容。理解目录结构是高效使用 Linux 的基础——知道配置文件在哪、日志在哪、可执行文件在哪，能让你快速定位问题。

#### 原理

FHS 标准的核心思想是"**分类存放**"：可执行文件放 `/bin` 和 `/usr/bin`，配置文件放 `/etc`，日志放 `/var/log`，用户数据放 `/home`，设备文件放 `/dev`，挂载点放 `/mnt` 和 `/media`。这种分类让系统管理有章可循，也让不同发行版保持一致性。

一个重要演变：早期 Linux 区分 `/bin`（基础命令，单用户模式可用）和 `/usr/bin`（更多命令），`/lib` 和 `/usr/lib` 类似。但现代发行版（Fedora 17 起、Ubuntu 16.04 起）已将 `/bin`、`/lib`、`/sbin` 软链接到 `/usr/bin`、`/usr/lib`、`/usr/sbin`，实现 **usrmerge**，简化了目录结构。理解这一点能解释为什么 `ls -l /bin` 显示的是符号链接。

另一个关键概念是**挂载点**（mount point）：一个磁盘分区或文件系统挂载到某个目录后，访问该目录就是访问该分区的内容。比如 `/home` 可以是独立分区，`/boot` 通常是独立分区。这种设计让系统可以跨多个物理磁盘，但用户视角仍是统一的目录树。

#### 例子

Linux 标准目录结构：

```
/
├── bin      -> usr/bin      # 基础命令（所有用户可用）
├── sbin     -> usr/sbin     # 系统管理命令（root 用）
├── lib      -> usr/lib      # 基础库文件
├── usr                     # 用户程序和数据
│   ├── bin                 # 大部分命令
│   ├── sbin                # 系统命令
│   ├── lib                 # 库文件
│   ├── local               # 本地安装的软件
│   ├── share               # 共享数据（文档、图标）
│   └── src                 # 源码
├── etc                     # 系统配置文件
├── home                    # 用户家目录
│   ├── alice/
│   └── bob/
├── root                    # root 用户家目录
├── var                     # 可变数据
│   ├── log                 # 日志
│   ├── cache               # 缓存
│   ├── lib                 # 应用状态数据
│   ├── spool               # 队列（邮件、打印）
│   └── tmp                 # 临时文件（重启保留）
├── tmp                     # 临时文件（重启清空）
├── dev                     # 设备文件
│   ├── sda, sdb            # 磁盘
│   ├── null, zero, random  # 特殊设备
│   └── pts                 # 伪终端
├── proc                    # 进程信息（虚拟文件系统）
├── sys                     # 内核与硬件信息（虚拟）
├── run                     # 运行时数据（PID 文件等）
├── mnt                     # 临时挂载点
├── media                   # 可移动介质挂载
├── opt                     # 第三方软件
└── boot                    # 启动文件
    ├── vmlinuz-*           # 内核镜像
    └── grub/               # 引导配置
```

各目录的典型内容和用途：

```bash
# /etc - 配置文件
ls /etc/ | head
# hostname, hosts, passwd, group, shadow, fstab, ssh/, nginx/, ...

# /var/log - 日志文件
ls /var/log/
# syslog, auth.log, dmesg, kern.log, nginx/, mysql/, ...

# /home - 用户家目录
ls /home/
# alice  bob

# /dev - 设备文件
ls /dev/ | head
# sda, sda1, sda2, null, zero, random, urandom, tty, pts/

# /proc - 内核与进程信息（虚拟）
ls /proc/ | head
# 1/  10/  cpuinfo  meminfo  uptime  version  ...

# 查看进程信息
cat /proc/1/cmdline        # PID 1 的启动命令
cat /proc/cpuinfo          # CPU 信息
cat /proc/meminfo          # 内存信息

# /sys - 内核设备模型（虚拟）
ls /sys/class/net/         # 网络接口

# 特殊设备文件
echo "hello" > /dev/null   # 黑洞，丢弃输出
dd if=/dev/zero of=file bs=1M count=10  # 生成 10MB 全零文件
head -c 16 /dev/urandom | xxd  # 随机字节

# 查看挂载情况
mount                      # 所有挂载
df -h                      # 磁盘使用
findmnt                    # 树形显示挂载
lsblk                      # 块设备
```

理解路径的绝对与相对：

```bash
# 绝对路径：从 / 开始
cat /etc/hostname
ls /var/log/

# 相对路径：从当前目录开始
cd /var/log
ls nginx/                  # 等价 ls /var/log/nginx
cd ../spool                # 等价 cd /var/spool

# 特殊目录
.                          # 当前目录
..                         # 上一级目录
~                          # 家目录
-                          # 上次所在目录
```

#### 总结

- Linux 是单根树形目录，所有文件从 `/` 开始，无盘符概念
- FHS 标准规范各目录用途：`/etc` 配置、`/var/log` 日志、`/home` 用户、`/dev` 设备
- 现代发行版已 usrmerge，`/bin`/`/lib`/`/sbin` 是 `/usr` 下的符号链接
- `/proc` 和 `/sys` 是虚拟文件系统，反映内核和进程状态
- 挂载点机制让多磁盘统一为单目录树，`df -h` 和 `lsblk` 查看挂载情况

## 第2章 命令行与文件操作

### 第4讲 终端、Shell 与基本命令

#### 概念

**终端**（Terminal）原本是物理设备（电传打字机 TTY），现在指模拟终端软件（如 GNOME Terminal、iTerm2、Windows Terminal）。**Shell** 是命令行解释器，接收用户输入的命令并执行，常见有 Bash、Zsh、Fish。**控制台**（Console）是系统直接连接的终端。理解终端、Shell、控制台的关系，是高效使用命令行的前提。本讲介绍日常最常用的基础命令。

#### 原理

终端模拟器是一个图形程序，它模拟传统硬件终端的行为，提供文本输入输出界面。当你在终端输入命令时，终端把字符传给 Shell（通过伪终端 PTY 机制）。Shell 解析命令行（处理变量替换、管道、重定向等），然后 fork 子进程执行命令，命令的输出通过 PTY 回传给终端显示。

Linux 上每个终端会话对应一个 PTY（伪终端对），主端由终端模拟器读写，从端由 Shell 及其子进程使用。`/dev/pts/` 目录下每个打开的终端对应一个数字文件。`tty` 命令显示当前终端对应的设备文件。这种 PTY 机制让多个终端会话独立运行，互不干扰。

Shell 的核心能力包括：**命令历史**（上下箭头调出历史命令）、**Tab 补全**（输入部分命令按 Tab 自动补全）、**通配符**（`*` 匹配任意字符，`?` 匹配单字符）、**管道**（`|` 连接命令）、**重定向**（`>` `>>` `<`）、**别名**（`alias` 自定义命令简称）、**作业控制**（`Ctrl+Z` 暂停、`fg`/`bg` 切换前后台）。熟练运用这些能力，命令行效率远超图形界面。

#### 例子

```bash
# 基本信息命令
whoami                    # 当前用户名
hostname                  # 主机名
date                      # 当前日期时间
uptime                    # 系统运行时长和负载
cal                       # 日历
cal 2026                  # 2026 年全年日历

# 终端与 Shell 信息
tty                       # 当前终端设备（如 /dev/pts/0）
echo $SHELL               # 当前 Shell（如 /bin/bash）
```

### 第5讲 文件与目录操作

#### 概念

文件与目录操作是 Linux 日常使用最频繁的动作。核心命令包括：`pwd`（显示当前目录）、`cd`（切换目录）、`ls`（列出目录内容）、`mkdir`（创建目录）、`rmdir`（删除空目录）、`touch`（创建空文件或更新时间戳）、`cp`（复制）、`mv`（移动/重命名）、`rm`（删除）、`ln`（创建链接）、`stat`（查看文件属性）。掌握这些命令的常用选项，能高效管理文件系统。

#### 原理

Linux 文件系统中的每个文件都有一个**inode**（索引节点），存储文件的元数据（权限、所有者、大小、时间戳、数据块位置），但不包含文件名。文件名存储在目录项中，目录项是"文件名 → inode 号"的映射。这种设计让**硬链接**（hard link）成为可能：多个文件名指向同一个 inode，删除其中一个不影响其他。`ls -i` 可以查看 inode 号。

**软链接**（symbolic link，又称符号链接）是另一种链接方式，它是一个特殊文件，内容是另一个文件的路径。软链接类似 Windows 的快捷方式，删除原文件后软链接失效（dangling link）。软链接可以跨文件系统、可以链接目录，而硬链接不行。`ln` 默认创建硬链接，`ln -s` 创建软链接。

`cp`、`mv`、`rm` 的行为：`cp` 默认复制文件，`-r` 递归复制目录，`-p` 保留属性，`-i` 交互确认；`mv` 既是移动也是重命名（同分区移动只改目录项，极快；跨分区移动需复制+删除）；`rm` 默认不删目录，`-r` 递归删除，`-f` 强制不确认。`rm -rf` 是危险命令，要慎用，特别是路径变量为空时可能误删根目录。

#### 例子

```bash
# pwd：显示当前目录
pwd                        # /home/alice/projects

# cd：切换目录
cd /var/log                # 切到绝对路径
cd ..                      # 上一级
cd ../..                   # 上两级
cd ~                       # 回家目录
cd                         # 同上
cd -                       # 回上次目录
cd ~/projects              # 家目录下的 projects

# ls：列出目录
ls                         # 当前目录
ls /var/log                # 指定目录
ls -l                      # 长格式（权限、属主、大小、时间）
ls -a                      # 包含隐藏文件（以 . 开头）
ls -la                     # 长格式 + 隐藏文件
ls -lh                     # 大小人类可读（K/M/G）
ls -lt                     # 按修改时间排序
ls -ltr                    # 按时间倒序（最旧在前）
ls -lS                     # 按大小排序
ls -li                     # 显示 inode 号
ls -R                      # 递归列出子目录
ls -d */                   # 只列出目录

# mkdir：创建目录
mkdir newdir               # 创建一个目录
mkdir -p a/b/c             # 递归创建（父目录不存在也不报错）
mkdir -p project/{src,doc,test}  # 一次创建多目录
mkdir -m 700 secret        # 创建时指定权限

# rmdir：删除空目录
rmdir emptydir             # 只能删空目录
rmdir -p a/b/c             # 递归删空目录

# touch：创建空文件或更新时间戳
touch newfile.txt          # 创建空文件
touch existing.txt         # 更新访问和修改时间
touch -t 202601010000 old.txt  # 设置指定时间
touch -a file              # 只更新访问时间
touch -m file              # 只更新修改时间

# cp：复制
cp file.txt backup.txt     # 复制文件
cp -i file.txt backup.txt  # 交互确认覆盖
cp -r dir1 dir2            # 递归复制目录
cp -a dir1 dir2            # 归档模式（保留权限、属主、时间、链接）
cp -p file.txt backup.txt  # 保留属性
cp -v file.txt backup.txt  # 显示复制过程
cp -u file.txt backup.txt  # 只在源更新时复制
cp *.txt /backup/          # 复制多个文件到目录

# mv：移动/重命名
mv old.txt new.txt         # 重命名
mv file.txt /tmp/          # 移动到目录
mv -i file.txt /tmp/       # 交互确认
mv -v file.txt /tmp/       # 显示过程
mv -u file.txt /tmp/       # 只在源更新时移动
mv dir1 dir2               # 移动目录（不需要 -r）

# rm：删除
rm file.txt                # 删除文件
rm -i file.txt             # 交互确认
rm -f file.txt             # 强制删除（不提示）
rm -r dir                  # 递归删除目录
rm -rf dir                 # 强制递归删除（危险！）
rm -- -file.txt            # 删除以 - 开头的文件
rm *.bak                   # 删除所有 .bak 文件

# ln：创建链接
ln file.txt hardlink.txt   # 硬链接（同分区，同 inode）
ln -s file.txt softlink.txt  # 软链接（可跨分区、可链目录）
ln -sf /usr/bin/python3 /usr/bin/python  # 强制重建软链接

# stat：查看文件属性
stat file.txt              # 大小、块、inode、权限、时间戳
stat -c '%n %s %A %U' file.txt  # 自定义格式

# file：查看文件类型
file file.txt              # ASCII text
file image.jpg             # JPEG image data
file script.sh             # POSIX shell script
file /bin/ls               # ELF 64-bit LSB executable

# tree：树形显示目录（需安装）
tree                       # 当前目录树
tree -L 2                  # 只显示 2 层
tree -d                    # 只显示目录
tree -a                    # 包含隐藏文件
tree -h                    # 显示文件大小
```

理解硬链接和软链接：

```bash
# 创建测试文件
echo "hello" > original.txt

# 硬链接
ln original.txt hard.txt
ls -li original.txt hard.txt
# 两个文件 inode 号相同，是同一个文件的两个名字
# 删除 original.txt 后 hard.txt 仍可读

# 软链接
ln -s original.txt soft.txt
ls -li original.txt soft.txt
# inode 不同，soft.txt 是独立文件，内容是路径
# 删除 original.txt 后 soft.txt 失效（红色闪烁）

# 实际应用
ln -sf /etc/nginx/sites-available/myapp /etc/nginx/sites-enabled/myapp
# Nginx 启用站点：创建软链接
```

#### 总结

- `ls -la` 是最常用的目录查看组合，`-l` 长格式 `-a` 含隐藏文件
- `cp -r` 复制目录，`cp -a` 保留属性，`mv` 同分区是改名跨分区是复制+删除
- `rm -rf` 极度危险，路径变量为空时会误删，脚本中要加 `${VAR:?}` 保护
- 硬链接同 inode 不能跨分区不能链目录，软链接是路径引用更灵活
- `stat` 查看完整属性，`file` 识别文件类型，`tree` 可视化目录结构

### 第6讲 文本查看与处理

#### 概念

Linux 系统中配置文件、日志、源代码都是纯文本，文本查看与处理是日常核心任务。本讲聚焦最常用的文本命令：`cat`/`tac`（输出/反向输出）、`less`/`more`（分页查看）、`head`/`tail`（查看头尾）、`grep`（搜索过滤）、`sort`/`uniq`（排序去重）、`cut`/`tr`（切分转换）、`wc`（统计）。这些命令通过管道组合，能完成复杂的数据处理。

#### 原理

文本命令的设计体现了 Unix 哲学：每个工具做一件事并做好，通过管道组合完成复杂任务。`cat` 顺序读取文件输出到 stdout，适合小文件；`less` 是分页器，按需加载支持搜索翻页，适合大文件。`head`/`tail` 默认各显示 10 行，`tail -f` 是运维神器——它持续跟踪文件末尾新增内容，实时查看日志。

`grep` 按**正则表达式**逐行匹配，输出匹配行。支持基础正则（BRE，默认）、扩展正则（ERE，`-E`）、Perl 正则（`-P`）。`sort` 排序，`-n` 数值排序（否则 "10" < "9"），`-r` 逆序，`-k` 按字段，`-u` 去重。`uniq` 只能去连续重复行，必须先 `sort` 再 `uniq`，`-c` 统计次数。`cut` 按字符或字段切分，`tr` 做字符级转换。`wc` 统计行数、单词数、字节数。

#### 例子

```bash
# cat：查看小文件
cat file.txt
cat -n file.txt            # 显示行号
cat -A file.txt            # 显示特殊字符（行尾$，Tab^I）
cat a.txt b.txt > merged.txt  # 合并文件

# tac：反向输出
tac file.txt               # 最后一行变第一行

# less：分页查看大文件
less /var/log/syslog
# 内部操作：
#   空格/f   向下翻页
#   b        向上翻页
#   j/k      上下移动
#   /word    向下搜索
#   ?word    向上搜索
#   n/N      下一个/上一个匹配
#   g/G      跳到开头/结尾
#   q        退出

# head：查看开头
head file.txt              # 前 10 行
head -n 20 file.txt        # 前 20 行
head -n -5 file.txt        # 除最后 5 行
head -c 100 file.txt       # 前 100 字节

# tail：查看结尾
tail file.txt              # 后 10 行
tail -n 20 file.txt        # 后 20 行
tail -n +5 file.txt        # 从第 5 行到结尾
tail -f /var/log/app.log   # 实时跟踪日志
tail -f -n 50 app.log      # 显示最后 50 行并持续跟踪

# grep：搜索过滤
grep "error" log.txt
grep -i "error" log.txt    # 忽略大小写
grep -n "error" log.txt    # 显示行号
grep -c "error" log.txt    # 统计匹配行数
grep -v "error" log.txt    # 反向：不含 error 的行
grep -r "TODO" /project/   # 递归搜索目录
grep -rl "TODO" /project/  # 只输出文件名
grep -E "error|warning" log.txt  # 扩展正则
grep -A 2 "error" log.txt  # 匹配行 + 后 2 行
grep -B 2 "error" log.txt  # 匹配行 + 前 2 行
grep -C 2 "error" log.txt  # 前后各 2 行
ps aux | grep nginx | grep -v grep  # 排除 grep 自身

# sort：排序
sort file.txt              # 字典序
sort -n numbers.txt        # 数值排序
sort -rn numbers.txt       # 数值逆序
sort -u file.txt           # 排序并去重
sort -k 2 data.txt         # 按第 2 字段
sort -t ',' -k 3 -n csv.txt  # 逗号分隔按第 3 字段数值排序

# uniq：去重（需先 sort）
sort file.txt | uniq       # 排序去重
sort file.txt | uniq -c    # 去重并统计次数
sort file.txt | uniq -c | sort -rn  # 按次数排序（词频统计）
sort file.txt | uniq -d    # 只显示重复的行

# cut：按列切分
cut -c 1-5 file.txt        # 每行第 1-5 字符
cut -d ',' -f 1,3 csv.txt  # 逗号分隔取第 1、3 字段
cut -d ':' -f 1,7 /etc/passwd  # 取用户名和 Shell

# tr：字符转换
echo "Hello" | tr 'a-z' 'A-Z'   # 转大写
echo "192.168.1.1" | tr '.' '-'  # 点转横线
echo "hello world" | tr -d ' '   # 删除空格
echo "a    b" | tr -s ' '        # 压缩连续空格

# wc：统计
wc file.txt                # 行数 单词数 字节数
wc -l file.txt             # 行数
wc -w file.txt             # 单词数
wc -c file.txt             # 字节数
ls -l /etc | wc -l         # 统计文件数
```

经典组合——日志分析：

```bash
# 统计访问量前 10 的 IP
cat access.log | awk '{print $1}' | sort | uniq -c | sort -rn | head -10

# 统计状态码分布
cat access.log | awk '{print $9}' | sort | uniq -c | sort -rn

# 找出 4xx 错误的 URL
grep ' 4[0-9][0-9] ' access.log | awk '{print $7}' | sort | uniq -c | sort -rn | head

# 实时监控错误日志
tail -f /var/log/app.log | grep --color=auto "ERROR"

cat article.txt | tr -s ' ' '\n' | tr 'A-Z' 'a-z' | sort | uniq -c | sort -rn | head -20
```

- `cat` 适合小文件，`less` 适合大文件，记住"less is more"
- `tail -f` 是实时查看日志的神器，配合 `grep` 过滤关键信息
- `grep` 常用选项：`-i`（忽略大小写）、`-v`（反向）、`-n`（行号）、`-r`（递归）、`-E`（扩展正则）
- `sort | uniq -c | sort -rn` 是词频统计的经典三连
- `cut` 按字符或字段切分，`tr` 做字符级转换，`wc -l` 统计行数最常用

## 第3章 用户与权限管理

### 第7讲 用户与组管理

#### 概念

Linux 是**多用户多任务**操作系统，每个用户有唯一 UID（用户 ID），每个组有唯一 GID（组 ID）。用户必须属于一个**主组**（primary group），还可以加入多个**附加组**（supplementary group）。用户和组信息存储在 `/etc/passwd`、`/etc/shadow`、`/etc/group`、`/etc/gshadow` 四个文件中。用户管理是系统管理员的核心职责。

#### 原理

Linux 用户分三类：① **root 用户**（UID 0），拥有所有权限；② **系统用户**（UID 1-999，不同发行版范围略有差异），用于运行服务（如 nginx、mysql），不登录；③ **普通用户**（UID 1000+），日常使用。`/etc/passwd` 存储用户基本信息（每行一个用户），格式为 `用户名:密码占位:UID:GID:描述:家目录:Shell`。密码实际存储在 `/etc/shadow`（只有 root 可读），格式为 `用户名:加密密码:最后修改:最短:最长:警告:不活动:过期:保留`。

组的机制用于批量授权：把多个用户加入同一组，对该组授权即对所有成员授权。`/etc/group` 格式为 `组名:密码占位:GID:成员列表`。用户创建时默认会创建同名主组（user private group 模式），这种设计避免了"用户共享主组"的权限混乱。用户切换用 `su`（switch user），`su -` 完整切换（加载目标用户环境），`sudo` 以其他用户身份执行命令（默认 root），`sudo` 比 `su` 更安全，因为不需要共享 root 密码。

#### 例子

```bash
# 查看用户和组信息
id                        # 当前用户 UID/GID/组
id alice                  # 指定用户
whoami                    # 当前用户名
groups                    # 当前用户所属组
groups alice              # 指定用户所属组

# /etc/passwd 文件格式
cat /etc/passwd | head
# root:x:0:0:root:/root:/bin/bash
# daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
# alice:x:1000:1000:Alice:/home/alice:/bin/bash
# 字段：用户名:密码占位:UID:GID:描述:家目录:Shell

# /etc/shadow 文件（root 才能读）
sudo cat /etc/shadow | head
# alice:$6$xxx...:19000:0:99999:7:::
# 字段：用户名:加密密码:最后修改天数:最短天数:最长天数:警告:不活动:过期:保留

# /etc/group 文件
cat /etc/group | head
# root:x:0:
# alice:x:1000:
# docker:x:998:alice,bob

# 用户管理命令
# 创建用户
sudo useradd alice                    # 基本创建
sudo useradd -m alice                 # 创建家目录
sudo useradd -m -s /bin/bash alice    # 指定 Shell
sudo useradd -m -s /bin/bash -c "Alice Smith" alice  # 加描述
sudo useradd -m -G docker,sudo alice  # 加入附加组

# 设置密码
sudo passwd alice                     # 给 alice 设密码
passwd                                # 改自己密码

# 修改用户
sudo usermod -aG docker alice         # 追加到附加组（-aG 必须配合）
sudo usermod -aG sudo alice           # 加入 sudo 组（获得 sudo 权限）
sudo usermod -s /bin/zsh alice        # 改 Shell
sudo usermod -c "Alice Lee" alice     # 改描述
sudo usermod -l alice2 alice          # 改用户名
sudo usermod -L alice                 # 锁定账号
sudo usermod -U alice                 # 解锁账号
sudo usermod -e 2026-12-31 alice      # 设置过期日期

# 删除用户
sudo userdel alice                    # 删除用户（保留家目录）
sudo userdel -r alice                 # 删除用户和家目录
sudo userdel -rf alice                # 强制删除（即使登录中）

# 组管理

sudo -i                # 用 sudo 切到 root（需自己密码 + sudo 权限）
sudo -u alice whoami   # 以 alice 身份执行命令
sudo su -              # 等价 sudo -i

# 查看登录用户
```

### 第8讲 文件权限与所有者

#### 概念

Linux 文件权限是系统安全的基石。每个文件有三类用户：**属主**（owner，u）、**属组**（group，g）、**其他**（other，o），每类有三个权限：**读**（r，4）、**写**（w，2）、**执行**（x，1）。权限用 9 位表示（3 类 × 3 权限），如 `rwxr-xr--` 等价于 `754`。`chmod` 改权限，`chown` 改属主属组，`chgrp` 改属组，`umask` 设默认权限。还有 SUID、SGID、Sticky 三个特殊权限位。

#### 原理

权限的底层实现是 inode 中的 mode 字段，16 位中 9 位存 rwx，3 位存特殊权限，4 位存文件类型。当进程访问文件时，内核按"属主 → 属组 → 其他"的顺序匹配：如果是属主，用属主权限；否则如果属组匹配，用属组权限；否则用其他权限。这种"最先匹配"规则意味着：如果属主权限是 `---`，即使属组权限是 `rwx`，属主也读不了——这是新手常踩的坑。

**读**权限允许查看文件内容（`cat`、`less`），**写**权限允许修改内容，**执行**权限允许运行文件（对脚本还需读权限）。对目录而言：**读**允许列出目录内容（`ls`），**执行**允许进入目录和访问其中文件（`cd`、`stat file`）。所以目录通常给 `r-x`（可看可进）或 `---`（完全禁止）。注意：目录的**写**权限允许在其中创建/删除文件，这意味着即使没有文件的写权限，只要对目录有写权限就能删除文件——这是 Sticky 位要解决的问题。

**SUID**（Set UID，4）：对可执行文件设置后，执行时以文件属主身份运行（如 `/usr/bin/passwd` 是 SUID root，普通用户能改密码）。**SGID**（Set GID，2）：对文件类似 SUID 但以属组身份；对目录设置后，目录下新建文件继承目录的属组（适合共享目录）。**Sticky**（1，t）：对目录设置后，目录下文件只有属主（或 root）能删除（如 `/tmp` 是 1777，所有人可写但只能删自己的文件）。

#### 例子

```bash
# 查看权限
ls -l file.txt
# -rw-r--r-- 1 alice staff 256 Jul 8 14:00 file.txt
# 第 1 字符：文件类型（- 普通文件，d 目录，l 符号链接，c 字符设备，b 块设备）
# 第 2-4 字符：属主权限 rw-
# 第 5-7 字符：属组权限 r--
# 第 8-10 字符：其他权限 r--

# 数字权限
# r=4, w=2, x=1，三类相加
# 7 = rwx, 6 = rw-, 5 = r-x, 4 = r--, 0 = ---

# chmod：修改权限
# 数字模式
chmod 755 script.sh        # rwxr-xr-x（脚本常用）
chmod 644 file.txt         # rw-r--r--（普通文件常用）
chmod 600 secret.key       # rw-------（密钥文件）
chmod 700 ~/.ssh           # rwx------（SSH 目录）
chmod 777 public/          # rwxrwxrwx（不推荐，过宽）
chmod -R 755 /var/www      # 递归

# 符号模式
chmod u+x script.sh        # 属主加执行
chmod g-w file.txt         # 属组去写
chmod o=r file.txt         # 其他只读
chmod a+r file.txt         # 所有人加读
chmod ugo+x script.sh      # 等价 a+x
chmod u+s myprog           # 设置 SUID
chmod g+s sharedir         # 设置 SGID
chmod +t /tmp/shared       # 设置 Sticky

# chown：修改属主属组
sudo chown alice file.txt          # 只改属主
sudo chown alice:staff file.txt    # 改属主和属组
sudo chown :staff file.txt         # 只改属组
sudo chgrp staff file.txt          # 只改属组
sudo chown -R alice:staff /project # 递归

# 特殊权限示例
# SUID（显示为 s 代替 x）
ls -l /usr/bin/passwd
# -rwsr-xr-x 1 root root 59688 Mar 8 10:00 /usr/bin/passwd
chmod 4755 /usr/bin/myprog    # 设置 SUID

# SGID 目录（共享目录）
chmod 2775 /shared
# 新建文件自动继承 /shared 的属组

# Sticky 目录（如 /tmp）
ls -ld /tmp
# drwxrwxrwt 20 root root 4096 Jul 8 14:00 /tmp
chmod 1777 /tmp

# umask：默认权限
# 文件默认 666，目录默认 777，减去 umask
umask                      # 查看当前 umask（如 022）
umask 022                  # 文件 644，目录 755
umask 027                  # 文件 640，目录 750
umask 077                  # 文件 600，目录 700（最严格）

# 永久设置 umask
echo 'umask 027' >> ~/.bashrc

# 查看详细属性
stat file.txt
# File: file.txt  Size: 256  ...
# Access: (0644/-rw-r--r--)  Uid: 1000  Gid: 1000

# ACL（访问控制列表）- 比传统权限更细粒度
getfacl file.txt           # 查看 ACL
setfacl -m u:bob:rw file.txt  # 给 bob 单独 rw 权限
setfacl -m g:devs:rx file.txt  # 给 devs 组 rx 权限
setfacl -x u:bob file.txt  # 移除 bob 的 ACL
setfacl -b file.txt        # 清除所有 ACL

# 查看文件属性（不可变等）
lsattr file.txt
sudo chattr +i file.txt    # 设为不可变（连 root 都不能删改）
sudo chattr -i file.txt    # 取消不可变
sudo chattr +a file.txt    # 只能追加
```

权限数字速查表：

| 数字 | 符号 | 含义 | 典型用途 |
|------|------|------|----------|
| 755 | rwxr-xr-x | 属主全权，其他读执行 | 脚本、目录 |
| 644 | rw-r--r-- | 属主读写，其他只读 | 普通文件 |
| 600 | rw------- | 仅属主读写 | 密钥、配置 |
| 700 | rwx------ | 仅属主全权 | SSH 目录 |
| 1777 | rwxrwxrwt | 所有人可写+Sticky | /tmp |
| 4755 | rwsr-xr-x | SUID | passwd 类命令 |

#### 总结

- 权限三类用户（属主/属组/其他）×三权限（rwx），用 3 位八进制表示
- 目录的 r 允许 ls，x 允许 cd 和访问文件，w 允许创建删除文件
- 权限匹配是"最先匹配"：属主权限为 `---` 时即使属组 rwx 也读不了
- SUID（4）以属主身份执行，SGID（2）目录下文件继承属组，Sticky（1）只能删自己文件
- `umask` 决定新建文件默认权限，文件 666-umask，目录 777-umask

### 第9讲 sudo 与 PAM 认证

#### 概念

**sudo**（superuser do）允许普通用户以其他用户身份（默认 root）执行命令，无需切换登录。它通过 `/etc/sudoers` 配置文件精细控制"谁能在哪台机器上以谁的身份执行什么命令"。**PAM**（Pluggable Authentication Modules，可插拔认证模块）是 Linux 的统一认证框架，让系统服务（登录、sudo、su 等）通过统一接口调用各种认证方式（密码、密钥、LDAP、双因素等）。两者共同构成 Linux 的权限与认证体系。

#### 原理

`sudo` 的工作原理：用户执行 `sudo cmd` 时，sudo 程序读取 `/etc/sudoers`（实际通过 `visudo` 编辑）和 `/etc/sudoers.d/` 下的配置，检查当前用户是否有权限执行该命令。如果有权限，sudo 提示输入**自己的密码**（不是 root 密码），验证通过后 fork 子进程以目标用户身份执行命令。sudo 默认缓存密码 5 分钟（`timestamp_timeout`），期间再次 sudo 不需要重新输入。

`/etc/sudoers` 的规则格式是 `用户 主机=(目标用户:目标组) 命令`，如 `alice ALL=(ALL) ALL` 表示 alice 可以在任何主机上以任何用户身份执行任何命令。`%sudo` 表示 sudo 组，`NOPASSWD:` 前缀表示免密。配置 sudoers 必须用 `visudo` 命令——它在保存前做语法检查，避免配置错误导致无法 sudo 的灾难。

**PAM** 的设计思想是"认证逻辑与应用解耦"。应用（如 login、sshd、sudo）在代码中调用 PAM 接口（`pam_authenticate` 等），具体认证方式由 `/etc/pam.d/` 下的配置文件决定。配置格式是 `类型 控制标志 模块路径 参数`，类型有 `auth`（认证）、`account`（账号）、`password`（密码）、`session`（会话）。模块如 `pam_unix.so`（传统密码）、`pam_ldap.so`（LDAP）、`pam_google_authenticator.so`（双因素）。这种设计让认证方式可插拔，无需修改应用代码。

#### 例子

```bash
# sudo 基本用法
sudo command              # 以 root 执行
sudo -u alice command     # 以 alice 执行
sudo -i                   # 切到 root 交互式 Shell
sudo -s                   # 切到 root 非登录 Shell
sudo -k                   # 清除密码缓存
sudo -l                   # 查看自己有什么 sudo 权限
sudo -v                   # 延长密码缓存时间

# 编辑 sudoers（必须用 visudo）
sudo visudo
# 或编辑 /etc/sudoers.d/ 下的文件（推荐）
sudo visudo -f /etc/sudoers.d/alice

# sudoers 配置示例
# 用户 alice 可以执行所有命令
alice ALL=(ALL) ALL

# sudo 组成员可以执行所有命令（Ubuntu 默认）
%sudo ALL=(ALL) ALL

# 用户 bob 只能执行特定命令

# 用户 carol 免密执行 docker

# 用户 dev 组免密执行所有命令
%dev ALL=(ALL) NOPASSWD: ALL

# 用户 ops 只能在 web-server 上以 www 身份执行命令
ops web-server=(www) /usr/bin/deploy.sh

# 别名简化配置
User_Alias ADMINS = alice, bob, carol
Cmnd_Alias RESTART = /usr/bin/systemctl restart *, /usr/bin/systemctl reload *
ADMINS ALL=(ALL) RESTART

# 查看自己的 sudo 权限
sudo -l
# 输出：
# User alice may run the following commands on this host:
#   (ALL) ALL

# sudo 日志（默认记录到 syslog）
sudo grep sudo /var/log/auth.log    # Debian/Ubuntu
sudo journalctl -t sudo             # systemd 系统
```

PAM 配置示例：

一个加固 sudo 的实践：

```bash

# 管理员组免密 sudo
%admins ALL=(ALL) NOPASSWD: ALL

# 开发组只能管理 docker

```

#### 总结

- `sudo` 让普通用户以其他身份执行命令，输入自己密码而非 root 密码，更安全可审计
- `/etc/sudoers` 格式：`用户 主机=(目标) 命令`，必须用 `visudo` 编辑
- `NOPASSWD:` 免密，`%group` 表示组，`/etc/sudoers.d/` 是推荐的配置方式
- PAM 是统一认证框架，应用调用 PAM 接口，认证方式由 `/etc/pam.d/` 配置
- PAM 四类型：auth（认证）、account（账号）、password（密码）、session（会话）

## 第4章 进程与服务管理

### 第10讲 进程查看与控制

#### 概念

**进程**是程序运行的实例，每个进程有唯一 PID（进程 ID）。Linux 进程有父子关系，所有进程的祖先是 `init`（现代系统是 systemd，PID 1）。进程有不同状态：运行（R）、睡眠（S）、不可中断睡眠（D）、停止（T）、僵尸（Z）。进程管理包括查看进程信息、控制进程优先级、发送信号终止/暂停进程。核心命令：`ps`、`top`/`htop`、`kill`、`pkill`、`killall`、`nice`/`renice`、`jobs`/`fg`/`bg`。

#### 原理

Linux 进程通过 **task_struct** 结构体在内核中维护，包含 PID、PPID（父 PID）、状态、优先级、内存映射、打开的文件描述符等。进程创建通过 `fork()`（复制当前进程）+ `exec()`（替换代码）实现：父进程 fork 出子进程，子进程 exec 加载新程序。进程结束时向父进程发送 SIGCHLD 信号，父进程用 `wait()` 回收。如果父进程没回收，子进程变成**僵尸进程**（Z 状态）——它已死但 task_struct 还在，占用 PID 资源。

进程状态：**R**（Running，运行或可运行）、**S**（Sleeping，可中断睡眠，等待事件）、**D**（Disk sleep，不可中断睡眠，通常在等 IO）、**T**（Stopped，暂停）、**Z**（Zombie，僵尸）、**I**（Idle，内核空闲线程）。`top` 中的 `S` 列显示状态。**信号**（signal）是进程间通信机制，`kill` 命令本质是发送信号。常用信号：SIGTERM(15，请求终止，可被捕获)、SIGKILL(9，强杀，不可捕获)、SIGINT(2，Ctrl+C)、SIGSTOP(19，暂停)、SIGCONT(18，继续)、SIGHUP(1，重载配置)。

**优先级**用 nice 值表示，范围 -20（最高）到 19（最低），默认 0。普通用户只能调高 nice 值（降低优先级），root 可以调低。`nice -n 10 cmd` 以 nice 10 启动，`renice 5 -p PID` 调整运行中进程。`top` 中的 NI 列是 nice 值，PR 列是内核调度优先级。

#### 例子

```bash

# 内部操作：
#   P       按 CPU 排序
#   M       按内存排序
#   N       按 PID 排序
#   T       按运行时间排序
#   k       杀进程
#   r       调整 nice
#   1       显示各 CPU
#   u       过滤用户
#   c       显示完整命令

htop

pgrep nginx                # 所有 nginx 的 PID
pgrep -u alice             # alice 的进程 PID

lsof -p 1234               # PID 1234 打开的所有文件
lsof -i :80                # 谁在使用 80 端口
lsof -i tcp                # 所有 TCP 连接
lsof /var/log/syslog       # 谁在用这个文件

# 查看进程的环境变量
cat /proc/1234/environ | tr '\0' '\n'

# 查看进程的命令行
cat /proc/1234/cmdline | tr '\0' ' '

# 查看进程的工作目录
ls -l /proc/1234/cwd

# 查看进程的可执行文件
ls -l /proc/1234/exe
```

排查僵尸进程：

```bash
# 找出僵尸进程
ps aux | awk '$8 ~ /Z/'

# 找出僵尸进程的父进程
ps -o pid,ppid,state,cmd -p $(pgrep -x zombie) 
# PPID 就是父进程

# 杀父进程让 init 回收
kill -9 <PPID>
```

#### 总结

- `ps aux` 是查看进程快照的标准命令，`top`/`htop` 是动态监控
- 进程状态：R 运行、S 睡眠、D 不可中断、T 暂停、Z 僵尸
- `kill` 按 PID 发信号，`pkill`/`killall` 按名杀，`-9` 是 SIGKILL 不可捕获
- nice 值 -20 到 19，越大优先级越低，普通用户只能调高
- 僵尸进程是父进程未回收的子进程，杀父进程让 init 回收

### 第11讲 systemd 服务管理

#### 概念

**systemd** 是现代 Linux（Fedora 15/2010 起，所有主流发行版已采用）的**初始化系统**（init system）和服务管理器，PID 1。它替代了传统的 SysV init 和 Upstart，提供并行启动、依赖管理、套接字激活、定时器、日志（journald）等能力。systemd 用 **unit**（单元）作为配置单位，类型包括 service（服务）、timer（定时器）、socket（套接字）、target（目标组）、mount（挂载）等。核心命令是 `systemctl`。

#### 原理

systemd 的核心创新是**并行启动**：传统 SysV init 串行启动服务，启动慢；systemd 通过套接字激活和依赖图分析，让无依赖的服务并行启动，大幅缩短启动时间。systemd 把每个服务配置在 `.service` 文件中（位于 `/lib/systemd/system/` 和 `/etc/systemd/system/`），定义启动命令、依赖关系、重启策略、资源限制等。`systemctl` 命令通过 D-Bus 与 systemd 守护进程通信，管理服务生命周期。

service unit 文件格式（典型）：

```ini
[Unit]
Description=My Application
After=network.target        # 在网络启动后启动
Requires=mysql.service      # 依赖 mysql

[Service]
Type=simple                 # 简单进程（默认）
ExecStart=/usr/bin/myapp --config /etc/myapp.conf
ExecReload=/bin/kill -HUP $MAINPID
Restart=on-failure          # 失败时重启
User=myapp                  # 以此用户运行
WorkingDirectory=/opt/myapp
Environment=NODE_ENV=production
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target  # 启用后在多用户目标下启动
```

`Type` 选项：`simple`（默认，ExecStart 是主进程）、`forking`（传统守护进程，fork 后父进程退出）、`oneshot`（一次性任务）、`notify`（服务通过 sd_notify 通知就绪）、`idle`（等控制台空闲再启动）。`WantedBy` 决定启用后在哪个 target 下激活，`multi-user.target` 是命令行多用户模式，`graphical.target` 是图形界面。

#### 例子

```bash
# 服务管理
systemctl status nginx             # 查看状态
systemctl start nginx              # 启动
systemctl stop nginx               # 停止
systemctl restart nginx            # 重启
systemctl reload nginx             # 重载配置（不重启）
systemctl enable nginx             # 开机自启
systemctl disable nginx            # 取消开机自启
systemctl enable --now nginx       # 启用并立即启动
systemctl disable --now nginx      # 取消并立即停止
systemctl is-active nginx          # 是否运行中
systemctl is-enabled nginx         # 是否开机自启
systemctl is-failed nginx          # 是否失败
systemctl list-units               # 所有已加载 unit
systemctl list-units --type=service           # 所有服务
systemctl list-units --type=service --state=running  # 运行中的服务
systemctl list-units --type=service --state=failed   # 失败的服务
systemctl list-unit-files --type=service      # 所有已安装的服务文件
systemctl list-dependencies nginx  # 服务的依赖关系

# 系统管理
systemctl get-default              # 当前默认启动目标
systemctl set-default multi-user.target  # 设置默认为命令行
systemctl set-default graphical.target   # 设置默认为图形
systemctl isolate multi-user.target      # 立即切到命令行
systemctl rescue                    # 进入救援模式
systemctl emergency                 # 进入紧急模式
systemctl reboot                    # 重启
systemctl poweroff                  # 关机
systemctl suspend                   # 挂起
systemctl hibernate                 # 休眠

# 查看和编辑 unit 文件
systemctl cat nginx                 # 查看 unit 文件内容
systemctl edit nginx                # 编辑 override（推荐方式）
systemctl edit --full nginx         # 编辑完整 unit 文件
systemctl daemon-reload             # 修改 unit 文件后重载配置
systemctl reset-failed nginx        # 清除失败状态

# 查看日志（journald）
journalctl                          # 所有日志
journalctl -u nginx                 # nginx 的日志
journalctl -u nginx -f              # 实时跟踪
journalctl --since today            # 今天的日志
journalctl --since "2026-07-08 10:00" --until "2026-07-08 12:00"
journalctl -p err                   # 错误级别以上
journalctl -b                       # 本次启动的日志
journalctl -b -1                    # 上次启动的日志
journalctl --disk-usage             # 日志占用空间
journalctl --vacuum-size=100M       # 限制日志大小
```

创建自定义服务的完整示例：

```bash
# 1. 创建服务文件
sudo tee /etc/systemd/system/myapp.service > /dev/null <<'EOF'
[Unit]
Description=My Web Application
After=network.target
Requires=network.target

[Service]
Type=simple
User=myapp
Group=myapp
WorkingDirectory=/opt/myapp
Environment=NODE_ENV=production
Environment=PORT=8080
ExecStart=/usr/bin/node /opt/myapp/server.js
ExecReload=/bin/kill -HUP $MAINPID
Restart=on-failure
RestartSec=5s
TimeoutStopSec=30

# 资源限制
LimitNOFILE=65536
MemoryMax=512M
CPUQuota=100%

# 安全加固
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ReadWritePaths=/var/lib/myapp /var/log/myapp

[Install]
WantedBy=multi-user.target
EOF

# 2. 创建用户（如不存在）
sudo useradd -r -s /usr/sbin/nologin myapp

# 3. 重载 systemd 配置
sudo systemctl daemon-reload

# 4. 启用并启动
sudo systemctl enable --now myapp

# 5. 查看状态
sudo systemctl status myapp
sudo journalctl -u myapp -f

# 6. 修改配置后
sudo systemctl daemon-reload
sudo systemctl restart myapp
```

#### 总结

- systemd 是现代 Linux 的 init 系统和服务管理器，PID 1，支持并行启动
- `systemctl` 是核心命令：`start`/`stop`/`restart`/`reload`/`enable`/`disable`/`status`
- service unit 文件三段式：`[Unit]`（描述依赖）、`[Service]`（启动配置）、`[Install]`（启用目标）
- `systemctl edit` 创建 override 文件，是修改服务配置的推荐方式
- `systemctl daemon-reload` 在修改 unit 文件后必须执行，让 systemd 重新加载

### 第12讲 定时任务（cron 与 timer）

#### 概念

定时任务是自动化运维的核心：定期备份、日志轮转、健康检查、数据同步等都需要按时间触发。Linux 有两种主流方案：① **cron**（传统，老牌稳定，所有发行版都支持）；② **systemd timer**（现代，功能更强，与 systemd 集成）。两者各有优势，cron 简单易用，timer 精确灵活。理解两种方案的配置和使用，是自动化运维的基础。

#### 原理

**cron** 由守护进程 `crond` 实现，每分钟检查一次 `/etc/crontab`、`/etc/cron.d/`、`/var/spool/cron/`（用户 crontab）中的任务，匹配当前时间的任务就执行。cron 表达式分 5 段：`分 时 日 月 周`，每段用空格分隔。例如 `30 2 * * *` 表示每天 2:30。`/etc/cron.{hourly,daily,weekly,monthly}` 是预定义目录，放进去的脚本会按对应频率执行（由 `/etc/cron.d/0hourly` 等触发）。

cron 表达式语法：

```
* * * * * 命令
| | | | |
| | | | +--- 星期 (0-7, 0和7都是周日)
| | | +----- 月份 (1-12)
| | +------- 日期 (1-31)
| +--------- 小时 (0-23)
+----------- 分钟 (0-59)

特殊字符：
*       任意值
*/N     每 N 个单位（*/5 在分钟位 = 每 5 分钟）
5-10    范围
1,3,5   列表
```

**systemd timer** 用 `.timer` unit 文件定义，配合同名 `.service` 使用。timer 支持两种触发方式：`OnCalendar=`（按日历时间，类似 cron）和 `OnBootSec=`/`OnUnitActiveSec=`（相对时间，如启动后 5 分钟、上次执行后 1 小时）。timer 的优势：精确到秒、支持依赖、日志进 journald、可设置触发精度、能查看下次执行时间。

#### 例子

**cron 使用**：

```bash
# 编辑当前用户的 crontab
crontab -e

# 查看当前用户的 crontab
crontab -l

# 删除当前用户的所有任务
crontab -r

# 编辑其他用户的 crontab（需 root）
sudo crontab -u alice -e
sudo crontab -u alice -l

# crontab 文件示例
# 每天凌晨 2:30 备份
30 2 * * * /opt/scripts/backup.sh

# 每周一上午 9 点清理日志
0 9 * * 1 /opt/scripts/clean_logs.sh

# 每 5 分钟检查服务
*/5 * * * * /opt/scripts/check_service.sh

# 每小时整点
0 * * * * /opt/scripts/hourly.sh

# 每天 0:00
0 0 * * * /opt/scripts/daily.sh

# 每月 1 号 0:00
0 0 1 * * /opt/scripts/monthly.sh

# 工作日（周一到周五）9:00
0 9 * * 1-5 /opt/scripts/workday.sh

# 每 10 分钟（用范围写法）
0,10,20,30,40,50 * * * * /opt/scripts/ten_min.sh

# 每年 1 月 1 日 0:00
0 0 1 1 * /opt/scripts/newyear.sh

# 系统级 crontab（/etc/crontab 格式，多一个用户字段）
# 分 时 日 月 周 用户 命令
30 2 * * * root /opt/scripts/backup.sh

# /etc/cron.d/ 下的文件（系统级，多用户字段）
sudo tee /etc/cron.d/backup > /dev/null <<'EOF'
SHELL=/bin/bash
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
30 2 * * * root /opt/scripts/backup.sh
EOF

# 预定义目录（脚本放进去自动按频率执行）
sudo cp backup.sh /etc/cron.daily/
sudo cp check.sh /etc/cron.hourly/
sudo cp report.sh /etc/cron.weekly/
sudo cp archive.sh /etc/cron.monthly/

# cron 日志
grep CRON /var/log/syslog       # Debian/Ubuntu
sudo journalctl -t cron         # systemd 系统
```

**systemd timer 使用**：

```bash
# 1. 创建 service 文件
sudo tee /etc/systemd/system/backup.service > /dev/null <<'EOF'
[Unit]
Description=Backup Service

[Service]
Type=oneshot
User=root
ExecStart=/opt/scripts/backup.sh
EOF

# 2. 创建 timer 文件
sudo tee /etc/systemd/system/backup.timer > /dev/null <<'EOF'
[Unit]
Description=Run backup daily at 2:30

[Timer]
OnCalendar=*-*-* 02:30:00
Persistent=true          # 错过的任务在启动后补执行
RandomizedDelaySec=5min # 随机延迟避免集中触发

[Install]
WantedBy=timers.target
EOF

# 3. 启用 timer
sudo systemctl daemon-reload
sudo systemctl enable --now backup.timer

# 4. 查看所有 timer
systemctl list-timers
# NEXT                        LEFT LAST                        ...
# Wed 2026-07-09 02:30:00     18h  Tue 2026-07-08 02:30:00     ...
# 1 timers listed.

# 5. 立即手动触发
sudo systemctl start backup.service

# 6. 查看执行日志
sudo journalctl -u backup.service
```

timer 的其他触发方式：

```ini
[Timer]
# 按日历（类似 cron）
OnCalendar=*-*-* 02:30:00          # 每天 2:30
OnCalendar=weekly                  # 每周一 00:00
OnCalendar=Mon *-*-* 09:00:00      # 每周一 9:00
OnCalendar=*-*-01 00:00:00         # 每月 1 号

# 相对时间
OnBootSec=5min                     # 启动后 5 分钟
OnUnitActiveSec=1h                 # 上次执行后 1 小时
OnUnitInactiveSec=30min            # 上次结束后 30 分钟

# 选项
Persistent=true                    # 错过的补执行
RandomizedDelaySec=5min            # 随机延迟
AccuracySec=1s                     # 触发精度
Unit=backup.service                # 触发的 service（默认同名）
```

#### 总结

- cron 表达式 5 段：`分 时 日 月 周`，`*/N` 表示每 N 个单位，`1-5` 范围，`1,3,5` 列表
- `crontab -e` 编辑用户任务，`/etc/cron.d/` 放系统任务，`/etc/cron.daily/` 等是预定义目录
- cron 任务要写绝对路径，环境变量有限，建议在脚本内 `source /etc/profile`
- systemd timer 用 `.timer` + `.service` 配合，`OnCalendar` 按日历，`OnBootSec` 按相对时间
- timer 优势：精确到秒、Persistent 补执行、日志进 journald、`systemctl list-timers` 查看调度

## 第5章 软件包管理

### 第13讲 RPM/DEB 与 YUM/APT

#### 概念

Linux 软件以**包**（package）形式分发，包含编译好的程序、配置文件、依赖信息。两大包体系：**RPM**（Red Hat Package Manager，用于 RHEL/CentOS/Fedora/SUSE）和 **DEB**（Debian Package，用于 Debian/Ubuntu）。底层工具 `rpm`/`dpkg` 管理单个包，高层工具 `yum`/`dnf`/`apt` 解决依赖并从仓库安装。理解包管理是 Linux 系统管理的基础技能。

#### 原理

RPM 包文件名格式：`名称-版本-发行号.架构.rpm`，如 `nginx-1.20.1-1.el8.x86_64.rpm`。包内含：① 文件清单（要安装到哪些路径）；② 脚本（安装前/后、卸载前/后执行）；③ 依赖信息（requires/provides）。`rpm` 命令能安装、查询、卸载，但不会自动解决依赖——这就是 `yum`/`dnf` 存在的原因。

DEB 包文件名格式：`名称_版本-修订号_架构.deb`。`dpkg` 是底层工具，`apt`/`apt-get` 是高层工具。`apt` 是较新的统一命令（Ubuntu 16.04+），整合了 `apt-get` 和 `apt-cache` 的常用功能，输出更友好。

**仓库**（repository）是存放包的服务器，发行版官方仓库经过测试，第三方仓库（如 EPEL、PPA）提供额外软件。仓库配置在 `/etc/yum.repos.d/`（RPM 系）或 `/etc/apt/sources.list` 及 `/etc/apt/sources.list.d/`（DEB 系）。`yum`/`apt` 从仓库下载包元数据（包列表、版本、依赖），计算依赖关系，下载所需包并安装。GPG 签名验证保证包的完整性和来源可信。

#### 例子

**RPM 系（RHEL/CentOS/Fedora）**：

```bash
# dnf 是 yum 的现代替代（Fedora 22+，RHEL 8+）
# yum 在老系统仍可用，命令基本一致

# 安装
sudo dnf install nginx              # 从仓库安装
sudo dnf install -y nginx           # 自动确认
sudo dnf install /path/to/pkg.rpm   # 安装本地 rpm 文件
sudo dnf reinstall nginx            # 重新安装

# 更新
sudo dnf check-update               # 检查可更新
sudo dnf update                     # 更新所有包
sudo dnf update nginx               # 更新单个包
sudo dnf upgrade                    # 升级（处理废弃包）

# 卸载
sudo dnf remove nginx               # 卸载
sudo dnf autoremove                 # 清理不需要的依赖

# 查询
dnf list nginx                      # 包是否可用
dnf list installed                  # 已安装的包
dnf list available                  # 可用的包
dnf info nginx                      # 包详情
dnf search nginx                    # 按名搜索
dnf search all "web server"         # 按描述搜索
dnf provides /usr/bin/curl          # 哪个包提供这个文件
dnf provides "*/libssl.so*"        # 哪个包提供这个库
dnf grouplist                       # 包组列表
dnf groupinstall "Development Tools"  # 安装开发工具组

# 历史
dnf history                         # 安装历史
dnf history info 5                  # 第 5 次事务详情
dnf history undo 5                  # 撤销第 5 次事务

# 仓库
dnf repolist                        # 已启用仓库
dnf repolist all                    # 所有仓库
dnf config-manager --add-repo https://repo.example.com/repo.repo
dnf config-manager --enable repo_id
dnf config-manager --disable repo_id

# 清理缓存
dnf clean all                       # 清理所有缓存

# 底层 rpm 命令
rpm -ivh pkg.rpm                    # 安装（i=install, v=verbose, h=hash）
rpm -Uvh pkg.rpm                    # 升级安装
rpm -e nginx                        # 卸载
rpm -q nginx                        # 查询是否安装
rpm -qa                             # 所有已安装包
rpm -qa | grep nginx                # 查找已安装的 nginx
rpm -qi nginx                       # 包信息
rpm -ql nginx                       # 包安装的文件列表
rpm -qf /usr/bin/curl               # 这个文件属于哪个包
rpm -qR nginx                       # 包的依赖
rpm -q --scripts nginx              # 包的安装脚本
rpm -V nginx                        # 校验包文件是否被修改
rpm --import /etc/pki/rpm-gpg/RPM-GPG-KEY  # 导入 GPG 密钥
```

**DEB 系（Debian/Ubuntu）**：

```bash
# apt 是现代统一命令（推荐）
# apt-get / apt-cache 是底层命令

# 安装
sudo apt update                     # 更新包索引（必须先做）
sudo apt install nginx              # 安装
sudo apt install -y nginx           # 自动确认
sudo apt install ./pkg.deb          # 安装本地 deb 文件
sudo apt install --reinstall nginx  # 重新安装
sudo apt install nginx=1.18.0*      # 安装指定版本

# 更新
sudo apt update                     # 刷新索引
sudo apt upgrade                    # 升级已安装包（不删旧包）
sudo apt full-upgrade               # 完整升级（可删旧包）
sudo apt --no-install-recommends install nginx  # 不装推荐包

# 卸载
sudo apt remove nginx               # 卸载（保留配置）
sudo apt purge nginx                # 卸载并删配置
sudo apt autoremove                 # 清理不需要的依赖
sudo apt autoremove --purge         # 清理并删配置

# 查询
apt list nginx                      # 包是否可用
apt list --installed                # 已安装的包
apt list --upgradable               # 可升级的包
apt show nginx                      # 包详情
apt search nginx                    # 搜索
apt-cache search "web server"       # 按描述搜索
dpkg -S /usr/bin/curl               # 哪个包提供这个文件
apt-file search /usr/bin/curl       # 同上（需安装 apt-file）

# 底层 dpkg 命令
sudo dpkg -i pkg.deb                # 安装本地 deb（不解决依赖）
sudo dpkg -r nginx                  # 卸载
sudo dpkg -P nginx                  # 卸载并删配置
dpkg -l                             # 所有已安装包
dpkg -l | grep nginx                # 查找已安装的 nginx
dpkg -L nginx                       # 包安装的文件列表
dpkg -s nginx                       # 包信息
dpkg -S /usr/bin/curl               # 文件属于哪个包
dpkg --configure -a                 # 修复中断的安装

# 仓库配置
# /etc/apt/sources.list 主配置
# /etc/apt/sources.list.d/ 额外仓库
# 添加 PPA（Ubuntu）
sudo add-apt-repository ppa:nginx/stable
sudo apt update

# 添加第三方仓库（如 Docker）
sudo tee /etc/apt/sources.list.d/docker.list > /dev/null <<'EOF'
deb [arch=amd64] https://download.docker.com/linux/ubuntu focal stable
EOF
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo apt-key add -
sudo apt update

# 清理缓存
sudo apt clean                      # 清理下载的 deb 文件
sudo apt autoclean                  # 只清理过期的
```

#### 总结

- RPM 系用 `dnf`/`yum`（高层）和 `rpm`（底层），DEB 系用 `apt`（高层）和 `dpkg`（底层）
- 高层工具自动解决依赖，底层工具只管单个包，日常优先用高层工具
- `dnf provides 文件` / `dpkg -S 文件` 反查文件属于哪个包，是排查依赖的利器
- DEB 系安装前必须 `apt update` 刷新索引，否则找不到最新包
- 仓库配置：RPM 在 `/etc/yum.repos.d/`，DEB 在 `/etc/apt/sources.list.d/`

### 第14讲 源码编译与第三方仓库

#### 概念

并非所有软件都在官方仓库中，有时需要：① 从**源码编译**安装（获取最新版或定制功能）；② 添加**第三方仓库**（如 EPEL、Remi、Docker 官方源）获取更多软件；③ 使用**通用打包格式**（如 AppImage、Flatpak、Snap）。本讲介绍这三种方式，让你能安装任何 Linux 软件。

#### 原理

源码编译的经典流程是 `./configure && make && make install`。`configure` 脚本检测系统环境（编译器、依赖库、安装路径），生成 `Makefile`；`make` 按 `Makefile` 编译源码生成可执行文件；`make install` 把文件复制到指定路径（默认 `/usr/local`）。这种方式灵活但复杂：要手动解决依赖、手动管理卸载（建议用 `checkinstall` 生成包代替直接 install）、手动更新。

第三方仓库是官方仓库的补充。**EPEL**（Extra Packages for Enterprise Linux）由 Fedora 社区维护，为 RHEL/CentOS 提供额外高质量包。**Remi** 仓库提供最新 PHP/MySQL。**Docker 官方源**提供 Docker CE。**PPA**（Personal Package Archive）是 Ubuntu 上的个人包仓库。添加第三方仓库要注意：① 信任级别（官方 > 社区 > 个人）；② GPG 密钥验证；③ 与官方包冲突的可能。

**AppImage** 是一种"下载即用"的格式，整个应用打包成单文件，无需安装，跨发行版通用。**Flatpak** 和 **Snap** 是新一代通用包格式，提供沙箱隔离和依赖捆绑，但体积较大。这些格式适合桌面应用，服务器场景仍以传统包管理为主。

#### 例子

**源码编译安装**（以 nginx 为例）：

```bash
# 1. 安装编译依赖
sudo dnf groupinstall "Development Tools"   # RHEL 系
# 或
sudo apt install build-essential            # Debian 系

sudo dnf install pcre-devel openssl-devel zlib-devel  # nginx 依赖
# 或
sudo apt install libpcre3-dev libssl-dev zlib1g-dev

# 2. 下载源码
cd /usr/local/src
wget https://nginx.org/download/nginx-1.25.0.tar.gz
tar -xzf nginx-1.25.0.tar.gz
cd nginx-1.25.0

# 3. 查看 configure 选项
./configure --help

# 4. 配置（指定安装路径和模块）
./configure \
    --prefix=/usr/local/nginx \
    --with-http_ssl_module \
    --with-http_v2_module \
    --with-http_realip_module \
    --with-http_gzip_static_module \
    --with-threads

# 5. 编译
make -j$(nproc)                  # -j 并行编译，nproc 是 CPU 核数

# 6. 安装
sudo make install
# 或用 checkinstall 生成 deb/rpm 包便于管理
sudo checkinstall --pkgname=nginx-custom --pkgversion=1.25.0

# 7. 验证
/usr/local/nginx/sbin/nginx -v

# 8. 创建 systemd 服务（推荐）
sudo tee /etc/systemd/system/nginx.service > /dev/null <<'EOF'
[Unit]
Description=nginx
After=network.target

[Service]
Type=forking
ExecStart=/usr/local/nginx/sbin/nginx
ExecReload=/usr/local/nginx/sbin/nginx -s reload
ExecStop=/usr/local/nginx/sbin/nginx -s stop
PIDFile=/usr/local/nginx/logs/nginx.pid

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl enable --now nginx

# 9. 卸载（如需）
sudo make uninstall              # 在源码目录执行
# 或
sudo rm -rf /usr/local/nginx
```

**添加第三方仓库**：

```bash

sudo dnf config-manager --set-enabled epel
# 验证
dnf repolist | grep epel

# Docker 官方源

# RPM Fusion（多媒体解码器）
sudo dnf install https://mirrors.rpmfusion.org/free/el/rpmfusion-free-release-8.noarch.rpm

# Ubuntu PPA
sudo add-apt-repository ppa:deadsnakes/ppa
sudo apt update
sudo apt install python3.11

sudo apt install ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings

    sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \

```

- 源码编译三步：`./configure`（检测环境生成 Makefile）→ `make`（编译）→ `make install`（安装）

- 用 `checkinstall` 代替 `make install` 能生成可管理的包，便于卸载
- EPEL 是 RHEL 系最重要的第三方仓库，Remi 提供 PHP 多版本，PPA 是 Ubuntu 个人仓库
- AppImage 下载即用，Flatpak/Snap 提供沙箱，桌面应用友好，服务器仍以传统包为主

## 第6章 网络配置

### 第15讲 网络基础与 IP 配置

#### 概念

Linux 网络配置是服务器运维的核心。关键概念：**IP 地址**（主机在网络中的标识）、**子网掩码**（区分网络号和主机号）、**网关**（跨网段通信的出口）、**DNS**（域名解析）、**路由表**（决定数据包去向）。现代 Linux 用 **NetworkManager**（`nmcli`/`nmtui`）或 **netplan**（Ubuntu）或 **systemd-networkd** 管理网络。核心命令：`ip`（现代，替代 `ifconfig`）、`nmcli`、`ping`、`ss`（替代 `netstat`）、`traceroute`、`dig`/`nslookup`。

#### 原理

Linux 网络协议栈实现 TCP/IP 模型，每张网卡（NIC）有一个或多个**接口**（interface），如 `eth0`、`ens33`、`enp0s3`。接口可以配置 IP 地址、MAC 地址、MTU 等。**路由表**决定数据包从哪个接口发出：内核按"最长前缀匹配"查找目标 IP 的路由，找到就用对应接口发送，找不到就走默认路由（default gateway）。

**NetworkManager** 是主流发行版的网络管理守护进程，提供 `nmcli`（命令行）和 `nmtui`（文本界面）工具。它用**连接**（connection）概念管理配置：一个连接定义一套网络参数（IP、DNS、网关），可以激活或停用。**netplan** 是 Ubuntu 18.04+ 的网络配置抽象层，用 YAML 描述网络，后端可以是 NetworkManager 或 systemd-networkd。

`ip` 命令是 `ifconfig`/`route`/`arp` 的现代替代，功能更强大。`ip addr` 查看地址，`ip route` 查看路由，`ip link` 管理接口。`ss`（socket statistics）替代 `netstat`，性能更好。`ping` 用 ICMP 测试连通性，`traceroute` 追踪路径，`dig`/`nslookup` 解析 DNS。

#### 例子

```bash

ip -br addr                   # 简洁视图
```

### 第16讲 防火墙（iptables/firewalld/ufw）

#### 概念

Linux 防火墙基于内核的 **netfilter** 框架，通过钩子函数在数据包经过协议栈时进行检查和过滤。用户态工具经历了 `iptables`（传统）→ `nftables`（现代）的演进。发行版提供高级前端：**firewalld**（RHEL 系，区域概念）和 **ufw**（Ubuntu，简化语法）。理解防火墙的"表-链-规则"模型和默认策略，是服务器安全的基础。

#### 原理

netfilter 在内核网络栈的五个钩子点（PREROUTING、INPUT、FORWARD、OUTPUT、POSTROUTING）拦截数据包。**iptables** 用"表-链-规则"组织：表（filter/nat/mangle/raw）包含链，链包含规则，规则匹配后执行动作（ACCEPT/DROP/REJECT/LOG/SNAT/DNAT）。`filter` 表用于过滤，`INPUT` 链处理入站，`FORWARD` 链处理转发，`OUTPUT` 链处理出站。

数据包匹配规则时按顺序进行，命中一条就执行动作并停止后续匹配。如果都没匹配，执行链的**默认策略**（default policy）。防火墙配置原则：① 默认拒绝（DROP），明确允许需要的；② 遵循"最小权限"；③ 先放行 SSH 再改默认策略，避免锁死自己。

**firewalld** 用"区域"（zone）概念简化管理：每个网络接口分配到一个区域（如 public、trusted、home），区域定义了允许的服务。`firewalld` 运行时配置立即生效，永久配置重启后生效，需要 `--permanent` 选项。**ufw**（Uncomplicated Firewall）是 Ubuntu 的简化前端，语法直观，适合新手。

#### 例子

**ufw（Ubuntu 推荐）**：

```bash
# 安装和启用
sudo apt install ufw
sudo ufw enable               # 启用（会同时启用 IPv4/IPv6）
sudo ufw disable              # 禁用
sudo ufw status               # 查看状态
sudo ufw status verbose       # 详细状态
sudo ufw status numbered      # 带编号（便于删除）

# 默认策略
sudo ufw default deny incoming    # 默认拒绝入站
sudo ufw default allow outgoing   # 默认允许出站

# 放行服务
sudo ufw allow ssh            # 放行 SSH（22）
sudo ufw allow 22/tcp         # 同上
sudo ufw allow 80/tcp         # 放行 HTTP
sudo ufw allow 443/tcp        # 放行 HTTPS
sudo ufw allow 8080:8090/tcp  # 放行端口范围

# 限制来源
sudo ufw allow from 192.168.1.0/24 to any port 22  # 只允许内网 SSH
sudo ufw allow from 192.168.1.100 to any port 3306  # 只允许特定 IP 访问 MySQL

# 拒绝
sudo ufw deny 23/tcp          # 拒绝 Telnet
sudo ufw reject 23/tcp        # 拒绝并回复（vs DROP 静默丢弃）

# 删除规则
sudo ufw delete allow 80/tcp  # 按规则删除
sudo ufw delete 3             # 按编号删除

# 重置
sudo ufw reset

# 应用层过滤
sudo ufw app list             # 列出应用配置
sudo ufw allow "Nginx Full"   # 放行 Nginx HTTP+HTTPS
```

**firewalld（RHEL 系推荐）**：

```bash
# 状态管理
sudo systemctl enable --now firewalld
sudo firewall-cmd --state
sudo firewall-cmd --reload    # 重载配置（保留运行时）
sudo firewall-cmd --complete-reload  # 完全重载（断开连接）

# 区域管理
sudo firewall-cmd --get-default-zone       # 默认区域
sudo firewall-cmd --set-default-zone=public
sudo firewall-cmd --get-active-zones       # 活动区域
sudo firewall-cmd --get-zones              # 所有区域
sudo firewall-cmd --zone=public --list-all  # 查看区域配置

# 接口分配区域
sudo firewall-cmd --zone=public --change-interface=eth0

# 放行服务（运行时 + 永久）
sudo firewall-cmd --add-service=http --permanent
sudo firewall-cmd --add-service=https --permanent
sudo firewall-cmd --add-service=ssh --permanent
sudo firewall-cmd --reload                  # 重载生效

# 放行端口
sudo firewall-cmd --add-port=8080/tcp --permanent
sudo firewall-cmd --add-port=10000-20000/tcp --permanent

# 限制来源
sudo firewall-cmd --add-rich-rule='rule family="ipv4" source address="192.168.1.0/24" service name="ssh" accept' --permanent

# 端口转发
sudo firewall-cmd --add-forward-port=port=80:proto=tcp:toport=8080 --permanent

# 查看已放行
sudo firewall-cmd --list-services
sudo firewall-cmd --list-ports
sudo firewall-cmd --list-all
```

**iptables（底层，了解原理）**：

```bash
# 查看规则
sudo iptables -L              # 列出所有链
sudo iptables -L -n           # 不解析 IP/端口
sudo iptables -L -n -v        # 详细（含计数）
sudo iptables -L INPUT -n -v  # 指定链
sudo iptables -t nat -L -n    # 查看 nat 表

# 添加规则
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT    # 放行 SSH
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT    # 放行 HTTP
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT   # 放行 HTTPS
sudo iptables -A INPUT -s 192.168.1.0/24 -j ACCEPT    # 放行内网
sudo iptables -A INPUT -j DROP                         # 默认拒绝

# 插入规则（顺序很重要）
sudo iptables -I INPUT 1 -p tcp --dport 22 -j ACCEPT   # 插到第 1 位

# 删除规则
sudo iptables -D INPUT -p tcp --dport 80 -j ACCEPT     # 按规则删
sudo iptables -D INPUT 3                                # 按编号删

# 默认策略
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT

# 保存规则（持久化）
sudo apt install iptables-persistent    # Debian/Ubuntu
sudo netfilter-persistent save
# 或
sudo iptables-save > /etc/iptables/rules.v4

sudo dnf install iptables-services      # RHEL 系
sudo iptables-save > /etc/sysconfig/iptables
sudo systemctl enable iptables

# NAT（端口转发）
sudo iptables -t nat -A PREROUTING -p tcp --dport 80 -j DNAT --to-destination 10.0.0.2:8080
sudo iptables -t nat -A POSTROUTING -j MASQUERADE
```

#### 总结

- netfilter 是内核框架，iptables/nftables 是用户态工具，firewalld/ufw 是高级前端
- iptables "表-链-规则"模型：filter 表 INPUT/FORWARD/OUTPUT 链处理过滤
- 规则按顺序匹配，命中即执行动作，未匹配走默认策略
- ufw 简单（`ufw allow 80`），firewalld 用区域概念（`--add-service --permanent`）
- 改防火墙前先放行 SSH，避免锁死自己；`--permanent` + `--reload` 持久化

### 第17讲 SSH 远程管理与安全加固

#### 概念

**SSH**（Secure Shell）是 Linux 远程管理的标准协议，替代了不安全的 Telnet。它提供加密的远程登录、文件传输（SCP/SFTP）、端口转发、密钥认证等能力。服务端是 `sshd`（OpenSSH daemon），客户端是 `ssh`。SSH 是服务器运维的生命线，掌握其配置和安全加固至关重要。

#### 原理

SSH 协议基于**非对称加密**：客户端连接服务端时，先用服务端的公钥加密会话密钥（防止中间人攻击），然后双方用对称加密通信。认证方式有：① **密码认证**（用户密码）；② **公钥认证**（用户私钥签名，服务端用公钥验证，更安全）；③ **主机认证**（验证服务端身份，防止 DNS 劫持）。公钥认证的流程：用户用 `ssh-keygen` 生成密钥对，把公钥复制到服务端 `~/.ssh/authorized_keys`，登录时用私钥签名证明身份，无需密码。

SSH 配置文件：服务端 `/etc/ssh/sshd_config`，客户端 `~/.ssh/config` 和 `/etc/ssh/ssh_config`。关键配置项：`Port`（端口，默认 22）、`PermitRootLogin`（是否允许 root 登录）、`PasswordAuthentication`（是否允许密码）、`PubkeyAuthentication`（公钥认证）、`AllowUsers`/`AllowGroups`（白名单）、`MaxAuthTries`（最大尝试次数）。

SSH 还支持**端口转发**（port forwarding）：本地转发（`-L`）把远程端口映射到本地，远程转发（`-R`）把本地端口映射到远程，动态转发（`-D`）创建 SOCKS 代理。这是穿透防火墙、访问内网服务的利器。

#### 例子

```bash
# 基本连接
ssh user@host                # 默认 22 端口
ssh user@host -p 2222        # 指定端口
ssh -l user host             # 等价写法
ssh user@host command        # 执行命令后退出
ssh -v user@host             # 详细输出（调试）
ssh -i ~/.ssh/id_rsa user@host  # 指定私钥

# 生成密钥对
ssh-keygen -t rsa -b 4096    # RSA 4096 位
ssh-keygen -t ed25519        # Ed25519（推荐，更短更安全）
ssh-keygen -t ed25519 -C "alice@example.com"  # 加注释
# 一路回车用默认路径，或设置 passphrase 加密私钥

# 复制公钥到服务端
ssh-copy-id user@host        # 自动复制到 ~/.ssh/authorized_keys
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@host  # 指定公钥
ssh-copy-id -p 2222 user@host  # 指定端口

# 手动复制（如 ssh-copy-id 不可用）
cat ~/.ssh/id_ed25519.pub | ssh user@host "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"

# SCP：加密复制
scp file.txt user@host:/path/         # 本地到远程
scp user@host:/path/file.txt ./       # 远程到本地
scp -r dir user@host:/path/           # 递归目录
scp -P 2222 file user@host:/path/     # 指定端口
scp file1 file2 user@host:/path/      # 多文件

# SFTP：交互式文件传输
sftp user@host
# sftp> put file.txt
# sftp> get file.txt
# sftp> ls / cd / pwd
# sftp> quit

# rsync：高效同步（基于 SSH）
rsync -avz /local/dir/ user@host:/remote/dir/  # 同步目录
rsync -avz --delete /local/ user@host:/remote/  # 删除目标多余文件
rsync -avz -e "ssh -p 2222" /local/ user@host:/remote/  # 指定端口
rsync -avz --exclude='*.log' /local/ user@host:/remote/  # 排除

# 端口转发
# 本地转发：把远程的 3306 映射到本地 13306
ssh -L 13306:localhost:3306 user@host
# 然后访问 localhost:13306 等于访问远程的 3306

# 远程转发：把本地的 8080 映射到远程的 8080
ssh -R 8080:localhost:80 user@remote_host

# 动态转发：SOCKS 代理
ssh -D 1080 user@host
# 然后浏览器配置 SOCKS5 代理 localhost:1080

# 跳板机
ssh -J jumpuser@jumphost user@target_host

# SSH agent（管理私钥 passphrase）
eval $(ssh-agent)            # 启动 agent
ssh-add ~/.ssh/id_ed25519    # 添加私钥
ssh-add -l                   # 列出已添加的密钥
ssh-add -D                   # 删除所有
```

**客户端配置 `~/.ssh/config`**：

```ssh-config

    ServerAliveInterval 60
    ServerAliveCountMax 3
    AddKeysToAgent yes
    IdentityFile ~/.ssh/id_ed25519

# 服务器别名

    HostName 192.168.1.100
    User alice

    Port 22

# 跳板机

    ProxyJump jumphost
    User deploy

# 之后直接 ssh web1 即可
```

**服务端安全加固 `/etc/ssh/sshd_config`**：



#### 总结

- SSH 基于非对称加密，公钥认证比密码更安全，推荐 `ssh-keygen -t ed25519`
- `ssh-copy-id` 自动复制公钥，`~/.ssh/config` 配置别名简化连接
- `scp`/`rsync` 传文件，`rsync -avz` 增量同步最常用
- 端口转发：`-L` 本地、`-R` 远程、`-D` 动态 SOCKS
- 安全加固：禁 root 登录、禁密码、改端口、限白名单、配 fail2ban 防暴力破解

## 第7章 存储管理

### 第18讲 磁盘分区与文件系统

#### 概念

新磁盘使用前需要：① **分区**（把物理磁盘划分为逻辑区域）；② **格式化**（在分区上创建文件系统）；③ **挂载**（把文件系统关联到目录）。分区工具有 `fdisk`（传统 MBR）、`parted`/`gdisk`（支持 GPT）。Linux 支持多种文件系统：ext4（默认）、xfs（RHEL 默认）、btrfs（现代，支持快照）、zfs（企业级）。理解磁盘命名、分区表、文件系统是存储管理的基础。

#### 原理

Linux 磁盘命名规则：① **ATA/SATA/SCSI 磁盘**：`/dev/sda`、`/dev/sdb`...（按检测顺序）；② **NVMe 磁盘**：`/dev/nvme0n1`、`/dev/nvme1n1`...；③ **虚拟磁盘**：`/dev/vda`、`/dev/xvda`...。分区命名在磁盘名后加数字：`/dev/sda1`、`/dev/sda2`，NVMe 用 `p` 分隔：`/dev/nvme0n1p1`。

**分区表**有两种：① **MBR**（Master Boot Record，传统）：最多 4 个主分区（或 3 主 + 1 扩展），最大 2TB，用 `fdisk`；② **GPT**（GUID Partition Table，现代）：几乎无限制分区数，支持大于 2TB，UEFI 系统必需，用 `gdisk`/`parted`。现代系统推荐 GPT。

**文件系统**是组织磁盘上数据的数据结构。**ext4**（Fourth Extended Filesystem）是 Linux 默认，稳定成熟，支持大文件和日志。**xfs** 是 SGI 开发的高性能文件系统，RHEL 默认，擅长大文件并行 IO。**btrfs** 是现代文件系统，支持快照、压缩、子卷、校验。**zfs** 集成了卷管理和文件系统，企业级首选但许可证问题不在内核主线。格式化就是写入文件系统的元数据结构（超级块、inode 表、数据块位图等）。

#### 例子

```bash
# 查看磁盘
lsblk                         # 块设备树（最直观）
sudo fdisk -l                 # 所有磁盘详情
sudo parted -l                # 所有磁盘（支持 GPT）
ls -l /dev/disk/by-id/        # 按硬件 ID
ls -l /dev/disk/by-uuid/      # 按 UUID（推荐挂载用）
ls -l /dev/disk/by-partlabel/ # 按分区标签

# 查看磁盘使用
df -h                         # 已挂载文件系统使用
df -hT                        # 显示文件系统类型
df -i                         # inode 使用情况

# 查看磁盘信息
sudo hdparm -I /dev/sda       # 硬盘详细信息
sudo smartctl -a /dev/sda     # SMART 健康状态
lsblk -o NAME,SIZE,TYPE,MOUNTPOINT,MODEL
```

**分区（以 parted 为例，支持 GPT）**：

```bash
# 交互式分区
sudo parted /dev/sdb
# (parted) mklabel gpt            # 创建 GPT 分区表
# (parted) mkpart primary 1MiB 100GiB   # 创建分区
# (parted) mkpart primary 100GiB 200GiB
# (parted) print                  # 查看
# (parted) quit

# 命令行一行
sudo parted /dev/sdb mklabel gpt
sudo parted /dev/sdb mkpart primary ext4 1MiB 100GiB
sudo parted /dev/sdb mkpart primary xfs 100GiB 100%

# fdisk（MBR，老式但简单）
sudo fdisk /dev/sdb
# Command: n (new), p (primary), 1, 默认起始, +100G
# Command: n, p, 2, 默认, 默认
# Command: w (write)

# gdisk（GPT 的 fdisk 风格）
sudo gdisk /dev/sdb
# Command: n, 1, 默认, +100G, 默认
# Command: w

# 验证
sudo parted /dev/sdb print
lsblk
```

**格式化（创建文件系统）**：

```bash
# 格式化为 ext4
sudo mkfs.ext4 /dev/sdb1
sudo mkfs.ext4 -L data /dev/sdb1     # 加标签
sudo mkfs.ext4 -b 4096 /dev/sdb1     # 指定块大小

# 格式化为 xfs
sudo mkfs.xfs /dev/sdb1
sudo mkfs.xfs -L data /dev/sdb1

# 格式化为 btrfs
sudo mkfs.btrfs /dev/sdb1
sudo mkfs.btrfs -L data /dev/sdb1

# 格式化为 swap
sudo mkswap /dev/sdb2
sudo swapon /dev/sdb2

# 查看文件系统类型
sudo blkid                    # 所有分区 UUID 和类型
sudo blkid /dev/sdb1          # 指定分区
lsblk -f                      # 文件系统类型

# 调整文件系统
sudo resize2fs /dev/sdb1      # ext4 扩展到分区大小
sudo xfs_growfs /mnt/data     # xfs 扩展（需已挂载）

# 检查和修复
sudo fsck /dev/sdb1           # 检查文件系统
sudo fsck.ext4 -p /dev/sdb1   # 自动修复
sudo e2fsck -f /dev/sdb1      # 强制检查
sudo xfs_repair /dev/sdb1     # xfs 修复
```

**Swap 交换分区**：

```bash
# 创建 swap
sudo mkswap /dev/sdb2
sudo swapon /dev/sdb2

# 查看 swap
swapon --show
free -h

# 调整 swappiness（0-100，越低越倾向用内存）
cat /proc/sys/vm/swappiness   # 默认 60
sudo sysctl vm.swappiness=10  # 临时
echo 'vm.swappiness=10' | sudo tee -a /etc/sysctl.conf  # 永久

# 关闭 swap
sudo swapoff /dev/sdb2

# 用文件做 swap（无空闲分区时）
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
```

#### 总结

- 磁盘命名：SATA/SCSI 是 `/dev/sda`，NVMe 是 `/dev/nvme0n1`，分区加数字
- MBR 最多 4 主分区、最大 2TB，GPT 无限制、UEFI 必需，现代推荐 GPT
- `parted` 支持 GPT，`fdisk` 传统 MBR，`gdisk` 是 GPT 的 fdisk 风格
- ext4 稳定默认，xfs 大文件高性能，btrfs 支持快照压缩
- `mkfs.ext4`/`mkfs.xfs` 格式化，`fsck` 检查修复，`blkid` 查看 UUID

### 第19讲 挂载与 fstab

#### 概念

**挂载**（mount）是把文件系统关联到目录树的过程——访问该目录就是访问该文件系统的内容。临时挂载用 `mount` 命令，重启失效；持久化挂载要写入 `/etc/fstab`。理解挂载点、挂载选项、自动挂载机制，是让磁盘在重启后可用的关键。本讲还介绍 `autofs`（按需自动挂载）和 `bind mount`（目录挂载到目录）。

#### 原理

Linux 的"单根树"目录结构通过挂载实现：根目录 `/` 挂载根文件系统，`/home`、`/var`、`/boot` 等可以是独立分区挂载到对应目录。挂载时内核把文件系统的根 inode 关联到挂载点目录，访问该目录的请求被重定向到该文件系统。挂载点目录在挂载前必须存在，挂载后原目录内容被"遮蔽"（unmount 后恢复）。

`/etc/fstab`（File System Table）是持久化挂载配置，每行格式：`设备 挂载点 类型 选项 dump频率 fsck顺序`。设备可用 `/dev/sda1`、`UUID=xxx`、`LABEL=xxx`，推荐 UUID（设备名可能变化）。启动时 `systemd` 读取 fstab 自动挂载。常见挂载选项：`defaults`（rw,suid,dev,exec,auto,nouser,async）、`noatime`（不更新访问时间，提升性能）、`nodiratime`、`discard`（SSD TRIM）、`errors=remount-ro`（出错只读）。

`mount` 命令选项：`-t` 指定类型、`-o` 指定选项、`-a` 挂载 fstab 中所有、`-r` 只读、`-B` bind 挂载。`umount` 卸载，`-l` 强制懒卸载（busy 时）。`findmnt` 查看挂载关系，`mount | column -t` 格式化查看。

#### 例子

```bash
# 临时挂载
sudo mount /dev/sdb1 /mnt/data                # 默认选项
sudo mount -t ext4 /dev/sdb1 /mnt/data        # 指定类型
sudo mount -o ro /dev/sdb1 /mnt/data          # 只读
sudo mount -o noatime /dev/sdb1 /mnt/data     # 不更新访问时间
sudo mount -o discard /dev/sdb1 /mnt/data     # SSD TRIM
sudo mount -o errors=remount-ro /dev/sdb1 /mnt/data

# 用 UUID 挂载（推荐）
sudo blkid /dev/sdb1                          # 获取 UUID
sudo mount -U "abc123-..." /mnt/data

# 用 LABEL 挂载
sudo mount -L data /mnt/data

# 挂载 ISO 镜像
sudo mount -o loop ubuntu.iso /mnt/iso

# 挂载 NFS
sudo mount -t nfs server:/share /mnt/nfs
sudo mount -t nfs -o vers=4,hard,timeo=600 server:/share /mnt/nfs

# 挂载 CIFS（Windows 共享）
sudo mount -t cifs //server/share /mnt/cifs -o username=user,password=pass

# bind 挂载（目录到目录）
sudo mount --bind /source /target
sudo mount -B /source /target

# 挂载 tmpfs（内存文件系统）
sudo mount -t tmpfs -o size=100M tmpfs /mnt/tmp

# 卸载
sudo umount /mnt/data
sudo umount /dev/sdb1
sudo umount -l /mnt/data          # 懒卸载（busy 时立即解绑，待空闲清理）
sudo umount -f /mnt/nfs           # 强制（NFS 失效时）

# 查看挂载
mount                            # 所有挂载
mount | column -t                # 格式化
findmnt                          # 树形显示
findmnt /mnt/data                # 查看指定挂载点
df -hT                           # 使用情况 + 类型

# 挂载 fstab 中所有
sudo mount -a                    # 挂载 fstab 中未挂载的
sudo umount -a                   # 卸载 fstab 中所有
```

**/etc/fstab 配置**：

```bash
# 查看 fstab
cat /etc/fstab

# 典型 fstab 内容
# 设备                          挂载点    类型    选项              dump fsck
UUID=abc-123...                 /         ext4    errors=remount-ro 0    1
UUID=def-456...                 /home     ext4    defaults          0    2
UUID=ghi-789...                 /var      xfs     defaults          0    2
UUID=jkl-012...                 /boot     ext4    defaults          0    2
UUID=mno-345...                 swap      swap    defaults          0    0
tmpfs                           /tmp      tmpfs   defaults,noatime,size=2G 0 0

# 编辑 fstab
sudo nano /etc/fstab

# 添加新挂载（推荐用 UUID）
echo "UUID=$(sudo blkid -s UUID -o value /dev/sdb1) /mnt/data ext4 defaults,noatime 0 2" | sudo tee -a /etc/fstab

# 测试 fstab 配置（重要！避免重启失败）
sudo mount -a                   # 无输出表示成功
sudo findmnt --verify           # 验证 fstab 语法

# 重新挂载（修改选项后）
sudo mount -o remount /mnt/data
sudo mount -o remount,rw /mnt/data   # 改为读写
```

**autofs 自动挂载**：

```bash
# 安装
sudo apt install autofs          # Debian/Ubuntu
sudo dnf install autofs          # RHEL 系

# 配置主映射
sudo tee /etc/auto.master.d/nfs.autofs > /dev/null <<'EOF'
/mnt/nfs  /etc/auto.nfs  --timeout=300
EOF

# 配置具体映射
sudo tee /etc/auto.nfs > /dev/null <<'EOF'
data  -rw,soft,intr  server:/export/data
home  -rw,soft,intr  server:/export/home
EOF

# 启动
sudo systemctl enable --now autofs

# 访问 /mnt/nfs/data 时自动挂载，5 分钟无操作自动卸载
ls /mnt/nfs/data
```

fstab 各字段说明：

| 字段 | 说明 | 示例 |
|------|------|------|
| 设备 | 设备路径/UUID/LABEL | `UUID=abc-123` 或 `/dev/sda1` |
| 挂载点 | 挂载到的目录 | `/mnt/data` |
| 类型 | 文件系统类型 | `ext4`/`xfs`/`nfs`/`swap` |
| 选项 | 挂载选项 | `defaults,noatime` |
| dump | dump 备份频率（0=不备份） | `0` |
| fsck | 启动时 fsck 顺序（0=不检查） | `0` 或 `2` |

#### 总结

- 挂载是把文件系统关联到目录，挂载点目录原内容被遮蔽
- `mount` 临时挂载，`/etc/fstab` 持久化，启动时 systemd 自动挂载
- fstab 推荐用 UUID（设备名可能变化），`mount -a` 测试配置避免重启失败
- 常用选项：`defaults`、`noatime`（性能）、`discard`（SSD TRIM）、`errors=remount-ro`
- `autofs` 按需挂载，适合 NFS 等网络文件系统，节省资源

### 第20讲 LVM 逻辑卷管理

#### 概念

**LVM**（Logical Volume Manager，逻辑卷管理器）是 Linux 的存储抽象层，它在物理磁盘之上引入"逻辑卷"概念，让存储管理变得灵活：可以动态调整大小、跨磁盘、做快照，不受物理分区限制。LVM 的三层结构：**PV**（Physical Volume，物理卷）→ **VG**（Volume Group，卷组）→ **LV**（Logical Volume，逻辑卷）。现代 Linux 服务器几乎都使用 LVM。

#### 原理

LVM 的核心思想是"存储虚拟化"。传统分区一旦划分，调整大小困难；LVM 把多个物理磁盘（PV）的存储空间汇聚成一个**卷组**（VG），从 VG 中划分出**逻辑卷**（LV）作为使用单元。LV 的大小可以动态调整（扩展或缩小），可以跨多个物理磁盘，可以创建快照用于备份。

三层关系：① **PV**（Physical Volume）：用 `pvcreate` 在磁盘或分区上创建，是 LVM 的基本存储单元；② **VG**（Volume Group）：用 `vgcreate` 把一个或多个 PV 组成卷组，VG 是存储池；③ **LV**（Logical Volume）：用 `lvcreate` 从 VG 中划分逻辑卷，LV 上创建文件系统后挂载使用。

LVM 扩展逻辑卷的流程：① `lvextend` 扩展 LV 大小；② `resize2fs`（ext4）或 `xfs_growfs`（xfs）扩展文件系统。这是 LVM 最大优势——在线扩展无需卸载。缩小逻辑卷较复杂（需卸载、先缩文件系统再缩 LV），且 xfs 不支持缩小。**LVM 快照**（snapshot）是某一时刻 LV 的只读副本，用于一致性备份，COW（Copy-On-Write）机制保证快照空间高效。

#### 例子

```bash
# 查看当前 LVM 状态
sudo pvs                       # 物理卷概览
sudo vgs                       # 卷组概览
sudo lvs                       # 逻辑卷概览
sudo pvdisplay                 # 物理卷详情
sudo vgdisplay                 # 卷组详情
sudo lvdisplay                 # 逻辑卷详情

# 完整流程：从裸盘到挂载

# 1. 准备磁盘（可以是整盘或分区）
sudo pvcreate /dev/sdb /dev/sdc
# Physical volume "/dev/sdb" successfully created
# Physical volume "/dev/sdc" successfully created

# 2. 创建卷组
sudo vgcreate vg_data /dev/sdb /dev/sdc
# Volume group "vg_data" successfully created

# 3. 创建逻辑卷
# 指定大小
sudo lvcreate -L 100G -n lv_data vg_data
# 用全部剩余空间
sudo lvcreate -l 100%FREE -n lv_data vg_data
# 用百分比
sudo lvcreate -l 50%VG -n lv_data vg_data

# 4. 格式化
sudo mkfs.ext4 /dev/vg_data/lv_data
# 或
sudo mkfs.xfs /dev/vg_data/lv_data

# 5. 挂载
sudo mkdir /mnt/data
sudo mount /dev/vg_data/lv_data /mnt/data

# 6. 写入 fstab（用 LV 设备路径或 UUID）
echo "/dev/vg_data/lv_data /mnt/data ext4 defaults,noatime 0 2" | sudo tee -a /etc/fstab
```

**扩展逻辑卷（在线，无需卸载）**：

```bash
# 场景：/mnt/data 空间不够，要扩展

# 1. 检查 VG 是否有剩余空间
sudo vgs
# VFree 列显示剩余空间

# 2. 如果 VG 没空间，先加新磁盘扩展 VG
sudo pvcreate /dev/sdd
sudo vgextend vg_data /dev/sdd

# 3. 扩展 LV
# 指定大小
sudo lvextend -L 200G /dev/vg_data/lv_data
# 增加 50G
sudo lvextend -L +50G /dev/vg_data/lv_data
# 用全部剩余空间
sudo lvextend -l +100%FREE /dev/vg_data/lv_data

# 4. 扩展文件系统
# ext4
sudo resize2fs /dev/vg_data/lv_data
# xfs（需挂载状态）
sudo xfs_growfs /mnt/data

# 5. 验证
df -h /mnt/data
sudo lvs
```

**LVM 快照（用于备份）**：

```bash
# 创建快照（COW，初始很小）
sudo lvcreate -L 10G -s -n lv_data_snap /dev/vg_data/lv_data

# 挂载快照（只读）
sudo mount -o ro /dev/vg_data/lv_data_snap /mnt/snap

# 从快照备份数据（一致性副本）
sudo tar -czf /backup/data-$(date +%F).tar.gz -C /mnt/snap .

# 用完删除快照
sudo umount /mnt/snap
sudo lvremove -f /dev/vg_data/lv_data_snap
```

**删除 LVM**：

```bash
# 顺序：LV → VG → PV
sudo umount /mnt/data
sudo lvremove /dev/vg_data/lv_data
sudo vgremove vg_data
sudo pvremove /dev/sdb /dev/sdc
```

**LVM 命令速查**：

| 操作 | 命令 |
|------|------|
| 创建 PV | `pvcreate /dev/sdb` |
| 查看 PV | `pvs` / `pvdisplay` |
| 删除 PV | `pvremove /dev/sdb` |
| 创建 VG | `vgcreate vg0 /dev/sdb /dev/sdc` |
| 查看 VG | `vgs` / `vgdisplay` |
| 扩展 VG | `vgextend vg0 /dev/sdd` |
| 删除 VG | `vgremove vg0` |
| 创建 LV | `lvcreate -L 100G -n lv0 vg0` |
| 查看 LV | `lvs` / `lvdisplay` |
| 扩展 LV | `lvextend -L +50G /dev/vg0/lv0` |
| 缩小 LV | `lvreduce -L -50G /dev/vg0/lv0`（慎用） |
| 删除 LV | `lvremove /dev/vg0/lv0` |
| 创建快照 | `lvcreate -L 10G -s -n snap /dev/vg0/lv0` |

#### 总结

- LVM 三层：PV（物理卷）→ VG（卷组，存储池）→ LV（逻辑卷，使用单元）
- LVM 最大优势：在线扩展 LV 无需卸载，先 `lvextend` 再 `resize2fs`/`xfs_growfs`
- 扩展流程：VG 没空间先 `vgextend` 加盘，再 `lvextend` 扩 LV，最后扩文件系统
- 快照是 COW 机制的一致性副本，用于在线备份
- xfs 只能扩展不能缩小，ext4 可扩展可缩小（缩小需卸载且先缩文件系统）

## 第8章 系统监控与日志

### 第21讲 系统资源监控

#### 概念

系统监控是运维的眼睛，让你实时了解 CPU、内存、磁盘、网络的使用情况，及时发现瓶颈和异常。核心工具：`top`/`htop`（实时进程）、`free`（内存）、`df`/`du`（磁盘）、`iostat`（IO）、`vmstat`（虚拟内存）、`sar`（历史数据）、`nethogs`/`iftop`（网络按进程）。掌握这些工具能让你快速定位性能问题。

#### 原理

Linux 性能监控的核心是 `/proc` 和 `/sys` 虚拟文件系统，内核实时把各种统计信息暴露为文件。`/proc/stat` 是 CPU 时间统计，`/proc/meminfo` 是内存信息，`/proc/diskstats` 是磁盘 IO 统计，`/proc/net/dev` 是网络流量。所有监控工具本质都是读取这些文件并计算差值或格式化输出。

**CPU 监控**关注：① **使用率**（user/system/idle/iowait 百分比）；② **负载均衡**（load average，1/5/15 分钟平均运行队列长度）；③ **上下文切换**和**中断**频率。`top` 的 `%Cpu(s)` 行显示 CPU 分布：us（用户）、sy（系统）、id（空闲）、wa（IO 等待）、st（虚拟化偷取）。**内存监控**要区分：total（总量）、used（已用）、free（完全空闲）、buff/cache（缓冲缓存）、available（实际可用）。`free -h` 的 available 才是关键指标，因为 Linux 会用空闲内存做缓存，free 少不代表内存紧张。

**磁盘 IO 监控**关注：① **tps**（每秒 IO 次数）；② **读写吞吐量**（KB/s）；③ **await**（IO 响应时间，毫秒）；④ **%util**（利用率）。`iostat -x` 是详细视图。**网络监控**关注带宽、连接数、丢包、重传。`iftop` 按连接显示流量，`nethogs` 按进程显示流量。

#### 例子

```bash

# 顶部摘要：任务数、CPU、内存、Swap

# 进程级监控
```

- `vmstat` 看虚拟内存综合，`sar` 看历史数据（需装 sysstat）
- 负载均衡（load average）反映 CPU 运行队列长度，长期高于 CPU 核数说明过载

### 第22讲 日志系统（journald 与 rsyslog）

#### 概念

日志是排查问题的金矿。Linux 有两套并行的日志系统：① **rsyslog**（传统，按配置写入文本文件，如 `/var/log/messages`、`/var/log/syslog`）；② **journald**（systemd 的二进制日志，用 `journalctl` 查询）。两者可以共存：journald 收集后转发给 rsyslog 写文本。理解日志的查看、过滤、轮转、远程收集，是运维必备能力。

#### 原理

**journald** 是 systemd 的日志守护进程，它收集内核、initrd、用户进程（通过 syslog 接口）的日志，存储为**二进制索引格式**（默认在 `/var/log/journal/` 或 `/run/log/journal/`）。二进制格式优势：① 支持结构化字段查询；② 自动轮转和空间管理；③ 不可篡改（有验证机制）。劣势：需用 `journalctl` 查看，不能直接 `cat`。

**rsyslog** 是传统 syslog 的增强版，通过 `/etc/rsyslog.conf` 和 `/etc/rsyslog.d/` 配置规则，把日志按**设施**（facility：kern/user/mail/auth/daemon...）和**级别**（priority：emerg/alert/crit/err/warning/notice/info/debug）路由到不同文件。如 `*.info;mail.none;authpriv.none;cron.none /var/log/messages` 表示所有 info 级别日志（除 mail/authpriv/cron）写入 messages。

**日志轮转**（log rotation）由 `logrotate` 工具完成，避免日志无限增长。它按配置（`/etc/logrotate.conf` 和 `/etc/logrotate.d/`）定期：① 重命名当前日志（加日期后缀）；② 压缩旧日志；③ 创建新日志文件；④ 通知服务重开文件；⑤ 删除超过保留数的旧日志。

#### 例子

**journalctl 使用**：

```bash
# 基本查看
journalctl                       # 所有日志（分页）
journalctl --no-pager            # 不分页（适合管道）
journalctl -n 50                 # 最近 50 条
journalctl -f                    # 实时跟踪（类似 tail -f）
journalctl -r                    # 逆序（最新在前）

# 按时间过滤
journalctl --since today
journalctl --since "2026-07-08 10:00:00"
journalctl --since "2026-07-08" --until "2026-07-08 12:00"
journalctl --since "1 hour ago"
journalctl --since "30 min ago"

# 按启动过滤
journalctl -b                    # 本次启动
journalctl -b -1                 # 上次启动
journalctl -b -2                 # 上上次
journalctl --list-boots          # 列出所有启动记录

# 按服务过滤
journalctl -u nginx              # nginx 服务日志
journalctl -u nginx -f           # 实时跟踪
journalctl -u nginx --since today
journalctl -u nginx -u mysql     # 多服务

# 按级别过滤
journalctl -p err                # 错误及以上
journalctl -p warning            # 警告及以上
journalctl -p crit               # 严重及以上
journalctl -p 3                  # 数字（0-7）
journalctl -p err -b             # 本次启动的错误

# 按进程/用户/设备
journalctl _PID=1234             # 指定 PID
journalctl _UID=1000             # 指定用户
journalctl _GID=1000             # 指定组
journalctl _COMM=sshd            # 指定命令名
journalctl _SYSTEMD_UNIT=ssh.service

# 按可执行文件
journalctl /usr/bin/nginx

# 按字段（结构化日志）
journalctl SYSLOG_FACILITY=10    # authpriv 设施
journalctl PRIORITY=6            # info 级别

# 输出格式
journalctl -o short              # 默认格式
journalctl -o short-iso          # ISO 时间
journalctl -o verbose            # 详细（含所有字段）
journalctl -o json               # JSON 格式
journalctl -o cat                # 只消息内容
journalctl -o json-pretty        # 美化 JSON

# 磁盘管理
journalctl --disk-usage          # 日志占用
sudo journalctl --vacuum-size=100M   # 限制总大小
sudo journalctl --vacuum-time=7days  # 只保留 7 天
sudo journalctl --vacuum-files=5     # 只保留 5 个文件

# 验证日志完整性
journalctl --verify
```

**rsyslog 配置**：

```bash
# 查看配置
cat /etc/rsyslog.conf
ls /etc/rsyslog.d/

# 配置规则格式：设施.级别  动作
# 例：mail.info  /var/log/mail.log
#     *.err      /var/log/errors.log
#     *.*        @logserver.example.com  (UDP)
#     *.*        @@logserver.example.com (TCP)

# 自定义日志
sudo tee /etc/rsyslog.d/myapp.conf > /dev/null <<'EOF'
# 把 myapp 的日志写到单独文件
if $programname == 'myapp' then /var/log/myapp.log
& stop   # 不再往下匹配
EOF

sudo systemctl restart rsyslog

# 在程序中发日志
logger -t myapp "Application started"
logger -t myapp -p user.err "Error occurred"
logger -t myapp "Message with structured data" 

# 查看传统日志文件
ls /var/log/
cat /var/log/syslog           # Debian/Ubuntu 主日志
cat /var/log/messages         # RHEL 系主日志
cat /var/log/auth.log         # Debian/Ubuntu 认证日志
cat /var/log/secure           # RHEL 系认证日志
cat /var/log/kern.log         # 内核日志
cat /var/log/dmesg            # 启动日志
dmesg                         # 内核环形缓冲区
dmesg -T                      # 带时间
dmesg --follow                # 实时跟踪
```

**logrotate 日志轮转**：

```bash
# 查看配置
cat /etc/logrotate.conf
ls /etc/logrotate.d/

# 示例配置（/etc/logrotate.d/myapp）
sudo tee /etc/logrotate.d/myapp > /dev/null <<'EOF'
/var/log/myapp/*.log {
    daily              # 每天轮转
    missingok          # 文件不存在不报错
    rotate 30          # 保留 30 份
    compress           # 压缩旧日志
    delaycompress      # 延迟压缩（下次才压缩）
    notifempty         # 空文件不轮转
    create 0640 myapp myapp   # 新文件的属主属组权限
    sharedscripts      # 多文件共享脚本
    postrotate
        systemctl reload myapp > /dev/null 2>&1 || true
    endscript
}
EOF

# 测试
sudo logrotate -d /etc/logrotate.d/myapp    # 调试模式（不实际执行）
sudo logrotate -f /etc/logrotate.d/myapp    # 强制轮转
sudo logrotate -v /etc/logrotate.d/myapp    # 详细模式执行

# 全局配置选项
# daily/weekly/monthly/yearly  轮转频率
# rotate N                     保留份数
# size 100M                    按大小轮转
# compress                     压缩
# delaycompress                延迟压缩
# missingok                    文件不存在不报错
# notifempty                   空文件不轮转
# create 0644 user group       创建新文件
# copytruncate                 复制后清空原文件（不重启服务）
# postrotate/endscript         轮转后执行脚本
# sharedscripts                多文件共享脚本
```

#### 总结

- journald 是 systemd 的二进制日志，用 `journalctl` 查询，支持结构化字段
- rsyslog 按设施.级别路由到文本文件，配置在 `/etc/rsyslog.d/`
- `journalctl -u 服务 -f` 实时跟踪服务日志，`-b` 按启动，`-p err` 按级别
- `logger -t 标签 "消息"` 在脚本中发日志到 syslog
- logrotate 按配置轮转压缩日志，`postrotate` 通知服务重开文件

### 第23讲 性能分析与故障排查

#### 概念

当系统变慢或异常时，需要系统化的性能分析方法定位瓶颈。Linux 提供丰富的性能分析工具，覆盖 CPU、内存、IO、网络各个层面。本讲介绍性能分析方法论、核心工具（`perf`、`strace`、`ltrace`、`tcpdump`、`bpftrace`），以及常见故障的排查思路。掌握这些能让你从"猜问题"升级到"定位问题"。

#### 原理

性能分析的核心方法论是 **USE 方法**（Utilization/Saturation/Errors）：对每个资源检查使用率（多忙）、饱和度（多排队）、错误（出错次数）。CPU 的使用率看 `top`/`mpstat`，饱和度看负载均衡和运行队列，错误看 `dmesg`。内存的使用率看 `free`，饱和度看 swap 和 OOM，错误看 `dmesg`。磁盘的使用率看 `%util`，饱和度看队列长度和 await，错误看 `dmesg` 和 SMART。网络的使用率看带宽，饱和度看重传和丢包，错误看接口统计。

另一方法是 **USE 的扩展——RED**（Rate/Errors/Duration），适合服务：请求速率、错误数、响应时长。对于应用性能，分层分析：① 系统层（CPU/内存/IO/网络）；② 进程层（线程状态、锁等待）；③ 应用层（函数耗时、SQL 慢查询）。工具链：`top`/`htop` 看宏观，`pidstat` 看进程，`strace` 看系统调用，`perf` 看函数级 CPU 占用，`tcpdump`/`wireshark` 看网络包，`bpftrace` 是现代 eBPF 工具。

#### 例子

```bash
# === CPU 分析 ===
# 进程级 CPU
top -p $(pgrep nginx | tr '\n' ',' | sed 's/,$//')
pidstat -p 1234 1            # 每秒统计指定进程
pidstat -t -p 1234 1         # 按线程

# 函数级 CPU（perf，需安装 linux-tools）
sudo perf top                # 实时函数热点
sudo perf top -p 1234        # 指定进程
sudo perf record -p 1234 -- sleep 30  # 采样 30 秒
sudo perf report             # 分析报告
sudo perf stat command       # 命令的统计信息

# 系统调用追踪
strace -p 1234               # 追踪运行中进程
strace -c -p 1234            # 统计系统调用
strace -e trace=network -p 1234  # 只追踪网络调用
strace -e trace=file -p 1234     # 只追踪文件调用
strace -T -tt -p 1234        # 带时间戳
strace -f command            # 追踪命令及子进程

# 库函数追踪
ltrace -p 1234               # 追踪库调用
ltrace -c command            # 统计

# === 内存分析 ===
# 进程内存映射
cat /proc/1234/maps          # 内存映射
pmap -x 1234                 # 内存映射详情
pmap -d 1234                 # 简洁版

# 内存分配追踪
sudo apt install valgrind
valgrind --tool=massif ./program  # 内存分配分析
valgrind --leak-check=full ./program  # 内存泄漏检测

# OOM 排查
dmesg | grep -i "killed process"  # OOM 记录
journalctl -k | grep -i oom

# === IO 分析 ===
# 进程 IO
iotop                        # 按 IO 排序（需安装）
iotop -P                     # 按进程
pidstat -d 1                 # 进程 IO 统计

# 文件打开
lsof -p 1234                 # 进程打开的文件
lsof /var/log/syslog         # 谁在用这个文件
lsof +D /var/log             # 递归目录

# IO 延迟分析
iostat -x 1                  # await 高表示 IO 慢
sudo perf record -e block:block_rq_issue -a -- sleep 10

# === 网络分析 ===
# 抓包
sudo tcpdump -i eth0 -n port 80   # 抓 80 端口
sudo tcpdump -i eth0 -n host 1.2.3.4  # 抓指定 IP
sudo tcpdump -i eth0 -w capture.pcap  # 保存文件
sudo tcpdump -r capture.pcap    # 读取
sudo tcpdump -i eth0 -nn -XX -vv port 443  # 详细

# 连接分析
ss -tn                       # TCP 连接
ss -tn state time-wait       # TIME_WAIT 状态
ss -tn state established | wc -l  # 活跃连接数
netstat -an | awk '/tcp/ {print $6}' | sort | uniq -c  # 状态分布

# 网络性能
iperf3 -c server             # 带宽测试
mtr 8.8.8.8                  # 路径质量
ping -c 100 8.8.8.8          # 丢包率

# === 综合工具 ===
# eBPF 现代工具（需安装 bpftrace 或 bcc-tools）
sudo bpftrace -e 'tracepoint:syscalls:sys_enter_* { @[probe] = count(); }'  # 系统调用统计
sudo execsnoop               # 跟踪进程创建
sudo opensnoop               # 跟踪文件打开
sudo biolatency              # IO 延迟分布
sudo runqlat                 # 调度延迟
sudo tcpdrop                 # TCP 丢包
sudo tcpretrans              # TCP 重传

# === 故障排查思路 ===
# 1. 系统是否慢？
uptime                       # 负载高？
top                          # CPU/内存高？

# 2. 哪个进程？
ps -eo pid,%cpu,%mem,cmd --sort=-%cpu | head
ps -eo pid,%cpu,%mem,cmd --sort=-%mem | head

# 3. 进程在做什么？
strace -p PID                # 系统调用
ltrace -p PID                # 库调用
perf top -p PID              # 函数热点

# 4. 资源是否瓶颈？
iostat -x 1                  # IO
vmstat 1                     # 内存/CPU
ss -tn                       # 网络

# 5. 日志怎么说？
journalctl -xe               # 最近错误
dmesg | tail                 # 内核消息
tail -f /var/log/syslog      # 系统日志
```

**常见故障排查**：

```bash
# 磁盘空间满
df -h                        # 哪个分区满
du -xah / | sort -rh | head  # 找大文件
find / -xdev -size +1G 2>/dev/null  # 找大于 1G 的文件

ps -eo pid,rss,cmd --sort=-rss | head  # 内存大户

# CPU 100%
top -c                       # 找进程
ps -eLf | grep PID           # 找线程
strace -p PID                # 看在做什么
perf top -p PID              # 函数热点

# 网络不通
ping 8.8.8.8                 # 基本连通

ss -tlnp                     # 服务是否监听
sudo iptables -L -n          # 防火墙
dig example.com              # DNS
traceroute 8.8.8.8           # 路径

# 服务无法启动
```

#### 总结

- USE 方法论：对每个资源检查使用率、饱和度、错误
- `strace` 追踪系统调用，`ltrace` 追踪库调用，`perf` 函数级 CPU 分析
- `tcpdump` 抓包，`ss` 看连接，`mtr` 看路径质量
- eBPF 工具（execsnoop/opensnoop/biolatency）是现代性能分析利器
- 故障排查五步：系统慢吗→哪个进程→在做什么→资源瓶颈吗→日志怎么说

## 第9章 内核与高级主题

### 第24讲 Linux 内核基础

#### 概念

**Linux 内核**是操作系统的核心，负责进程调度、内存管理、文件系统、设备驱动、网络协议栈、安全等。它运行在**内核态**（ring 0），应用程序运行在**用户态**（ring 3），通过**系统调用**（syscall）切换。理解内核的基本结构、启动流程、与用户态的关系，是深入 Linux 的必经之路。

#### 原理

Linux 内核采用**宏内核**架构，所有核心服务（调度、内存、文件系统、驱动、网络）都运行在同一地址空间。这与**微内核**（如 Mach、QNX）形成对比——微内核只把最基本功能（调度、IPC）放内核，其他作为用户态服务。宏内核优势是性能高（无需进程间通信），劣势是耦合度高（一个驱动 bug 可能导致内核崩溃）。Linux 通过**可加载内核模块**（LKM）机制缓解耦合：驱动、文件系统等编译为模块，按需加载/卸载，无需重启。

**用户态与内核态**的隔离通过 CPU 特权级实现：x86 有 ring 0-3，内核运行在 ring 0，应用在 ring 3。应用要访问硬件或内核服务，必须通过**系统调用**陷入内核态（trap 指令切换特权级）。常见系统调用：`read`/`write`（文件）、`fork`/`exec`/`wait`（进程）、`socket`/`connect`/`send`/`recv`（网络）、`mmap`（内存映射）。`strace` 命令能追踪进程的系统调用。

**内核启动流程**：① BIOS/UEFI 加电自检，加载引导程序（GRUB）；② GRUB 加载内核镜像（vmlinuz）和初始 RAM 磁盘（initramfs/initrd）到内存；③ 内核初始化：检测硬件、挂载根文件系统、启动 PID 1（systemd）；④ systemd 启动各服务，进入默认 target。`dmesg` 显示内核启动日志，`/var/log/dmesg` 是启动后的快照。

#### 例子

```bash
# 内核版本
uname -r                      # 如 5.15.0-91-generic
uname -a                      # 完整信息
cat /proc/version             # 编译信息

# 版本号含义：主版本.次版本.修订号-ABI-风格
# 5.15.0-91-generic
# 5      主版本
# 15     次版本（偶数=稳定，奇数=开发，现代已不严格区分）
# 0      修订号
# 91     ABI 编号（Ubuntu 风格）
# generic 风格（generic=通用，aws=AWS 优化，azure=Azure 优化）

cat /proc/filesystems         # 支持的文件系统

# 启动参数

cat /proc/sys/kernel/random/uuid  # 每次不同

# 4. 验证
uname -r
```

#### 总结

- Linux 是宏内核，核心服务都在内核态，通过 LKM 机制实现动态扩展
- 用户态（ring 3）通过系统调用陷入内核态（ring 0），`strace` 可追踪系统调用
- 启动流程：BIOS → GRUB → 内核+initramfs → systemd → 服务
- `uname -r` 看版本，`dmesg`/`journalctl -k` 看内核日志，`/proc/` 是内核信息接口
- 运行级别 3（命令行）和 5（图形）对应 systemd 的 multi-user.target 和 graphical.target

### 第25讲 内核模块与参数调优

#### 概念

**内核模块**（Kernel Module）是可动态加载的内核代码，用于扩展内核功能（驱动、协议、文件系统等），无需重新编译内核或重启。**内核参数**是运行时可调整的内核配置，通过 `/proc/sys/` 和 `/etc/sysctl.conf` 控制。掌握模块管理和参数调优，能让你优化系统性能、启用新功能、解决硬件兼容问题。

#### 原理

内核模块（`.ko` 文件，kernel object）位于 `/lib/modules/$(uname -r)/` 目录。`lsmod` 列出已加载模块，`modprobe` 智能加载（自动解决依赖），`insmod`/`rmmod` 直接加载/卸载单个模块（不处理依赖）。模块加载时执行 init 函数注册自身，卸载时执行 cleanup 函数释放资源。模块配置在 `/etc/modprobe.d/` 下，可以设置参数、黑名单（禁止加载）、别名。

**sysctl** 是内核参数管理接口。`/proc/sys/` 是虚拟文件系统，每个文件对应一个可调参数。例如 `/proc/sys/net/ipv4/ip_forward` 控制是否转发 IP 包，`1` 启用 `0` 禁用。`sysctl` 命令读取或设置这些参数，`sysctl -a` 列出所有，`sysctl -w 参数=值` 临时设置，`/etc/sysctl.conf` 和 `/etc/sysctl.d/` 持久化配置。

参数调优涉及网络（TCP 缓冲区、连接数）、内存（swap 倾向、脏页比例）、文件系统（最大文件描述符）、安全（源路由、ICMP 重定向）等。调优原则：① 先测量再调优，避免盲目；② 一次只改一个参数；③ 记录基线和调整后性能对比；④ 持久化到 sysctl.conf。

#### 例子

```bash
# === 内核模块管理 ===

# 查看已加载模块
lsmod                         # 列表
lsmod | grep nfs              # 查找
cat /proc/modules             # 同 lsmod

# 模块信息
modinfo nfs                   # 模块详情
modinfo -p nfs                # 模块参数
modinfo -F depends nfs        # 依赖

# 加载模块
sudo modprobe nfs             # 智能加载（含依赖）
sudo modprobe nfs version=4   # 带参数
sudo insmod /path/to/mymod.ko # 直接加载（不处理依赖）

# 卸载模块
sudo modprobe -r nfs          # 智能卸载（含依赖）
sudo rmmod nfs                # 直接卸载

# 模块配置
ls /etc/modprobe.d/
# 黑名单（禁止加载）
echo "blacklist pcspkr" | sudo tee /etc/modprobe.d/blacklist.conf
# 别名
echo "alias eth0 e1000e" | sudo tee /etc/modprobe.d/network.conf
# 参数
echo "options nfs version=4" | sudo tee /etc/modprobe.d/nfs.conf

# 重新生成模块依赖
sudo depmod -a

# 查看模块参数
ls /sys/module/nfs/parameters/  # 运行时参数
cat /sys/module/nfs/parameters/version

# === 内核参数（sysctl）===

# 查看所有参数
sysctl -a                     # 所有（很多）
sysctl -a | grep net.ipv4     # 过滤

# 查看单个参数
sysctl net.ipv4.ip_forward
cat /proc/sys/net/ipv4/ip_forward

# 临时设置
sudo sysctl -w net.ipv4.ip_forward=1
sudo sysctl -w vm.swappiness=10
sudo sysctl -w fs.file-max=1000000

# 持久化（写入配置文件）
sudo tee /etc/sysctl.d/99-custom.conf > /dev/null <<'EOF'
# 网络优化
net.ipv4.ip_forward = 1
net.ipv4.tcp_tw_reuse = 1
net.ipv4.tcp_fin_timeout = 30
net.ipv4.tcp_keepalive_time = 600
net.ipv4.tcp_max_syn_backlog = 65535
net.ipv4.tcp_max_tw_buckets = 65535
net.core.somaxconn = 65535
net.core.netdev_max_backlog = 65535

# 内存优化
vm.swappiness = 10
vm.dirty_ratio = 10
vm.dirty_background_ratio = 5
vm.overcommit_memory = 1

# 文件描述符
fs.file-max = 1000000
fs.inotify.max_user_watches = 524288

# 安全
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.all.accept_source_route = 0
net.ipv4.icmp_echo_ignore_broadcasts = 1
EOF

# 应用配置
sudo sysctl --system          # 加载所有 sysctl.d
sudo sysctl -p /etc/sysctl.d/99-custom.conf  # 加载指定文件

# === 常用调优参数 ===

# 网络相关
# 启用 IP 转发（路由器/容器场景）
net.ipv4.ip_forward = 1
# TCP 快速回收 TIME_WAIT
net.ipv4.tcp_tw_reuse = 1
net.ipv4.tcp_fin_timeout = 30
# TCP keepalive 探测间隔
net.ipv4.tcp_keepalive_time = 600
# SYN 队列长度（高并发）
net.ipv4.tcp_max_syn_backlog = 65535
# TIME_WAIT 队列长度
net.ipv4.tcp_max_tw_buckets = 65535
# listen 队列长度
net.core.somaxconn = 65535
# 网卡队列长度
net.core.netdev_max_backlog = 65535
# TCP 缓冲区
net.ipv4.tcp_rmem = 4096 87380 6291456
net.ipv4.tcp_wmem = 4096 65536 4194304
# BBR 拥塞控制（现代内核）
net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr

# 内存相关
# swappiness（0-100，越低越不用 swap）
vm.swappiness = 10
# 脏页比例（写缓存）
vm.dirty_ratio = 10
vm.dirty_background_ratio = 5
# 内存超分配策略（0=启发式，1=总是允许，2=严格不超）
vm.overcommit_memory = 1

# 文件描述符
fs.file-max = 1000000
# inotify watch 数（文件监控）
fs.inotify.max_user_watches = 524288

# 用户进程数限制
cat /proc/sys/kernel/pid_max  # 默认 32768，可调大
cat /proc/sys/kernel/threads-max

# === ulimit（用户级限制）===
ulimit -a                     # 查看所有限制
ulimit -n                     # 文件描述符
ulimit -u                     # 进程数
ulimit -s                     # 栈大小

# 临时调整
ulimit -n 65535               # 当前 Shell 生效

# 永久调整（/etc/security/limits.conf）
sudo tee /etc/security/limits.d/99-custom.conf > /dev/null <<'EOF'
*  soft  nofile  65535
*  hard  nofile  65535
*  soft  nproc   65535
*  hard  nproc   65535
root soft  nofile  65535
root hard  nofile  65535
EOF

# systemd 服务的限制（在 unit 文件中）
# [Service]
# LimitNOFILE=65535
# LimitNPROC=65535
```

#### 总结

- 内核模块用 `lsmod`/`modprobe`/`rmmod` 管理，`modprobe` 自动处理依赖
- `/etc/modprobe.d/` 配置模块参数、黑名单、别名
- `sysctl` 管理内核参数，`/proc/sys/` 是接口，`/etc/sysctl.d/` 持久化
- 网络调优：`tcp_tw_reuse`、`somaxconn`、`tcp_max_syn_backlog`、BBR 拥塞控制
- `ulimit` 是用户级限制，`/etc/security/limits.d/` 持久化，systemd 服务用 `LimitNOFILE`

### 第26讲 容器基础（namespace 与 cgroup）

#### 概念

**容器**是现代应用部署的主流方式，Docker/Kubernetes 的底层都依赖 Linux 内核的两个特性：**namespace**（命名空间，实现资源隔离）和 **cgroup**（控制组，实现资源限制）。理解这两个内核机制，能让你从原理上掌握容器技术，而不是停留在"会用 docker 命令"的层面。本讲介绍 namespace 的六种类型、cgroup 的资源控制、以及它们如何构成容器。

#### 原理

**namespace** 让进程看到"自己独占"的系统资源视图。Linux 有六种 namespace：① **PID**（进程 ID）：容器内进程从 1 开始，看不到宿主其他进程；② **NET**（网络）：独立的网卡、路由表、iptables、端口空间；③ **MNT**（挂载）：独立的文件系统视图；④ **UTS**（主机名）：独立的主机名和域名；⑤ **IPC**（进程间通信）：独立的消息队列、共享内存、信号量；⑥ **USER**（用户）：UID/GID 映射，容器内 root 对应宿主非 root。`unshare` 命令创建新 namespace，`nsenter` 进入已有 namespace。

**cgroup**（Control Group）把进程分组，对每组限制资源：CPU、内存、IO、网络、进程数等。cgroup v1 按资源类型分层级（cpu/memory/blkio/...），v2 统一层级更简洁。限制示例：CPU 配额（`cpu.cfs_quota_us`）、内存上限（`memory.max`）、IO 带宽（`blkio.throttle.read_bps_device`）。`systemd-cgls` 查看层级，`systemd-run` 创建临时 cgroup。

**容器**的本质就是：namespace 提供隔离 + cgroup 提供限制 + 镜像（分层文件系统）提供运行环境。Docker 把这些内核能力封装成易用的命令（`docker run`/`build`/`pull`）。容器相比虚拟机：① 共享内核，启动快、开销小；② 隔离性弱于虚拟机（内核漏洞影响所有容器）；③ 适合微服务部署。

#### 例子

```bash
# === Namespace ===

# 查看进程的 namespace
ls -l /proc/$$/ns/
# lrwxrwxrwx ... net -> net:[4026531956]
# lrwxrwxrwx ... pid -> pid:[4026531836]
# ...

# 查看所有 namespace
sudo lsns                       # 所有
sudo lsns -t pid                # PID 类型
sudo lsns -t net                # NET 类型

# 用 unshare 创建 namespace
# 创建新的 UTS namespace（改主机名不影响宿主）
sudo unshare -u bash
hostname mycontainer
hostname                        # mycontainer
exit
hostname                        # 宿主主机名不变

# 创建新的 PID namespace
sudo unshare -f --pid --mount-proc bash
ps aux                          # 只看到自己（PID 1）
# 现在你在容器化的 Shell 中

# 创建新的网络 namespace
sudo unshare -n bash
ip addr                         # 只有 lo
# 在新 namespace 中配置网络
ip link set lo up
exit

# 创建新的 mount namespace
sudo unshare -m bash
mount -t tmpfs none /tmp
# 在新 mount namespace 中挂载，不影响宿主
exit

# nsenter：进入已有 namespace
sudo nsenter -t 1234 -m -u -i -n -p
# 进入 PID 1234 的所有 namespace

# 容器本质演示
# 用 unshare + cgroup 手动创建一个"容器"
sudo unshare --pid --mount --uts --net --user --fork bash
# 在其中：
hostname myapp
ip link set lo up
ps aux
# 这就是一个简易容器

# === Cgroup ===

# 查看 cgroup
cat /proc/cgroups               # 所有子系统
systemd-cgls                    # 树形查看
systemd-cgtop                   # 按资源使用排序

# 查看进程的 cgroup
cat /proc/$$/cgroup
# 0::/user.slice/user-1000.slice/session-1.scope

# cgroup v2（现代系统）
ls /sys/fs/cgroup/
cat /sys/fs/cgroup/cgroup.controllers  # 可用控制器

# 创建 cgroup（v2）
sudo mkdir /sys/fs/cgroup/mygroup
echo "+memory +cpu" | sudo tee /sys/fs/cgroup/mygroup/cgroup.subtree_control

# 限制内存
echo "512M" | sudo tee /sys/fs/cgroup/mygroup/memory.max
# 限制 CPU
echo "100000 1000000" | sudo tee /sys/fs/cgroup/mygroup/cpu.max  # 10% CPU

# 把进程加入 cgroup
echo $$ | sudo tee /sys/fs/cgroup/mygroup/cgroup.procs

# 用 systemd-run 创建临时 cgroup
sudo systemd-run --uid=1000 --gid=1000 \
    --property=MemoryMax=512M \
    --property=CPUQuota=50% \
    /usr/bin/python3 /opt/app/server.py

# 查看 systemd 服务的 cgroup 限制
systemctl show myapp.service -p MemoryCurrent -p MemoryMax -p CPUQuotaPerSecUSec

# === Docker（容器封装）===

# 安装 Docker
sudo apt install docker.io      # Ubuntu
sudo dnf install docker         # RHEL 系

# 基本操作
sudo systemctl enable --now docker
sudo docker run hello-world     # 测试
sudo docker run -it ubuntu bash  # 运行 Ubuntu 容器
sudo docker run -d --name web -p 80:80 nginx  # 后台运行 nginx
sudo docker ps                  # 运行中的容器
sudo docker ps -a               # 所有容器
sudo docker images              # 本地镜像
sudo docker logs web            # 容器日志
sudo docker exec -it web bash   # 进入容器
sudo docker stop web            # 停止
sudo docker rm web              # 删除容器
sudo docker rmi nginx           # 删除镜像

# 资源限制
sudo docker run -d --name web \
    --memory=512m \             # 内存限制
    --cpus=1.5 \                # CPU 限制
    --pids-limit=100 \          # 进程数限制
    nginx

# 查看容器的 namespace
sudo docker inspect web | grep -i pidfile
# 容器进程的 /proc/PID/ns/ 就是其 namespace

# 查看容器的 cgroup
sudo docker stats              # 实时资源使用
```

**namespace 与 cgroup 的关系**：

```
┌─────────────────────────────────────────────────┐
│  宿主机 Linux 内核                                │
│  ┌───────────────────────────────────────────┐  │
│  │  Namespace（隔离）                        │  │
│  │  ┌─────────────┐  ┌─────────────┐         │  │
│  │  │ PID ns      │  │ NET ns      │  ...    │  │
│  │  │ 容器内 PID 1 │  │ 独立网卡    │         │  │
│  │  └─────────────┘  └─────────────┘         │  │
│  └───────────────────────────────────────────┘  │
│  ┌───────────────────────────────────────────┐  │
│  │  Cgroup（限制）                           │  │
│  │  ┌─────────────┐  ┌─────────────┐         │  │
│  │  │ CPU 限制    │  │ 内存限制    │  ...    │  │
│  │  │ 1.5 核      │  │ 512MB       │         │  │
│  │  └─────────────┘  └─────────────┘         │  │
│  └───────────────────────────────────────────┘  │
│                                                  │
│  Docker = Namespace + Cgroup + 镜像（分层文件系统）│
└─────────────────────────────────────────────────┘
```

#### 总结

- namespace 提供隔离：PID/NET/MNT/UTS/IPC/USER 六种，让容器看到独立视图
- cgroup 提供限制：CPU/内存/IO/进程数，v2 统一层级更简洁
- 容器 = namespace + cgroup + 镜像，共享内核所以轻量但隔离弱于虚拟机
- `unshare` 创建新 namespace，`nsenter` 进入已有 namespace，`lsns` 查看
- `systemd-run --property=MemoryMax=...` 创建带资源限制的临时服务

### 第27讲 服务器初始化配置实战

#### 概念

拿到一台新服务器，第一件事是做"初始化配置"——把它从裸系统调教成符合生产标准的状态。本讲通过一个完整的初始化脚本，综合运用前面学过的用户管理、SSH 加固、防火墙、时间同步、内核参数、日志配置等知识，演示如何把一台服务器配置成安全、可观测、高性能的生产环境。

#### 原理

服务器初始化的核心原则：① **最小化攻击面**——关闭不必要的服务、端口、用户；② **最小权限**——用普通用户+sudo 而非 root，限制 SSH 来源；③ **可观测性**——配置日志、监控、时间同步；④ **可重复性**——用脚本而非手动操作，便于批量部署和审计；⑤ **版本化**——配置纳入 Git 管理，变更可追溯。

初始化的标准步骤：① 更新系统到最新补丁；② 创建运维用户并配置 sudo；③ 配置 SSH 密钥登录、禁用 root 和密码；④ 配置防火墙只开必要端口；⑤ 配置时间同步（chrony/ntp）；⑥ 调整内核参数（网络、文件描述符）；⑦ 配置日志轮转和远程收集；⑧ 安装基础工具（vim/git/curl/wget/rsync/htop/iotop）；⑨ 配置 fail2ban 防暴力破解；⑩ 安装监控 agent（如 node_exporter）。每步都要可回滚、可验证。

#### 例子

完整的服务器初始化脚本：

```bash
#!/bin/bash
# server-init.sh - 服务器初始化配置脚本
# 用法：sudo ./server-init.sh
set -euo pipefail

# ============ 配置变量 ============
ADMIN_USER="ops"
ADMIN_PUBKEY="ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI... ops@example.com"
SSH_PORT="2222"
TIMEZONE="Asia/Shanghai"
NTP_SERVER="ntp.aliyun.com"

# 颜色输出
info()  { printf '\033[0;32m[INFO]\033[0m %s\n' "$*"; }
warn()  { printf '\033[0;33m[WARN]\033[0m %s\n' "$*"; }
err()   { printf '\033[0;31m[ERROR]\033[0m %s\n' "$*" >&2; }
die()   { err "$*"; exit 1; }

# 检查 root
[ "$(id -u)" -eq 0 ] || die "需要 root 权限运行"

# ============ 1. 更新系统 ============
update_system() {
    info "更新系统软件包..."
    if command -v apt > /dev/null; then
        apt update && apt upgrade -y
        apt install -y vim git curl wget rsync htop iotop \
                       tree unzip jq chrony fail2ban \
                       ca-certificates gnupg
    elif command -v dnf > /dev/null; then
        dnf update -y
        dnf install -y vim git curl wget rsync htop iotop \
                        tree unzip jq chrony fail2ban \
                        ca-certificates
        dnf install -y epel-release
    fi
    info "系统更新完成"
}

# ============ 2. 创建运维用户 ============
create_admin_user() {
    info "创建运维用户 $ADMIN_USER..."
    if ! id "$ADMIN_USER" &>/dev/null; then
        useradd -m -s /bin/bash -c "Operations" "$ADMIN_USER"
        # 加入 sudo/admin 组
        if getent group sudo > /dev/null; then
            usermod -aG sudo "$ADMIN_USER"
        elif getent group wheel > /dev/null; then
            usermod -aG wheel "$ADMIN_USER"
        fi
        # 配置 SSH 密钥
        local ssh_dir="/home/$ADMIN_USER/.ssh"
        mkdir -p "$ssh_dir"
        echo "$ADMIN_PUBKEY" > "$ssh_dir/authorized_keys"
        chmod 700 "$ssh_dir"
        chmod 600 "$ssh_dir/authorized_keys"
        chown -R "$ADMIN_USER:$ADMIN_USER" "$ssh_dir"
        info "运维用户 $ADMIN_USER 创建完成"
    else
        warn "用户 $ADMIN_USER 已存在，跳过"
    fi
    
    # 配置 sudo 免密
    echo "$ADMIN_USER ALL=(ALL) NOPASSWD: ALL" > /etc/sudoers.d/$ADMIN_USER
    chmod 440 /etc/sudoers.d/$ADMIN_USER
    visudo -c -f /etc/sudoers.d/$ADMIN_USER
}

# ============ 3. 加固 SSH ============
harden_ssh() {
    info "加固 SSH 配置..."
    local sshd_config="/etc/ssh/sshd_config"
    local sshd_dir="/etc/ssh/sshd_config.d"
    mkdir -p "$sshd_dir"
    
    cat > "$sshd_dir/hardening.conf" <<EOF
# 端口
Port $SSH_PORT

# 认证
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
MaxAuthTries 3
LoginGraceTime 30

# 用户限制
AllowUsers $ADMIN_USER

# 会话
ClientAliveInterval 300
ClientAliveCountMax 2

# 安全
X11Forwarding no
AllowTcpForwarding yes
PermitTunnel no

# 日志
LogLevel VERBOSE
EOF

    # 确保主配置包含 sshd_config.d
    if ! grep -q "^Include.*sshd_config.d" "$sshd_config"; then
        echo "Include /etc/ssh/sshd_config.d/*.conf" >> "$sshd_config"
    fi
    
    # 测试并重载
    sshd -t || die "SSH 配置语法错误"
    systemctl reload ssh 2>/dev/null || systemctl reload sshd
    info "SSH 加固完成，端口 $SSH_PORT"
}

# ============ 4. 配置防火墙 ============
configure_firewall() {
    info "配置防火墙..."
    if command -v ufw > /dev/null; then
        ufw --force reset
        ufw default deny incoming
        ufw default allow outgoing
        ufw allow $SSH_PORT/tcp comment 'SSH'
        ufw allow 80/tcp comment 'HTTP'
        ufw allow 443/tcp comment 'HTTPS'
        ufw --force enable
        ufw status verbose
    elif command -v firewall-cmd > /dev/null; then
        systemctl enable --now firewalld
        firewall-cmd --permanent --add-port=$SSH_PORT/tcp
        firewall-cmd --permanent --add-service=http
        firewall-cmd --permanent --add-service=https
        firewall-cmd --reload
        firewall-cmd --list-all
    fi
    info "防火墙配置完成"
}

# ============ 5. 配置时间同步 ============
configure_time() {
    info "配置时间同步..."
    timedatectl set-timezone "$TIMEZONE"
    
    # 停用 systemd-timesyncd（如使用 chrony）
    systemctl disable --now systemd-timesyncd 2>/dev/null || true
    
    if command -v chronyc > /dev/null; then
        cat > /etc/chrony/chrony.conf <<EOF
server $NTP_SERVER iburst
driftfile /var/lib/chrony/chrony.drift
makestep 1.0 3
rtcsync
allow 127.0.0.1
EOF
        systemctl enable --now chrony
        chronyc sources
    fi
    
    timedatectl set-ntp yes
    timedatectl status
    info "时间同步配置完成"
}

# ============ 6. 调整内核参数 ============
tune_kernel() {
    info "调整内核参数..."
    cat > /etc/sysctl.d/99-production.conf <<'EOF'
# 网络优化
net.ipv4.ip_forward = 1
net.ipv4.tcp_tw_reuse = 1
net.ipv4.tcp_fin_timeout = 30
net.ipv4.tcp_keepalive_time = 600
net.ipv4.tcp_max_syn_backlog = 65535
net.ipv4.tcp_max_tw_buckets = 65535
net.core.somaxconn = 65535
net.core.netdev_max_backlog = 65535
net.ipv4.tcp_rmem = 4096 87380 6291456
net.ipv4.tcp_wmem = 4096 65536 4194304
net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr

# 内存
vm.swappiness = 10
vm.dirty_ratio = 10
vm.dirty_background_ratio = 5

# 文件描述符
fs.file-max = 1000000
fs.inotify.max_user_watches = 524288

# 安全
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.all.accept_source_route = 0
net.ipv4.icmp_echo_ignore_broadcasts = 1
kernel.kptr_restrict = 2
kernel.dmesg_restrict = 1
EOF
    sysctl --system > /dev/null
    info "内核参数调整完成"
    
    # ulimit
    cat > /etc/security/limits.d/99-production.conf <<'EOF'
*  soft  nofile  65535
*  hard  nofile  65535
root soft  nofile  65535
root hard  nofile  65535
EOF
    info "文件描述符限制调整完成"
}

# ============ 7. 配置 fail2ban ============
configure_fail2ban() {
    info "配置 fail2ban..."
    cat > /etc/fail2ban/jail.local <<EOF
[DEFAULT]
bantime = 3600
findtime = 600
maxretry = 3
backend = systemd

[sshd]
enabled = true
port = $SSH_PORT
EOF
    systemctl enable --now fail2ban
    fail2ban-client status sshd
    info "fail2ban 配置完成"
}

# ============ 8. 配置日志轮转 ============
configure_logrotate() {
    info "配置日志轮转..."
    cat > /etc/logrotate.d/custom <<'EOF'
/var/log/custom/*.log {
    daily
    rotate 30
    compress
    delaycompress
    missingok
    notifempty
    create 0640 root adm
}
EOF
    info "日志轮转配置完成"
}

# ============ 9. 禁用不必要的服务 ============
disable_services() {
    info "禁用不必要的服务..."
    local services=(
        "cups"           # 打印服务
        "avahi-daemon"   # mDNS
        "bluetooth"      # 蓝牙
        "modemmanager"   # 调制解调器
        "postfix"        # 邮件（如不需要）
    )
    for svc in "${services[@]}"; do
        if systemctl is-enabled "$svc" 2>/dev/null | grep -q enabled; then
            systemctl disable --now "$svc"
            info "已禁用 $svc"
        fi
    done
}

# ============ 10. 生成报告 ============
generate_report() {
    info "生成配置报告..."
    cat <<EOF

========================================
  服务器初始化完成
========================================
主机名：$(hostname)
IP 地址：$(hostname -I)
时区：$(timedatectl show -p Timezone --value)
SSH 端口：$SSH_PORT
运维用户：$ADMIN_USER
防火墙：已启用
时间同步：$(timedatectl show -p NTP --value)
fail2ban：已启用

请用以下命令测试 SSH 登录：
  ssh -p $SSH_PORT $ADMIN_USER@$(hostname -I | awk '{print $1}')

重要：请先测试 SSH 登录成功后再关闭当前会话！
========================================
EOF
}

# ============ 主流程 ============
main() {
    echo "===================================="
    echo "  服务器初始化脚本"
    echo "  时间：$(date)"
    echo "===================================="
    
    update_system
    create_admin_user
    harden_ssh
    configure_firewall
    configure_time
    tune_kernel
    configure_fail2ban
    configure_logrotate
    disable_services
    generate_report
    
    info "所有配置完成！"
}

main "$@"
```

使用方式：

```bash

wget https://your-repo/server-init.sh

# 2. 检查脚本内容（重要！运行前一定要审查）
less server-init.sh

# 3. 修改配置变量（用户名、公钥、端口等）
vim server-init.sh

# 4. 执行

# 5. 在新终端测试 SSH 登录（不要关闭当前会话！）

# 6. 确认能登录后再关闭原会话
```

#### 总结

- 服务器初始化原则：最小攻击面、最小权限、可观测、可重复、版本化
- 标准步骤：更新系统→建用户→加固SSH→防火墙→时间同步→内核调优→fail2ban→日志
- 脚本要 `set -euo pipefail` 严格模式，每步有日志，可回滚
- 改 SSH 配置后先在新终端测试，确认能登录再关闭原会话
- 配置脚本纳入 Git 管理，便于审计和批量部署

### 第28讲 系统故障排查实战

#### 概念

系统故障是运维的日常：服务起不来、磁盘满了、网络不通、性能骤降。本讲通过几个典型故障场景，演示如何用前面学过的工具系统化排查问题。核心方法论：① **先观察现象**（错误信息、监控指标）；② **定位范围**（单机还是集群、单服务还是系统级）；③ **分层排查**（网络→系统→应用）；④ **验证假设**（修改后观察）；⑤ **记录归档**（形成知识库）。

#### 原理

故障排查的核心是**二分法**和**隔离变量**。面对复杂系统，先判断"是哪一层的问题"：网络层（ping/tcpdump）、系统层（CPU/内存/IO/磁盘）、应用层（日志/配置/代码）。每层内继续二分：网络是路由问题还是防火墙？系统是 CPU 还是 IO 瓶颈？应用是配置错误还是代码 bug？

关键思维：① **先看日志**——`journalctl`、应用日志、`dmesg` 通常有直接错误信息；② **对比基线**——和正常状态对比，找出变化；③ **最小复现**——简化场景定位触发条件；④ **不要同时改多个变量**——否则无法判断哪个修改生效；⑤ **保留现场**——重要数据先备份再操作。常见故障类型：资源耗尽（磁盘满、内存不足、文件描述符满）、配置错误（语法错、权限错、路径错）、依赖问题（库缺失、版本不兼容）、网络问题（DNS、防火墙、路由）。

#### 例子

**场景 1：服务无法启动**

```bash
# 现象：nginx 启动失败
sudo systemctl start nginx
# Job for nginx.service failed because the control process exited with error code.
# See "systemctl status nginx.service" and "journalctl -xe" for details.

# 排查步骤：
# 1. 查看状态
sudo systemctl status nginx
# ● nginx.service - The nginx HTTP and reverse proxy server
#    Loaded: loaded (/usr/lib/systemd/system/nginx.service; enabled)
#    Active: failed (Result: exit-code)
#    Process: 12345 ExecStartPre=/usr/sbin/nginx -t (code=exited, status=1/FAILURE)

# 2. 查看日志
sudo journalctl -u nginx -n 50 --no-pager
# nginx: [emerg] bind() to 0.0.0.0:80 failed (98: Address already in use)
# nginx: [emerg] bind() to 0.0.0.0:80 failed (98: Address already in use)

# 3. 定位：80 端口被占用
sudo ss -tlnp | grep :80
# LISTEN 0 128 0.0.0.0:80 0.0.0.0:* users:(("apache2",pid=1234,fd=4))

# 4. 解决：停掉占用端口的进程
sudo systemctl stop apache2
sudo systemctl disable apache2
sudo systemctl start nginx
sudo systemctl status nginx
# Active: active (running)
```

**场景 2：磁盘空间满**

```bash
# 现象：无法写入文件
echo "test" > /tmp/test
# bash: /tmp/test: No space left on device

# 排查步骤：
# 1. 查看磁盘使用
df -h
# /dev/sda1  50G  50G  0  100% /

# 2. 找大文件
sudo du -xah / 2>/dev/null | sort -rh | head -20
# 20G /var/log/nginx/access.log
# 10G /var/log/app.log
# 5G  /tmp/large_dump.sql
# ...

# 3. 处理日志
sudo truncate -s 0 /var/log/nginx/access.log
# 或轮转
sudo logrotate -f /etc/logrotate.d/nginx

# 4. 找已删除但未释放的文件
sudo lsof +L1 | grep deleted
# nginx  1234  www-data  5w  REG  8,1  1073741824  0 (deleted) /var/log/nginx/access.log
# 进程还持有已删除文件，空间未释放

# 5. 解决：重启进程释放
sudo systemctl reload nginx

# 6. inode 满的情况（df -h 看不出）
df -i
# /dev/sda1  3276800  3276800  0  100% /
# 找小文件多的目录
sudo find / -xdev -type f 2>/dev/null | sed 's@/[^/]*$@@' | sort | uniq -c | sort -rn | head
# 500000 /var/spool/postfix/maildrop
# 清理
sudo find /var/spool/postfix/maildrop -type f -delete
```

**场景 3：CPU 100%**

```bash
# 现象：系统响应慢
top
# PID  USER   %CPU %MEM  COMMAND
# 1234 alice  99.9 1.2   python3 app.py

# 排查步骤：
# 1. 确认进程
ps -p 1234 -o pid,ppid,user,etime,cmd
# PID PPID USER ELAPSED CMD
# 1234 1000 alice 01:23:34 python3 /opt/app/server.py

# 2. 看进程在做什么
sudo strace -p 1234 -c
# % time     seconds  usecs/call     calls    errors syscall
# ------ ----------- ----------- --------- --------- ----------------
#   85.00    1.23456         123     10000           futex
#   10.00    0.14567          12     12000           read
# ...

# 3. 函数级分析
sudo perf top -p 1234
# 或者
sudo perf record -p 1234 -- sleep 10
sudo perf report

# 4. 看线程
ps -T -p 1234
# PID  SPID TTY  STAT TIME COMMAND
# 1234 1235 ?    R    01:23 python3
# 1234 1236 ?    R    01:23 python3

# 5. 看应用日志
sudo journalctl -u app -n 50
# 或 tail -f /var/log/app.log

# 6. 解决：如果是死循环，重启
sudo systemctl restart app
# 如果是正常负载，考虑扩容或优化代码
```

**场景 4：网络不通**

```bash
# 现象：无法访问外部服务
curl http://example.com
# curl: (6) Could not resolve host: example.com

# 排查步骤（分层）：
# 1. DNS 层
dig example.com
# ;; connection timed out; no servers could be reached
cat /etc/resolv.conf
# nameserver 8.8.8.8
# 测试 DNS 服务器是否可达
ping -c 3 8.8.8.8
# PING 8.8.8.8: 56 data bytes
# 64 bytes from 8.8.8.8: icmp_seq=0 ttl=117 time=5.123 ms
# DNS 服务器可达，但 DNS 查询超时

# 2. 检查防火墙
sudo iptables -L -n | grep 53
# 或
sudo ufw status
# 检查是否阻挡了 53 端口（DNS）

# 3. 测试 TCP 53
nc -zv 8.8.8.8 53
# Connection to 8.8.8.8 53 port [tcp/domain] succeeded!

# 4. 测试 UDP 53
nc -zuv 8.8.8.8 53
# 测试本地到 8.8.8.8 的 UDP 53

# 5. 换 DNS 测试
dig @1.1.1.1 example.com
# 如果 1.1.1.1 可以，说明 8.8.8.8 被封

# 6. 修改 DNS
sudo tee /etc/resolv.conf > /dev/null <<'EOF'
nameserver 1.1.1.1
nameserver 8.20.247.20
EOF

# 7. 验证
dig example.com
curl http://example.com
```

**场景 5：OOM（内存不足）**

```bash
# 现象：进程被杀
sudo journalctl -k | grep -i "killed process"
# Jul 8 10:00:00 server kernel: Out of memory: Killed process 1234 (java) total-vm:4G, anon-rss:3G

# 排查步骤：
# 1. 查看内存状态
free -h
#               total  used  free  shared  buff/cache  available
# Mem:          4.0G   3.5G  100M  50M     400M        200M
# Swap:         2.0G   2.0G  0

# 2. 找内存大户
ps -eo pid,rss,vsz,cmd --sort=-rss | head -10
# PID   RSS  VSZ  CMD
# 1234  3.0G 4.0G java -Xmx4G -jar app.jar
# 5678  200M 500M nginx

# 3. 查看 OOM 历史
sudo dmesg | grep -i oom
# 或
sudo journalctl -k --since "1 hour ago" | grep -i oom

# 4. 解决方案：
# a. 限制进程内存（Java 调小堆）
# b. 增加 swap
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
# c. 调整 OOM 行为
echo 'vm.overcommit_memory = 2' | sudo tee /etc/sysctl.d/oom.conf
# d. 升级内存
```

**通用排查工具箱**：

```bash
# 一键收集系统状态
#!/bin/bash
echo "=== 系统状态快照 $(date) ==="
echo ""
echo "--- 主机 ---"
hostname; uptime; uname -r
echo ""
echo "--- CPU/内存 ---"
top -bn1 | head -5
free -h
echo ""
echo "--- 磁盘 ---"
df -h | grep -v tmpfs
echo ""
echo "--- 网络 ---"
ip -br addr
ss -s
echo ""
echo "--- 最近错误日志 ---"
journalctl -p err --since "1 hour ago" --no-pager | tail -20
echo ""
echo "--- dmesg 末尾 ---"
dmesg | tail -20
```

#### 总结

- 故障排查方法论：观察现象→定位范围→分层排查→验证假设→记录归档
- 先看日志（journalctl/dmesg/应用日志），通常有直接错误信息
- 分层排查：网络（ping/dig/ss/tcpdump）→系统（top/free/df/iostat）→应用（日志/配置）
- 不要同时改多个变量，保留现场先备份再操作
- 常见故障：端口占用、磁盘满、CPU 100%、DNS 故障、OOM，各有标准排查路径
