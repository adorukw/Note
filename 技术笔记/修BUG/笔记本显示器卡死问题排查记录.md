# 笔记本显示器卡死问题排查记录

日期：2026-09-26
机型：MECHREVO WUJIE Series（T142-STX，BIOS：T142_STXKRK_V15，2025-07-11）

## 一、问题现象

- 屏幕画面会突然静止（停在最后一帧），**不是刷新率问题**。
- 键盘、鼠标等输入依然有效，系统没有真正死机。
- 只能通过合盖或按电源键息屏（触发睡眠/唤醒）才能让画面刷新。
- 往往要反复合盖/唤醒好几次，才能恢复正常使用。

## 二、环境信息

| 项目 | 内容 |
| --- | --- |
| 系统 | Debian GNU/Linux 13 (trixie) |
| 内核 | 6.12.107+deb13-amd64 |
| 桌面 | GNOME 48.7，Wayland |
| 显卡 | AMD Strix Point（Radeon 880M / 890M，显示控制器 63:00.0） |
| 屏幕 | eDP-1，2880x1800 |
| 固件 | firmware-amd-graphics 20250410-2，DMUB 固件版本 0x09001B00 |
| 睡眠模式 | 仅支持 s2idle（无 S3/deep 可选） |

## 三、排查过程

### 1. 查看硬件与内核日志

```bash
lspci | grep -Ei 'vga|3d|display'
uname -a
sudo dmesg | grep -Ei 'amdgpu|drm|error|timeout|ring'
```

在 dmesg 中发现两类内核 WARNING（几乎每次开机后都会出现 1~2 次）：

```
WARNING: CPU: 13 PID: 3601 at drivers/gpu/drm/amd/amdgpu/../display/dc/dce/dmub_replay.c:89 dmub_replay_enable+0x100/0x110 [amdgpu]

WARNING: CPU: 2 PID: 3606 at drivers/gpu/drm/amd/amdgpu/../display/dc/dc_dmub_srv.c:1587 dc_dmub_srv_apply_idle_power_optimizations+0x1d9/0x550 [amdgpu]
```

### 2. 对照内核源码确认警告含义

从 Debian 6.12.107 的源码中确认，这两处都是 `ASSERT(0)`：

- `dmub_replay.c:89`：开启 **Panel Replay** 时等待 DMUB 固件响应超时（重试 1000 次，每次 500us，约 0.5 秒）。
- `dc_dmub_srv.c:1587`：`dc_dmub_srv_apply_idle_power_optimizations()` 中 **IPS 空闲电源状态**的 `idle_exit_counter` 计数失衡（小于 0）。

同时确认 6.12 内核中 `dcdebugmask` 的掩码定义（`drivers/gpu/drm/amd/include/amd_shared.h`）：

| 掩码 | 值 | 含义 |
| --- | --- | --- |
| DC_DISABLE_PSR | 0x10 | 禁用 PSR |
| DC_DISABLE_PSR_SU | 0x200 | 禁用 PSR-SU |
| DC_DISABLE_REPLAY | 0x400 | 禁用 Panel Replay |
| DC_DISABLE_IPS | 0x800 | 禁用 IPS（空闲电源状态） |
| DC_DISABLE_IPS_DYNAMIC | 0x1000 | 除挂起外禁用 IPS |

### 3. 关联卡死发生的时间点

用 journalctl 还原时间线，发现警告集中出现在**从睡眠唤醒时**：

```
23:35:54 PM: suspend entry (s2idle)
23:44:44 PM: suspend entry (s2idle)
23:44:45 SMU is resuming...
23:44:57 WARNING dmub_replay_enable 超时      ← 唤醒时开启 Panel Replay 失败
23:45:15 又 suspend（合盖）
23:46:12 又 suspend
23:46:46 WARNING IPS 计数失衡                 ← 又一次唤醒失败
23:46:52、23:47:54 又各 suspend 一次          ← 用户反复合盖尝试恢复
```

时间线与"合盖/电源键息屏才能刷新、反复几次才正常"的现象完全吻合：每次唤醒时驱动要重新开启 Panel Replay 和 IPS，DMUB 固件没有正常响应，显示管道就卡住，画面停留在最后一帧，而系统与输入仍在运行。

### 4. 检查运行时开关（确认无法热修复）

- `eDP-1/psr_capability`：`Driver support: no`，PSR 本来就是关闭的，排除 PSR。
- `eDP-1/replay_capability`：`Driver support: yes / Config support: yes`，Panel Replay 处于启用状态。
- `eDP-1/replay_state`：68（活动状态）。
- Panel Replay 与 IPS 在 debugfs 中**没有可写开关**，`amdgpu.dcdebugmask` 也只读且仅在模块加载时生效，无法运行时修改。
- `/sys/power/mem_sleep` 只有 `[s2idle]`，无法切换到 deep(S3) 睡眠来绕开。

## 四、根因

AMD Strix Point（DCN 3.5 显示核心）在**从 s2idle 唤醒时**，显示驱动的省电特性 **Panel Replay** 与 **IPS（Idle Power State）** 与 DMUB 固件通信失败（超时、电源状态计数失衡），导致显示管道卡死在低功耗状态无法恢复。

- 画面冻结但输入正常：系统和合成器没有死，只是显示输出停了。
- 合盖/息屏能恢复：睡眠/唤醒会重新初始化显示管道，相当于一次"软复位"。
- 反复几次才正常：每次唤醒都是一次"赌运气"，直到某次唤醒成功。

## 五、解决方案（已实施）

不修改 GRUB、不更换内核，通过内核模块参数关闭 Panel Replay：

1. 新建配置文件 `/etc/modprobe.d/amdgpu-replay.conf`：

```
# Disable AMD Panel Replay to work around DMUB replay_enable timeout
# causing display freeze on resume from s2idle (Strix Point / DCN 3.5).
# DC_DISABLE_REPLAY = 0x400
options amdgpu dcdebugmask=0x400
```

2. 重建 initramfs（amdgpu 模块在 initramfs 中加载，必须重建）：

```bash
sudo update-initramfs -u
```

3. 已验证配置文件被包含进 initramfs。
4. 重启后生效。

## 六、重启后验证

```bash
# 应显示 1024（即 0x400）
cat /sys/module/amdgpu/parameters/dcdebugmask

# Driver support 应变回 no
cat /sys/kernel/debug/dri/0000:63:00.0/eDP-1/replay_capability
```

然后正常合盖睡眠使用几天，观察是否还会卡死。

## 七、备选与后续方案

1. **若仍偶发卡死**：把配置中的 `0x400` 改为 `0xc00`（Panel Replay + IPS 一起禁用），再次执行 `sudo update-initramfs -u` 并重启。
2. **BIOS 更新**：当前 BIOS 为 2025-07-11 的 T142_STXKRK_V15，可关注 MECHREVO 官网是否有新版本。
3. **等待 Debian 稳定版内核更新**：后续 6.12 点版本可能回合上游修复（保持 `sudo apt full-upgrade`）。
4. **代价说明**：禁用 Panel Replay/IPS 只会略微增加待机功耗，不影响性能与其他功能。

## 八、临时恢复技巧

万一再遇到画面冻结（输入仍有效）：

- 按 `Ctrl+Alt+F3` 切到 TTY，再按 `Ctrl+Alt+F1` 切回图形界面，可强制重新初始化显示，比反复合盖快。
