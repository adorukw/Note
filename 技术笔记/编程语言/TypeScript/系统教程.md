## 第一章：基础入门

### 第 1 讲：TypeScript 简介与环境搭建

#### 概念

TypeScript（简称 TS）是微软于 2012 年开源的一门编程语言，它是 JavaScript 的**超集**（superset）。这意味着任何合法的 JavaScript 代码都是合法的 TypeScript 代码，你在 TS 中可以继续使用熟悉的 JS 语法。TS 在 JS 的基础上增加了**静态类型系统**，允许开发者在编写代码时为变量、函数参数、返回值等标注类型，编译器会在编译阶段进行类型检查，提前发现潜在错误。

TypeScript 的"超集"关系可以理解为：JavaScript 是 TypeScript 的子集。TS 并没有创造全新的运行时，它最终会被编译（更准确地说是"转译"，transpile）成纯 JavaScript 代码运行在浏览器或 Node.js 中。因此 TS 是一种**开发时工具**，运行时并不存在"TypeScript 类型"这一概念——所有类型信息在编译后都会被擦除。

#### 原理

TypeScript 的工作原理可以拆解为三个阶段：

1. **源码解析**：TS 编译器（tsc）读取 `.ts` 文件，将其解析为抽象语法树（AST）。
2. **类型检查**：编译器根据类型注解和类型推断，对 AST 进行静态分析，检查类型是否匹配。这一步发生在**编译时**，不会运行代码。
3. **代码生成**：类型检查通过后，编译器将 TS 代码转译为目标版本的 JS 代码（如 ES5、ES2015 等），同时**擦除所有类型信息**。

这种"类型只在编译时存在"的设计被称为**类型擦除**（type erasure）。它的好处是零运行时开销——编译产物与手写的 JS 一样轻量。代价是你无法在运行时获取类型信息（除非使用装饰器或自定义元数据方案）。

TS 采用的是**结构化类型系统**（structural typing），也叫"鸭子类型"：只要两个类型的结构（属性名和类型）兼容，就认为它们兼容，而不关心它们的命名或继承关系。这与 Java、C# 的"名义类型系统"（nominal typing）有本质区别。

#### 例子

**安装 TypeScript**：

```bash
# 全局安装 TypeScript 编译器
npm install -g typescript

# 验证安装
tsc --version
```

**第一个 TS 程序** `hello.ts`：

```typescript
// 为参数和返回值标注类型
function greet(name: string): string {
  return `Hello, ${name}!`;
}

const message: string = greet('TypeScript');
console.log(message);
```

**编译并运行**：

```bash
tsc hello.ts        # 生成 hello.js
node hello.js       # 输出: Hello, TypeScript!
```

编译后的 `hello.js`：

```javascript
function greet(name) {
  return `Hello, ${name}!`;
}
var message = greet('TypeScript');
console.log(message);
```

可以看到，所有类型注解都被擦除了。

**类型错误的演示**：

```typescript
function add(a: number, b: number): number {
  return a + b;
}

add(1, 2);      // OK
add(1, '2');    // 错误: 类型"string"的参数不能赋给类型"number"的参数
```

这段代码在编译时会报错，避免了运行时出现 `12` 这样的隐式拼接 bug。

#### 总结

- TypeScript 是 JavaScript 的超集，核心价值是**静态类型检查**，在编译时发现错误
- TS 采用**类型擦除**机制，编译产物是纯 JS，无运行时开销
- TS 使用**结构化类型系统**，关注形状而非命名
- 学习 TS 的第一步是搭建环境：`npm i -g typescript`，用 `tsc` 编译运行
- TS 与 JS 完全兼容，可以渐进式迁移现有项目

### 第 2 讲：基础类型系统

#### 概念

TypeScript 的类型系统是其核心。最基础的类型包括两大类：**原始类型**（primitive types）和**特殊类型**（special types）。原始类型对应 JavaScript 的 6 种原始值：`string`、`number`、`boolean`、`null`、`undefined`、`symbol`（以及 ES2020 的 `bigint`）。特殊类型则是 TS 独有的，包括 `any`、`unknown`、`void`、`never`、`object` 等，它们用于表达更抽象的类型语义。

掌握这些基础类型是写出类型安全代码的前提。每一种类型都有其适用场景，滥用 `any` 会让 TS 退化为 JS，而合理使用 `unknown` 和 `never` 则能显著提升代码的严谨性。

#### 原理

TS 的类型系统遵循**子类型关系**（subtyping）。理解类型之间的层级关系至关重要：

- `never` 是所有类型的子类型（底部类型，bottom type），表示"永远不会发生"
- `undefined` 和 `null` 是所有类型的子类型（在非严格模式下），可以赋值给任何类型
- 原始类型之间互不兼容，`string` 不能赋给 `number`
- `unknown` 是所有类型的父类型（顶部类型，top type），任何值都可以赋给它，但它不能直接赋给其他类型
- `any` 类似 `unknown`，但**绕过了类型检查**，相当于关闭了 TS

`void` 表示函数没有返回值，`never` 表示函数永远不会正常返回（抛异常或死循环）。`unknown` 和 `any` 的区别在于：`unknown` 强制你在使用前进行类型检查，是"类型安全版的 any"。

#### 例子

**原始类型**：

```typescript
let userName: string = 'Alice';
let age: number = 30;
let isActive: boolean = true;
let bigNum: bigint = 100n;
let sym: symbol = Symbol('id');
let nothing: null = null;
let undef: undefined = undefined;
```

**特殊类型**：

```typescript
// any: 放弃类型检查（不推荐）
let loose: any = 4;
loose = 'string';      // OK
loose.toFixed();       // OK，但运行时可能报错

// unknown: 类型安全的 any
let safe: unknown = 4;
safe.toFixed();        // 错误: unknown 类型上不存在 toFixed
if (typeof safe === 'number') {
  safe.toFixed();      // OK，类型收窄后可用
}

// void: 函数无返回值
function log(msg: string): void {
  console.log(msg);
}

// never: 永不返回
function throwError(msg: string): never {
  throw new Error(msg);
}

function infiniteLoop(): never {
  while (true) {}
}
```

**类型注解语法**：

```typescript
// 变量注解
let count: number = 10;

// 函数参数与返回值注解
function divide(a: number, b: number): number {
  if (b === 0) {
    throw new Error('除数不能为 0');
  }
  return a / b;
}
```

#### 总结

- 原始类型：`string`、`number`、`boolean`、`null`、`undefined`、`symbol`、`bigint`
- `any` 是逃生舱，应尽量避免；`unknown` 是类型安全的替代方案
- `void` 用于无返回值函数，`never` 用于永不返回的场景
- 类型注解语法：`变量名: 类型`，函数参数和返回值都可标注
- 理解类型层级关系（`never` < 原始类型 < `unknown`/`any`）是后续学习的基础

### 第 3 讲：变量声明与类型推断

#### 概念

在 TypeScript 中，你不必为每个变量显式标注类型——编译器能够根据上下文**自动推断**变量的类型，这被称为**类型推断**（type inference）。同时，TS 提供了**类型断言**（type assertion）机制，允许开发者手动"告诉"编译器某个值的具体类型。理解何时让编译器推断、何时显式标注、何时使用断言，是写出优雅 TS 代码的关键。

类型推断让 TS 在保持类型安全的同时，不至于过于啰嗦。而类型断言则是开发者在"比编译器更了解类型"时的干预手段，但滥用断言会绕过类型检查，引入隐患。

#### 原理

类型推断主要发生在以下场景：

1. **变量初始化**：`let x = 3` 推断 `x` 为 `number`
2. **函数返回值**：根据 `return` 语句推断返回类型
3. **结构化类型**：对象字面量的属性类型会被推断

对于 `let` 声明，TS 推断为**宽类型**（widening），如 `let x = 3` 推断为 `number` 而非字面量 `3`。对于 `const` 声明，TS 推断为**字面量类型**（literal type），如 `const x = 3` 推断为 `3`，因为 const 变量不可重新赋值。

**最佳通用类型**（Best Common Type）：当从多个候选类型推断时（如数组的多个元素），TS 会选择一个能兼容所有候选的"父类型"。

**类型断言**有两种语法：`<T>value`（JSX 中不兼容）和 `value as T`（推荐）。断言不会改变运行时行为，只是让编译器"相信"你的判断。如果断言不合理，编译器仍会报错。

#### 例子

**类型推断**：

```typescript
// 变量推断
let count = 10;          // 推断为 number
const pi = 3.14;         // 推断为 3.14（字面量类型）
let name = 'Alice';      // 推断为 string
const greeting = 'Hi';   // 推断为 "Hi"

// 函数返回值推断
function double(x: number) {
  return x * 2;          // 返回类型推断为 number
}

// 数组推断（最佳通用类型）
let arr = [1, 2, 3];           // 推断为 number[]
let mixed = [1, '2', true];    // 推断为 (string | number | boolean)[]
```

**类型断言**：

```typescript
// 场景：DOM 操作
const input = document.getElementById('user') as HTMLInputElement;
input.value = 'hello';

// 场景：从 unknown 收窄
let value: unknown = 'hello';
let len = (value as string).length;

// 场景：联合类型收窄
let data: string | number = 'abc';
console.log((data as string).toUpperCase());

// 非空断言（non-null assertion）
function process(el: HTMLElement | null) {
  el!.style.color = 'red';   // 告诉编译器 el 不是 null
}
```

**何时显式标注**：

```typescript
// 推荐显式标注的场景
let age: number;              // 无初始值时必须标注，否则推断为 any
function greet(name: string): string { ... }   // 函数签名应显式
interface User { ... }        // 公共 API 应显式

// 推荐让编译器推断的场景
const user = { name: 'Alice', age: 30 };   // 无需标注
const result = compute(input);             // 无需标注返回值
```

#### 总结

- 类型推断让 TS 代码简洁，无需处处标注
- `let` 推断宽类型，`const` 推断字面量类型
- 类型断言用 `as` 语法（JSX 友好），用于"比编译器更了解类型"的场景
- 非空断言 `!` 用于排除 null/undefined，但要谨慎使用
- 原则：函数签名和公共 API 显式标注，局部变量让推断工作
- 滥用断言会绕过类型检查，应优先用类型守卫（见第 10 讲）

## 第二章：核心类型

### 第 4 讲：接口（Interface）

#### 概念

**接口**（Interface）是 TypeScript 描述对象形状的核心工具。它定义了一组属性名及其类型，任何"具有这些属性且类型匹配"的对象都被认为实现了该接口。接口本身不产生运行时代码（编译后会被擦除），它纯粹是编译时的类型约束。

接口可以描述对象的属性、函数的签名、可索引类型、类的结构等。它是 TS 中最常用的类型构造方式，几乎所有真实项目都会大量使用接口来定义数据模型和 API 契约。

#### 原理

TypeScript 采用**结构化类型**（structural typing）系统，也叫"鸭子类型"：类型兼容性基于结构而非命名。这意味着，只要一个对象"看起来像"接口定义的形状（拥有所需的属性且类型匹配），就认为它实现了该接口，**无需显式声明 `implements`**。这与 Java/C# 的名义类型系统截然不同。

接口支持以下特性：
- **可选属性** `prop?: type`：属性可以不存在
- **只读属性** `readonly prop: type`：只能在创建时赋值
- **索引签名** `[key: string]: type`：允许任意额外属性
- **函数类型**：用调用签名描述函数
- **可索引类型**：描述数组或字典

接口还支持**声明合并**：同名接口会自动合并属性。这一特性在扩展第三方类型时很有用，但也可能引入意外行为。

#### 例子

**基本接口**：

```typescript
interface User {
  id: number;
  name: string;
  email: string;
  age?: number;              // 可选属性
  readonly createdAt: Date;  // 只读属性
}

const user: User = {
  id: 1,
  name: 'Alice',
  email: 'alice@example.com',
  createdAt: new Date(),
};

user.name = 'Bob';           // OK
user.createdAt = new Date(); // 错误: 只读属性
```

**函数类型接口**：

```typescript
interface Comparator<T> {
  (a: T, b: T): number;
}

const numberCompare: Comparator<number> = (a, b) => a - b;
numberCompare(1, 2);   // -1
```

**索引签名与可索引类型**：

```typescript
interface StringMap {
  [key: string]: string;
  // 也可以有固定属性，但类型必须兼容索引签名
  name: string;
}

const map: StringMap = { name: 'Alice', city: 'Beijing' };

interface NumberArray {
  [index: number]: string;
}
const arr: NumberArray = ['a', 'b', 'c'];
```

**接口扩展（继承）**：

```typescript
interface Animal {
  name: string;
}

interface Dog extends Animal {
  breed: string;
  bark(): void;
}

const dog: Dog = {
  name: 'Rex',
  breed: 'Labrador',
  bark() { console.log('Woof!'); },
};
```

**声明合并**：

```typescript
interface Window {
  customProp: string;
}
// 与 lib.dom.d.ts 中的 Window 合并
window.customProp = 'hello';
```

#### 总结

- 接口用于描述对象形状，是 TS 最常用的类型工具
- TS 采用结构化类型，对象"形状匹配"即兼容，无需显式 implements
- 可选属性 `?`、只读属性 `readonly`、索引签名 `[key: string]` 是常用特性
- 接口支持继承（`extends`）和声明合并
- 接口 vs 类型别名：接口可重复声明合并，更适合描述对象；类型别名更灵活，可描述联合、交叉等
- 接口编译后会被擦除，无运行时开销

### 第 5 讲：类型别名与联合类型

#### 概念

**类型别名**（Type Alias）通过 `type` 关键字为一个类型起一个新名字。与接口不同，类型别名可以描述**任何类型**：原始类型、联合类型、交叉类型、元组、函数等。**联合类型**（Union Type）用 `|` 连接多个类型，表示一个值可以是其中任意一种。**字面量类型**（Literal Type）则将类型限制为具体的值，如 `"success"`、`42`、`true`。

类型别名与联合类型组合，是表达"有限取值集合"和"多形态数据"的利器，在真实业务中极为常用。

#### 原理

联合类型的语义是"或"（OR）：值属于联合类型中的**某一个**成员类型。但要注意，当直接访问联合类型的成员时，TS 只允许访问**所有成员共有的属性**。要访问某个成员特有的属性，必须先进行**类型收窄**（narrowing），通过 `typeof`、`in`、`instanceof` 等方式判断当前是哪个成员。

字面量类型是原始类型的"子类型"。例如 `"hello"` 是 `string` 的字面量类型。字面量类型常与联合类型结合，模拟枚举效果，且比枚举更轻量（编译后无运行时代码）。

类型别名与接口的关键区别：
- 类型别名可描述联合、交叉、元组、原始类型；接口主要用于对象
- 类型别名不能重复声明（不会合并）；接口同名会合并
- 二者在描述对象时功能接近，可互换

#### 例子

**类型别名**：

```typescript
type ID = number | string;
type Callback = (data: any) => void;
type Point = { x: number; y: number };

const id: ID = 123;
const id2: ID = 'abc';
const p: Point = { x: 1, y: 2 };
```

**联合类型**：

```typescript
type Status = 'pending' | 'success' | 'error';

function handle(status: Status) {
  if (status === 'pending') {
    console.log('加载中...');
  } else if (status === 'success') {
    console.log('成功');
  } else {
    console.log('失败');
  }
}

// 联合类型只能访问共有属性
type Text = string | string[];
function first(t: Text) {
  // t.length OK，因为 string 和 string[] 都有 length
  console.log(t.length);
  // t.charAt(0) 错误，string[] 没有 charAt
}
```

**字面量类型**：

```typescript
type Direction = 'up' | 'down' | 'left' | 'right';
type Dice = 1 | 2 | 3 | 4 | 5 | 6;
type Bool = true | false;

function move(dir: Direction) {
  switch (dir) {
    case 'up':    return [0, 1];
    case 'down':  return [0, -1];
    case 'left':  return [-1, 0];
    case 'right': return [1, 0];
  }
}
```

**可辨识联合**（Discriminated Union）：

```typescript
// 用一个公共字段（tag）区分不同形态
type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'square'; size: number }
  | { kind: 'rectangle'; width: number; height: number };

function area(shape: Shape): number {
  switch (shape.kind) {
    case 'circle':    return Math.PI * shape.radius ** 2;
    case 'square':    return shape.size ** 2;
    case 'rectangle': return shape.width * shape.height;
  }
}

area({ kind: 'circle', radius: 5 });        // 78.54
area({ kind: 'rectangle', width: 3, height: 4 }); // 12
```

可辨识联合是 TS 中表达"多形态数据"的最佳实践，比传统的类继承更轻量。

#### 总结

- `type` 别名可描述任何类型，比 `interface` 更灵活
- 联合类型 `|` 表示"或"，访问成员时只能用共有属性，需收窄后访问特有属性
- 字面量类型将类型限制为具体值，常与联合结合模拟枚举
- **可辨识联合**是处理多形态数据的利器：每个分支带一个 `kind`/`type` 字段
- 类型别名不产生运行时代码，纯编译时
- 选择建议：描述对象形状用 interface，描述联合/交叉/元组用 type

### 第 6 讲：数组、元组与枚举

#### 概念

本讲介绍三种常用的复合类型：
- **数组**（Array）：同类型元素的有序集合
- **元组**（Tuple）：固定长度、每项类型可不同的数组
- **枚举**（Enum）：一组命名的常量集合

数组是日常开发最常用的数据结构；元组适合表达"固定结构的数据对"，如坐标 `[x, y]`、HTTP 响应 `[status, body]`；枚举则用于管理一组相关的常量，提升代码可读性。

#### 原理

**数组类型**有两种写法：`T[]` 和 `Array<T>`，二者等价。TS 会检查数组操作的类型安全，如 `push`、`map`、`filter` 的回调参数类型。

**元组**是 TS 对 JS 数组的类型扩展。元组明确指定每个位置的元素类型和数量。元组支持**可选元素**（`[T, U?]`）和**剩余元素**（`[T, ...U[]]`）。注意，元组在运行时仍是普通数组，TS 只在编译时检查长度和位置类型。

**枚举**有四种形式：
1. **数字枚举**：默认从 0 递增，可双向映射（`Enum[key]` 和 `Enum[value]` 都可访问）
2. **字符串枚举**：必须显式赋值，无双向映射
3. **常量枚举**（`const enum`）：编译时完全内联，无运行时对象
4. **异构枚举**：混合数字和字符串（不推荐）

枚举在编译后会生成真实的 JS 对象（常量枚举除外），这是它与字面量联合类型的主要区别。社区对枚举有争议：它增加了运行时体积，且与结构化类型系统不完全契合。许多项目改用"字面量联合 + `as const`"替代枚举。

#### 例子

**数组类型**：

```typescript
let numbers: number[] = [1, 2, 3];
let names: Array<string> = ['Alice', 'Bob'];
let matrix: number[][] = [[1, 2], [3, 4]];

// 类型安全的数组方法
numbers.push(4);          // OK
numbers.push('4');        // 错误
const doubled = numbers.map(n => n * 2);  // number[]
```

**元组**：

```typescript
// 基本元组
let point: [number, number] = [10, 20];
let response: [number, string] = [200, 'OK'];

// 解构使用
const [x, y] = point;

// 可选元素与剩余元素
type Options = [string, ...number[]];
const opt: Options = ['cmd', 1, 2, 3];

// 标签元组（TS 4.0+，提升可读性）
type Pair = [first: number, second: number];
```

**数字枚举**：

```typescript
enum Direction {
  Up,      // 0
  Down,    // 1
  Left,    // 2
  Right,   // 3
}

let dir: Direction = Direction.Up;
console.log(Direction[0]);  // "Up"（双向映射）
```

**字符串枚举**：

```typescript
enum Color {
  Red = '#FF0000',
  Green = '#00FF00',
  Blue = '#0000FF',
}

const c: Color = Color.Red;  // '#FF0000'
```

**常量枚举**：

```typescript
const enum Status {
  Active = 1,
  Inactive = 0,
}

const s = Status.Active;
// 编译后: const s = 1;（无运行时对象）
```

**枚举的现代替代方案**：

```typescript
// 用字面量联合 + as const 替代枚举
const Direction = {
  Up: 'UP',
  Down: 'DOWN',
  Left: 'LEFT',
  Right: 'RIGHT',
} as const;

type Direction = typeof Direction[keyof typeof Direction];
// 'UP' | 'DOWN' | 'LEFT' | 'RIGHT'
```

#### 总结

- 数组类型：`T[]` 或 `Array<T>`，TS 会检查元素类型和方法回调
- 元组：固定长度和位置类型，适合表达结构化数据对
- 枚举：数字枚举有双向映射，字符串枚举更安全，常量枚举编译时内联
- 枚举会生成运行时对象，与结构化类型系统不完全契合，社区有争议
- 现代实践：优先用"字面量联合 + `as const`"替代枚举，更轻量、更类型友好
- 元组在运行时仍是数组，TS 只在编译时检查长度和位置

### 第 7 讲：函数类型

#### 概念

函数是 JavaScript 的一等公民，TypeScript 为函数提供了完整的类型支持。函数类型涉及三个方面：**参数类型**、**返回值类型**和**函数本身的类型**。TS 还支持**函数重载**（overloads），允许同一个函数根据不同参数类型返回不同类型，以及 `this` 类型的显式标注。

掌握函数类型是写出可复用、类型安全 API 的基础。无论是回调函数、高阶函数还是事件处理器，都需要准确的函数类型定义。

#### 原理

TS 中定义函数类型有两种方式：
1. **函数签名**：`(param: T) => U`，描述参数和返回值
2. **接口调用签名**：`interface Fn { (param: T): U }`

二者等价，函数签名更简洁，接口形式可扩展（可添加属性）。

**函数重载**的原理：TS 允许为一个函数提供多个**重载签名**（overload signatures）， followed by 一个**实现签名**（implementation signature）。调用时，TS 根据传入参数匹配最合适的重载签名，返回对应类型。实现签名对外不可见，调用者只能使用重载签名。注意，重载签名之间不能有冲突，且实现签名必须兼容所有重载。

**`this` 类型**：在普通函数中，`this` 的类型默认是 `any`（严格模式下报错）。TS 允许在函数第一个参数位置声明 `this` 类型，该参数是"伪参数"，编译后会被移除，仅用于类型检查。

#### 例子

**基本函数类型**：

```typescript
// 函数声明
function add(a: number, b: number): number {
  return a + b;
}

// 函数表达式
const multiply: (a: number, b: number) => number = (a, b) => a * b;

// 类型别名
type MathOp = (a: number, b: number) => number;
const divide: MathOp = (a, b) => a / b;
```

**可选参数与默认参数**：

```typescript
function greet(name: string, greeting?: string): string {
  return `${greeting || 'Hello'}, ${name}!`;
}

function greet2(name: string, greeting: string = 'Hello'): string {
  return `${greeting}, ${name}!`;
}

greet('Alice');              // "Hello, Alice!"
greet('Alice', 'Hi');        // "Hi, Alice!"
```

**剩余参数**：

```typescript
function sum(...nums: number[]): number {
  return nums.reduce((a, b) => a + b, 0);
}
sum(1, 2, 3, 4);   // 10
```

**函数重载**：

```typescript
// 重载签名
function parse(input: string): object;
function parse(input: string, asArray: true): any[];
function parse(input: string, asArray?: boolean): object | any[] {
  if (asArray) {
    return JSON.parse(input) as any[];
  }
  return JSON.parse(input) as object;
}

const obj = parse('{"a":1}');        // object
const arr = parse('[1,2,3]', true);  // any[]
```

**`this` 类型**：

```typescript
interface Button {
  text: string;
  onClick(this: Button, event: MouseEvent): void;
}

const btn: Button = {
  text: 'Click',
  onClick(event) {
    console.log(this.text);   // OK，this 被标注为 Button
  },
};
```

**高阶函数**：

```typescript
function memoize<T extends (...args: any[]) => any>(fn: T): T {
  const cache = new Map();
  return ((...args: any[]) => {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);
    const result = fn(...args);
    cache.set(key, result);
    return result;
  }) as T;
}

const slowSquare = memoize((n: number) => n * n);
```

#### 总结

- 函数类型由参数类型和返回值类型组成，语法 `(params) => returnType`
- 可选参数 `?`、默认参数 `=`、剩余参数 `...` 都有类型支持
- 函数重载：多个重载签名 + 一个实现签名，实现签名对外不可见
- `this` 类型用伪参数声明，编译后移除，用于严格模式下的 this 检查
- 高阶函数（接收函数返回函数）配合泛型，是函数式编程的基础
- 公共 API 的函数应显式标注参数和返回值，避免依赖推断

## 第三章：进阶类型

### 第 8 讲：泛型基础

#### 概念

**泛型**（Generics）是 TypeScript 最强大的特性之一。它允许你编写**可复用的、类型无关的**代码：函数、接口或类在定义时不指定具体类型，而是用**类型变量**（type variable，通常用 `T`、`U`、`K` 等表示）作为占位符，在使用时再传入具体类型。泛型让"同一份逻辑适用于多种类型"成为可能，同时保持完整的类型安全。

可以把泛型理解为"类型的参数"——就像函数接收值参数一样，泛型接收类型参数。`Array<T>` 就是一个典型泛型：`Array<number>`、`Array<string>` 都是它的具体化。

#### 原理

泛型的核心思想是**参数化类型**。当你调用一个泛型函数时，TS 会根据传入参数的类型**自动推断**类型变量的具体类型，你也可以显式指定。泛型类型变量在函数内部可像普通类型一样使用，但受到声明时的约束。

泛型的工作流程：
1. 定义时声明类型变量：`function fn<T>(arg: T): T`
2. 调用时推断或指定类型：`fn<string>('hi')` 或 `fn('hi')`（推断为 `string`）
3. 函数体内 `T` 被替换为具体类型进行类型检查

泛型不仅用于函数，还可用于接口（`interface Box<T> { value: T }`）、类型别名（`type Box<T> = { value: T }`）和类（`class Container<T> { ... }`）。多个类型变量可以同时使用，如 `<T, U>`。

泛型与 `any` 的本质区别：`any` 放弃类型检查，而泛型**保留类型关系**——输入和输出都是同一个 `T`，编译器能追踪类型流转。

#### 例子

**泛型函数**：

```typescript
// identity 函数：返回传入的值，类型保持一致
function identity<T>(value: T): T {
  return value;
}

const num = identity<number>(42);      // 显式指定，number
const str = identity('hello');          // 类型推断，string
```

**泛型接口**：

```typescript
interface Box<T> {
  value: T;
}

const numberBox: Box<number> = { value: 123 };
const stringBox: Box<string> = { value: 'abc' };
```

**泛型类**：

```typescript
class Stack<T> {
  private items: T[] = [];

  push(item: T): void {
    this.items.push(item);
  }

  pop(): T | undefined {
    return this.items.pop();
  }
}

const numberStack = new Stack<number>();
numberStack.push(1);
numberStack.push(2);
const top = numberStack.pop();   // number | undefined
```

**多类型变量**：

```typescript
function pair<K, V>(key: K, value: V): [K, V] {
  return [key, value];
}

const p = pair('age', 30);   // [string, number]
```

**泛型在工具函数中的应用**：

```typescript
// 类型安全的 API 请求
async function fetchJSON<T>(url: string): Promise<T> {
  const res = await fetch(url);
  return res.json() as Promise<T>;
}

interface User { id: number; name: string; }
const user = await fetchJSON<User>('/api/user/1');
user.name;   // string，类型安全
```

#### 总结

- 泛型是"类型的参数"，让代码可复用且类型安全
- 类型变量（`T`、`U`、`K`）在定义时占位，使用时具体化
- 泛型可用于函数、接口、类型别名、类
- 调用时可显式指定类型，也可让 TS 根据参数推断
- 泛型 vs `any`：泛型保留类型关系，`any` 放弃类型检查
- `Array<T>`、`Promise<T>` 是最常见的内置泛型

### 第 9 讲：泛型进阶与约束

#### 概念

裸泛型 `<T>` 有一个局限：在函数体内，`T` 可以是任何类型，因此你只能访问所有类型共有的属性（实际上几乎没有）。**泛型约束**（Generic Constraints）通过 `extends` 关键字限制类型变量的范围，要求它必须满足某种结构，从而允许访问特定属性。本讲还涉及 `keyof` 操作符、泛型默认值，以及它们组合出的强大模式。

掌握泛型约束是写出高级工具类型和类型安全 API 的关键，许多内置工具类型（如 `Pick`、`Record`）都建立在约束之上。

#### 原理

**`extends` 约束**：`<T extends SomeType>` 要求 `T` 必须是 `SomeType` 的子类型（或兼容类型）。在结构化类型系统下，这意味着 `T` 必须至少拥有 `SomeType` 的所有属性。约束后，函数体内可以安全访问 `SomeType` 上的属性。

**`keyof` 操作符**：`keyof T` 获取类型 `T` 的所有属性名的联合类型。例如 `keyof {a:1, b:2}` 得到 `'a' | 'b'`。`keyof` 常与泛型约束结合，用于实现"属性访问器"模式：`function get<T, K extends keyof T>(obj: T, key: K): T[K]`，确保 `key` 是 `obj` 的合法属性，且返回类型精确到该属性的类型。

**`T[K]` 索引访问类型**：用类型 `K` 去索引类型 `T`，得到对应属性的类型。

**泛型默认值**：`<T = DefaultType>` 为类型变量提供默认类型，当调用者未指定且无法推断时使用。

#### 例子

**基本约束**：

```typescript
interface HasLength {
  length: number;
}

// T 必须有 length 属性
function logLength<T extends HasLength>(arg: T): T {
  console.log(arg.length);
  return arg;
}

logLength('hello');      // OK，string 有 length
logLength([1, 2, 3]);    // OK，数组有 length
logLength(123);          // 错误，number 没有 length
```

**`keyof` 与索引访问**：

```typescript
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const user = { name: 'Alice', age: 30, email: 'a@b.com' };

const name = getProperty(user, 'name');    // string
const age = getProperty(user, 'age');      // number
getProperty(user, 'phone');                // 错误，'phone' 不是合法 key
```

**`keyof` 实现类型安全的对象遍历**：

```typescript
function setProperty<T, K extends keyof T>(obj: T, key: K, value: T[K]): void {
  obj[key] = value;
}

const config = { host: 'localhost', port: 3000 };
setProperty(config, 'port', 8080);    // OK
setProperty(config, 'port', '8080');  // 错误，port 是 number
setProperty(config, 'debug', true);   // 错误，'debug' 不是合法 key
```

**泛型默认值**：

```typescript
interface PaginatedResponse<T = any> {
  data: T[];
  total: number;
  page: number;
}

// 不指定 T 时，data 为 any[]
const res1: PaginatedResponse = { data: [1, 'a'], total: 2, page: 1 };
// 指定 T 时，data 为 User[]
const res2: PaginatedResponse<User> = { data: [...], total: 1, page: 1 };
```

**工厂函数模式**：

```typescript
function createInstance<T>(Ctor: new () => T): T {
  return new Ctor();
}

class Person {
  greet() { console.log('Hi'); }
}

const p = createInstance(Person);   // Person
p.greet();
```

**多重约束**：

```typescript
interface Serializable {
  serialize(): string;
}
interface Cloneable {
  clone(): this;
}

function process<T extends Serializable & Cloneable>(obj: T): string {
  return obj.serialize();
}
```

#### 总结

- `extends` 约束泛型范围，约束后可访问约束类型的属性
- `keyof T` 获取属性名联合类型，是类型安全属性访问的基础
- `T[K]` 索引访问类型，精确获取属性类型
- 泛型默认值 `<T = Default>` 提供回退类型
- `getProperty`/`setProperty` 模式是 `keyof` 的经典应用
- 多重约束用交叉类型 `T extends A & B` 实现

### 第 10 讲：交叉类型与类型守卫

#### 概念

**交叉类型**（Intersection Type）用 `&` 连接多个类型，表示一个值**同时满足**所有类型——它是联合类型（"或"）的对偶，语义是"与"（AND）。**类型守卫**（Type Guard）则是用于在运行时检查类型、并在编译时**收窄**（narrow）类型范围的机制。二者配合，能优雅地处理复杂的类型组合与运行时类型判断。

类型守卫是 TS 类型系统的"动态收窄"核心：通过 `typeof`、`instanceof`、`in` 和自定义谓词函数，让编译器在条件分支内精确推断类型。

#### 原理

**交叉类型** `A & B` 的语义是：结果类型拥有 `A` 和 `B` 的**所有属性**。如果 `A` 和 `B` 有同名属性且类型冲突，该属性会变成 `never`（理论上不可赋值）。交叉类型常用于**混入**（mixin）模式——将多个能力组合到一个对象上。

**类型守卫**的工作原理是**控制流分析**（control flow analysis）。TS 编译器会跟踪代码的条件分支，在 `if`、`else if`、`else`、`switch`、三元表达式、`return`、赋值等位置收窄类型。常见的内置守卫：

1. **`typeof` 守卫**：`typeof x === 'string'`，收窄原始类型
2. **`instanceof` 守卫**：`x instanceof Date`，收窄类实例
3. **`in` 守卫**：`'name' in x`，收窄对象是否有某属性
4. **自定义类型谓词**：`x is Type`，用户定义的判断函数

**自定义类型谓词**的返回类型是 `x is Type`，告诉编译器"如果函数返回 true，则 x 是 Type 类型"。这是处理复杂类型收窄的终极武器。

#### 例子

**交叉类型**：

```typescript
interface Loggable {
  log(msg: string): void;
}
interface Serializable {
  serialize(): string;
}

// 同时拥有两个接口的所有方法
type Logger = Loggable & Serializable;

const obj: Logger = {
  log(msg) { console.log(msg); },
  serialize() { return JSON.stringify(this); },
};
```

**`typeof` 守卫**：

```typescript
function pad(value: string | number): string {
  if (typeof value === 'string') {
    // 这里 value 收窄为 string
    return value.padStart(10, '0');
  }
  // 这里 value 收窄为 number
  return value.toFixed(0).padStart(10, '0');
}
```

**`instanceof` 守卫**：

```typescript
function format(date: Date | string): string {
  if (date instanceof Date) {
    return date.toISOString();   // Date
  }
  return new Date(date).toISOString();   // string
}
```

**`in` 守卫**：

```typescript
interface Fish { swim(): void; }
interface Bird { fly(): void; }

function move(animal: Fish | Bird) {
  if ('swim' in animal) {
    animal.swim();   // Fish
  } else {
    animal.fly();    // Bird
  }
}
```

**自定义类型谓词**：

```typescript
interface ApiError { error: string; code: number; }
interface ApiSuccess { data: any; }

function isError(res: ApiError | ApiSuccess): res is ApiError {
  return (res as ApiError).error !== undefined;
}

function handle(res: ApiError | ApiSuccess) {
  if (isError(res)) {
    console.error(res.error);    // ApiError
  } else {
    console.log(res.data);       // ApiSuccess
  }
}
```

**可辨识联合 + 类型守卫**：

```typescript
type Result =
  | { ok: true; value: number }
  | { ok: false; error: string };

function process(result: Result) {
  if (result.ok) {
    console.log(result.value);   // ok 为 true 时收窄
  } else {
    console.log(result.error);
  }
}
```

#### 总结

- 交叉类型 `A & B` 表示"同时满足"，拥有所有属性，常用于 mixin
- 类型守卫通过控制流分析在条件分支内收窄类型
- 四种守卫：`typeof`（原始类型）、`instanceof`（类）、`in`（属性）、自定义谓词（`x is T`）
- 自定义谓词是处理复杂收窄的终极方案
- 可辨识联合配合 `if`/`switch` 能实现零成本的多形态处理
- 优先用类型守卫而非类型断言，前者安全、后者危险

### 第 11 讲：映射类型与条件类型

#### 概念

**映射类型**（Mapped Type）和**条件类型**（Conditional Type）是 TypeScript 类型系统的"图灵完备"基石。映射类型基于一个已有类型，**遍历其属性**生成新类型（如把所有属性变成可选、只读）。条件类型则像类型层面的"if-else"，根据类型关系选择不同的结果类型。二者结合，能实现极其强大的类型变换——这就是"类型体操"（Type Gymnastics）的基础。

掌握映射类型和条件类型，意味着你能读懂 TS 内置工具类型的源码，并编写自定义的类型变换工具。

#### 原理

**映射类型**的语法是 `{ [K in keyof T]: NewType }`，其中 `K in keyof T` 遍历 `T` 的所有属性键，`NewType` 可以引用 `K` 和原属性类型 `T[K]`。映射类型支持两个修饰符：`+`/`-` 添加或移除 `readonly` 和 `?`（可选）。例如 `-readonly` 移除只读，`-?` 移除可选。

**条件类型**的语法是 `T extends U ? X : Y`，语义是"如果 `T` 可赋值给 `U`，则结果为 `X`，否则为 `Y`"。当 `T` 是联合类型时，条件类型会**分发**（distribute）：`A | B extends U ? X : Y` 等价于 `(A extends U ? X : Y) | (B extends U ? X : Y)`。用 `[T]` 包裹可阻止分发。

**`infer` 关键字**在条件类型的 `extends` 子句中声明待推断的类型变量，常用于提取函数参数、返回值、数组元素等类型。例如 `ReturnType<T> = T extends (...args: any[]) => infer R ? R : never`。

#### 例子

**映射类型**：

```typescript
// 把所有属性变成可选（等价于内置 Partial）
type MyPartial<T> = {
  [K in keyof T]?: T[K];
};

// 把所有属性变成只读（等价于内置 Readonly）
type MyReadonly<T> = {
  readonly [K in keyof T]: T[K];
};

interface User { name: string; age: number; }
type OptionalUser = MyPartial<User>;    // { name?: string; age?: number }
type ReadonlyUser = MyReadonly<User>;   // { readonly name: string; readonly age: number }
```

**修饰符移除**：

```typescript
// 移除 readonly
type Mutable<T> = { -readonly [K in keyof T]: T[K] };
// 移除可选
type Required<T> = { [K in keyof T]-?: T[K] };

interface Props { readonly id: number; name?: string; }
type MutableProps = Mutable<Props>;     // { id: number; name?: string }
type RequiredProps = Required<Props>;   // { readonly id: number; name: string }
```

**条件类型**：

```typescript
// 判断是否是字符串
type IsString<T> = T extends string ? true : false;

type A = IsString<string>;    // true
type B = IsString<number>;    // false
type C = IsString<string | number>;  // true | false（分发）
```

**`infer` 提取类型**：

```typescript
// 提取函数返回值类型（等价于内置 ReturnType）
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never;

// 提取函数参数类型（等价于内置 Parameters）
type MyParameters<T> = T extends (...args: infer P) => any ? P : never;

// 提取 Promise 的内部类型
type Unpacked<T> = T extends Promise<infer U> ? U : T;

type R = MyReturnType<() => string>;          // string
type P = MyParameters<(a: number, b: string) => void>;  // [number, string]
type U = Unpacked<Promise<number>>;           // number
```

**键重映射**（TS 4.1+）：

```typescript
// 给所有属性名加前缀
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

interface Person { name: string; age: number; }
type PersonGetters = Getters<Person>;
// { getName: () => string; getAge: () => number }
```

**实战：深度 Partial**：

```typescript
type DeepPartial<T> = {
  [K in keyof T]?: T[K] extends object ? DeepPartial<T[K]> : T[K];
};

interface Config {
  server: { host: string; port: number };
  debug: boolean;
}
type PartialConfig = DeepPartial<Config>;
// { server?: { host?: string; port?: number }; debug?: boolean }
```

#### 总结

- 映射类型 `[K in keyof T]: ...` 遍历属性生成新类型，是工具类型的基础
- 修饰符 `+`/`-` 控制 `readonly` 和 `?` 的添加与移除
- 条件类型 `T extends U ? X : Y` 是类型层面的 if-else
- 联合类型在条件类型中会**分发**，用 `[T]` 阻止分发
- `infer` 在条件类型中提取子类型，是 `ReturnType`、`Parameters` 的核心
- 键重映射 `as` 可变换属性名，配合模板字面量类型实现强大变换
- 这两特性是"类型体操"的基础，能实现编译时的复杂类型计算

## 第四章：高级特性

### 第 12 讲：装饰器（Decorators）

#### 概念

**装饰器**（Decorator）是一种特殊的声明，用 `@` 符号标记，可以附加到类、方法、属性、访问器、参数上，以修改或扩展它们的行为。装饰器本质是一个**高阶函数**：接收目标对象，返回修改后的对象。装饰器是实验性特性（TS 5.0 后已稳定支持 Stage 3 装饰器），在 NestJS、TypeORM、Angular 等框架中广泛使用。

装饰器实现了**面向切面编程**（AOP）的思想：将日志、权限、缓存等横切关注点与业务逻辑分离，通过声明式方式注入。

#### 原理

装饰器按位置分为五类：
1. **类装饰器**：应用于类构造函数，接收 `constructor`，返回新构造函数
2. **方法装饰器**：接收 `(target, propertyKey, descriptor)`，可修改方法行为
3. **属性装饰器**：接收 `(target, propertyKey)`，常配合元数据反射
4. **访问器装饰器**：类似方法装饰器，应用于 getter/setter
5. **参数装饰器**：接收 `(target, propertyKey, parameterIndex)`，常用于参数注入

装饰器的执行顺序：实例属性 → 实例方法 → 访问器 → 参数 → 类装饰器（自下而上）。多个装饰器叠加时，从上到下求值，从下到上执行。

装饰器常配合 `reflect-metadata` 库实现**运行时元数据**：通过 `Reflect.defineMetadata`/`Reflect.getMetadata` 存取类型信息，实现依赖注入（DI）。NestJS 的 `@Injectable()`、`@Controller()` 就是基于此机制。

注意：旧版装饰器（`experimentalDecorators: true`）与 TS 5.0 的标准装饰器语法略有差异，本讲以旧版（更广泛使用）为主。

#### 例子

**类装饰器**：

```typescript
// 添加日志能力的类装饰器
function logged<T extends new (...args: any[]) => any>(constructor: T) {
  return class extends constructor {
    created = new Date().toISOString();
  };
}

@logged
class Service {
  constructor(public name: string) {}
}

const s = new Service('API');
console.log(s.name, s.created);   // 'API' '2026-...'
```

**方法装饰器**：

```typescript
// 日志装饰器：自动记录方法调用
function log(target: any, key: string, desc: PropertyDescriptor) {
  const original = desc.value;
  desc.value = function (...args: any[]) {
    console.log(`调用 ${key}，参数:`, args);
    const result = original.apply(this, args);
    console.log(`返回:`, result);
    return result;
  };
}

class Calculator {
  @log
  add(a: number, b: number): number {
    return a + b;
  }
}

new Calculator().add(1, 2);
// 调用 add，参数: [1, 2]
// 返回: 3
```

**属性装饰器 + 元数据**（依赖注入雏形）：

```typescript
import 'reflect-metadata';

function Inject(token: string) {
  return (target: any, key: string) => {
    // 在类实例化时注入对应依赖
    Object.defineProperty(target, key, {
      get() {
        return container.get(token);
      },
    });
  };
}

class UserService {
  @Inject('Logger') logger: Logger;

  getUser(id: number) {
    this.logger.log(`获取用户 ${id}`);
  }
}
```

**参数装饰器**（NestJS 风格）：

```typescript
function Body() {
  return (target: any, key: string, index: number) => {
    Reflect.defineMetadata('param:body', index, target, key);
  };
}

class UserController {
  create(@Body() body: any) {
    return body;
  }
}
```

**装饰器工厂**（带参数的装饰器）：

```typescript
function Route(path: string) {
  return (target: any, key: string, desc: PropertyDescriptor) => {
    Reflect.defineMetadata('route', path, target, key);
  };
}

class UserController {
  @Route('/users/:id')
  getUser() {}

  @Route('/users')
  list() {}
}
```

#### 总结

- 装饰器用 `@` 标记，是高阶函数，可附加到类、方法、属性、访问器、参数
- 五类装饰器：类、方法、属性、访问器、参数，各有不同参数签名
- 装饰器工厂返回真正的装饰器函数，用于接收配置参数
- 配合 `reflect-metadata` 可实现运行时元数据，是依赖注入的基础
- NestJS、TypeORM、Angular 大量使用装饰器
- TS 5.0 支持标准 Stage 3 装饰器，旧版需 `experimentalDecorators: true`
- 装饰器实现 AOP，将横切关注点（日志、权限、缓存）与业务逻辑解耦

### 第 13 讲：模块与命名空间

#### 概念

TypeScript 的模块系统建立在 ES Module 之上，通过 `import`/`export` 组织代码。除了标准模块，TS 还保留了早期的**命名空间**（namespace）机制，以及用于描述 JS 库类型的**声明文件**（`.d.ts`）。理解模块解析、声明文件编写和 `declare` 关键字，是工程化 TS 项目的必备知识。

现代 TS 项目几乎都使用 ES Module，命名空间主要用于向后兼容或全局脚本场景。声明文件则是 TS 与 JS 生态的桥梁——为没有类型定义的 JS 库补充类型。

#### 原理

**ES Module**：每个 `.ts`/`.tsx` 文件默认是一个模块。`export` 导出，`import` 导入。TS 支持具名导出、默认导出、命名空间导出、类型导出（`export type`）。

**模块解析策略**：TS 提供两种解析策略：
1. **Classic**（旧版）：主要用于 AMD/SystemJS，较少使用
2. **Node**（推荐）：模拟 Node.js 的解析逻辑，支持 `node_modules` 查找、`index.ts`、`package.json` 的 `types` 字段

**声明文件**（`.d.ts`）：仅包含类型声明，无实现代码。用 `declare` 关键字描述已存在的 JS 变量、函数、类、模块。`@types/xxx` 包就是社区维护的声明文件集合。`declare global` 可扩展全局类型，`declare module 'xxx'` 可为无类型模块补充声明。

**命名空间**（namespace）：用 `namespace` 关键字定义全局命名空间，通过 `export` 暴露内部成员。命名空间编译后会生成真实的 JS 对象（与模块不同，模块编译后是闭包）。现代项目不推荐使用命名空间，应优先用模块。

**三斜线指令**（`/// <reference ... />`）：早期 TS 的依赖声明方式，现已基本被 `import` 取代，仅在编写 `.d.ts` 时偶尔使用。

#### 例子

**ES Module 导入导出**：

```typescript
// math.ts
export function add(a: number, b: number): number {
  return a + b;
}

export const PI = 3.14;

export default function multiply(a: number, b: number): number {
  return a * b;
}

// app.ts
import multiply, { add, PI } from './math';
import * as Math from './math';
import type { add as AddType } from './math';   // 仅导入类型
```

**声明文件**：

```typescript
// global.d.ts —— 为全局变量补充类型
declare const __DEV__: boolean;
declare function gtag(...args: any[]): void;

// 使用时无需 import
if (__DEV__) { console.log('开发模式'); }
```

**为 JS 模块补充类型**：

```typescript
// old-lib.d.ts
declare module 'old-lib' {
  export function doSomething(input: string): boolean;
  export const version: string;
}

// 使用
import { doSomething } from 'old-lib';
doSomething('hi');   // 类型安全
```

**扩展第三方类型**：

```typescript
// 扩展 Express 的 Request
declare module 'express' {
  interface Request {
    user?: { id: string; name: string };
  }
}

// 使用
app.get('/', (req, res) => {
  req.user?.name;   // 类型安全
});
```

**命名空间**（了解即可）：

```typescript
namespace Validation {
  export interface StringValidator {
    isValid(s: string): boolean;
  }

  const lettersRegexp = /^[A-Za-z]+$/;

  export class LettersOnlyValidator implements StringValidator {
    isValid(s: string) {
      return lettersRegexp.test(s);
    }
  }
}

const v = new Validation.LettersOnlyValidator();
```

**模块解析配置**（tsconfig.json 片段）：

```json
{
  "compilerOptions": {
    "moduleResolution": "node",
    "baseUrl": "./src",
    "paths": {
      "@/*": ["*"]
    }
  }
}
```

#### 总结

- 现代 TS 使用 ES Module，`import`/`export` 组织代码
- 模块解析推荐 `node` 策略，`baseUrl` + `paths` 配置路径别名
- 声明文件 `.d.ts` 用 `declare` 描述 JS 类型，是 TS 与 JS 生态的桥梁
- `@types/xxx` 提供主流库的声明，缺类型时可自己写 `.d.ts`
- `declare module` 扩展第三方模块类型，`declare global` 扩展全局
- 命名空间是旧机制，现代项目应优先用模块
- 三斜线指令基本被 import 取代，仅在 `.d.ts` 中偶尔使用

### 第 14 讲：类型体操与内置工具类型

#### 概念

**工具类型**（Utility Types）是 TS 内置的类型变换工具，基于映射类型和条件类型实现。它们像"类型层面的函数"，接收类型参数，返回新类型。**类型体操**（Type Gymnastics）则指利用 TS 类型系统编写复杂类型变换的技巧，是高级 TS 开发者的必修课。

掌握工具类型能让你避免重复造轮子，而理解类型体操则让你能编写自定义工具类型，解决业务中的类型变换需求。

#### 原理

TS 内置约 20 个工具类型，按功能分类：

**属性变换类**：
- `Partial<T>`：所有属性变可选
- `Required<T>`：所有属性变必选
- `Readonly<T>`：所有属性变只读
- `Mutable<T>`（非内置，需自定义）：移除只读

**属性筛选类**：
- `Pick<T, K>`：从 T 中挑选属性 K
- `Omit<T, K>`：从 T 中排除属性 K
- `Record<K, V>`：构造属性键为 K、值为 V 的对象类型

**联合类型操作**：
- `Exclude<T, U>`：从联合 T 中排除可赋值给 U 的成员
- `Extract<T, U>`：从联合 T 中提取可赋值给 U 的成员
- `NonNullable<T>`：排除 null 和 undefined

**函数相关**：
- `Parameters<T>`：提取函数参数类型（元组）
- `ReturnType<T>`：提取函数返回值类型
- `ConstructorParameters<T>`：构造函数参数类型
- `InstanceType<T>`：构造函数实例类型

**其他**：
- `Awaited<T>`：递归解包 Promise
- `Uppercase`/`Lowercase`/`Capitalize`/`Uncapitalize`：字符串字面量变换

类型体操的核心技巧：递归类型、条件类型分发、`infer` 提取、模板字面量类型、映射类型修饰符。这些技巧组合，能实现编译时的任意类型计算。

#### 例子

**属性变换工具**：

```typescript
interface User {
  id: number;
  name: string;
  email?: string;
}

type PartialUser = Partial<User>;       // { id?: number; name?: string; email?: string }
type RequiredUser = Required<User>;     // { id: number; name: string; email: string }
type ReadonlyUser = Readonly<User>;     // 所有属性只读
```

**属性筛选工具**：

```typescript
interface User {
  id: number;
  name: string;
  email: string;
  password: string;
}

type PublicUser = Pick<User, 'id' | 'name' | 'email'>;
// { id: number; name: string; email: string }

type SafeUser = Omit<User, 'password'>;
// { id: number; name: string; email: string }

type UserMap = Record<string, User>;    // { [key: string]: User }
```

**联合类型操作**：

```typescript
type T = 'a' | 'b' | 'c';
type U = 'a' | 'b';

type Excluded = Exclude<T, U>;     // 'c'
type Extracted = Extract<T, U>;    // 'a' | 'b'

type Maybe = string | null | undefined;
type NonNull = NonNullable<Maybe>; // string
```

**函数相关工具**：

```typescript
function greet(name: string, age: number): string {
  return `Hi ${name}, ${age}`;
}

type Params = Parameters<typeof greet>;    // [string, number]
type Return = ReturnType<typeof greet>;    // string

class Person { constructor(public name: string) {} }
type CtorParams = ConstructorParameters<typeof Person>;  // [string]
type Instance = InstanceType<typeof Person>;             // Person
```

**`Awaited` 解包 Promise**：

```typescript
type T1 = Awaited<Promise<string>>;           // string
type T2 = Awaited<Promise<Promise<number>>>;  // number（递归解包）
```

**自定义工具类型（类型体操）**：

```typescript
// 深度只读
type DeepReadonly<T> = {
  readonly [K in keyof T]: T[K] extends object ? DeepReadonly<T[K]> : T[K];
};

// 获取对象所有函数的键
type FunctionKeys<T> = {
  [K in keyof T]: T[K] extends Function ? K : never;
}[keyof T];

// 路径类型（如 'a.b.c'）
type Path<T> = T extends object
  ? { [K in keyof T & string]: K | `${K}.${Path<T[K]>}` }[keyof T & string]
  : never;

interface Data { user: { name: string; age: number } }
type DataPath = Path<Data>;   // 'user' | 'user.name' | 'user.age'
```

**实战：API 响应包装**：

```typescript
type ApiResponse<T> = {
  code: number;
  message: string;
  data: T;
};

type Paginated<T> = {
  list: T[];
  total: number;
  page: number;
};

// 组合使用
type UserListResponse = ApiResponse<Paginated<User>>;
```

#### 总结

- 工具类型是"类型层面的函数"，基于映射类型和条件类型实现
- 属性变换：`Partial`、`Required`、`Readonly`
- 属性筛选：`Pick`、`Omit`、`Record`
- 联合操作：`Exclude`、`Extract`、`NonNullable`
- 函数相关：`Parameters`、`ReturnType`、`ConstructorParameters`、`InstanceType`
- `Awaited` 递归解包 Promise，处理异步类型
- 类型体操技巧：递归、`infer`、模板字面量、条件分发
- 自定义工具类型能解决业务中的类型变换需求，如深度只读、路径类型等

### 第 15 讲：tsconfig 配置详解

#### 概念

`tsconfig.json` 是 TypeScript 项目的核心配置文件，控制编译器的行为：编译目标、模块系统、严格级别、路径解析、输出目录等。合理的 tsconfig 配置能提升类型安全性、优化构建产物、改善开发体验。本讲详解最常用的配置项，并给出推荐配置。

tsconfig 有上百个选项，但日常开发只需关注其中 20 个左右。理解这些核心配置，足以应对绝大多数项目需求。

#### 原理

tsconfig 的配置分为几大类：

1. **编译目标与模块**：`target`（JS 版本）、`module`（模块系统）、`lib`（可用 API 类型）
2. **严格模式**：`strict`（总开关）及其子选项（`noImplicitAny`、`strictNullChecks` 等）
3. **模块解析**：`moduleResolution`、`baseUrl`、`paths`、`rootDirs`
4. **输出控制**：`outDir`、`rootDir`、`sourceMap`、`declaration`
5. **工程检查**：`noUnusedLocals`、`noUnusedParameters`、`noFallthroughCasesInSwitch`
6. **JS 互操作**：`allowJs`、`checkJs`、`esModuleInterop`
7. **实验特性**：`experimentalDecorators`、`emitDecoratorMetadata`

`strict: true` 等价于开启一组严格选项，是现代项目的标配。`esModuleInterop` 解决 CommonJS 与 ES Module 互操作问题，导入 React 等库时必需。

#### 例子

**基础配置**：

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "ESNext",
    "moduleResolution": "node",
    "lib": ["ES2020", "DOM", "DOM.Iterable"],
    "jsx": "react-jsx",

    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noFallthroughCasesInSwitch": true,
    "noImplicitReturns": true,

    "esModuleInterop": true,
    "allowSyntheticDefaultImports": true,
```

### 第 16 讲：TypeScript 与面向对象编程

#### 概念

TypeScript 完整支持**面向对象编程**（OOP）的四大特性：封装、继承、多态、抽象。它提供了类（`class`）、访问修饰符（`public`/`private`/`protected`）、抽象类（`abstract`）、接口实现（`implements`）、泛型类等能力。虽然 TS 的类型系统在运行时会被擦除，但 OOP 的代码结构会保留在编译后的 JS 中。

掌握 TS 的 OOP 特性，能帮助你设计出结构清晰、可扩展、易维护的领域模型，尤其在复杂业务系统、游戏开发、Node.js 后端等场景中价值显著。

#### 原理

TS 类的核心特性：

1. **访问修饰符**：`public`（默认，公开）、`private`（仅类内）、`protected`（类内及子类）。TS 4.0+ 还支持 `#` 私有字段（运行时真正私有）。
2. **`readonly` 修饰符**：属性只读，只能在构造函数中赋值。
3. **参数属性**：构造函数参数加修饰符，自动创建并赋值同名属性，简化样板代码。
4. **抽象类**：用 `abstract` 声明，不能直接实例化，只能被继承。抽象方法由子类实现。
5. **接口实现**：`class Foo implements IFoo`，类必须满足接口契约。一个类可实现多个接口。
6. **继承**：`class Dog extends Animal`，单继承，子类获得父类所有成员。
7. **存取器**：`get`/`set` 实现属性拦截，可在读写时执行逻辑。

TS 的 OOP 与 Java/C# 接近，但有一个关键区别：TS 的 `private`/`protected` 是**编译时检查**，运行时无效（编译后变成普通属性）。要实现运行时私有，需用 `#` 私有字段。

#### 例子

**基本类与参数属性**：

```typescript
class User {
  // 参数属性：自动创建并赋值
  constructor(
    public readonly id: number,
    public name: string,
    private email: string,
  ) {}

  get displayEmail(): string {
    return this.email.replace(/(.{2}).*@/, '$1***@');
  }

  set setEmail(value: string) {
    if (!value.includes('@')) throw new Error('无效邮箱');
    this.email = value;
  }
}

const user = new User(1, 'Alice', 'alice@example.com');
console.log(user.name, user.displayEmail);   // Alice al***@example.com
```

**继承与多态**：

```typescript
abstract class Animal {
  constructor(public name: string) {}

  abstract speak(): string;   // 抽象方法，子类必须实现

  move(distance: number): string {
    return `${this.name} 移动了 ${distance} 米`;
  }
}

class Dog extends Animal {
  speak(): string {
    return `${this.name}: 汪汪！`;
  }
}

class Cat extends Animal {
  speak(): string {
    return `${this.name}: 喵喵！`;
  }
}

// 多态：同一接口，不同行为
const animals: Animal[] = [new Dog('Rex'), new Cat('Tom')];
animals.forEach(a => console.log(a.speak()));
```

**接口实现**：

```typescript
interface Serializable {
  serialize(): string;
}

interface Comparable<T> {
  compareTo(other: T): number;
}

class Product implements Serializable, Comparable<Product> {
  constructor(
    public id: number,
    public name: string,
    public price: number,
  ) {}

  serialize(): string {
    return JSON.stringify({ id: this.id, name: this.name, price: this.price });
  }

  compareTo(other: Product): number {
    return this.price - other.price;
  }
}

const products = [
  new Product(1, 'A', 100),
  new Product(2, 'B', 50),
];
products.sort((a, b) => a.compareTo(b));
```

**运行时私有字段**：

```typescript
class BankAccount {
  #balance: number;   // 真正私有，运行时也无法访问

  constructor(initial: number) {
    this.#balance = initial;
  }

  deposit(amount: number) {
    this.#balance += amount;
  }

  get balance() {
    return this.#balance;
  }
}

const acc = new BankAccount(100);

console.log(acc.balance);      // 150
// acc.#balance;  // 错误，外部无法访问
```

**泛型类与工厂模式**：

```typescript
abstract class Repository<T extends { id: number }> {
  protected items: T[] = [];

  add(item: T): void {
    this.items.push(item);
  }

  findById(id: number): T | undefined {
    return this.items.find(i => i.id === id);
  }

  abstract validate(item: T): boolean;
}

class UserRepository extends Repository<User> {
  validate(user: User): boolean {
    return user.name.length > 0;
  }
}
```

#### 总结

- TS 完整支持 OOP 四大特性：封装、继承、多态、抽象
- 访问修饰符 `public`/`private`/`protected` 是编译时检查，`#` 字段是运行时私有
- 参数属性简化构造函数样板代码：`constructor(public name: string)`
- 抽象类用 `abstract` 声明，不能实例化，抽象方法由子类实现
- 接口实现 `implements` 可多实现，类必须满足接口契约
- 存取器 `get`/`set` 实现属性拦截
- 泛型类配合抽象方法，可实现仓储模式、工厂模式等设计模式
- OOP 适合复杂领域建模，但不要过度设计——简单场景用函数和类型即可

### 第 17 讲：TypeScript 在前端框架中的应用

#### 概念

TypeScript 已成为现代前端开发的标配，React、Vue、Angular 三大框架都提供一流的 TS 支持。本讲聚焦如何在真实框架中落地 TypeScript：React 的组件 Props/State 类型、Hooks 类型、事件类型；Vue 3 的 Composition API 类型、`defineProps`/`defineEmits` 类型；以及通用的 API 请求层类型设计。

掌握框架中的 TS 实践，能让你写出类型安全的前端代码，在重构时获得编译器保驾护航，大幅减少运行时错误。

#### 原理

**React + TS** 的核心是函数组件的 Props 类型标注。React 18+ 推荐用 `React.FC<Props>` 或直接 `function Comp(props: Props)`。Hooks 的类型由 TS 自动推断，自定义 Hook 应显式标注返回类型。事件类型如 `React.ChangeEvent<HTMLInputElement>` 提供精确的 DOM 事件类型。

**Vue 3 + TS** 的核心是 `<script setup lang="ts">`。`defineProps<T>()` 用泛型定义 Props 类型，`defineEmits<T>()` 定义事件类型。Vue 的响应式 API（`ref`、`computed`、`reactive`）都有完整的类型推断。

**API 请求层**的通用模式：用泛型封装请求函数，结合可辨识联合表达请求状态（loading/success/error），实现端到端类型安全——从后端响应类型到组件渲染数据，全链路类型贯通。

#### 例子

**React 函数组件与 Props**：

```tsx

    setFollowing(!following);
    onFollow?.(user.id);
  };

  return (
    <div className={`card card-${size}`}>
      <img src={user.avatar} alt={user.name} />
      <h3>{user.name}</h3>
      <button onClick={handleClick}>
        {following ? '已关注' : '关注'}
      </button>
    </div>
  );
}
```

**自定义 Hook 类型**：


**请求状态的可辨识联合**：

```typescript
type AsyncState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: string };

function useAsync<T>(fn: () => Promise<T>) {
  const state = ref<AsyncState<T>>({ status: 'idle' });

  const run = async () => {
    state.value = { status: 'loading' };
    try {
      const data = await fn();
      state.value = { status: 'success', data };
    } catch (e) {
      state.value = { status: 'error', error: (e as Error).message };
    }
  };

  return { state, run };
}

// 使用：状态收窄后访问 data 安全
const { state } = useAsync(() => api.getUser(1));
if (state.value.status === 'success') {
  console.log(state.value.data.name);   // 类型安全
}
```

- `withDefaults` 为 Props 提供默认值
- API 请求层用泛型封装，实现后端响应到组件的全链路类型安全
- 可辨识联合表达异步状态（idle/loading/success/error），收窄后访问数据安全
- 框架 + TS 的核心：让类型贯穿数据流，编译时消灭运行时错误

### 第 18 讲：类型安全的项目实践与最佳实践

#### 概念

掌握 TS 语法只是起点，真正的挑战在于**如何在真实项目中设计类型、组织类型、维护类型**。本讲总结类型安全的工程实践：类型设计原则、第三方类型管理、类型与运行时校验的结合、常见反模式与规避、团队协作规范。这些经验来自大量真实项目的沉淀，能帮助你避免踩坑，写出可维护的类型代码。

类型安全不是"类型越多越好"，而是"在关键边界用类型约束，在内部让推断工作"。好的类型设计应该既严格又灵活，既安全又不过度复杂。

#### 原理

**类型设计原则**：
1. **单一职责**：一个类型只描述一个概念，避免"上帝类型"
2. **组合优于继承**：用交叉类型、联合类型组合，而非深层继承
3. **精确优于宽泛**：用字面量类型、可辨识联合代替宽泛的 string
4. **边界严格，内部灵活**：API 边界显式标注，内部让推断工作
5. **避免 `any`**：用 `unknown` + 类型守卫替代，保留类型检查

**类型与运行时校验**：TS 类型在编译后被擦除，无法在运行时校验外部数据（如 API 响应、用户输入）。解决方案是用 **Zod**、**io-ts**、**class-validator** 等库，从运行时校验器推导 TS 类型，实现"单一数据源"——校验器即类型。

**第三方类型管理**：优先用 `@types/xxx`，缺类型时自己写 `.d.ts`。`skipLibCheck` 可跳过 `.d.ts` 检查加速编译。`@ts-expect-error` 用于临时绕过第三方类型错误，但应定期清理。

**常见反模式**：
- 滥用 `any` 和 `as` 断言
- 类型定义与运行时数据脱节
- 过度复杂的类型体操（难以维护）
- 在热路径上做运行时类型检查

#### 例子

**用 Zod 实现运行时校验 + 类型推导**：

```typescript
import { z } from 'zod';

// 1. 定义 Schema（单一数据源）
const UserSchema = z.object({
  id: z.number(),
  name: z.string().min(1).max(50),
  email: z.string().email(),
  age: z.number().int().min(0).max(150).optional(),
  role: z.enum(['admin', 'user', 'guest']),
});

// 2. 从 Schema 推导 TS 类型
type User = z.infer<typeof UserSchema>;
// 等价于:
// { id: number; name: string; email: string; age?: number; role: 'admin' | 'user' | 'guest' }

// 3. 运行时校验外部数据
function fetchUser(id: number): Promise<User> {
  return fetch(`/api/users/${id}`)
    .then(res => res.json())
    .then(data => UserSchema.parse(data));   // 校验失败抛错
}

// 4. 类型安全使用
const user = await fetchUser(1);
user.role;   // 'admin' | 'user' | 'guest'
```

**避免 `any`，用 `unknown` + 守卫**：

```typescript
// ❌ any 放弃类型检查
function parseAny(data: any) {
  return data.user.name;   // 运行时可能崩溃
}

// ✅ unknown + 类型守卫
function parseSafe(data: unknown): string {
  if (typeof data === 'object' && data !== null && 'user' in data) {
    const user = (data as any).user;
    if (typeof user?.name === 'string') {
      return user.name;
    }
  }
  throw new Error('Invalid data');
}

// ✅ 更优：用 Zod
const parseWithZod = (data: unknown): string => {
  return UserSchema.parse(data).name;
};
```

- 类型设计原则：单一职责、组合优于继承、精确优于宽泛、边界严格内部灵活
- 用 Zod 等库实现"校验器即类型"，解决运行时校验与编译时类型的脱节

- `@ts-expect-error` 临时绕过需注释原因，定期清理
- 团队应建立 TS 规范：禁用 any、统一 interface/type 使用场景、类型文件组织
- 类型安全的终极目标：让编译器在编译时消灭运行时错误，让重构有据可依

## 课程结语

恭喜你完成了 TypeScript 系统教程的全部 18 讲！从最基础的类型注解，到高级的类型体操，再到真实项目的工程实践，你已经具备了系统运用 TypeScript 的能力。

**TypeScript 的核心价值**不在于"多写类型注解"，而在于用类型系统**表达业务约束**、**消灭运行时错误**、**提升代码可维护性**。好的 TS 代码，是类型与逻辑的和谐统一——类型为逻辑服务，逻辑受类型保护。

**持续精进的路径**：
1. **多读优秀源码**：阅读 `@types/react`、`zod`、`tRPC` 等库的类型定义，学习类型设计
2. **刻意练习类型体操**：在 type-challenges 网站刷题，提升类型编程能力
3. **在真实项目中实践**：把所学应用到工作项目，从错误中学习
4. **关注社区动态**：TS 每年发布新版本，跟进新特性（如装饰器、`satisfies`、`const` 类型参数等）

类型安全是一场没有终点的修行。愿你在 TypeScript 的世界里，写出既严谨又优雅的代码。
